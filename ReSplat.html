ReSplat 把"前馈一次性预测"和"基于渲染误差的迭代修正"统一进同一个可微网络：先用紧凑初始化得到少量高斯，再在每一轮把输入视图上的 RGB 差与冻结 ResNet 特征差投影回 3D，经多视图注意力聚合后，由一个共享权重的循环模块预测高斯参数增量与循环状态，从而在固定高斯集合上逼近优化式 3DGS 的质量，同时把重建时间压到亚秒级。

01研究背景与动机

新视角合成（Novel View Synthesis, NVS）的目标是：给定一组已知相机位姿的输入图像，重建出场景的几何与外观表示，并能从任意未见视角渲染出照片级真实的图像。2023 年提出的 3D Gaussian Splatting（3DGS） 用一组各向异性的 3D 高斯作为场景表示，配合可微光栅化器，在质量和速度上同时超越了 NeRF 类方法，迅速成为实时 NVS 的事实标准。

但经典 3DGS 是一个逐场景优化范式：需要从 SfM 点云初始化，然后对每个场景单独跑数千步梯度下降，过程中不断分裂、克隆、修剪高斯（自适应稠密化，densification）。这意味着每个新场景都要付出分钟级到小时级的优化成本，无法做到"输入即出"。

为了解决这一瓶颈，前馈式（feed-forward）重建方法应运而生：训练一个大型网络，在测试时一次性直接预测出场景的高斯或神经场。DepthSplat、Scaffold-GS、FSGS 等工作在这条路线上取得了显著进展，但它们通常面临一个核心矛盾——高斯数量与表达能力的权衡：要覆盖整个场景，要么预测海量逐像素高斯（计算与显存昂贵），要么用稀疏高斯（细节丢失）。

ReSplat 的出发点是：能否兼得两者之长？既保留前馈方法"一次前向即可用"的速度，又获得优化式方法"迭代修正、越渲越准"的质量。作者给出的答案是——把迭代修正本身变成网络的一部分：网络不直接输出最终高斯，而是输出"当前高斯应该往哪个方向改"，每一轮都用渲染结果与真值的差作为监督信号，循环若干次。

关键区别：经典 3DGS 的迭代是"对损失做梯度下降"，而 ReSplat 的迭代是"网络预测参数增量"。前者每步都要反传渲染器梯度，后者是纯前向预测；前者会自适应增删高斯，后者高斯集合固定。因此 ReSplat 被称为 gradient-free test-time adaptation——测试时没有显式的梯度优化，但训练时仍然用反向传播学习这个"预测增量"的能力。

023D 高斯泼溅预备知识

理解 ReSplat 前，先明确 3DGS 的基本表示。一个 3D 高斯由中心、不透明度、协方差和球谐颜色四元组描述：

$$\mathcal{G}=\{(\mu_j,\alpha_j,\Sigma_j,\mathrm{sh}_j)\}_{j=1}^{M},\qquad \mu_j\in\mathbb{R}^3,\ \alpha_j\in\mathbb{R},\ \Sigma_j\in\mathbb{R}^{3\times3},\ \mathrm{sh}_j\in\mathbb{R}^{3\times16}$$

其中 $M$ 是高斯总数，$\mathrm{sh}_j$ 是 $3\times 16$ 的球谐系数（sh_degree=3 时每个颜色通道有 $(3+1)^2=16$ 个系数）。高斯的各向异性形状由协方差矩阵 $\Sigma$ 决定，它由尺度向量 $s\in\mathbb{R}^3$ 和单位四元数 $q\in\mathbb{R}^4$ 构造：

$$\Sigma = R\,S\,S^\top R^\top,\qquad S=\mathrm{diag}(s_1,s_2,s_3),\quad R=R(q)$$

渲染时，世界系下的 3D 高斯先投影到相机系，再经雅可比 $J$ 映射到 2D 图像平面，得到 2D 协方差 $\Sigma'$，并加入一个小的各向同性正则项（代码中 eps2d=0.1）防止退化。最终每个像素的颜色由沿视线从前到后的 alpha 合成得到：

$$C = \sum_{i} c_i\,\alpha_i \prod_{j

同理可渲染期望深度。ReSplat 直接复用 gsplat 的 rasterization 作为可微渲染器，使用 rasterize_mode="antialiased" 与 render_mode="RGB+ED"（同时输出 RGB 与期望深度），并开启 packed=True 以减少显存。

03整体架构总览

ReSplat 的输入是 $N$ 张有位姿图像及其内参、外参，输出是一组可渲染的 3D 高斯：

$$\{I_i,K_i,R_i,t_i\}_{i=1}^{N} \;\longrightarrow\; \{(p_j,f_j)\}_{j=1}^{M}$$

整个系统由四个核心模块串成一个循环：紧凑初始化给出初始高斯 $\mathcal{G}^0$，渲染得到输入视角的预测图像，与真值计算渲染误差，误差经多视图聚合后送入循环更新模块预测增量，得到 $\mathcal{G}^{t+1}$。如此往复 $T$ 轮。

两个贯穿全文的设计选择

  • 固定高斯集合：循环过程只修改高斯的属性（中心、尺度、旋转、不透明度、球谐），不做 3DGS 式的 densification / pruning。$M$ 在初始化时就确定。
  • 两阶段训练：先训练初始化网络（num_refine=0），再冻结非循环参数、单独训练更新模块。这避免了"初始化还没学好，更新模块就学不动"的耦合问题。

04Compact Gaussian Initialization

前馈方法通常在每个输入视图的每个像素上预测一个或多个高斯，导致 $M$ 随分辨率暴涨。ReSplat 的初始化只在一个下采样后的潜在网格上预测高斯，从而把高斯数量压到原来的 $1/16$。

设输入图像分辨率为 $H\times W$，潜在特征下采样倍数为 $s$（默认 latent_downsample=4），每个潜在点预测的高斯倍数为 $q$（默认 init_gaussian_multiple=1），则 $N$ 个视图产生的高斯总数为：

$$M = N \cdot \frac{H}{s} \cdot \frac{W}{s} \cdot q$$
重要：16× 缩减只适用于主多视图配置，不通用。论文默认 $s=4,\ q=1$ 时 $M=NHW/16$（比逐像素少 16×）。但官方发布的 RealEstate10K 两视图脚本用了不同组合：
  • 初始化脚本：latent_downsample=4，init_gaussian_multiple=16 → $M=NHW$
  • 循环精修脚本：latent_downsample=2，init_gaussian_multiple=4 → $M=NHW$
两者都得到逐像素量级的高斯，但下采样率和倍数不同。因此不能笼统说"ReSplat 总是用 16× 更少的高斯"。

初始高斯的 59 维参数

每个高斯的原始回归向量 $g_j^0\in\mathbb{R}^{59}$ 由以下部分拼接而成（sh_degree=3）：

  • 中心 $\mu$：3 维（由 2D 像素坐标 + 预测深度反投影得到，代码中还有 2 维 offset 精修）
  • 尺度 $s$：3 维
  • 四元数 $q$（未归一化）：4 维
  • 不透明度 logit：1 维
  • 球谐系数：$3\times(3+1)^2=48$ 维

源码中这一切分由 raw_gaussians.split 完成，随后做尺度约束、四元数归一化、世界系协方差构造、以及从射线反投影求中心：

053D Context Aggregation

紧凑初始化只在稀疏网格上预测，每个潜在点的感受野有限，容易丢失跨视图、跨空间的信息。为此 ReSplat 在初始化和循环更新中都插入了一个交替式上下文聚合模块：局部 kNN 注意力 + 多视图全局注意力交替堆叠。

局部 kNN 注意力

对每个 3D 点，在其 $k$ 个最近邻（默认初始化 knn_samples=16，循环 refine_knn_samples=8）内做注意力。这捕捉局部几何与外观的一致性：

$$\mathrm{out}_i = \sum_{j\in\mathcal{N}_k(i)} \mathrm{softmax}\!\left(\frac{q_i^\top k_j}{\sqrt{d}}\right) v_j$$

源码中 KNNAttention 的核心就是这段缩放点积：

src/model/encoder/point_transformer/layer.py — KNNAttention
scores = torch.matmul(
    x_q.unsqueeze(1),
    x_k.permute(0, 2, 1)
) * scale_factor
out = torch.matmul(
    torch.softmax(scores, dim=2), x_v
).squeeze(1)

多视图全局注意力

单靠局部 kNN 无法让相距较远的同一物体的多个视图互通信息。MultViewLowresAttn 先把每个视图的 token 分辨率降下来，做一次全局自注意力，再升回原分辨率，从而以可接受的成本实现跨视图全局信息交换。

初始化阶段默认用 6 个交替块（局部 ↔ 全局），循环阶段用 4 个 kNN 块加 1 个渲染误差多视图注意力块（render_error_mv_attn_blocks=1）。

工程加速：local_knn

当分辨率高或视图多时，全局暴力最近邻搜索代价大。官方实现的 local_knn.py 不做全空间搜索，而是先构造候选集：同视图的 2D 空间窗口（默认半径 $r_s=3$，即 $7\times7$）+ 跨视图投影窗口（半径 $r_c=3$），再只在候选集内算精确 3D 距离取 top-k：

src/model/encoder/point_transformer/local_knn.py — 候选集 + 精确 top-k
all_indices = torch.cat([spatial_indices, cross_indices], dim=1)
sq_dist = ((candidate_pos - query_pos) ** 2).sum(dim=-1)
sq_dist[~all_valid] = float("inf")
topk_dist, topk_local = sq_dist.topk(k, largest=False)

论文附录报告：把全局 kNN 换成局部 kNN 后，重建时间从 0.816s 降到 0.591s，而 PSNR 仅从 27.70 微降到 27.65——以极小质量损失换来 27% 的加速。

06Recurrent Gaussian Update

循环更新模块是 ReSplat 的心脏。它维护每个高斯的一个循环状态 $z_j$，并在每一轮根据"当前高斯参数 + 循环状态 + 渲染误差"预测参数增量：

$$g_j^{t+1}=g_j^t+\Delta g_j^t,\qquad z_j^{t+1}=z_j^t+\Delta z_j^t$$

这里 $g_j^t$ 是当前高斯参数，$\Delta g_j^t$ 是增量。这种残差式预测而非直接回归绝对值，是循环网络稳定训练的关键：初始高斯已经不错，增量只需做小幅修正。

循环结构

每一轮的数据流为：把当前高斯参数 $g^t$、循环状态 $z^t$、渲染误差 $E^t$ 拼接，先过一次 Point Transformer 编码得到点特征，再经 4 个 kNN 注意力块更新状态，最后由一个线性头 update_head 输出 $\Delta g$：

src/model/encoder/encoder_resplat.py — forward_update 核心
# 拼接: 高斯参数 + 循环状态 + 渲染误差
concat = torch.cat((tmp_gaussian, tmp_state, tmp_render_error), dim=-1)

# 第一层 Point Transformer 编码点特征
pxo = self.update_module[0]([point_cloud, concat, offset])

# kNN 注意力块更新循环状态 (残差)
tmp_state = self.update_module[1](pxo, **refine_pt_kwargs) + tmp_state

# 线性头预测参数增量
delta_gaussians = self.update_head(tmp_state)

增量再逐项加回原始参数（尺度要重新裁剪到合法范围）：

src/model/encoder/encoder_resplat.py — 增量施加
prev_means = prev_means + delta_means
prev_scales = (prev_scales + delta_scales).clamp(
    min=self.cfg.gaussian_adapter.clamp_min_scale
)
prev_rotations_unnorm = prev_rotations_unnorm + delta_rotations
prev_opacities_raw = prev_opacities_raw + delta_opacities
prev_shs = prev_shs + delta_shs

论文附录观察到一个有趣现象：循环更新主要修改中心、尺度和零阶球谐，高阶球谐的调整几乎可以忽略。这说明循环修正的核心是把几何摆对、把低频颜色对齐，而非重新学习高频纹理。

07Rendering Error Feedback

循环更新需要一个"往哪改"的信号。ReSplat 用渲染结果与真值输入视图的差作为反馈，包含两条互补的通路：RGB 像素差和冻结 ResNet-18 特征差。

形式化地，第 $t$ 轮的渲染误差为：

$$\hat E^t = \{\hat F_i^t - F_i\}_{i=1}^{N} \;+\; \mathrm{proj}\Big(\{\hat I_i^t - I_i\}_{i=1}^{N}\Big)$$

其中 $\hat F_i^t$ 是第 $t$ 轮渲染图像经冻结 ResNet 提取的特征，$F_i$ 是真值图像的特征；$\hat I_i^t - I_i$ 是 RGB 差，经一个投影层 update_rgb_error_proj 映射到特征空间后与特征差相加。随后误差再经过多视图全局注意力聚合，得到用于更新的 $E^t$：

$$E^t = \mathrm{global\_attention}(\hat E^t)$$
src/model/encoder/encoder_resplat.py — 渲染误差构造
# 特征差: 渲染特征 - 真值输入特征 (ResNet 提取, 冻结且 no_grad)
corr = render_view_features - input_view_features

# RGB 差: 渲染 - 真值, 投影后加到特征差上
rgb_render_error = input_render.color - context["image"]
rgb_render_error = self.update_rgb_error_proj(rgb_render_error)
input_render_error = input_render_error + rgb_render_error

为什么需要两条通路？

消融实验（论文 Table 6，DL3DV 8 视图 256×448 Small）给出了清晰答案：

  • 只用 RGB 误差：27.90 dB
  • 只用特征误差：28.77 dB
  • RGB + 特征拼接：28.93 dB
  • RGB + 特征相加（本文最终）：29.07 dB

特征差比像素差更强，因为它对光照、对比度的微小偏移更鲁棒；而 RGB 差提供精确的像素级对齐信号。两者相加优于拼接，说明它们在特征空间是可加的互补信号。

精确的 detach 语义（易误解点）：源码并非"每轮都把整张计算图截断"。实际 detach 的只有：送入循环模块的初始高斯参数、以及作为更新输入的上一轮 means / scales / 未归一化旋转 / opacity logits / SH，还有 condition_features 在 update_proj 之前。但循环状态 $z$ 并非每轮都统一 detach，RGB 渲染误差通路也不是全局 no-gradient，只有 ResNet 特征提取本身在 torch.no_grad() 下。

08两阶段训练策略

ReSplat 采用两阶段训练，核心目的是解耦初始化与循环更新：

  1. 第一阶段：设 num_refine=0，只训练初始化网络，使其能独立产出不错的初始高斯。
  2. 第二阶段：加载第一阶段检查点，冻结所有参数名不含 encoder.update 的参数，只训练循环更新模块。初始化前向在 torch.no_grad() 下运行。

中间监督的指数加权

第二阶段中，循环的每一轮输出都会被渲染并计算损失，但权重按指数衰减，越靠后的输出权重越大：

$$L_{\mathrm{2nd}} = \sum_{t=0}^{T-1} \gamma^{\,T-1-t} \sum_{v=1}^{V} \ell_{\mathrm{render}}(\hat I_v^t, I_v),\qquad \gamma=0.9$$

即最后一轮输出权重恒为 1，倒数第二轮 0.9，依此类推。源码中：

src/model/model_wrapper.py — 中间输出加权
curr_loss_weight = self.train_cfg.intermediate_loss_weight ** (
    num_output - 1 - i
)
total_loss = total_loss + curr_loss_weight * loss

损失与优化器的几个"名不副实"

读官方代码时要特别注意命名与实际行为的差异：

配置项 / 名称实际行为说明
loss_mse加权 L1（F.l1_loss）名字叫 MSE，实际不是平方误差
warm_up_steps=2000未被实际 configure_optimizers 使用真正的 warmup 由 OneCycleLR 的 pct_start 控制
perceptual loss weight=0.5apply_after_step=0从第 0 步就生效
Shell 脚本 override优先于 YAML 默认值以可执行脚本为准，不要只看 YAML

优化器用 AdamW（默认 weight_decay=0.01），调度器是 OneCycleLR，余弦退火，pct_start=warm_up_ratio（默认 0.01），cycle_momentum=False，每次 optimizer step 后调度器 step。

训练时的随机循环步数

测试时循环数由 model.encoder.num_refine 固定控制（如 2 或 4），但训练时为了增强鲁棒性会在区间内随机采样：

src/model/encoder/encoder_resplat.py — 训练时随机循环步数
num_refine = self.cfg.num_refine
if self.training and self.cfg.train_min_refine > 0 \
        and self.cfg.train_max_refine > 0:
    num_refine = np.random.randint(
        self.cfg.train_min_refine,
        self.cfg.train_max_refine + 1
    )

DL3DV 8 视图配置中训练时 train_min_refine=1, train_max_refine=4，即每轮随机选 1~4 次更新，让模型对不同循环深度都鲁棒。

09推理流程与复杂度分析

推理时，整个流程是纯前向的：初始化一次 → 循环 $T$ 次"渲染输入视图 → 算误差 → 更新高斯" → 用最终高斯渲染任意新视角。没有梯度反传，没有 densification。

论文 Table 1 给出了 DL3DV 8 视图 512×960 上的完整耗时曲线（见下节图表）：每增加一轮循环约增加 0.125s，4 轮总耗时 0.816s，而经典 3DGS 跑 4000 步优化需约 70s。论文 Figure 4 进一步显示，4 次 ReSplat 循环就超过了 3DGS 80 步优化，在该对比中报告了 53× 的重建加速。

复杂度的两个主要开销：(1) 深度预测（128 个深度候选的代价体）是初始化阶段最重的部分；(2) kNN 注意力是循环阶段的主要计算量，因此 local_knn 加速对高分辨率配置至关重要。

13局限性与常见误解

作者明确陈述的局限

  1. 固定高斯数量，不做自适应稠密化/修剪：初始化时 $M$ 已定，循环只改属性。这意味着对几何极复杂或初始覆盖严重不足的区域，无法像 3DGS 那样自动分裂出新高斯来补充细节。
  2. 收益在约 4 轮后饱和：从 Table 1 可见，0→4 轮 PSNR 提升 1.49 dB，但 3→4 轮只提升 0.05 dB。继续增加循环步数边际收益极小，反而增加延迟。
  3. 当前处理固定的静态视图集，不支持流式输入：模型假设输入视图在开始时全部给定，无法增量地接纳新到达的图像。

独立分析的潜在局限

  • 反馈依赖输入视图覆盖：渲染误差只能在输入视角上计算。若初始几何在某些区域严重错误而该区域又缺乏输入视图覆盖，误差信号不足，循环可能无法纠正。
  • 深度预测与 kNN 仍是主要计算瓶颈：128 候选的深度代价体和高分辨率下的 kNN 注意力限制了在超大规模场景上的扩展性。
  • 附录部分视图数对比并非严格单变量消融：不同视图数实验可能伴随分辨率或配置变化，解读时需注意。

常见误解澄清

误解："测试时无梯度 = 训练也无梯度"

错误。gradient-free 仅指测试时不做显式梯度优化；训练时仍用反向传播学习更新模块，且 RGB 误差通路并非全局无梯度。

误解："每轮都 detach 整张图"

错误。源码只 detach 送入更新模块的初始高斯参数和上一轮参数输入；循环状态不统一 detach，ResNet 特征提取才在 no_grad 下。

误解："ReSplat 总是用 16× 更少的高斯"

仅主多视图默认配置（downsample=4, multiple=1）如此。RE10K 两视图脚本用 downsample=4×multiple=16 或 downsample=2×multiple=4，均得到逐像素量级。

误解："loss_mse 就是 MSE"

源码中 loss_mse.py 实际调用 F.l1_loss，是加权 L1。命名是历史遗留，复现实验时要按实际行为理解。

15结论

ReSplat 的核心贡献在于把"迭代修正"从一个外部优化过程变成了网络内部的一个可学习模块。它证明了：给定一个尚可的初始高斯集合，一个共享权重的循环网络仅凭渲染误差反馈，就能在 4 轮以内把质量推到超越逐场景梯度优化的水平，同时保持亚秒级重建速度和 1/16 的高斯数量。

从方法论看，ReSplat 代表了前馈重建的一个新方向——不再追求"一次预测完美"，而是接受"先大致对，再反复改"，并让网络学会"怎么改"。循环状态、渲染误差双通道反馈、局部 kNN 与多视图全局注意力的组合，共同支撑了这种学习式迭代。其参数效率（77M 循环 4 次超 559M）也提示：在推理时复用参数，可能比在训练时堆参数更值得探索。

未来的自然延伸包括：把自适应稠密化融入循环（让高斯集合也能演化）、支持流式视图输入、以及把这套"渲染误差→参数增量"的循环框架迁移到其他可微渲染表示（如神经辐射场、四面体网格）上。
