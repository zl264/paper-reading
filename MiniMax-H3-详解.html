01MiniMax H3 是什么

一句话：MiniMax H3 是 MiniMax 于 2026 年 7 月底发布、8 月初开源的「全模态视频生成系统」——输入文本、图像、视频、音频的任意组合，输出一条自带原生立体声音轨的视频。它不是「视频模型 + 配音模型」的拼盘，而是一个模型在同一次去噪循环里同时生成画面与声音。

1.1 基本事实

  • 发布时间线：2026-07-31 API 上线；2026-08-03 权重开源（HuggingFace 与 ModelScope 双渠道）。
  • 定位：通用全模态生成系统。输入侧接受文本 / 图像 / 视频 / 音频，输出侧是视频 + 同步音轨；支持 11 种语言的对话式提示词。
  • 生成规格：24 fps；开源管线约束 5–15 秒（产品端宣传口径 4–15 秒）；短边 768 像素（2K 成片走闭源再生成模块，见 1.2）；音轨为 32 kHz 原生立体声。
  • 宽高比：21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16。
  • 成绩：发布时登顶 Artificial Analysis 视频编辑榜。

02原理预备：Flow Matching 的 H3 约定

H3 的数学骨架是「双潜空间 + 整流流（rectified flow）」，与 Wan 2.1 同源。但 H3 在三处「符号级」细节上与 diffusers 通用实现相反——这三处看不懂，第 8 章的调度器源码就全是天书。本章先把通用形式讲清楚，再逐一指出镜像点。

2.1 两个潜空间

视频与音频各配一个 VAE，把两种媒体都搬进各自的潜空间，扩散过程只在潜空间里发生：

视频 (3, 124, 768, 1344) → VisualVAE encode → (24, 37, 48, 84) 时间 4× / 空间 16× / 通道 24，第 5 章
音频 (1, 160000) → AudioVAE encode → (32, 200) 时域 800× / 40 latent·s⁻¹ / 通道 32，第 6 章

两路 latent 随后拼进同一个序列、在同一个 transformer 里联合去噪（第 3 章）——这是 H3 与「先生视频再配音」方案的本质区别。注意两路的时间分辨率不同：视频 37 个 latent 帧对应 5.17 秒，音频同 duration 约 207 个 latent 帧（124 帧 ÷ 24 fps × 40 Hz），token 数量差一个量级。

2.2 整流流：一条直线

设 x₁ 为真实数据（某路 latent），ε 为标准高斯噪声。整流流在两点之间做线性插值构造训练样本，模型学的是沿直线的速度场：

xt = (1 − t) · ε + t · x1，   v*(xt, t) = x1 − ε 路径是直线 → ODE 数值求解误差小 → 几十步就能收敛
LFM = Ex₁, ε, t [ ‖ vθ(xt, t) − (x1 − ε) ‖² ]

到这里为止一切都是教科书内容。分歧出现在参数化方向上：diffusers 的通用 rectified-flow 调度器用 σ（σ=1 为纯噪声、σ=0 为干净），而 H3 用 t（t=1 为干净）——两者互为 t = 1 − σ。方向一镜像，速度的符号也跟着镜像：

图 2-1　两种参数化对比。几何上是同一条直线（噪声 → 数据），差别只在参数方向与速度符号：t = 1 − σ。H3 的模型输出是指向数据的速度，所以恢复干净样本用加号。

把 H3 的插值与恢复式写成公式（后面源码里会一字不差地出现）：

xt = t · x1 + (1 − t) · ε，    x0 = xt + (1 − t) · vθ 换回 σ 记号（σ = 1 − t）：x₀ = x_t + σ · v —— 与 diffusers 标准的 x₀ = x_t − σ · v 恰好差一个符号

2.3 指数 shift：把步数花在高噪声段

均匀网格 linspace(1, 0, N) 上直接积分效果一般——去噪前期（高噪声）最难也最重要。H3 沿用指数 shift 把 σ 网格推向高噪声端：

σ′ = s · σ / ( 1 + (s − 1) · σ ) s>1 时 σ′ ≥ σ：网格整体上移，更多步数落在高噪声区间

发布 checkpoint 用两组值：视频 s = 12.0，音频 s = 3.0。以 6 步网格为例看看 shift 的实际效果（这张表第 8 章还会回来）：

2.4 CFG 蒸馏：没有 negative prompt 的世界

Wan 2.1 每步要做两次 forward（条件 + 无条件，靠 guidance_scale≈5 加权合并）。H3 的两个 transformer 分区都是 guidance-distilled 的：引导信息被蒸馏进权重本身，于是——

  • 没有 negative_prompt，没有 guidance_scale，也没有 guider 组件；
  • 每个采样步恰好一次 forward，算力直接省一半；
  • 代价是无法再用负面提示词压制坏案例，只能靠正面描述。

2.5 双模态双调度：一次 forward，两条时间轴

视频与音频各自持有一个 MiniMaxH3Scheduler 实例（shift 分别为 12.0 / 3.0），两份 σ 网格独立演进；但每个采样步只做一次 transformer forward——视频行与音频行在同一序列里，各自按自己调度的 (timestep, modality) 取 AdaLN 调制参数，各自被自己调度器的 step() 更新。完整机制在第 8 章配源码精读。

本章三个镜像点（背下来再看第 8 章）

① 模型输出是数据向速度，x₀ = x_t + σ·v（加号）；② timestep 直接用 t = 1−σ ∈ [0,1]（t=1 干净），不加 1000 倍缩放；③ σ 网格是 linspace(1, 0, N) 含终点 0，N 个网格点对应 N−1 次 forward。

03系统架构与 packed sequence

H3 最核心的设计决策只有一个：把一个请求里的所有东西——文本条件、条件媒体、目标视频 latent、目标音频 latent——拼成一个序列，放进同一个 transformer 里联合去噪。本章讲清这个「packed multimodal sequence」的行布局、每行携带的三个坐标，以及为什么这个设计让 cross-attention 彻底消失。

3.1 Contextual Omni Representation：进模型之前先把世界结构化

H3-Base 的输入不是用户敲的原始 prompt，而是 Context-IR（或你自建的等价物）产出的序列化结构化表示。它承担四件事：

  • 指令解析：把口语化描述拆成可执行的生成指令；
  • 跨模态关联：解析「第二张图里的人物」「这段音频的说话人」这类指代；
  • 时序理解：把「前 3 秒……随后……最后……」对齐到时间轴；
  • 复杂逻辑推理：处理因果、转折、多镜头叙事。

产出物的形态可以从 ref2va 的实现反推：参考媒体在「prompt presentation」里以 <Picture 1>、<Audio 1>、<Video 1> 这样的占位标签出现在文本流中，台词则通过 Qwen3-VL tokenizer 的特殊 token <d> 标注——也就是说，结构化表示本质上是「带媒体占位标签与台词标记的富文本」，随后整体送入 Qwen3-VL 编码（第 4 章）。

3.2 一个请求 = 一个序列

编码完成后，四类行按固定顺序拼接（顺序即语义，参考媒体的位置会推进共享的旋转位置时钟，见第 9 章）：

图 3-1　packed sequence 行布局。四段按序拼接；每行带三个坐标，其中派生的 adaln_indices 决定该行在 AdaLN 调制表里取哪一组 (timestep, modality) 参数——这是「双调度单 forward」得以成立的机关（第 8 章）。

也就是说，一次典型 forward 的序列长度在四万行上下，其中视频行占九成以上——这解释了为什么 H3 的工程重心全在序列侧：MM-RoPE 共享频率表（省显存）、AdaLN 表格化寻址（免逐行投影）、注意力后端可替换（FlashAttention-3 等，第 10 章）。

3.4 单流设计：cross-attention 的消失

传统视频 DiT（包括 Wan 2.1）的文本注入靠 cross-attention：视频 token 当 Q，文本 token 当 K/V。H3 的注意力处理器源码里有一句斩钉截铁的注释：

MiniMaxH3AttnProcessor 类 docstring（原文）Python
class MiniMaxH3AttnProcessor:
    r"""
    Full self-attention over one packed sequence. There is no cross-attention anywhere in MiniMax-H3.
    """

条件注入改走三条正交通道，各管一件事：

  • 序列拼接（内容）：文本行、媒体行就在序列里，视频行做 self-attention 时自然 attend 到它们——跨模态对齐不再是专门的模块，而是注意力的副产品；
  • MM-RoPE（位置）：文本行、视频行、音频行共用 (t, h, w) 三轴坐标系，参考媒体的顺序天然编码在位置里；
  • AdaLN（噪声水平 × 模态）：每行按自己的 (timestep, modality) 取调制参数——噪声水平不同的行在同一层里被「区别对待」。

代价与收益都很清楚：注意力与 FFN 的权重完全跨模态共享（没有 per-modality 专家），模型必须学会在同一组参数下同时服务三种分布；换来的是参数效率、以及「画面看声音、声音看画面」这种细粒度跨模态交互在架构层面免费获得——对口型（lip-sync）正是 ref2va 的招牌能力（第 9 章）。

为什么条件行也要过完整的 50 层？

因为序列是拼在一起的，注意力无法跳过某些行。条件行一路被更新，但其速度输出会被管线丢弃（transformer 只原样返回，见 3.2 代码注释），只有目标行进入调度器的 step()。这让「条件」与「目标」的区别退化为每行的 timestep 标签：条件行 timestep 固定，目标行随调度推进。

04H3-Encoder：Qwen3-VL 与 TokenRefiner

文本（以及结构化表示里的媒体占位标签）由一个完整的 Qwen3-VL 编码——这是 H3 仓库里最大的单一组件（62.1 GB bfloat16），也是「全模态输入」在编码侧的落点。本章讲它怎么被使用，以及上面那层轻得出奇的 TokenRefiner。

4.1 一个 62 GB 的「文本编码器」

diffusers 转换后的组件清单里，conditioner 是 Qwen3VLForConditionalGeneration——一个完整的视觉语言模型。H3 对它的用法非常克制：

  • 读第 50 层 decoder 层的 unnormalized hidden state，而不是最后一层；语言模型头（LM head）完全不用——官方文档原话是「the full released checkpoint is used with its language-model head unused」；
  • 输出维度 text_dim = 5120，由 transformer 侧的 context_embedder 投影到 5376（第 7.2 节）；
  • tokenizer 带 <d> 台词特殊 token，台词在结构化表示里就位后由它标出；
  • 本身就是 VL 模型，天然消化 <Picture 1> 这类图文混合占位标签。
为什么取中间层、为什么 unnormalized

最后一层 hidden state 高度特化于 next-token 预测（且常带最终 RMSNorm 的「归一化风味」），对「当条件用」并不最优；中间层保留了更丰富的语义表征。类似的取法在 SD3（取 T5 倒数第二层）等模型里也出现过。对 H3 更关键的是：Context-IR 的结构化表示里混着媒体占位标签与台词标记，需要一个真正理解多模态文本的编码器——通用 T5 类模型不够用，这就是 62 GB 花得值的原因。

结构化表示 → Qwen3-VL（第 50 层, unnormalized）→ (num_text_tokens, 5120) → context_embedder → (num_text_tokens, 5376) → token_refiner → 文本条件行 tags=1，进入 packed sequence ① 段

4.2 TokenRefiner：两层的「域适配器」

Qwen3-VL 的输出之上，H3 只加了一个极轻的精炼器：2 层普通 pre-norm transformer block + 一个 final norm。没有 AdaLN、没有 RoPE——因为它处理的是无噪声概念的条件流，不参与去噪调度。完整源码：

class MiniMaxH3TokenRefinerBlock(nn.Module):
    r"""
    Plain pre-norm transformer block used to refine the projected text stream. No AdaLN and no rotary embedding.
    """
    def __init__(
        self,
        hidden_size: int,
        num_attention_heads: int,
        attention_head_dim: int,
        ffn_dim: int,
        norm_eps: float,
        qk_norm_eps: float,
    ):
        super().__init__()
        self.norm1 = nn.RMSNorm(hidden_size, eps=norm_eps)
        self.attn = MiniMaxH3Attention(
            hidden_size=hidden_size,
            heads=num_attention_heads,
            dim_head=attention_head_dim,
            qk_norm_eps=qk_norm_eps,
        )
        self.norm2 = nn.RMSNorm(hidden_size, eps=norm_eps)
        self.ff = FeedForward(hidden_size, inner_dim=ffn_dim, activation_fn="swiglu", bias=False)

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        hidden_states = hidden_states + self.attn(self.norm1(hidden_states))
        hidden_states = hidden_states + self.ff(self.norm2(hidden_states))
        return hidden_states


class MiniMaxH3TokenRefiner(nn.Module):
    def __init__(
        self,
        hidden_size: int,
        num_attention_heads: int,
        attention_head_dim: int,
        ffn_dim: int,
        num_layers: int,
        norm_eps: float,
        qk_norm_eps: float,
        final_norm_eps: float,
    ):
        super().__init__()
        self.refiner_blocks = nn.ModuleList(
            [
                MiniMaxH3TokenRefinerBlock(
                    hidden_size=hidden_size,
                    num_attention_heads=num_attention_heads,
                    attention_head_dim=attention_head_dim,
                    ffn_dim=ffn_dim,
                    norm_eps=norm_eps,
                    qk_norm_eps=qk_norm_eps,
                )
                for _ in range(num_layers)
            ]
        )
        self.final_norm = nn.RMSNorm(hidden_size, eps=final_norm_eps)
        self.gradient_checkpointing = False

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        for block in self.refiner_blocks:
            if torch.is_grad_enabled() and self.gradient_checkpointing:
                hidden_states = self._gradient_checkpointing_func(block, hidden_states)
            else:
                hidden_states = block(hidden_states)
        return self.final_norm(hidden_states)

逐行看几个点：

  • 复用主干的注意力类：MiniMaxH3Attention 与第 7.5 节的主干注意力是同一个类（含 QK-Norm），只是这里不传 RoPE——一套实现两处使用，减少转换时的形状分歧；
  • SwiGLU FFN：与主干 block 的 FFN 结构一致（activation_fn="swiglu"，无 bias），同样是为权重布局统一；
  • final_norm 用独立的 eps（config 里 final_norm_eps 与 norm_eps 分开登记），说明训练时这两处是分开调的；
  • 保留了 gradient_checkpointing 分支：推理用不到，但为社区微调留了路。
为什么 refiner 这么薄？

Qwen3-VL 输出的已经是高质量语义特征，refiner 的任务不是「理解」而是域适配：把语言模型的表征分布平移到扩散模型条件分布上。两层的容量足够完成这件事——对照 Wan 2.1 时代 umT5 输出直接进 cross-attention 的做法，H3 等于把「cross-attention 的适配职责」压缩成了这两层 + 序列拼接。

6.2 抗混叠积木：Kaiser-sinc 滤波器与 Snake 激活

先看两块最小积木。kaiser_sinc_filter1d 造出 Kaiser 窗加权的 sinc 低通核——它是所有上下采样器的抗混叠心脏：

diffusers/models/autoencoders/autoencoder_kl_minimax_h3_audio.py（完整）Python
def kaiser_sinc_filter1d(cutoff: float, half_width: float, kernel_size: int) -> torch.Tensor:
    r"""Kaiser-windowed sinc low-pass filter of shape `[1, 1, kernel_size]`.
    Kept arithmetically identical to the `alias-free-torch` implementation the checkpoint was trained with, because the
    resulting tensor is stored as a persistent buffer.
    """
    half_size = kernel_size // 2
    attenuation = 2.285 * (half_size - 1) * math.pi * (4 * half_width) + 7.95
    if attenuation > 50.0:
        beta = 0.1102 * (attenuation - 8.7)
    elif attenuation >= 21.0:
        beta = 0.5842 * (attenuation - 21) ** 0.4 + 0.07886 * (attenuation - 21.0)
    else:
        beta = 0.0
    window = torch.kaiser_window(kernel_size, beta=beta, periodic=False)
    if kernel_size % 2 == 0:
        time = torch.arange(-half_size, half_size) + 0.5
    else:
        time = torch.arange(kernel_size) - half_size
    filter_ = 2 * cutoff * window * torch.sinc(2 * cutoff * time)
    # Normalize to sum 1 so a constant input does not leak through the resampler.
    filter_ /= filter_.sum()
    return filter_.view(1, 1, kernel_size)

两条工程注释值得停一下：① 数值上刻意与训练时的 alias-free-torch 保持逐位一致——因为滤波器作为 persistent buffer 存进 checkpoint，任何数值漂移都会造成加载不兼容；② 末尾的 sum-to-one 归一化保证直流分量无损通过（常数输入不泄漏）。

接着是两种 Snake 周期激活——音频生成里比 ReLU/GELU 更契合波形周期性的选择：

class MiniMaxH3AudioSnake1d(nn.Module):
    r"""`x + (alpha + 1e-9)^-1 * sin(alpha * x)^2` over `[batch_size, channels, length]`, with a
    per-channel learnable `alpha` of shape `[1, channels, 1]`. Used throughout the DAC encoder."""
    def __init__(self, channels: int):
        super().__init__()
        self.alpha = nn.Parameter(torch.ones(1, channels, 1))

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        return hidden_states + (self.alpha + 1e-9).reciprocal() * torch.sin(self.alpha * hidden_states).pow(2)


class MiniMaxH3AudioSnakeBeta(nn.Module):
    r"""`x + (exp(beta) + 1e-9)^-1 * sin(exp(alpha) * x)^2` over `[batch_size, channels, length]`.
    The BigVGAN decoder's activation: separate frequency (`alpha`) and magnitude (`beta`) parameters, both stored in
    log space as `[channels]` vectors.
    """
    def __init__(self, channels: int):
        super().__init__()
        self.alpha = nn.Parameter(torch.zeros(channels))
        self.beta = nn.Parameter(torch.zeros(channels))

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        alpha = torch.exp(self.alpha.unsqueeze(0).unsqueeze(-1))
        beta = torch.exp(self.beta.unsqueeze(0).unsqueeze(-1))
        return hidden_states + (beta + 1e-9).reciprocal() * torch.sin(alpha * hidden_states).pow(2)

Snake1d（DAC 侧）一个可学的逐通道频率 alpha；SnakeBeta（BigVGAN 侧）拆成频率与幅度两个参数、且都存 log 空间保证为正。围绕它们还有四个薄包装：LowPassFilter1d / UpSample1d / DownSample1d（Kaiser-sinc 核的跨步/转置卷积实现）与 Activation1d（上采样 → 激活 → 下采样的 alias-free 激活包装，BigVGAN 的招牌操作）。

class MiniMaxH3AudioResidualUnit(nn.Module):
    r"""DAC residual unit: `Snake -> dilated Conv1d(k=7) -> Snake -> Conv1d(k=1)`, plus a shortcut
    that is center-cropped when the dilated convolution shrinks the time axis."""
    def __init__(self, dim: int, dilation: int):
        super().__init__()
        self.block = nn.Sequential(
            MiniMaxH3AudioSnake1d(dim),
            weight_norm(nn.Conv1d(dim, dim, kernel_size=7, dilation=dilation, padding=((7 - 1) * dilation) // 2)),
            MiniMaxH3AudioSnake1d(dim),
            weight_norm(nn.Conv1d(dim, dim, kernel_size=1)),
        )

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        residual = self.block(hidden_states)
        pad = (hidden_states.shape[-1] - residual.shape[-1]) // 2
        if pad > 0:
            hidden_states = hidden_states[..., pad:-pad]
        return hidden_states + residual


class MiniMaxH3AudioEncoderBlock(nn.Module):
    r"""Three residual units at dilations 1/3/9, then a strided channel-doubling convolution."""
    def __init__(self, dim: int, stride: int):
        super().__init__()
        self.block = nn.Sequential(
            MiniMaxH3AudioResidualUnit(dim // 2, dilation=1),
            MiniMaxH3AudioResidualUnit(dim // 2, dilation=3),
            MiniMaxH3AudioResidualUnit(dim // 2, dilation=9),
            MiniMaxH3AudioSnake1d(dim // 2),
            weight_norm(
                nn.Conv1d(
                    dim // 2,
                    dim,
                    kernel_size=2 * stride,
                    stride=stride,
                    padding=math.ceil(stride / 2),
                )
            ),
        )

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        return self.block(hidden_states)


class MiniMaxH3AudioEncoder(nn.Module):
    r"""DAC waveform encoder: `[batch_size, 1, samples] -> [batch_size, latent_dim, samples / 800]`."""
    def __init__(self, d_model: int, strides: tuple[int, ...], d_latent: int):
        super().__init__()
        block: list[nn.Module] = [weight_norm(nn.Conv1d(1, d_model, kernel_size=7, padding=3))]
        for stride in strides:
            d_model *= 2
            block.append(MiniMaxH3AudioEncoderBlock(d_model, stride=stride))
        block += [
            MiniMaxH3AudioSnake1d(d_model),
            weight_norm(nn.Conv1d(d_model, d_latent, kernel_size=3, padding=1)),
        ]
        self.block = nn.Sequential(*block)

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        return self.block(hidden_states)

encoder 输出是 2048 通道、40 Hz 的特征图，而 latent 只要 32 通道。H3 没有用一个 1×1 卷积草草了事，而是插入一个因果注意力 + GeGLU 的残差块（checkpoint 名 pre_block），让 32 个 latent 通道各自「挑」自己需要的 encoder 通道组合：

class MiniMaxH3AudioGeGluMlp(nn.Module):
    r"""Pre-norm GeGLU MLP used inside the attention projection block."""
    def __init__(self, in_features: int, hidden_features: int):
        super().__init__()
        self.norm = nn.LayerNorm(in_features)
        self.act = nn.GELU(approximate="tanh")
        self.w0 = nn.Linear(in_features, hidden_features)
        self.w1 = nn.Linear(in_features, hidden_features)
        self.w2 = nn.Linear(hidden_features, in_features)

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        hidden_states = self.norm(hidden_states)
        hidden_states = self.act(self.w0(hidden_states)) * self.w1(hidden_states)
        return self.w2(hidden_states)

    r"""Processor of [`MiniMaxH3AudioCausalAttention`].
    The causal mask is expressed as `is_causal=True` rather than as a materialized mask. Every attention backend
    honours that flag, with two exceptions: `_native_npu`, whose kernel takes no causal argument and would compute
    *bidirectional* attention, and context parallelism, which raises for causal attention.
    """

    _parallel_config = None

            qkv.reshape(batch_size, seq_len, 3, attn.num_heads, attn.head_dim).permute(2, 0, 1, 3, 4).unbind(0)
        )
        hidden_states = dispatch_attention_fn(
            query,
            key,
            value,
            attn_mask=None,
            is_causal=True,
            backend=self._attention_backend,
            parallel_config=self._parallel_config,
        )
        # The heads are mean-pooled away instead of being concatenated, and the head dimension that
        # remains is adaptively average-pooled down to `out_dim`.
        hidden_states = torch.mean(hidden_states, dim=2)
        hidden_states = F.adaptive_avg_pool1d(hidden_states, attn.out_dim)
        return attn.proj(hidden_states)


class MiniMaxH3AudioCausalAttention(nn.Module, AttentionModuleMixin):
    r"""Causal self-attention that narrows the feature width from `in_dim` to `out_dim`.
    QKV is a single bias-less `nn.Linear`; query and value biases are separate parameters and the key bias is a frozen
    zero buffer (`zero_k_bias`), exactly as stored in the checkpoint. Heads are `in_dim // num_heads` wide; instead of
    being concatenated they are **mean-pooled away**, and the remaining head dimension is adaptively average-pooled
    down to `out_dim`.
    """
    _default_processor_cls = MiniMaxH3AudioAttnProcessor
    _available_processors = [MiniMaxH3AudioAttnProcessor]
    # The checkpoint stores one fused `qkv` projection, so there is nothing to fuse.
    _supports_qkv_fusion = False

    def __init__(self, in_dim: int, out_dim: int, num_heads: int):
        super().__init__()
        self.out_dim = out_dim
        self.num_heads = num_heads
        self.head_dim = in_dim // num_heads
        self.qkv = nn.Linear(in_dim, in_dim * 3, bias=False)
        self.q_bias = nn.Parameter(torch.zeros(in_dim))
        self.v_bias = nn.Parameter(torch.zeros(in_dim))
        self.register_buffer("zero_k_bias", torch.zeros(in_dim))
        self.proj = nn.Linear(out_dim, out_dim)
        self.set_processor(MiniMaxH3AudioAttnProcessor())

    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        return self.processor(self, hidden_states)

这个类浓缩了四个「checkpoint 兼容优先」的教科书案例：

  • 融合 QKV 的手拼 bias：F.linear(input, qkv.weight, bias=cat(q_bias, zero_k_bias, v_bias))——权重存成一个 3in_dim×3in_dim 矩阵，但 q/v bias 是独立参数、k 的 bias 是冻结的零 buffer（zero_k_bias），前向时三段拼接。这也是 _supports_qkv_fusion = False 的原因：本来就是融合的，没有再融合的空间；
  • 因果性用 is_causal=True 表达而非实体 mask——但 docstring 提醒：NPU 原生后端不接受 causal 参数、会算成双向，上下文并行则直接 raise；
  • heads 被均值池化掉（torch.mean(hidden_states, dim=2)）而不是拼接，剩下的 head_dim 再用 adaptive_avg_pool1d 压到 out_dim——「2048 → 8 头 × 256 → mean → 256 → pool → 32」，宽度收缩全靠两次平均；
  • GeGLU 的 tanh 近似：GELU(approximate="tanh")，与编码器主干的数值行为保持一致。

class MiniMaxH3AudioDiagonalGaussianDistribution:
    r"""Posterior of the MiniMax-H3 audio autoencoder, parameterized as `(mean, log_std)`.
    The checkpoint keeps two separate `Conv1d` heads (`mean_proj`, `logs_proj`) instead of one fused moments
    projection, and the second head predicts the **log standard deviation**, not the log variance. The two tensors are
    therefore stored as produced, and `mode()` is bit-for-bit `mean_proj`'s output.
    Args:
        mean (`torch.Tensor`): Posterior mean, `[batch_size, latent_channels, num_frames]`.
        logs (`torch.Tensor`): Posterior log standard deviation, same shape as `mean`.
    """
    def __init__(self, mean: torch.Tensor, logs: torch.Tensor):
        self.mean = mean
        self.logs = logs
        self.std = torch.exp(logs)

    def mode(self) -> torch.Tensor:
        return self.mean

    def sample(self, generator: torch.Generator | None = None) -> torch.Tensor:
        noise = randn_tensor(self.mean.shape, generator=generator, device=self.mean.device, dtype=self.mean.dtype)
        return self.mean + self.std * noise

diffusers 其余 KL 自编码器的惯例是单个 proj 输出双倍通道然后 chunk 成 (mean, logvar)；H3 音频 VAE 是两个独立头，且第二个头预测 log 标准差。如果你要写自己的采样代码，std = exp(logs) 这行就是全部区别所在——当成 logvar 用会开错一次方。mode() 逐位等于 mean_proj 的输出，而 H3 的管线总是取 mode()（编码条件音频时不加采样噪声）。

6.6 decoder：BigVGAN 一侧

decoder 侧（decoder_dim = 1024，decoder_rates = [5, 5, 2, 2, 2, 2, 2]，积同样是 800）走 BigVGAN 配方：dec_in_proj 把 32 通道 latent 抬到 1024 宽；每一级是「AMP 残差块（SnakeBeta 激活、膨胀卷积）+ 转置卷积上采样 + 通道折半」；Activation1d 包装让非线性也发生在 2 倍上采样域里以抑制混叠。结构上是 encoder 的镜像，不再贴代码——重点是它继承了 BigVGAN 的全部抗混叠纪律，32 kHz 全带宽重建靠的就是这套。

7.3 MM-RoPE：三轴共享频率的旋转位置编码

第 3 章说过每行 token 携带 (t, h, w) 三坐标。把它们变成注意力内的相对位置信号的，是下面两个逐字摘录的函数/模块——H3 的 RoPE 与多数视频模型「按轴切分 head_dim」的做法不同：三轴共享同一组 16 个频率，每轴各产 16 个角度，三个块拼成 48 维再自拼成 96 维。

def _apply_rotary_emb(hidden_states: torch.Tensor, cos: torch.Tensor, sin: torch.Tensor) -> torch.Tensor:
    r"""
    Rotate the leading `rotary_dim` channels of every head and pass the remaining channels through unchanged.
    `hidden_states` is `(batch_size, seq_len, num_heads, head_dim)` and `cos`/`sin` are `(seq_len, rotary_dim)`.
    """
    rotary_dim = cos.shape[-1]
    hidden_states_rotary = hidden_states[..., :rotary_dim]
    hidden_states_pass = hidden_states[..., rotary_dim:]
    cos = cos.to(hidden_states.dtype)[None, :, None, :]
    sin = sin.to(hidden_states.dtype)[None, :, None, :]
    x1, x2 = hidden_states_rotary.chunk(2, dim=-1)
    hidden_states_rotated = torch.cat((-x2, x1), dim=-1)
    hidden_states_rotary = hidden_states_rotary * cos + hidden_states_rotated * sin
    return torch.cat((hidden_states_rotary, hidden_states_pass), dim=-1).contiguous()


class MiniMaxH3RotaryPosEmbed(nn.Module):
    r"""
    3-axis rotary embedding over the `(t, h, w)` coordinates of the packed sequence.
    A single `inv_freq` buffer of `rope_freq_dim` frequencies is shared by the three axes. Each axis contributes
    `rope_freq_dim` angles, the three blocks are concatenated to `3 * rope_freq_dim` and then concatenated with
    themselves so that the `rotate_half` convention rotates `2 * 3 * rope_freq_dim` of the `head_dim` channels.
    """
    def __init__(self, rope_freq_dim: int = 16, rope_theta: float = 10000.0):
        super().__init__()
        self.rope_freq_dim = rope_freq_dim
        inv_freq = 1.0 / (
            rope_theta ** (torch.arange(0, 2 * rope_freq_dim, 2, dtype=torch.float32) / (2 * rope_freq_dim))
        )
        self.register_buffer("inv_freq", inv_freq, persistent=False)

    def forward(self, position_ids: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        # position_ids: (seq_len, 3) -> cos/sin: (seq_len, 2 * 3 * rope_freq_dim)
        position_ids = position_ids.to(torch.float32)
        freqs = position_ids.unsqueeze(-1) * self.inv_freq.view(1, 1, -1)  # (seq_len, 3, rope_freq_dim)
        freqs_t, freqs_h, freqs_w = freqs.unbind(dim=1)
        freqs = torch.cat((freqs_t, freqs_h, freqs_w), dim=-1)
        freqs = torch.cat((freqs, freqs), dim=-1)
        return freqs.cos(), freqs.sin()

四个值得停下来的细节：

(1) 16 频率 × 3 轴，角度拼接而非维度切分。常见 3D-RoPE（包括很多视频 DiT）把 head_dim 切成 t/h/w 三段，每轴独占一段维度、用各自的 inv_freq。H3 不切——每个头 128 维里，三轴用的是同一组频率（theta=10000，指数 0/32, 2/32, …, 30/32，共 16 档），时间角度、行角度、列角度在 96 维里首尾相接。位置区分完全靠 (t,h,w) 三元组的组合，所以文本行、音频行、参考行只要各自有合法坐标，就和视频行住在同一套约定里——第 9 章 ref2va 的「参考 token 与目标 token 共享同一 rotary clock、按插入顺序推进」正是这么落地的。

(2) 96 旋转、32 直通。rotary_dim = 2 × 3 × 16 = 96：每轴 16 频率对应每头 32 个角度维，三轴 96 个角度维参与旋转，head_dim=128 的最后 32 维原样通过。这 32 维是内容通道，不编码位置。

(3) 自拼与 rotate_half 的配对。freqs = cat(freqs, freqs) 把 48 维角度复制成 96 维，与 torch.cat((-x2, x1)) 的 rotate_half 约定严格匹配——前 48 维乘 cos、把「另一半」（-x2）乘 sin 相加，等价于标准 RoPE 的复数旋转，只是拼接顺序写在了 cos/sin 侧而不是 x 侧。

(4) 只旋转 Q 和 K。调用发生在注意力 processor 里（7.5 节的逐字代码），V 与输出不进 RoPE——注意力的位置敏感性只体现在 logits 的 QKᵀ 上。

7.4 AdaLN：把 (timestep, modality) 调成 6 组向量

AdaLN 是 H3 里参数最重的部件（每块 260M，全模型 13B，第 1.4 节），逻辑却只有三步：adaln_proj 把 (T, 2688) 的 temb 投成 6 组 (3T, 5376) 的调制表，块的 forward 再按每行的 adaln_indices 从表里逐行取参。逐字代码：

class MiniMaxH3AdaLayerNormModulation(nn.Module):
    r"""
    Projects the shared timestep embedding into the six per-(timestep, modality) modulation parameters of one
    transformer block.
    `(num_timesteps, time_embed_dim)` -> six tensors of shape `(num_timesteps * MINIMAX_H3_MODALITY_NUM, hidden_size)`,
    in the diffusers `shift_msa, scale_msa, gate_msa, shift_mlp, scale_mlp, gate_mlp` order. The row layout of the
    returned tensors is `[t0_mod0, t0_mod1, t0_mod2, t1_mod0, ...]`, which is what `timestep_indices *
    MINIMAX_H3_MODALITY_NUM + token_tags` addresses.
    A single projection is shared by `norm1` and `norm2` and by the three modalities, so it cannot be folded into
    either norm the way [`~models.normalization.AdaLayerNormZero`] does. It is therefore a block-level module of its
    own, named after the checkpoint's `adaln_proj`, with the modulation projection under the `linear` name diffusers
    uses inside every AdaLN module.
    """
    def __init__(self, time_embed_dim: int, hidden_size: int):
        super().__init__()
        self.hidden_size = hidden_size
        self.linear = nn.Linear(time_embed_dim, 6 * hidden_size * MINIMAX_H3_MODALITY_NUM, bias=True)

    def forward(self, temb: torch.Tensor) -> tuple[torch.Tensor, ...]:
        # The activation runs at `temb`'s own precision — float32, since `time_embedder` is a float32 module in this
        # mixed-precision checkpoint — and only its result is cast down to the bfloat16 projection. Every block reads
        # the same `temb`, so a rounding applied before the activation biases every block's modulation parameters
        # identically at every sampling step, which accumulates coherently over the denoising trajectory.
        temb = self.linear(nn.functional.silu(temb).to(get_parameter_dtype(self.linear)))
        temb = temb.view(-1, 6 * self.hidden_size)
        return temb.chunk(6, dim=-1)

形状链值得手工推一遍——view 那一行是整个机关：

(T, 2688) → silu(fp32) → cast bf16 → Linear(2688→96768) → (T, 96768) 96768 = 6 × 5376 × 3，内存布局按 [timestep][模态][6 组 × 5376] 排
(T, 96768) → view(-1, 32256) → (3T, 32256) → chunk(6, dim=-1) → 6 × (3T, 5376) 行布局 [t0·m0, t0·m1, t0·m2, t1·m0, …]——正是 adaln_indices = timestep_idx×3 + tag 的寻址表

主类最终层的 norm_out 用的是同一个思想的不带模态版本——只按 timestep 出 shift/scale（10752 = 2×5376），仍逐行寻址：

class MiniMaxH3AdaLayerNormOut(nn.Module):
    r"""
    Final norm of the packed sequence, shift/scale modulated per row.
    Same module layout and checkpoint keys as [`~models.normalization.AdaLayerNormContinuous`] (`norm` plus a `linear`
    projecting the conditioning embedding to `2 * hidden_size`), with two MiniMax-H3 specifics: the modulation table
    holds one row per *timestep* and is addressed per row of the packed sequence rather than per batch item, and the
    two halves of the projection are `shift` then `scale`, the order `LTX2Transformer3DModel` and
    `WanTransformer3DModel` also use in their output layers.
    """
    def __init__(self, hidden_size: int, time_embed_dim: int, eps: float):
        super().__init__()
        self.norm = nn.RMSNorm(hidden_size, eps=eps)
        self.linear = nn.Linear(time_embed_dim, 2 * hidden_size, bias=True)

    def forward(self, hidden_states: torch.Tensor, temb: torch.Tensor, timestep_indices: torch.Tensor) -> torch.Tensor:
        # As in `MiniMaxH3AdaLayerNormModulation`: activate at `temb`'s precision, cast to the projection's dtype after.
        shift, scale = self.linear(nn.functional.silu(temb).to(get_parameter_dtype(self.linear))).chunk(2, dim=-1)
        # The modulation itself stays at the block stack's precision; `forward` casts to the output heads' dtype.
        hidden_states = self.norm(hidden_states)
        return hidden_states * (1.0 + scale.index_select(0, timestep_indices)) + shift.index_select(
            0, timestep_indices
        )

三处工程细节值得点名：

fp32 silu。两个 AdaLN 模块的注释都强调：激活在 temb 自身的精度（fp32，因为 time_embedder 是 fp32 模块）上计算，之后才 cast 到 bf16 权重做投影。理由写在源码里——50 个 block 读同一 temb，若先把 temb 舍入再激活，这个舍入偏置会在所有 block、每一步采样里同向累积。这是混合精度训练/推理里典型的「精度锚点」设计。

投影不可折叠。diffusers 的 AdaLayerNormZero 惯例是把调制投影做成 norm 模块的一部分；H3 的这个投影被 norm1 和 norm2 以及三个模态共享，只能独立成块级的 adaln_proj——这也解释了 96768 为什么一次性生成 6 组：省掉任何重复权重。

可预计算。temb 与调制表只依赖 timestep 集合（与序列内容无关），adaln_proj(temb) 的 6 组输出可以在采样循环外对全部 timestep 一次算完、进循环后只做 index_select——第 10 章 int8 部署把 time_embedder 排除在量化与 offload 之外，正是围绕这个精度锚点做的保守选择。第 1.4 节说过：13B 的 AdaLN 权重不等于每步 13B 的算力。

class MiniMaxH3AttnProcessor:
    r"""
    Full self-attention over one packed sequence. There is no cross-attention anywhere in MiniMax-H3.
    """
    _attention_backend = None
    _parallel_config = None

    def __call__(
        self,
        attn: "MiniMaxH3Attention",
        hidden_states: torch.Tensor,
        rotary_emb: tuple[torch.Tensor, torch.Tensor] | None = None,
        attention_mask: torch.Tensor | None = None,
    ) -> torch.Tensor:
        if attn.fused_projections:
            query, key, value = attn.to_qkv(hidden_states).chunk(3, dim=-1)
        else:
            query = attn.to_q(hidden_states)
            key = attn.to_k(hidden_states)
            value = attn.to_v(hidden_states)
        query = query.unflatten(-1, (attn.heads, -1))
        key = key.unflatten(-1, (attn.heads, -1))
        value = value.unflatten(-1, (attn.heads, -1))
        query = attn.norm_q(query)
        key = attn.norm_k(key)
        if rotary_emb is not None:
            query = _apply_rotary_emb(query, *rotary_emb)
            key = _apply_rotary_emb(key, *rotary_emb)
        # MiniMax-H3 packs one request into a single attention document, so the model passes no mask and every
        # attention backend stays available; `attention_mask` is here because it is the processor signature every
        # other one in diffusers has, and a custom processor may need it.
        hidden_states = dispatch_attention_fn(
            query,
            key,
            value,
            attn_mask=attention_mask,
            dropout_p=0.0,
            is_causal=False,
            backend=self._attention_backend,
            parallel_config=self._parallel_config,
        )
        hidden_states = hidden_states.flatten(2, 3).type_as(query)
        hidden_states = attn.to_out[0](hidden_states)
        hidden_states = attn.to_out[1](hidden_states)
        return hidden_states


class MiniMaxH3Attention(nn.Module, AttentionModuleMixin):
    _default_processor_cls = MiniMaxH3AttnProcessor
    _available_processors = [MiniMaxH3AttnProcessor]

    def __init__(
        self,
        hidden_size: int,
        heads: int,
        dim_head: int,
        qk_norm_eps: float = 1e-5,
        processor=None,
    ):
        super().__init__()
        self.heads = heads
        self.head_dim = dim_head
        self.inner_dim = heads * dim_head
        self.use_bias = False
        self.to_q = nn.Linear(hidden_size, self.inner_dim, bias=False)
        self.to_k = nn.Linear(hidden_size, self.inner_dim, bias=False)
        self.to_v = nn.Linear(hidden_size, self.inner_dim, bias=False)
        self.norm_q = nn.RMSNorm(dim_head, eps=qk_norm_eps)
        self.norm_k = nn.RMSNorm(dim_head, eps=qk_norm_eps)
        self.to_out = nn.ModuleList([nn.Linear(self.inner_dim, hidden_size, bias=False), nn.Dropout(0.0)])
        if processor is None:
            processor = self._default_processor_cls()
        self.set_processor(processor)

    def forward(
        self,
        hidden_states: torch.Tensor,
        rotary_emb: tuple[torch.Tensor, torch.Tensor] | None = None,
        attention_mask: torch.Tensor | None = None,
    ) -> torch.Tensor:
        return self.processor(self, hidden_states, rotary_emb, attention_mask)

五个结构性事实，每个都有下文：

(1) 没有 cross-attention，一个字都没有。processor 的 docstring 说得直白：There is no cross-attention anywhere in MiniMax-H3。文本 token 不是「条件」，它们就是 packed 序列里的行（第 3 章段①），和视频、音频行一起进同一套 QKV。这与 Wan 2.1 t2v 的 cross-attention、MMDiT 的双流设计都不同——H3 是彻底的单流。

(2) 单请求 = 单 document，所以无 mask。一个请求的全部 token 拼成一条序列后，任意两行互相可见——包括条件行与目标行、视频行与音频行。attention_mask 参数存在只是为了兼容 diffusers 的 processor 签名。这也是「不传 mask、所有注意力后端都可用」的原因（见 (4)）。

(3) RoPE 时机在 QK-norm 之后。顺序是投影 → unflatten 成头 → RMSNorm(头维) → 旋转 → 注意力。先归一化再旋转，保证进入旋转的每对 (cos, sin) 乘的是单位 RMS 的向量。

(4) 后端可插拔。注意力本体走 dispatch_attention_fn，processor 的类属性 _attention_backend 可以换成 "_flash_3_hub" 等（第 10 章：Hopper 上官方报告约 3× 提速），SGLang 部署则用 ulysses 序列并行切分这条长序列（第 11 章）。is_causal=False：非因果，双向可见。

(5) fused 分支。attn.fused_projections 为真时走 to_qkv 单矩阵（一次 GEMM 出三份），否则三次独立 GEMM——两条路径数学等价，选哪条由部署时的算子融合配置决定。

class MiniMaxH3TransformerBlock(nn.Module):
    r"""
    MiniMax-H3 block: pre-norm self-attention and feed-forward, each modulated by AdaLN parameters selected per row of
    the packed sequence from the `(timestep, modality)` table.
    """
    def __init__(
        self,
        hidden_size: int,
        num_attention_heads: int,
        attention_head_dim: int,
        ffn_dim: int,
        time_embed_dim: int,
        norm_eps: float,
        qk_norm_eps: float,
    ):
        super().__init__()
        self.norm1 = nn.RMSNorm(hidden_size, eps=norm_eps)
        self.attn = MiniMaxH3Attention(
            hidden_size=hidden_size,
            heads=num_attention_heads,
            dim_head=attention_head_dim,
            qk_norm_eps=qk_norm_eps,
        )
        self.norm2 = nn.RMSNorm(hidden_size, eps=norm_eps)
        self.ff = FeedForward(hidden_size, inner_dim=ffn_dim, activation_fn="swiglu", bias=False)
        self.adaln_proj = MiniMaxH3AdaLayerNormModulation(time_embed_dim=time_embed_dim, hidden_size=hidden_size)

    def forward(
        self,
        hidden_states: torch.Tensor,
        temb: torch.Tensor,
        adaln_indices: torch.Tensor,
        rotary_emb: tuple[torch.Tensor, torch.Tensor],
        attention_mask: torch.Tensor | None = None,
    ) -> torch.Tensor:
        shift_msa, scale_msa, gate_msa, shift_mlp, scale_mlp, gate_mlp = self.adaln_proj(temb)
        residual = hidden_states
        norm_hidden_states = self.norm1(hidden_states)
        norm_hidden_states = norm_hidden_states * (
            1.0 + scale_msa.index_select(0, adaln_indices)
        ) + shift_msa.index_select(0, adaln_indices)
        attn_output = self.attn(norm_hidden_states, rotary_emb, attention_mask)
        hidden_states = residual + gate_msa.index_select(0, adaln_indices) * attn_output
        residual = hidden_states
        norm_hidden_states = self.norm2(hidden_states)
        norm_hidden_states = norm_hidden_states * (
            1.0 + scale_mlp.index_select(0, adaln_indices)
        ) + shift_mlp.index_select(0, adaln_indices)
        # —— 以下三行按注意力分支的同构模式补全（WebFetch 抓取截断于上一行）：
        ff_output = self.ff(norm_hidden_states)
        hidden_states = residual + gate_mlp.index_select(0, adaln_indices) * ff_output
        return hidden_states

和第 4 章的 MiniMaxH3TokenRefinerBlock 并排看，差别一目了然——骨架完全相同，H3 只是往三个位置插了 per-row 调制：

TokenRefinerBlock（第 4 章）TransformerBlock（本节）
norm1 后直接 attn(norm1(x))×(1+scale_msa[idx]) + shift_msa[idx] 再进 attn
注意力残差x + attn_outx + gate_msa[idx] * attn_out（门控）
norm2 后直接 ff(norm2(x))×(1+scale_mlp[idx]) + shift_mlp[idx] 再进 ff

额外依赖无（纯序列函数）temb、adaln_indices、rotary_emb

注意三处 index_select(0, adaln_indices) 的语义：同一个 adaln_indices（每行一个 int）在 shift、scale、gate 上各查一次表，把 (seq_len, 5376) 的 hidden_states 与 (3T, 5376) 的参数表对齐——高 token 数（37,700 行）与低参数行数（3T 行）之间的桥梁就这一句广播式的 gather。50 个 block 全部如此，唯一的层间状态就是 hidden_states 本身：没有 KV cache（去噪不需要）、没有层间旁路。

7.7 小结：为什么「最普通」的结构反而是 omni 的正确答案

把本章零件拼起来，一个 block 的完整生命周期是：

(seq, 5376) + (T, 2688) fp32 + (seq,) adaln_indices + (seq, 96) cos/sin → adaln_proj 产 6 组 (3T, 5376) → norm1 → shift/scale per-row → 7168 宽自注意力（QK-norm + RoPE，无 mask） → gate per-row → 残差 → norm2 → shift/scale per-row → SwiGLU → gate per-row → 残差 × 50 层，层间只传 hidden_states

回看设计选择：权重完全模态无关（attention 与 FFN 没有一行代码知道 token 是视频还是音频），模态差异全部外置到三样「数据」里——tag（查哪行 AdaLN 参数）、(t,h,w) 坐标（RoPE 位置）、token 本身的通道布局（进主干前的三个投影负责对齐）。这使得：同一个 checkpoint 无改动能吃下 t2va / fl2va / ref2va 三种任务（第 9 章，后者甚至只要换一份权重同结构的 ref2va 分支）；视频与音频可以在同一 forward 里用不同的噪声水平去噪（第 8 章的双调度）；音频这种 token 数少两个量级的模态不会稀释训练（它共享全部注意力容量，只占序列尾部一小段）。

代价同样清晰：注意力长度是全部模态 token 之和（O((N_v+N_a+N_t)²)），37,296 个视频 token 的平方级注意力是显存与延迟的大头——这也是官方把「原生稀疏注意力」留在闭源侧、开源侧靠 FlashAttention 后端与序列并行兜底的原因（第 11 章）。下一章看这些速度预测如何被两个调度器消费。

8.1 三大差异：为什么不复用现成的调度器

diffusers/schedulers/scheduling_minimax_h3.py（模块 docstring，逐字摘录）Python
"""Rectified-flow Euler scheduler for MiniMax-H3.

Three things make this incompatible with a [`FlowMatchEulerDiscreteScheduler`] config, which is why it is a separate
class:

1. **The velocity sign is reversed.** MiniMax-H3's transformer predicts a *data-ward* velocity, so `x0 = x_t + sigma *
   v` instead of diffusers' `x0 = x_t - sigma * v`.

2. **Timesteps are `t = 1 - sigma` in `[0, 1]`**, with `t = 1` meaning *clean*. Flow-match schedulers expose `timesteps
   = sigma * num_train_timesteps`, i.e. the opposite direction on a 1000x scale. The transformer's AdaLN consumes the
   H3 convention directly.

3. **The sigma grid starts from `linspace(1, 0, num_inference_steps)`** — the terminal zero is part of the requested
   step count, and duplicates created by the shift are collapsed with `unique_consecutive`.
   `FlowMatchEulerDiscreteScheduler` instead builds `linspace(1, 1/num_train_timesteps, ...)` and appends a terminal
   sigma afterwards, so `len(sigmas)` and every interior value differ.

Everything else is ordinary rectified flow: the exponential shift `sigma' = s*sigma / (1 + (s-1)*sigma)`, and an Euler
update written as the `x_t` / `x0` blend `x_next = r*x_t + (1 - r)*x0` with `r = sigma_next / sigma`, evaluated in
float32. Despite the reference class being named "euler ancestral", `eta` is 0.

With `stochastic_sampling=True` the Euler blend is replaced by a re-noising update: each step predicts the clean sample
`x0`, then re-noises it to the next sigma with fresh noise, so the last step (`sigma_next = 0`) returns `x0`. The
few-step Pika H3 Flex adapters post-trained on MiniMax-H3 were trained for this update. They run a fixed schedule of
six steps, which their pipeline passes to `set_timesteps` as explicit `sigmas`; with `shift_provided_sigmas=True` the
scheduler shifts that grid like its own `linspace` grid. Explicit sigmas used to be taken verbatim; that default is
deprecated and flips in 0.44.0.

MiniMax-H3 runs **two schedules per request**, one per modality (`shift=12.0` for video, `shift=3.0` for audio). The
modality is not a property of the scheduler: a pipeline holds two instances, e.g. `scheduler` and `audio_scheduler`.
"""

8.2 set_timesteps：σ 网格的构造

这是「N 个网格点、N−1 次 forward」规则的出处，逐字摘录：

diffusers/schedulers/scheduling_minimax_h3.py（逐字摘录）Python
    def set_timesteps(
        self,
        num_inference_steps: int | None = None,
        device: str | torch.device | None = None,
        sigmas: list[float] | torch.Tensor | None = None,
    ) -> None:
        r"""
        Build the sigma / timestep schedule.

        The grid is `linspace(1, 0, num_inference_steps)` pushed through the exponential shift, with consecutive
        duplicates collapsed, or the explicit `sigmas`, shifted as well when `shift_provided_sigmas` is set. The
        terminal `0` is already part of the grid — the shift maps `0` to exactly `0` — so the schedule holds
        `num_inference_steps` sigmas and drives `num_inference_steps - 1` model evaluations, exposed as `self.timesteps
        = 1 - sigmas[:-1]`.
        """
        if sigmas is None:
            if num_inference_steps is None or num_inference_steps < 2:
                raise ValueError(
                    "`set_timesteps` requires either an explicit `sigmas` schedule or "
                    f"`num_inference_steps` >= 2, got {num_inference_steps}."
                )
            # The rectified-flow sigma range is fixed at [1.0, 0.0].
            base = torch.linspace(1.0, 0.0, int(num_inference_steps), dtype=torch.float32)
            sigmas = self._shift * base / (1 + (self._shift - 1) * base)
            # The shift compresses the grid near sigma = 1; collapse any float32 collisions it creates.
            sigmas = torch.unique_consecutive(sigmas)
        else:
            sigmas = torch.as_tensor(sigmas, dtype=torch.float64).flatten().cpu()
            if self.config.shift_provided_sigmas is None:
                deprecate(
                    "sigmas",
                    "0.44.0",
                    "`MiniMaxH3Scheduler.set_timesteps` takes explicit `sigmas` verbatim, but from 0.44.0 it will "
                    "push them through the scheduler's shift. Set `shift_provided_sigmas=True` in the scheduler "
                    "config to opt in now, or `shift_provided_sigmas=False` to keep passing a finished schedule.",
                    standard_warn=False,
                )
            if self.config.shift_provided_sigmas:
                # Shifted in float64 before the float32 cast, which is how the few-step reference builds its schedule.
                sigmas = self._shift * sigmas / (1 + (self._shift - 1) * sigmas)
            sigmas = sigmas.to(torch.float32)
            if sigmas.numel() < 2 or not bool((sigmas[1:] < sigmas[:-1]).all()) or sigmas[-1].item() != 0.0:
                raise ValueError("`sigmas` must hold at least two strictly decreasing values ending at 0.0.")
        self.sigmas = sigmas.to(device=device)
        # t = 1 - sigma, and t = 1 is clean. The terminal sigma has no model evaluation.
        self.timesteps = (1.0 - sigmas[:-1]).to(device=device)
        self.num_inference_steps = int(self.timesteps.numel())
        self._step_index = None
        self._begin_index = None

四个要点，每个都对着上面的代码行：

(1) linspace 含终点 0。请求 num_inference_steps=50 时网格有 50 个点（σ=1 起步、σ=0 收尾），timesteps = 1 - sigmas[:-1] 砍掉终态 σ=0（那里没有模型评估），所以 forward 次数是 49。这也是管线文档强调「num_inference_steps 数的是 σ 网格点、含 0」的原因——用户直觉里的「50 步」实际跑 49 次模型。

(2) 指数 shift 只在构造时应用一次。σ' = s·σ/(1+(s−1)·σ)，s=12（视频）把网格压向高噪声端（前几步 σ 掉得慢、后面收得快），s=3（音频）温和得多——两组具体数值见第 2 章的 N=6 对照表。shift 是纯 σ 域的操作，t 由 σ 反推。

(3) unique_consecutive 收拾 fp32 碰撞。shift 在 σ→1 端把网格压得很密，fp32 表示下相邻点可能舍入成同一个值；unique_consecutive 把重复折叠掉，保证 timesteps 严格递增——代价是实际步数可能少于请求值（N 很大时才会发生）。

(4) 显式 sigmas 分支是为 few-step 适配器准备的。Pika H3 Flex 少步适配器（后训练在 H3 上）跑固定的 6 步调度，由管线以显式 sigmas 传入；shift_provided_sigmas=True 表示这是「基网格」、还要过一遍 shift（float64 中转再降 fp32，与参考实现一致），False 表示成品调度原样使用。旧默认（原样使用）已弃用，0.44.0 起默认翻转。校验三连：至少两个值、严格递减、以 0 结尾。

diffusers/schedulers/scheduling_minimax_h3.py（逐字摘录）Python
    def scale_noise(
        self,
        sample: torch.FloatTensor,
        timestep: float | torch.FloatTensor,
        noise: torch.FloatTensor,
    ) -> torch.FloatTensor:
        r"""
        Rectified-flow forward process, in MiniMax-H3's `t` convention: `x_t = t*x_0 + (1 - t)*noise`.

        MiniMax-H3 uses this to noise its conditioning anchors, where `t` is the `noise_aug` level rather than a
        schedule entry, so `timestep` is taken at face value and is *not* looked up in `self.timesteps`.
        """
        if not isinstance(timestep, torch.Tensor):
            # A Python float keeps `1 - t` at double precision: `1 - 0.999` evaluated in float32 comes out 1.3e-5
            # relative too small, which the bfloat16 forward amplifies into a visibly different sample.
            return timestep * sample + (1.0 - timestep) * noise
        timestep = timestep.to(device=sample.device, dtype=sample.dtype)
        while timestep.ndim < sample.ndim:
            timestep = timestep.unsqueeze(-1)
        return timestep * sample + (1.0 - timestep) * noise

两个细节：第一，这里的 timestep 是 noise_aug 档位（比如 0.999 意味着锚几乎干净），不查调度表——它是前向加噪公式而非去噪步。第二，注释里那句 fp32 教训值得抄下来：1 - 0.999 在 float32 里相对误差 1.3e-5，会被 bfloat16 的 forward 放大成肉眼可见的样本差异——所以 Python float 路径保留双精度、只在最后与张量相乘时才降精度。这与第 7.4 节 AdaLN 的 fp32 silu 是同一种工程纪律：精度损失的来源要一个一个掐掉。

8.4 step：Euler 混合与随机重噪化两个分支

step 是整个采样循环的心脏。开头与 stochastic 分支逐字摘录；Euler 分支摘录到公开抓取截断处，尾部按 docstring 给出的公式补全并标注：

diffusers/schedulers/scheduling_minimax_h3.py（逐字摘录 + Euler 尾部补全）Python
    def step(
        self,
        model_output: torch.FloatTensor,
        timestep: float | torch.FloatTensor,
        sample: torch.FloatTensor,
        generator: torch.Generator | None = None,
        return_dict: bool = True,
    ) -> MiniMaxH3SchedulerOutput | tuple:
        r"""
        Take one Euler (`eta = 0`) step, or one re-noising step with `stochastic_sampling`.

        The model output is a data-ward velocity, so the denoised estimate is `x0 = x_t + (1 - t) * v` — note the `+`,
        the opposite of the usual flow-match convention. The update is then the blend `x_next = r*x_t + (1 - r)*x0`
        with `r = sigma_next / sigma`, evaluated in float32 for half-precision samples. With `stochastic_sampling` the
        update is `x_next = (1 - sigma_next) * x0 + sigma_next * noise` with fresh noise from `generator`, everything
        in float32, so the last step (`sigma_next = 0`) returns `x0`.
        """
        if isinstance(timestep, int) or (isinstance(timestep, torch.Tensor) and not timestep.is_floating_point()):
            raise ValueError(
                "Passing integer indices (e.g. from `enumerate(timesteps)`) as timesteps to"
                " `MiniMaxH3Scheduler.step()` is not supported. Make sure to pass one of the"
                " `scheduler.timesteps` values."
            )
        if self._step_index is None:
            self._step_index = self.index_for_timestep(timestep) if self._begin_index is None else self._begin_index
        if self.config.stochastic_sampling:
            # Few-step re-noising: x0 from the grid sigma, then re-noised to the next sigma with fresh noise. The
            # released few-step sampler works in float32 off the grid sigma, so this branch does too.
            sigma = self.sigmas[self._step_index].to(device=sample.device, dtype=torch.float32)
            sigma_next = self.sigmas[self._step_index + 1].to(device=sample.device, dtype=torch.float32)
            denoised = sample.to(torch.float32) + sigma * model_output.to(torch.float32)
            noise = randn_tensor(sample.shape, generator=generator, device=sample.device, dtype=torch.float32)
            prev_sample = ((1.0 - sigma_next) * denoised + sigma_next * noise).to(dtype=sample.dtype)
            self._step_index += 1
            if not return_dict:
                return (prev_sample,)
            return MiniMaxH3SchedulerOutput(prev_sample=prev_sample)
        # x0 from the data-ward velocity. The sigma used here is recovered from the *timestep* the
        # transformer was conditioned on, whereas the Euler ratio below uses the sigma grid: for
        # sigma < 0.5 the float32 round trip `1 - (1 - sigma)` is not exact, and the reference keeps
        # the two sources apart.
        if not isinstance(timestep, torch.Tensor):
            timestep = torch.tensor(timestep, dtype=sample.dtype)
        sigma_from_timestep = 1 - timestep.to(device=sample.device, dtype=torch.float32)
        # —— 抓取截断于上行参数列表中途（device= 之后）；dtype 参数及以下按 stochastic 分支的
        # 同构取参模式与 step docstring 给出的公式补全：
        sigma = self.sigmas[self._step_index].to(device=sample.device, dtype=torch.float32)
        sigma_next = self.sigmas[self._step_index + 1].to(device=sample.device, dtype=torch.float32)
        denoised = sample.to(torch.float32) + sigma_from_timestep * model_output.to(torch.float32)
        ratio = sigma_next / sigma
        prev_sample = (ratio * sample.to(torch.float32) + (1.0 - ratio) * denoised).to(dtype=sample.dtype)
        self._step_index += 1
        if not return_dict:
            return (prev_sample,)
        return MiniMaxH3SchedulerOutput(prev_sample=prev_sample)

两条更新规则并排看（公式里的 σ 均取自网格，t 为行内 timestep）：

Euler（默认）：x₀ = x_t + (1−t)·v，　r = σ_next / σ，　x_next = r·x_t + (1−r)·x₀　（全程 fp32） 注意 x₀ 用的 (1−t) 来自 timestep 反推、r 用的 σ 来自网格——两个来源刻意不合并，因为 σ<0.5 时 fp32 往返 1−(1−σ) 不精确
stochastic（few-step 适配器）：x_next = (1−σ_next)·x₀ + σ_next·ε_fresh　（ε_fresh 每步新抽，fp32） 最后一步 σ_next = 0，恰好返回 x₀——「重噪化」链条自然终止；base 权重没有为此训练过，别对 base 开这个开关

把 Euler 分支展开成代码里没有直说的形式：x_next = r·x_t + (1−r)·(x_t + σ·v) = x_t + σ·(1−r)·v = x_t + (σ−σ_next)·v——正是数据向速度意义下的标准 Euler 步（diffusers 通用符号约定里是 x_t − (σ−σ_next)·v）。写成混合式而非增量式是为了 fp32 数值稳定，第 2 章图 2-1 的右半幅画的就是这件事。

8.5 管线编排：一次 forward，两次 step

最后把双调度装回采样循环。管线持有 scheduler（视频，s=12）与 audio_scheduler（音频，s=3）两个实例，每步的编排是：

初始化 → 两个调度器各自 set_timesteps(N) → 三连抽噪声（条件锚 → 视频 → 音频，同一 generator） 生成约束之一：同 generator 状态 → 同样的视频+音轨
每步 i = 0 … N−2： t_v = 1−σᵛᵢ、t_a = 1−σᵃᵢ → timestep 并集去重 → time_embedder → (T, 2688) → 一次 transformer forward（packed 序列全行） 视频行按 t_v、音频行按 t_a 标注，AdaLN 各查各的表（第 7.4 节）
→ scheduler.step（video latent，mask 条件行）＋ audio_scheduler.step（audio latent） 两个 _step_index 各自独立推进；输出条件行清零是调用方职责
收尾 → VisualVAE decode（36 层 ViT）＋ AudioVAE decode（BigVGAN）→ 24fps 视频 + 32kHz 立体声
CFG 蒸馏贯穿所有工作流

两个 transformer 分区（transformer/ 与 transformer_ref/）都是 guidance 蒸馏过的：没有 guider、没有 negative_prompt、没有 guidance_scale，每步恰好一次 forward。上面流程图里的「一次 forward」不是优化，是权重本身的性质——这也是 61.7GB 的分区能以可接受速度跑完 49 步的前提之一。

四件事值得点破：

(1) 视频与音轨是两个并列输出。管线产出 videos、audio、sampling_rate 三样（output= 让返回只含指定字段而不是整个管线状态）；混流成单文件是调用方的事，encode_video(..., audio=..., audio_sample_rate=...) 就是一例。

(2) 关键帧锚定的是 packed 序列的段②。image 的 latent 经 scale_noise（第 8.3 节的 noise_aug）加噪后作为条件行进入序列——这就是第 3 章图 3-1 里「条件媒体行」的来源。首帧+末帧（last_image）同时给定时，模型拿到的是「开头+结尾、中间自由发挥」的约束。

(3) 画布跟首帧走。有首帧时 height/width 默认取其宽高比（仍要 32 倍数、768 短边），无首帧则 16:9。

(4) 调度参数在请求级覆盖。flow_shift / audio_flow_shift、num_inference_steps、noise_aug 都是调用参数（经 set_shift / set_timesteps / scale_noise 生效，第 8 章）。

另一个杠杆比显存更便宜：画布尺寸。height/width 只要求 32 的倍数，960×544 的每步耗时约为训练分辨率 1344×768 的 1/2.3（token 数随面积线性下降、注意力随 token 数平方下降）——这是所有档位上最大的提速开关。

10.2 一张 80GB：自动 CPU offload + Hopper 注意力后端

diffusers 官方文档 · 80GB 单卡配方（逐字摘录）Python
import torch
from diffusers import ComponentsManager, ModularPipeline

manager = ComponentsManager()
pipe = ModularPipeline.from_pretrained("MiniMaxAI/MiniMax-H3", components_manager=manager)
pipe.load_components(workflow="t2va", dtype=torch.bfloat16)
manager.enable_auto_cpu_offload(device="cuda", memory_reserve_margin="12GB")
pipe.transformer.set_attention_backend("_flash_3_hub")  # Hopper, roughly 3x faster; kernels fetched from the Hub

三行配置各管一件事：ComponentsManager 让权重常驻 host RAM、块执行到谁就把谁搬上加速器（第 7.4 节说过 AdaLN 表可预计算，这里的搬运粒度是组件级）；memory_reserve_margin="12GB" 给非权重开销（激活、CUDA 图、临时张量）留出安全垫，避免「刚好装下」的 OOM；set_attention_backend("_flash_3_hub") 就是第 7.5 节 processor 的 _attention_backend——Hopper 上官方报告约 3× 注意力提速，kernel 从 Hub 拉取。

10.3 24–32GB 消费卡：int8 量化 + 块级流式 offload

两步走：把两个大组件在加载时就量化到 int8（weight-only），再让 transformer 的 50 个 block 以每块一组的方式从 host RAM 流式进出：

diffusers 官方文档 · int8 配方（逐字摘录）Python
import torch
from diffusers import MiniMaxH3Transformer3DModel, ModularPipeline, TorchAoConfig
from diffusers.hooks import apply_group_offloading
from transformers import Qwen3VLForConditionalGeneration
from transformers import TorchAoConfig as TransformersTorchAoConfig
from torchao.quantization import Int8WeightOnlyConfig

pipe = ModularPipeline.from_pretrained("MiniMaxAI/MiniMax-H3")
pipe.update_components(
    transformer=MiniMaxH3Transformer3DModel.from_pretrained(
        "MiniMaxAI/MiniMax-H3", subfolder="transformer", dtype=torch.bfloat16,
        quantization_config=TorchAoConfig(
            Int8WeightOnlyConfig(version=2),
            modules_to_not_convert=[
                "proj_in", "audio_proj_in", "context_embedder", "time_embedder", "time_proj",
                "token_refiner", "norm_out", "proj_out", "audio_proj_out",
            ],
        ),
        low_cpu_mem_usage=False,
    ),
    text_encoder=Qwen3VLForConditionalGeneration.from_pretrained(
        "MiniMaxAI/MiniMax-H3", subfolder="text_encoder", dtype=torch.bfloat16,
        quantization_config=TransformersTorchAoConfig(
            Int8WeightOnlyConfig(version=2),
            modules_to_not_convert=["model.visual", "model.language_model.embed_tokens", "model.language_model.norm", "lm_head"],
        ),
    ),
)
pipe.load_components(workflow="t2va", dtype=torch.bfloat16)

# version=2 int8 tensors are pinnable, which streamed offload needs, and freezing removes the one autograd
# path the quantized tensors cannot serve.
pipe.transformer.requires_grad_(False)
pipe.text_encoder.requires_grad_(False)

offload = dict(onload_device=torch.device("cuda"), offload_device=torch.device("cpu"), use_stream=True)
pipe.transformer.enable_group_offload(offload_type="block_level", num_blocks_per_group=1, **offload)
apply_group_offloading(pipe.text_encoder.model, offload_type="leaf_level", **offload)
pipe.vae.to("cuda")
pipe.audio_vae.to("cuda")

两个排除清单值得对照第 7.2 节的模块地图读——被排除的恰好是全部小模块：

transformer 排除的 9 个名字（proj_in、audio_proj_in、context_embedder、time_embedder、time_proj、token_refiner、norm_out、proj_out、audio_proj_out）就是第 7.2 节模块地图里 blocks 之外的一切——量化只打 50 个 block 的主体权重，输入/输出投影与 AdaLN 精度锚点全部保持 bf16。这解释了第 7.2 节那张表的来历：官方文档正是用这份清单「自证」了模块结构。

text_encoder 排除的 4 项（model.visual、embed_tokens、language_model.norm、lm_head）——视觉塔与词嵌入不量化（第 4 章说过 H3 用的是 50 层处的 unnormalized hidden，视觉塔负责吃图）；lm_head 虽不用也排除在外。

两个工程注释直接写在代码里：version=2 的 int8 张量是 pinnable 的（流式 offload 需要页锁定内存）；requires_grad_(False) 砍掉量化张量无法服务的 autograd 路径。offload 一侧：transformer 用 block_level、每组 1 个 block、use_stream=True（异步搬运与计算重叠）；Qwen3-VL 用 leaf_level（按叶子模块搬运）。两个 VAE 小到可以常驻。代价是 host RAM：int8 下预期 约 75 GB 的系统内存占用。

10.4 12–16GB：再挤一层 + 小画布

同一套 int8 配方再加两个动作即可下探到 12–16GB：① 视频 VAE 也做组 offload（offload_type="leaf_level"、不开 stream——36 层 ViT 解码是一次性操作，同步搬运可接受）；② 画布换 960×544 一类的小尺寸。官方口径：这套组合下权重全部住在 host RAM，12–16GB 显存即可完整跑通开源管线。

10.5 双卡：把 conditioner 拆出去，一卡一半

有两张卡就什么都不用 offload：把管线沿「文本编码 / 其余」切成两半，各自常驻一张卡。官方示例（逐字摘录）——注意它顺带展示了 ModularPipeline 的两段式调用（conditioner 先算出 state、rest 再消费）：

diffusers 官方文档 · 双卡拆分（逐字摘录）Python
import torch
from diffusers import ComponentsManager, ModularPipeline

workflow = ModularPipeline.from_pretrained("MiniMaxAI/MiniMax-H3").blocks.get_workflow("t2va")

text_manager = ComponentsManager()
text_manager.enable_auto_cpu_offload(device="cuda:1")
conditioner = workflow.sub_blocks.pop("text_encoder").init_pipeline(
    "MiniMaxAI/MiniMax-H3", components_manager=text_manager
)
conditioner.load_components(dtype=torch.bfloat16)

manager = ComponentsManager()
manager.enable_auto_cpu_offload(device="cuda:0")
rest = workflow.init_pipeline("MiniMaxAI/MiniMax-H3", components_manager=manager)
rest.load_components(dtype=torch.bfloat16)

prompt = "A red fox trotting through a snowy pine forest, snow crunching underfoot"
state = conditioner(prompt=prompt)
results = rest(
    state=state,
    num_frames=124,
    generator=torch.Generator().manual_seed(42),
    output=["videos", "audio", "sampling_rate"],
)

两张 80GB 卡这样跑全量 bf16：每半各有一整卡，权重一旦常驻就不再回退到 host 内存；两张 48GB 卡则把 10.3 节的 int8 加载应用到两个组件上，同样布局。
