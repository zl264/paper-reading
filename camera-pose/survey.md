## 1. 研究背景与总体脉络

**什么是相机可控视频生成？** 指在视频扩散模型（Video Diffusion Model, VDM）基础上，允许用户**显式指定相机运动**（平移、旋转、变焦、推拉摇移等），使生成的视频按照预定轨迹"运镜"，而不是仅由文本模糊地暗示。

**为什么重要？**
- 电影语言的核心是镜头调度；
- 3D 一致性要求视频在不同视角下保持物理合理；
- 世界模型 / 具身 AI 需要在虚拟场景中自由导航；
- 内容创作需要可重复、可编辑的运镜。

**技术演进脉络（按时间）：**

| 阶段 | 时间 | 代表工作 | 核心思想 |
|------|------|----------|----------|
| 起步期 | 2024.04–2024.12 | MotionCtrl、CameraCtrl、CamCo、VD3D | 用 Plücker 坐标 / 外参矩阵编码相机，ControlNet 式注入 |
| 探索期 | 2024.06–2025.06 | CamTrol、MotionMaster、Latent-Reframe、LightMotion | 免训练、latent 操作、latent 重排 |
| 几何化 | 2025.01–2025.12 | GEN3C、ViewCrafter、Wonderland、TrajectoryCrafter、Uni3C | 用点云 / 深度 / 3DGS 做显式几何引导 |
| 重定向 | 2024.11–2026.06 | ReCapture、ReCamMaster、TrajectoryCrafter、EX-4D、SierpinskiCam | 把已有视频按新相机轨迹重新渲染 |
| 长程世界 | 2025.06–2026.11 | Voyager、CameraCtrl II、Spatia、WorldWarp、SPARC、MemCam | 维护 3D 记忆、长时程一致性、可探索世界 |
| 融合控制 | 2025.02–2026.11 | CineMaster、VidCRAFT3、SymphoMotion、UniCaMo、CineOrchestra | 相机与物体 / 光照 / 动作联合解耦控制 |
| 智能运镜 | 2025.12–2026.11 | ShotDirector、ShotVerse、CamPilot、OmniCam(轨迹)、TKCAM、VERTIGO | 让模型自动生成专业级运镜 |
| 编码精细化 | 2025.12–2026.11 | ReRoPE、MeRoPE、CRePE、UCPE、Infinite-Homography | 改进相机的位置编码表达 |
| RL 后训练 | 2025.12–2026.09 | Verifiable Geometry Reward、Geo-Align、PartiCam | 用可验证几何奖励做 RL 精调 |

## 2. 类别 A：相机参数作为条件信号（Pose-conditioned）

**思路**：将相机内外参（6-DoF 位姿、内参矩阵、Plücker 坐标等）编码成 embedding，通过 ControlNet、Adapter、cross-attention 等方式注入到预训练 VDM 中。

| 论文 | 时间 | 核心贡献 |
|------|------|---------|
| **CameraCtrl** (2404.02101) | 2024.04 | 提出 Plücker embedding 编码相机；即插即用相机模块，可在多个 T2V 基座（AnimateDiff、SVD、VideoCrafter）上加载；系统研究了训练数据分布的影响。**该方向事实上的奠基之作。** |
| **CamViG** (2405.13195) | 2024.05 | Google 出品；用多模态 transformer 把 3D 相机运动作为 token 序列条件注入，验证了单图 + 相机信号的可控生成。 |
| **Collaborative Video Diffusion (CVD)** (2405.17414) | 2024.05 | 同一**场景**多相机轨迹同时生成；用极线注意力（epipolar attention）保证跨视角一致性。 |
| **CamCo** (2406.02509) | 2024.06 | 基于 SVD 的 I2V；Plücker 坐标 + 极线约束 attention block；SfM 标注真实视频训练，提升 3D 一致性。 |
| **VD3D** (2407.12781) | 2024.07 | **首个把相机控制做到视频 DiT**（Snap Video 级）；ControlNet 式时空 Plücker 注入。 |
| **Boosting Camera Motion Control for VDT** (2410.10802) | 2024.10 | 揭示 DiT 上相机控制退化的根因不在位姿表达而在条件注入方式；提出 **Camera Motion Guidance (CMG)** 把精度提升 400%。 |
| **AC3D** (2411.18673) | 2024.11 | 第一性原理分析：相机引起的运动是**低频信号**；据此调整训练 / 测试噪声调度；只在少数层注入相机信息反而更精确。 |
| **CamCtrl3D** (2501.06006) | 2025.01 | Google；同时整合 4 种条件（外参 token、Plücker、图像重投影、2D↔3D transformer），做系统消融。 |
| **FloVD** (2502.08244) | 2025.02 | 用**光流**统一表达相机与物体运动，无需 GT 相机参数即可训练；两阶段：先生成光流，再以光流为条件生成视频。 |
| **CamC2V** (2504.06022) | 2025.04 | 从"单图条件"扩展到"多图上下文条件"+ 3D 约束，强调 context-to-video 范式。 |
| **OmniCam** (2504.02312) | 2025.04 | 统一框架支持文本 / 视频 / 图像混合输入，配合 OmniTr 长轨迹数据集。 |
| **PostCam** (2511.17185) | 2025.11 | 提出 **Query-Shared Cross-Attention**，把 6-DoF 位姿与渲染特征投到同一隐空间，避免细节丢失。 |
| **DualCamCtrl** (2511.23127) | 2025.11 | **双分支同时生成 RGB + 深度**，用 SIGMA（语义引导互对齐）机制互强几何感知。 |
| **CETCAM** (2512.19020) | 2025.12 | 利用 VGGT 等几何基础模型把深度 + 相机统一为 token，无需人工标注即可大规模训练。 |
| **Do View-Consistent Representations Matter?** (2511.18991) | 2025.11 | 诊断性研究：发现"内部表征的视角一致性"与输出 3D 一致性高度相关，并提出 ViCoDR 监督。 |

## 3. 类别 B：点轨迹 / 光流 / 运动向量控制（Trajectory / Flow-based）

**思路**：不直接用相机外参，而是把"相机运动"翻译成**像素级运动信号**（点轨迹、光流、2D 位移），与物体运动解耦或联合建模。

| 论文 | 时间 | 核心贡献 |
|------|------|---------|
| **I2VControl-Camera** (2411.06525) | 2024.11 | 在相机坐标系下用点轨迹代替外参；显式建模高阶运动分量，可调"主体运动强度"。 |
| **Trajectory Attention** (2411.19324) | 2024.11 | 沿像素轨迹做注意力，作为时序注意力的并行分支，兼顾精度与新内容生成。 |
| **MotionFlow** (2509.21119) | 2025.09 | 把相机运动 + 物体运动统一转成像素运动；先生成参考运动图，再以图为条件做 I2V。 |
| **Track2View** (2606.15534) | 2026.06 | **成对 3D 点轨迹**作为条件：把场景点在源视角和目标视角的投影同时送入 DiT，建立显式时空对应。 |
| **Gen Through the Lens** (2610.15900) | 2026.10 | 把相机坐标 / 世界坐标 / 物体坐标三种空间的控制信号融合，覆盖相机、焦距、构图。 |
| **UniCaMo** (2611.00810) | 2026.10 | **直接用 3D 信息构造输入噪声**——不需要任何额外控制模块，配合 LoRA 即可控制相机 + 物体。 |

## 4. 类别 C：免训练 / 测试时优化方法（Training-free & Test-time）

**思路**：不改模型权重，在采样阶段通过 latent 操作、guidance、mask 等手段实现相机控制，即插即用。

| 论文 | 时间 | 核心贡献 |
|------|------|---------|
| **CamTrol** (2406.10126) | 2024.06 | 经典免训练方法；重排 noisy latent 中的像素即相当于相机运动，适配多种 VDM。 |
| **MotionMaster (COMD)** (2404.15789) | 2024.04 | 把源视频分解为相机运动 + 物体运动，免训练地把相机运动迁移到新视频。 |
| **Latent-Reframe** (2412.06029) | 2024.12 | 用 time-aware 点云把 latent 重新投影到目标相机，再做 latent inpainting + 调和。 |
| **LightMotion** (2503.06508) | 2025.03 | 纯 latent 空间的 permutation + resampling 模拟平移 / 缩放 / 旋转；分析并修复 SNR 漂移。 |
| **Zero-Shot Personalized Camera Motion** (2504.09472) | 2025.04 | 双 LoRA + 正交正则化把外观和运动分离；仅需 1 个参考视频即可迁移电影级运镜。 |
| **Probing into Camera Control** (2605.14815) | 2026.05 | 把相机控制重新表述为 latent 上的**可微重采样位移场**，无需成对数据。 |
| **Warp-as-History** (2605.15182) | 2026.05 | 把目标相机的 warp 结果当作"伪历史"送入模型的视觉历史通道，**单条训练视频即可泛化**。 |
| **WorldForge V2** (2610.31640) | 2026.10 | 用 warped reference 在测试时迭代精化；光流分析识别 motion 通道做选择性引导。 |
| **FreeOrbit4D** (2601.18993) | 2026.01 | 免训练完成大角度相机重定向，关键是构建"前景完整 4D 代理"作结构地基。 |
| **PartiCam** (2609.39504) | 2026.09 | 基于粒子滤波的全局-局部奖励引导框架，兼顾精度与多样性。 |
| **DynaTokens** (2609.35704) | 2026.09 | 在测试时为静态相机控制模型**注入场景动态**，通过少量可学习 token 学习物体运动。 |

## 5. 类别 D：3D 几何引导的生成（3D-Aware / Point-Cloud / Gaussian-Guided）

**思路**：显式构建 3D 场景（点云 / 3DGS / 网格），沿目标轨迹渲染得到"引导视频"，再用扩散模型精修。

| 论文 | 时间 | 核心贡献 |
|------|------|---------|
| **ViewCrafter** (2409.02048) | 2024.09 | 单图 + 点云先验 + 迭代视角扩展，做高保真新视角合成。 |
| **Wonderland** (2412.12091) | 2024.12 | 视频 latent 直接预测 3DGS，单图前向出大场景。 |
| **GEN3C** (2503.03751) | 2025.03 | **3D cache 思想**：预测每帧深度，构建点云缓存，新视角条件用 cache 的 2D 渲染；相机控制极精确。 |
| **CamCtrl3D** (2501.06006) | 2025.01 | 见 A 类，融合多种几何条件。 |
| **RealCam-I2V** (2502.10059) | 2025.02 | 引入单目**度量深度**做 3D 重建，把相对相机参数转换到度量尺度，便于用户交互。 |
| **Uni3C** (2504.14899) | 2025.04 | **PCDController**：把单目深度反投影的点云作为相机控制信号；同时统一人体运动控制。 |
| **EPiC** (2505.21876) | 2025.05 | 不依赖相机 / 点云估计，直接用"基于首帧可见性的源视频 mask"构造**精确对齐的 anchor video**。 |
| **Voyager** (2506.04225) | 2025.06 | 端到端生成 RGB-D 点云序列，避免显式 SfM / MVS，长程世界一致性。 |
| **EX-4D** (2506.05554) | 2025.06 | **Depth Watertight Mesh** 显式建模可见 + 遮挡区域，极端视角仍保持几何一致。 |
| **IDCNet** (2508.04147) | 2025.08 | 联合生成 RGB + 深度，构建度量对齐的 RGBD 数据集，几何感知 transformer block。 |
| **Dream4D** (2508.07769) | 2025.08 | 两阶段：先少样本预测相机轨迹，再做位姿条件扩散，最后落到持久 4D 表征。 |
| **Diff4Splat** (2511.00503) | 2025.11 | 单图前向预测**可变形的 3D 高斯场**，30 秒合成 4D 场景。 |
| **Pixel-to-4D** (2601.00678) | 2026.01 | 用动态 3D 高斯做中间表征的 I2V，相机控制精确且几何完整。 |
| **Beyond Inpainting / DepthDirector** (2601.10214) | 2026.01 | 用**深度视频**而非 RGB 作相机控制引导，避免"inpainting trap"导致的主体漂移。 |
| **LaVR** (2601.14674) | 2026.01 | 不重建显式几何，直接用大型 4D 重建模型的**隐式 latent** 作条件。 |
| **FlexAM** (2602.13185) | 2026.02 | 多频位置编码 + 深度感知编码的点云信号，统一外观-运动解耦。 |
| **Geometry-as-Context** (2602.21929) | 2026.02 | 把"几何估计 + 视角渲染"作为模型的两个任务交替执行，迭代精化。 |
| **CamDirector** (2603.02256) | 2026.02 | 静态区域渐进融合进 world cache、动态区域直接 warp，混合 warping 做长时程一致。 |
| **WorldStereo** (2603.02049) | 2026.03 | **全局几何记忆** + **空间立体记忆**双模块；注意力限制在 3D 对应位置。 |
| **NavCrafter** (2604.02828) | 2026.04 | 多阶段相机注入 + 碰撞感知轨迹规划 + 增强 3DGS。 |
| **CT-1** (2604.09201) | 2026.04 | **Vision-Language-Camera 模型**，把空间推理知识迁移到相机轨迹估计。 |
| **CamGeo** (2605.30895) | 2026.05 | 把 VGGT 的 3D 几何知识**蒸馏**到扩散骨干，推理零延迟。 |
| **3D Scene Prompting** (2510.14945) | 2025.10 | 双时空条件 + 3D 场景记忆（仅静态几何），用动态 SLAM 分离动静。 |
| **Virtually Being** (2510.14179) | 2025.10 | 用 4DGS 重渲染体积捕获数据做训练，得到角色一致 + 相机可控模型。 |

## 6. 类别 E：单视频相机重定向 / 重渲染（Video Re-rendering / Re-taking）

**思路**：输入一段已有视频，输出同一场景沿**新相机轨迹**重新拍摄的视频，保持外观与动态同步。

| 论文 | 时间 | 核心贡献 |
|------|------|---------|
| **ReCapture** (2411.05003) | 2024.11 | Google；先生成含噪 anchor video（多视角扩散 / 深度点云渲染），再做 masked video fine-tuning 精修。 |
| **ReCamMaster** (2503.11647) | 2025.03 | 快手；用预训练 T2V 的**视频条件机制**做重渲染；用 UE5 合成多机位同步数据集解决训练数据稀缺。 |
| **TrajectoryCrafter** (2503.05638) | 2025.03 | 腾讯 + 港中文；双流条件（点云渲染 + 源视频）；双重投影策略构造混合数据集。 |
| **Reangle-A-Video** (2503.09151) | 2025.03 | 把多视角视频生成视为 video-to-video translation；用 DUSt3R 做推理时跨视角一致性引导。 |
| **Vid-CamEdit** (2506.13697) | 2025.06 | 时序一致几何估计 + 因子化微调（空间 / 时间分开训），无需大规模 4D 数据。 |
| **CamCloneMaster** (2506.03140) | 2025.06 | **参考视频式相机克隆**：无需显式相机参数，直接学参考视频的运镜。 |
| **Infinite-Homography** (2512.17040) | 2025.12 | 用无穷单应性作为条件，避开深度估计误差的敏感性。 |
| **BulletTime** (2512.05076) | 2025.12 | **解耦时间与相机位姿**，4D 位置编码 + AdaLN；独立参数化的 4D 数据集。 |
| **RealCam** (2605.06051) | 2026.05 | **自回归、实时**的相机可控 V2V；跨帧 in-context learning + 教师-学生蒸馏。 |
| **FlashRender** (2609.03563) | 2026.09 | **少步数生成渲染**：RETA 对齐源 / 目标表征 + MeanFlow 目标，秒级重拍。 |
| **SierpinskiCam** (2606.17310) | 2026.06 | 在几何引导上加 **Sierpinski 三角纹理 cue**，即使大角度也能追踪。 |
| **Geo-Align** (2605.23903) | 2026.05 | **首个 RL 框架做相机可控 V2V**；尺度感知感知奖励。 |
| **SemCam** (2610.05141) | 2026.10 | **语义级相机控制**：用户只说"保持正面跟拍"，模型自动调整轨迹。 |

## 7. 类别 F：多视角与 4D 视频生成（Multi-view & 4D Generation）

**思路**：生成同一动态场景在多个视角下的视频，或直接生成可自由探索的 4D 内容。

| 论文 | 时间 | 核心贡献 |

## 14. 类别 M：相机编码方式研究（Positional Encoding & Representation）

**思路**：**怎么把"相机"告诉模型**——这是整个领域的底层问题，2025 下半年起成为热点。

| 编码方式 | 代表工作 | 特点 |
|---------|---------|------|
| **外参矩阵 / RT** | MotionCtrl、早期方法 | 简单，但缺乏空间感 |
| **Plücker 坐标** | CameraCtrl、CamCo、VD3D | 像素级射线表示，主流方案 |
| **RoPE-based** | ReRoPE (2602.08068)、MeRoPE (2609.01252) | 用旋转位置编码承载相对位姿，平移不变性好 |
| **CRePE** | 2605.12938 | 曲线射线期望，支持鱼眼 |
| **Relative Ray Encoding** | UCPE (2512.07237) | 统一 6-DoF + 内参 + 畸变 |
| **Raxels** | Rays as Pixels (2604.09429) | 像素对齐的密集射线，与视频同 latent 空间 |
| **Infinite Homography** | 2512.17040 | 对深度估计误差鲁棒 |
| **Anchor Object** | AnyCam (2611.34944) | 用场景中的锚定物体 3D 渲染作相机信号，尺度感知 |
| **Spherical Plücker** | CamPVG (2509.19979) | 球面 Plücker，适配全景 |

**关键洞察**：
- Boosting Camera Motion Control (2410.10802) 证明：**条件注入方式比位姿表达更重要**；
- AC3D (2411.18673) 证明：**只在少数层注入即可**，全层反而有损；
- MeRoPE (2609.01252) 指出：metric 尺度下 Plücker 类编码会让 attention logit 无界增长。

## 18. 发展趋势与开放问题

### 18.1 五大趋势

1. **从位姿条件到几何条件**：早期（CameraCtrl 时代）直接把外参喂进网络；2025 起主流做法是先用单目深度估计构建点云 / 3DGS，再用渲染图引导扩散（GEN3C、Voyager、WorldWarp）。
2. **从单视角到多视角 / 4D**：从"控制一个相机"演变为"同一场景多视角联合生成"（CVD、WorldReel、See4D）。
3. **从片段到长程 / 世界模型**：维护持久 3D 记忆（Spatia、WorldWarp、SPARC、MemCam）成为长时程一致性的标准范式。
4. **从手动到自动运镜**：VLM / MLLM 开始承担"导演"角色（Auteur、CamPilot、ShotVerse、CT-1），把自然语言翻译为专业轨迹。
5. **从 SFT 到 RL 后训练**：可验证几何奖励（VGR、Geo-Align、PartiCam）显著提升相机对齐精度。

### 18.2 开放问题

- **大角度 / 极端视角下的内容补全**：超过 180° 转弯、仰视俯视等场景仍然容易出现幻觉。
- **相机与物体运动的解耦**：MotionCtrl 时代就提出，但 UniCaMo、SymphoMotion、BulletTime 等仍在改进。
- **真实世界度量尺度**：单目视频的绝对尺度模糊（AnyCam、RealCam-I2V、MeRoPE 都在攻这一问题）。
- **统一相机模型**：针孔假设限制了广角 / 鱼眼 / 全景的应用，CRePE / UCPE 才开始触及。
- **评测体系**：CamWorldQA、WorldScore、DisCoBench 等还在早期，缺乏公认标准。
- **实时性与质量权衡**：FlashRender、Sparse Diffusion 等开始有突破，但 <100ms 延迟仍有差距。

### 18.3 推荐入门阅读顺序
