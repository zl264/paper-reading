逐像素射线几何 × AnimateDiffV3 × 时序注意力

CameraCtrl：把相机轨迹写成 Plücker 射线场，再注入视频扩散模型

从 19 字段位姿文件、首帧相对化与逐像素反投影，到四级 CameraPoseEncoder、QKV 零初始化融合及 DDIM/CFG 推理的源码级解析。

论文依据：arXiv:2404.02101v2，2025-03-13。官方代码已公开；本文的源码事实固定于 hehao13/CameraCtrl，af45a7a0dbeedb7f6ed66aac4a9e5411a279f0d2，即 AnimateDiffV3 的 main 分支快照。论文另含 SVD/I2V 实验，但 README 将其放在 svd 分支，不能与这里的 main 实现混写。本文为静态论文与源码解读，未执行训练或推理，也不报告本地性能实测。

1. 要控制的不是“运动风格”，而是逐帧观察几何

“镜头缓慢推进”只能描述一种语义倾向；CameraCtrl 要接收的是每一帧相机的内参与外参，并让生成视频的全局视角变化跟随这条离散轨迹。这里的控制对象是观察者的位置和朝向，而非单独指定人物、车辆等物体的运动。文本仍负责内容与风格，随机初噪声仍参与采样，因此同一条轨迹并不保证得到同一场景。

方法的关键不是把 3×4 矩阵直接拼到文本 embedding，而是将每个像素反投影成世界坐标系中的一条射线。对第 i 帧，得到 Pi ∈ ℝ6×H×W；整段视频是 P ∈ ℝB×6×F×H×W（论文写作 B×F×6×H×W，代码进入编码器前会换轴）。其中 B 为批量、F 为帧数、H/W 是 RGB 图像空间尺寸，不是 VAE latent 的高宽。编码器只接收这份几何场，不接收带噪视频 latent，这是它与 ControlNet 式“图像特征 + 条件”路线的重要区别。

公开 main 配置的完整主干是 SD1.5 空间 U-Net、AnimateDiffV3（ADV3）motion module 和新训练的相机控制模块。先用 PixelUnshuffle 与四尺度卷积—时序注意力编码射线，再在 U-Net 下采样和上采样路径的首个 temporal self-attention 处，以零初始化线性层将相机特征混入 Q、K、V 的输入。最终网络仍预测扩散噪声，VAE 将去噪 latent 解码成视频。

阅读边界：“插件式”指原视频生成器参数在 CameraCtrl 训练阶段保持冻结、相机模块单独加载；并不表示训练好的控制权重能不加修改地接到任意架构。通道数、特征分辨率、temporal attention 接口与 QKV 处理器必须匹配。论文展示了 ADV3、个性化 T2I 主干及 SVD 的应用，本文的结构与 shape 结论针对固定 main 快照。

2. 输入契约：19 个字段怎样变成 c2w，首帧相对化做了什么

官方 --trajectory_file 是文本文件：第一行通常是视频 URL，读取时直接跳过；之后每帧一行，恰为 19 个以空格分隔的数。仓库示例文件共有 17 行，即 URL 加 16 帧；inference.py 默认 video_length=16，但读取位置本身没有用 video_length 对轨迹切片，因此自定义文件应直接写成所需的 16 行位姿，不要依赖入口替你截断。

列（从 0 开始）数量含义与使用方式
01timestamp；工具按微秒 ÷ 106 从原视频取帧，数值本身不输入网络。
1–44fx、fy、cx、cy，示例以图像宽/高归一化；入口再乘回目标像素尺寸。
5–62示例为 0、0；Camera 类不读取它们，不能把它们当作额外的畸变参数来设置。
7–1812按行展开的 3×4 w2c = [Rcw | tcw]，不是 c2w。

Camera 构造函数 用 entry[1:5] 取内参，用 entry[7:] 重建 3×4 外参，补上齐次行 [0,0,0,1] 后求逆。因此若以 xc、xw 表示相机系和世界系中的齐次点：

xc = [ Rcw | tcw ] xw；　c2w = w2c−1 = [ Rwc | ow ]，　Rwc = RcwT，　ow = −RcwTtcw(1)

其中 ow 才是世界系相机中心。若把 w2c 的最后一列直接当作相机位置，或误把输入矩阵当 c2w 再求一次逆，都会生成错误的 Plücker 图。代码的图像约定可从反投影直接读出：x 向右、y 向下、相机前方 z 为正；世界坐标轴方向由用户提供的 w2c 决定，仓库没有统一把任意外部数据的坐标系自动转换过来。

inference.get_relative_pose 固定 cam_to_origin=0，首帧 c2w 为单位阵，其余为 A·c2wi，A = w2c0：

C0rel = I4×4；　Cirel = W0Ci，　i = 1,…,F−1(2)

这把整段轨迹放到“首帧相机坐标系”中，去掉共同的世界坐标刚体变换，同时保留后续帧相对首帧的旋转和平移。不是把每帧相对上一帧编码，也不是只保留位移差分。训练数据集还有保留首帧到世界原点距离的模式：当 zero_t_first_frame=false 时首帧中心置于 (0,−‖o0‖,0)；但公开 YAML 与推理均走零平移的首帧相对模式。

内参还需区分“归一化存储”和“像素计算”。inference.py 的预处理 根据原视频宽高比与目标 384/256 的比例，仅补偿 fx 或 fy 中的一个，随后执行 fx←fx·W、fy←fy·H、cx←cx·W、cy←cy·H。这里的补偿对应 resize/crop 的数据处理假设；若自定义内参已经是像素单位，就不能再乘一次宽高。

3. Plücker 条件：正确射线公式，以及论文 Eq.3 与代码的差别

对第 i 帧、像素坐标 (u,v)，代码使用像素中心 u+0.5、v+0.5。令 Kipix 只含 fx、fy、cx、cy，Cirel=[Ri|oi]，则公开实现表达的几何为：

d̂c(u,v) = normalize([ (u+0.5−cx)/fx, (v+0.5−cy)/fy, 1 ]T)(3)
di,u,v = Rid̂c(u,v)，　mi,u,v = oi × di,u,v，　pi,u,v = [ mi,u,v ; di,u,v ] ∈ ℝ6(4)

方向 d 经单位归一化，原点 o 在同一射线的所有像素上重复；叉乘 m=o×d 同时编码相机位置与方向，而且对同一条射线上的 o+λd 不变。六个通道按 [o×d 的三个分量，d 的三个分量] 排列，不能交换成 [d;o×d]。这既提供了逐像素不同的空间图，又避免把量纲差异很大的旋转矩阵元素和原始平移直接作为网络条件。

论文 Eq.3 与官方实现不一致。论文写 du,v=RK−1[u,v,1]T+t，而 inference.ray_condition 和 dataset.ray_condition 都是先在相机系归一化方向，再仅右乘 c2w 的旋转部分；平移只进入 rays_o，不加到 rays_d。复现时应以实际训练/推理代码为准，不应照论文把 t 加到方向向量。
代码 2 · 官方源码节选：逐像素 Plücker 图（inference.py:81-99）
fx, fy, cx, cy = K.chunk(4, dim=-1)  # K: [B,F,4]，像素内参
zs = torch.ones_like(i)
xs = (i - cx) / fx * zs               # i,j 已分别加 0.5
ys = (j - cy) / fy * zs

directions = directions / directions.norm(dim=-1, keepdim=True)

rays_o = c2w[..., :3, 3]
rays_o = rays_o[:, :, None].expand_as(rays_d)
rays_dxo = torch.cross(rays_o, rays_d)
plucker = torch.cat([rays_dxo, rays_d], dim=-1)
plucker = plucker.reshape(B, c2w.shape[1], H, W, 6)
# 入口随后 permute 为 [F,6,H,W]，再整理成 [B,6,F,H,W]

可以做一个直观核对：首帧相对化后 C0=I，所以 o0=0、m0,u,v=0，首帧条件实际只含世界系方向 d0,u,v=d̂c(u,v)。相机纯旋转时 o 不变而 d 改变；纯平移时 d 不变而 m 改变。若 o∥d，叉乘为零，说明该射线经过世界原点，而不是计算失败。

射线是无限几何线，不含深度，因此 Plücker 条件本身不指定某个 3D 点，更不携带遮挡关系或场景网格。论文还展示了固定外参、逐帧改变 cx/cy 或焦距来控制画面位移与变焦；这属于相机成像参数变化，不能简单等同于物理相机中心平移。原始参数、Euler 角、“方向+重复原点”与 Plücker 的消融比较见论文第 4.3 节；这些结果支持设计选择，但不是逐像素几何渲染约束。

4. 实际网络：四级 CameraPoseEncoder、8 个 temporal 块与 QKV 融合位置

4.1 四尺度不是四个简单卷积输出

CameraPoseEncoder 先把 [B,6,F,H,W] 合并成 [BF,6,H,W]，经 PixelUnshuffle(8) 得 [BF,384,H/8,W/8]，再用卷积映射至 320 通道。每个尺度由若干个 ResnetBlock 与一一对应的 TemporalTransformerBlock 串联，并将该尺度最后一个输出保存到 features。公开配置的 nums_rb=2，不是类构造函数的默认值 3；因此实际为每尺度 2 个 ResBlock + 2 个时序块，共 8 对。

尺度进入尺度的操作每尺度结构输出 [B,C,F,h,w]
1384→320，不下采样2×(ResBlock → Temporal)[B,320,16,32,48]
2首个 ResBlock 空间 ÷2，320→6402×(ResBlock → Temporal)[B,640,16,16,24]
3首个 ResBlock 空间 ÷2，640→12802×(ResBlock → Temporal)[B,1280,16,8,12]
4首个 ResBlock 空间 ÷2，1280→12802×(ResBlock → Temporal)[B,1280,16,4,6]

上表是 F=16、H×W=256×384 且采用公开 YAML 配置 的结果。配置还指定 cin=384, ksize=1, sk=true, use_conv=false, compression_factor=1：残差卷积核为 1×1，下采样走平均池化而非 stride-2 卷积；入口 encoder_conv_in 则固定为 3×3。忽略 YAML、只看类默认值会得到错误结构。

4.2 时序注意力在空间位置内部交换帧信息

每做完一个 ResBlock，代码将 [BF,C,h,w] 重排为 [(B·h·w),F,C]，即每个 batch、每个空间位置形成一条长度为 F 的序列。公开 encoder 的 attention_block_types=["Temporal_Self"]，每块包含 LayerNorm、单头组意义上的多头 temporal self-attention（8 heads）、残差、LayerNorm 与 GEGLU FeedForward，并使用最长 16 帧的正弦时间位置编码。它不是沿 h、w 做全局空间 attention；不同像素位置的几何混合由卷积/下采样和后续 U-Net 完成。接口细节见 TemporalTransformerBlock。

ADV3 主干 motion module 另有两个 Temporal_Self attention。它们处理的是视频 latent 特征，而 encoder 的时序块处理 Plücker 特征，二者不能混为一层。主干的完整 temporal transformer 是 GroupNorm → 重排 [(Bhw),F,C] → proj_in → transformer blocks → proj_out → 加回残差，见 TemporalTransformer3DModel.forward。

4.3 融合发生在 Q、K、V 投影之前，而非只加在 attention 输出

对 temporal self-attention，视频 token 矩阵 X∈ℝ(Bhw)×F×C，同尺度相机特征 Cp 具有相同 shape。配置 query_condition=true, key_value_condition=true, scale=1，故采用 qkv_merge：

X′ = X + s·M0(X + Cp)，　Q = X′WQ，K = X′WK，V = X′WV(5)

M0 是 C→C 线性层，权重和 bias 都零初始化，所以刚开始训练时 X′=X，原生成器行为不被随机控制分支破坏；它不是 LoRA，也不是单位阵初始化。注意力仍为 softmax(QKT/√dh)V，再走原 to_out、dropout 和 attention 残差。初始化 与 前向 QKV 计算 是理解注入方式的核心。

5. 训练：冻结什么、优化什么，以及 epsilon/CFG 的对应关系

5.1 数据与几何监督来自原视频，而不是生成结果

论文 T2V 实验选择 RealEstate10K，约 65K clips。每个样本取 16 帧、stride=8、resize 到 256×384；文本 caption 用 LAVIS 生成。公开 YAML 打开首帧相对化、内参重标定和水平翻转。数据选择遵循两种分布的平衡：Objaverse 的相机分布宽，但白底物体的外观与 WebVid10M 差距大；MVImageNet 单条轨迹可复杂，却偏向水平环绕；RealEstate10K 的室内外场景和轨迹多样性更适合本文目标。论文也报告 RealEstate10K+ACID 没有带来改善，说明“加更多数据”并非自动有效。

论文还描述先在该数据集训练 image LoRA，再在此基础上训练 CameraCtrl，训练完成后可以移除该 LoRA。公开 main 的 realestate_lora.yaml 与相机 YAML 分开；相机阶段加载 LoRA 权重后，train_camera_control.py 冻结 VAE、CLIP text encoder 和整个 U-Net，再开启 pose encoder 及 attention processors，但随后将名字含 lora 的参数重新冻结，最终 optimizer 只收集 pose encoder 与名字含 merge 且不含 lora 的参数。ADV3 motion module、空间 attention、文本 cross-attention 等保持冻结。

5.2 扩散目标是 epsilon MSE，相机通过条件支路进入

VAE 编码原视频并乘 0.18215，采 ε∼N(0,I)，随机 t 后得到 zt；文本 encoder 不产生梯度，Plücker 序列与 zt、t、文本 embedding 一起输入 PoseAdaptor。公开训练代码仅接受 epsilon prediction，损失为：

L = 𝔼z₀,ε,c,text,t ‖ ε − ε̂θ(zt,t,text,Φc(P)) ‖22(6)

这 10% dropout 为文本 classifier-free guidance 提供无条件分支，不是“10% 丢弃相机”，也没有额外的 camera CFG。训练损失不含显式 COLMAP 重投影误差、光度误差或点云一致性项；位姿标签参与 Plücker 条件构造，噪声重建误差反向传播到 encoder 与 merge linear。

6. 自定义轨迹与推理：如何真正接到 pipeline，而不是只生成一个矩阵

推理阶段先从 SD1.5/ADV3 构建 UNet，再分别加载 pose_encoder_state_dict 与 attention_processor_state_dict；两者缺一不可。get_pipeline 返回 CameraCtrlPipeline，主入口把文本位姿文件变成 [B,6,F,H,W] 后通过 pose_embedding= 传入。默认输出为 16×256×384，25 个 DDIM steps，guidance_scale=14.0（inference.py 默认；pipeline 函数自身默认 7.5），初始随机种子为 42，可在 JSON 中指定每条 prompt 的 seed。

若已有自定义 c2w 轨迹，最直接的教学接入方式是先逐帧求逆成 w2c，按原视频画幅归一化内参，再写官方 19 字段格式。以下代码只生成轨迹文件，不加载模型；它沿用首帧相对化在 inference 内执行的路径，避免“先相对化一次、入口又相对化一次”。这里采用 x 右、y 下、z 前的 pinhole 约定，并显式检查帧数、有限值与旋转正交性。

    F = c2ws.shape[0]
    assert c2ws.shape == (16, 4, 4)
    assert np.isfinite(c2ws).all()
    assert np.allclose(c2ws[:, 3], [0, 0, 0, 1], atol=1e-6)
    assert np.allclose(c2ws[:, :3, :3].transpose(0, 2, 1)
                       @ c2ws[:, :3, :3], np.eye(3), atol=1e-5)
    if timestamps_us is None:
        timestamps_us = np.arange(F, dtype=np.int64) * 250_000
    assert len(timestamps_us) == F
    width, height = original_wh
    K = np.asarray([fx, fy, cx, cy], dtype=np.float64)
    assert np.isfinite(K).all() and fx > 0 and fy > 0
    K = K / [width, height, width, height]
    w2cs = np.linalg.inv(c2ws)
    with open(path, "w", encoding="utf-8") as f:
        f.write("custom_trajectory\n")  # 第一行只作为被跳过的来源头
        for ts, w2c in zip(timestamps_us, w2cs):
            fields = [int(ts), *K.tolist(), 0.0, 0.0,
                      *w2c[:3, :4].reshape(-1).tolist()]
            assert len(fields) == 19
            f.write(" ".join(map(str, fields)) + "\n")

# 调用 inference.py 时，original_pose_width/height 必须设为同一个 original_wh。

如果已经有绝对 w2c，就不必来回求逆，只需填第 7–18 列。若原始轨迹来自 OpenCV/COLMAP 之外的软件，须先确认相机轴、单位、左右手系与矩阵乘法方向；本仓库的 txt 格式转换不提供通用的 Blender/NeRF/OpenGL 轴变换。平移单位无需转换为米，但整条轨迹必须自洽：首帧相对化消除整体位置，不消除整体尺度，相邻帧平移幅度会改变 m=o×d 的量级和预期镜头运动强度。

CameraCtrlPipeline 在去噪循环之前只对相机编码一次，再把四尺度特征按 batch 复制成文本/空文本两路。每个 DDIM step 将同一个 latent 复制两路，分别使用空文本/negative prompt 与正文本，但两路都使用同一组 pose features：

ε̂CFG = ε̂(zt,∅,P) + s·[ ε̂(zt,text,P) − ε̂(zt,∅,P) ](7)

所以 main 的 CFG 强度调的是文本，不是“有相机 vs 无相机”的差分。25 个 step 中每步都要运行 U-Net 的有/无文本两路（合并 batch 计算），但 CameraPoseEncoder 只运行一次。pipeline 的 multidiff_total_steps=1 为默认单段；若改成多段，输入 pose 的列表/时间切片语义也需一起处理，不能仅提高 video_length 就假定长视频位姿自动正确。

不运行模型也能检查的入口：trajectory_file → Camera(entry) → 内参 resize → get_relative_pose → ray_condition → [B,6,F,H,W] → pose_encoder → 四个 [B,C,F,h,w] → unet(pose_embedding_features=...) → DDIM step → VAE decode。任何“只改了轨迹却没改输出”的排查，都应先确认该 tensor 确实进入这两条 CFG 分支。

文件职责阅读时最值得核对的内容

数据侧还有一条容易被忽略的流水线：gather_realestate.py 将 clips 按 YouTube 视频聚合，get_realestate_clips.py 将 timestamp 按微秒转秒后抽取视频，再生成 clip 与 pose 的 JSON 索引。select_realestate_poses.py 是仓库实际存在的轨迹抽取脚本，会随机选择窗口、按 stride 取样，并把原 URL 首行保留下来。README 中若出现不同脚本名，应以固定快照的实际文件为准。

ADV3 adaptor 与 RealEstate10K image LoRA 不是同一个东西。README 要求先用 merge_lora2unet.py 将 ADV3 adaptor 融入 SD1.5 U-Net，另存为类似 unet_webvidlora_v3 的 subfolder；可选的 RealEstate10K image LoRA 通过 --image_lora_ckpt 加载。个性化 SD checkpoint 则替换 VAE、U-Net 与 text encoder 的相应权重。排错时应记录四类权重来源：SD 基座、ADV3 motion、CameraCtrl、可选图像 LoRA/个性化基座，不能只保留一个总 ckpt 路径。

还有两个复现边界：其一，固定 main 已包含 train_image_lora.py，可用于图像 LoRA 阶段；但它依赖的基座、AnimateDiff 组件与模型权重仍需另行准备，文件存在不等于本文已跑通训练。其二，训练恢复路径 含 pdb.set_trace()，且 optimizer 状态加载被注释，不能直接视为无缝 resume。它们是公开代码状态，不是本文运行发现的错误。

8. 3D 一致性、相机—物体解耦、代价与失败模式

8.1 几何在哪里，能力边界也就在哪里

Plücker 场把内外参变成可供卷积和 temporal attention 学习的局部几何编码；RealEstate10K 的多视角视频提供真实视差与场景变化样本；U-Net 原有时序建模能力负责把这些线索映射成连续视频。这三者共同解释 3D 一致性的来源。它没有显式深度估计、NeRF、点云、mesh、可微渲染或跨帧重投影损失，故不能将其描述为严格的几何重建器，也不能保证任意大视角变化下被遮挡区域仍满足同一 3D 场景。

相机与物体运动只得到条件层面的部分分离：相机走 Plücker 支路，文本描述物体与动作，原生视频先验仍可同时生成两者。论文中 ODD 用 Grounded-SAM-2 选出主体、RAFT 估计主体光流，用来检查加入相机控制后物体动态程度；这并不等价于学习出独立、可交换的物体运动控制量。动态场景中 COLMAP 还可能将物体运动误当作相机运动，因此评估和解耦都受SfM估计质量影响。

8.2 已知失败与使用风险

  • 大角度旋转不足：论文附录 I 报告垂直 100° 与水平 150° 的失败示例，后者生成约 90°；作者推测 RealEstate10K 缺少足够的大旋转轨迹。这是论文声明，不是本地复测。
  • 新视图内容需要“想象”：T2V 没有参考场景，I2V 也只有有限观测；离开原视锥后没有真实几何可查询，结构与身份可能漂移。
  • 尺度与内参敏感：首帧相对化不归一化平移尺度；fx/fy/cx/cy 的像素/归一化错误会系统性地改变整个射线场。不一致的原视频宽高比也会引入错误的 resize 补偿。
  • 短视频估计瓶颈：论文指出 COLMAP 在 16 帧 T2V、14 帧 I2V 上不稳定；RotErr/TransErr 会剔除失败样本，并做首帧相对化与尺度归一化。指标不是无需校正的绝对物理误差。
  • 跨域不是无限制：不输入视频 latent 能减少外观泄漏，RealEstate10K 又缩小外观域差，但论文自己的数据消融表明外观和相机分布都会影响泛化。

8.3 计算代价的结构性判断

本快照不增加每个 denoising step 的 CameraPoseEncoder 重算，且 merge 是少量线性层；但编码器含 8 次逐空间位置的 temporal attention，其序列长度为 F，空间位置数为 Bhw，直接代价随空间面积与 F² 增长。U-Net 仍是主要去噪计算，CFG 默认使每步的有/无文本 U-Net 计算合成双倍 batch，VAE 又逐帧解码。以上是源码路径推导的复杂度分析，不是显存或帧率实测；论文提供的硬件耗时是训练配置声明，也不应作为本地 benchmark。

8.4 与代表方法的真实差别

方法控制表示与注入与 CameraCtrl 的边界
AnimateDiff MotionLoRA学习有限的镜头运动类别/模式不是任意逐帧 K、R、t 轨迹；不能对未定义的轨迹直接计算几何跟随。
MotionCtrl统一物体/相机控制；相机分支使用数值位姿序列并改造时序层CameraCtrl 使用逐像素射线几何，且本文训练时冻结视频主干；二者不是同一种 12 维矩阵投影。
CamCo / Recapture 等后续方法分别强调对极约束/3D 一致性，或已有视频的重摄相机控制任务输入与几何约束不同，不能把它们的深度、warp 或视频重摄机制归到 CameraCtrl。

9. 复现检查清单：先验证几何和路由，再评价生成质量

  1. 固定版本：记录论文 v2、源码 commit af45a7a0…、SD1.5/ADV3/CameraCtrl 权重版本与可选 LoRA。环境文件指定 Python 3.10、PyTorch 1.13.1、CUDA 11.7、diffusers 0.24.0；不要任意升级 attention API 后假定 processor 仍兼容。
  2. 核对文件形状：首行被跳过；其余每行 19 列，7–18 为 w2c；默认恰好 16 帧。检查 K 是否为归一化值，original_pose_width/height 是否匹配来源画幅，避免双重缩放。
  3. 验证矩阵：检查 RTR≈I、det(R)≈+1、齐次底行；用 xc=w2c·xw 的小例子确认方向。c2w 最后一列应为相机中心 o，而非未变换的 w2c 平移。
  4. 验证首帧：推理相对化后 C0=I，Ci=W0Ci；首帧 Plücker 的前三通道应为零。纯平移时方向不变，纯旋转时原点不变，这两个 sanity case 能迅速定位 w2c/c2w 混淆。
  5. 验证射线：使用像素中心 +0.5，先归一化相机系方向再旋转，顺序是 [o×d,d]，输出 [1,6,16,256,384]。不要把论文的 +t 混入方向，也不要一开始就降到 32×48 才计算 Plücker。
  6. 核对 encoder 配置：实际 YAML 为 nums_rb=2、ksize=1、sk=true、use_conv=false、四通道 320/640/1280/1280；输出空间尺寸 32×48、16×24、8×12、4×6，时间维保持 16。
  7. 核对 8 个注入点：down/up 各 4 个，均位于 motion module 的首个 temporal self-attention，Q/K/V 投影共享融合后的 X′。merge 从零初始化开始学习；没有 mid motion module，也没有默认 spatial pose 注入。
  8. 核对 checkpoint 加载：CameraCtrl.ckpt 内的 pose encoder 与 attention processor 两组 state dict 都要加载，且无 missing/unexpected keys；更换个性化基座不能覆盖掉新加载的 merge 参数。
  9. 核对采样：inference 默认 DDIM 25、CFG 14、16 帧、256×384；训练时验证 CFG=8 是另一处设置。CFG 两路共享相机条件，不能误写成第二路 pose=None。
  10. 训练时留痕：记录真实 world size、总 batch、gradient accumulation、25K/50K 选择、AdamW β 与 resume 行为。公开配置训练项 shuffle_frames=true 会打乱采样帧顺序，若进行严格复现应保留并记录；若研究连续轨迹，需明确将其作为代码差异单独消融，而非悄悄改动。
  11. 评价时报告失败样本：沿用 RotErr/TransErr 时记录 COLMAP 成功率、尺度对齐和人工过滤规则，同时报告 FVD/CLIPSIM/FC/ODD 所需参考集；论文 RealEstate10K 测试轨迹的估计下界说明误差不能按零解释。
  12. 明确未覆盖项：若需 SVD/I2V，应切换到官方 svd 分支并重新核对结构、shape 与 scheduler；不要把本文 main 的 ADV3 参数、25K YAML 或 [B,4,16,32,48] latent 直接套过去。
