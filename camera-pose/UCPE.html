00 / READING GUIDE

先建立全局图景：UCPE 到底统一了什么？

UCPE 的关键并不是再设计一种“相机向量”，而是把相机条件放入注意力机制的几何结构中：图像 token 不再只带有二维位置，还带有其对应三维射线的位置与朝向。不同镜头模型先被转换为同一种射线语言，再通过逐射线变换参与 Q、K、V、O 的计算。

这里的“统一”有三层含义。第一，统一投影模型：针孔、广角、鱼眼等模型都可以经反投影得到相机坐标系射线。第二，统一几何表达：射线方向与相机中心共同构造世界到射线局部坐标系的刚体变换。第三，统一网络接口：几何变换与绝对朝向嵌入分别通过乘法和加法进入一个轻量注意力分支，无需重写视频扩散主干。

一句话理解 RRE

给每条射线建立一个“z 轴沿视线、原点位于相机中心”的局部坐标系，让注意力直接读取射线之间的相对三维关系。

一句话理解 AOE

相对几何不知道世界的“上”在哪里，因此额外提供射线纬度与向上扰动在图像中的位移方向。

一句话理解适配器

复制一条独立、压缩的相机自注意力支路，以零初始化输出投影并行加回主干，使训练从原模型行为附近开始。

pose + x_fov + xi → d_cam → raymats → viewmats，同时生成 cam_emb，最后进入 cam_self_attn。

01 / MOTIVATION

问题定义：视频模型需要的不只是轨迹，而是可计算的空间关系

可控视频生成的目标是：给定文本、初始图像或其他内容条件，再给定镜头内参与相机轨迹，生成既满足语义又遵循指定观察几何的视频。难点在于，相机控制本质上定义了三维世界到二维图像的映射，而视频 DiT 接收的是潜空间 token 序列；两种表示之间存在明显的结构鸿沟。

设第 \(t\) 帧的外参为 \(T_t^{cw}=[R_t\mid \mathbf t_t]\)，它把世界坐标点变到相机坐标系；其逆 \(T_t^{wc}\) 则给出相机在世界中的位置与朝向。用户指定的“向左移动”“抬头”“扩大视场角”“鱼眼畸变”，最终都会改变每个像素所观察到的三维射线。若网络只得到一个拼接后的外参向量，它必须自行学习从矩阵数值到每个 token 几何含义的复杂映射。

早期方法常把相机参数编码为全局条件，再经交叉注意力或特征拼接注入。这种设计在固定针孔相机、有限轨迹范围内可以工作，但存在三个问题：

  • 空间粒度不匹配。一个相机矩阵对应整帧，而一帧内不同像素具有不同视线方向；局部透视与畸变信息被压平。
  • 模型形式不统一。针孔、广角、鱼眼的内参与畸变参数维度不同，直接拼接难以形成稳定、共享的表示。
  • 绝对与相对关系混杂。世界坐标原点可以任意选取，真正决定多视图对应关系的往往是射线间相对几何；但只保留相对几何又会丢失重力和绝对朝向。

UCPE 将问题重新表述为：对视频 token \((t,u,v)\)，先找到它所对应的射线，再构造该射线的局部三维坐标系。这样，网络不必从抽象矩阵反推“这个 token 看向哪里”，而是直接在该 token 的几何坐标系中执行注意力。

\[\mathcal V=\operatorname{VideoDiT}_{\theta}(\mathbf z,\ c_{text},\ \Phi_\psi,\ \{T_t^{wc}\}_{t=1}^{F})\] (1.1)

其中 \(\Phi_\psi\) 是投影模型决定的像素到射线映射，\(\psi\) 可包含视场角和 UCM 参数 \(\xi\)。UCPE 并不替代视频生成模型，而是给模型增加一个几何一致的条件接口。

1.1 为什么“相机位置编码”比“相机特征”更准确

“特征”通常指一个与内容特征相加或拼接的向量；UCPE 的主体 RRE 却不是一个六维或十二维向量，而是作用在注意力隐藏维度上的分块线性变换。每个 token 的 \(4\times4\) 矩阵被展开成适用于 head 子空间的矩阵操作，直接改变 Q/K/V/O 所表达的坐标系。因此，它更接近 RoPE：RoPE 用位置相关旋转让注意力感知相对位置，UCPE 用射线相关的 SE(3) 变换让注意力感知相对三维观察几何。

这也解释了为何 UCPE 可以同时改变内参、外参和畸变，而无需为每种相机设置独立控制分支。模型看到的一直是统一形式的射线局部坐标系；投影模型只影响射线如何生成，不影响后续注意力的数据类型。

核心洞察 把相机控制从“整帧条件嵌入”提升为“逐 token 坐标系变换”。UCPE 的表达力来自几何结构，而不只是增加参数或提高嵌入维度。

1.2 RRE 与 AOE 缺一不可

仅有 RRE 时，同一组相机整体绕世界任意旋转，射线之间的相对关系可以保持不变；但生成视频中的地平线、重力和天空方向通常需要与世界坐标对齐。AOE 因而补充绝对朝向：射线纬度描述俯仰，Up 图描述将射线朝世界上方向轻微旋转后，在图像平面产生的方向性位移。论文实验显示，加入 AOE 后 Pitch、Roll 和视觉质量明显改善，但平移相关指标不一定同步改善，这说明两种编码承担的是不同任务，而非简单叠加越多越好。

02 / GEOMETRY

几何基础：从像素到世界坐标中的射线

理解 UCPE 最重要的前置知识，是区分“相机坐标系中的点”“相机中心”“射线方向”和“世界到局部坐标系的变换”。下面统一采用列向量、齐次坐标和左乘矩阵。

2.1 四个坐标系与两类外参

对象本文记号含义
像素坐标\((u,v)\)图像或潜空间网格上的位置，经过内参与畸变模型映射到射线。
相机坐标系cam本文采用 x 向右、y 向下、z 向前；射线方向默认在该坐标系生成。
世界坐标系world / wld所有帧共享的参考系；世界上方向为 \(u^{wld}=[0,-1,0]^T\)。

代码中的 c2w 明确表示 camera-to-world。若输入轨迹是 world-to-camera，必须先求逆；若直接把二者混用，射线会转向错误方向，相机中心也会错误。WorldCrafter 的本地接口同样要求轨迹字段名为 c2w。

2.2 统一射线表示

对任意投影模型，定义像素到相机射线的映射：

\[\Phi_\psi:(u,v)\longmapsto\left(\mathbf o_{u,v}^{cam},\mathbf d_{u,v}^{cam}\right)\] (2.1)

对于中心投影相机，所有射线共享相机中心，因此 \(\mathbf o_{u,v}^{cam}=\mathbf 0\)，差异完全由方向 \(\mathbf d_{u,v}^{cam}\) 表达。UCPE 的一般定义允许非中心相机，即不同像素可以有不同的射线原点；但在本文核查的官方默认路径中，t_cam 被广播到一帧所有 \(H\times W\) 个网格位置，实际实现主要对应中心投影模型。不能把一般定义扩展成“公开训练代码已经支持任意非中心相机”。

已知 camera-to-world 外参后，方向只旋转不平移，射线原点则等于世界中的相机中心：

\[\mathbf d^{world}=R_{cam}\mathbf d^{cam},\qquad \mathbf o^{world}=t_{cam}\] (2.2)

方向是否归一化不影响射线所代表的直线，但会影响后续局部坐标轴的构造。官方 RRE 代码对 \(d_{world}\) 做 F.normalize，因此 \(z_{ray}\) 是单位向量。UCM 反投影本身输出的方向不必为单位长度，这一点不应与最终局部坐标的归一化混为一谈。

2.3 针孔反投影：最简单的特例

忽略畸变时，针孔模型满足 \(u=f_xX/Z+c_x\)、\(v=f_yY/Z+c_y\)。从像素恢复方向可直接写成：

\[\widetilde{\mathbf d}^{cam}=\left[\frac{u-c_x}{f_x},\frac{v-c_y}{f_y},1\right]^T,\qquad \mathbf d^{cam}=\frac{\widetilde{\mathbf d}^{cam}}{\|\widetilde{\mathbf d}^{cam}\|_2}\] (2.3)

这一公式揭示：内参不是只能作为网络输入的标量，它天然决定每个空间 token 的方向。视场角增大时，同样的像素偏移对应更大的光线倾角；主点偏移时，整幅图像的射线束随之偏移。UCPE 将这些变化转化为统一的几何操作。

2.4 SE(3) 与齐次变换的方向

\[T_{a\leftarrow b}=\begin{bmatrix}R_{a\leftarrow b}&t_{a\leftarrow b}\\0^T&1\end{bmatrix},\qquad x_a=R_{a\leftarrow b}x_b+t_{a\leftarrow b}\] (2.4)

读矩阵时应始终问“输入坐标属于哪个系、输出坐标属于哪个系”。若 \(T_{l2w}=[R_{l2w}\mid t_{cam}]\) 把射线局部点变到世界，那么其逆 \(T_{w2l}\) 才是 UCPE 代码中的 raymats：

\[R_{w2l}=R_{l2w}^{T},\qquad t_{w2l}=-R_{w2l}t_{cam}\] (2.5)

平移项不是简单的 \(-t_{cam}\)，而是先把相机中心取负，再旋转到射线局部坐标系。这个细节决定跨帧平移是否能被正确表达。

维度速查：d_cam: [B,H,W,3]；c2w: [B,F,4,4]；d_world: [B,F,H,W,3]；raymats: [B,F,H,W,4,4]；展平后 viewmats: [B,F·H·W,4,4]。
03 / REPRESENTATION EVOLUTION

表示演进：Direct、Plücker、CaPE、GTA、PRoPE 到 UCPE

UCPE 并非孤立出现。它继承了两条路线：一条把相机或射线编码成向量，另一条把相机几何作为注意力的坐标变换。理解这些前代方案，有助于准确判断 UCPE 的创新究竟发生在哪里。

3.1 Direct embedding：直接拼接相机参数

Direct 方法把内外参展开成向量，经 MLP 后与文本或视频特征结合。它实现简单，但参数排列依赖相机模型，数值尺度和坐标约定也会直接影响学习。更重要的是，整帧共用一个向量，无法自然描述“同一帧中左上角与右下角射线方向不同”这一事实。

3.2 Plücker embedding：用直线几何统一射线

三维直线可用 Plücker 坐标表示。设射线上一点为 \(\mathbf o\)，方向为 \(\mathbf d\)，则矩向量 \(\mathbf m=\mathbf o\times\mathbf d\)，六维表示为：

\[\mathbf m=\mathbf o\times\mathbf d,\qquad \mathcal P(\mathbf o,\mathbf d)=[\mathbf m,\mathbf d]\in\mathbb R^6\] (3.1)

叉积消除了沿射线方向选择不同点的歧义：若 \(\mathbf o'=\mathbf o+\lambda\mathbf d\)，则 \(\mathbf o'\times\mathbf d=\mathbf o\times\mathbf d\)。因此 Plücker 坐标非常适合表达射线，并可逐像素构造特征图。然而 \([\mathbf m,\mathbf d]\) 仍依赖世界坐标原点与轴方向；网络还需自行从六维数值学习两射线间的关系。它提供的是统一输入，不是坐标系不变的注意力。

对于中心相机，所有射线原点相同，\(\mathbf m=t_{cam}\times\mathbf d\)。当相机中心位于世界原点时，所有矩向量都为零，Plücker 图只剩方向。这并非信息错误，但说明其六维数值会随参考系选取发生显著变化。

3.3 CaPE 与 GTA：把几何放入注意力

CaPE 的核心是把相机变换应用于 Q/K，使点积反映两个位置之间的相对相机关系。GTA 在此基础上进一步变换 V 和注意力输出 O：如果只有 Q/K 感知几何，注意力权重具有几何意义，但被聚合的 Value 仍留在原坐标表达中；同时变换 V/O 能让整个注意力块在几何一致的表示下工作。

这一思路与 UCPE 的 Q/K/V/O 设计直接相关。UCPE 的改进不是首次提出“变换注意力”，而是把变换的粒度从每个相机或每帧推进到每条射线，并用统一的射线局部 SE(3) 处理不同镜头。

3.4 PRoPE：投影矩阵与 RoPE 的组合

PRoPE 将针孔内参形成的投影矩阵引入注意力，同时保留 RoPE 对二维图像位置的表达。其典型做法是把 head 通道划分为不同子空间：一部分应用相机投影相关线性变换，另一部分分别应用水平和垂直旋转位置编码。

但逐相机投影矩阵仍不能完整表达一帧内每条射线的局部三维朝向，尤其在强畸变和非针孔模型中。UCPE 保留这种混合通道设计，却把 \(P\) 替换为逐射线世界到局部变换，使注意力从“相机投影感知”升级为“射线几何感知”。

04 / RAY-BASED RELATIVE ENCODING

RRE：为每条射线建立一个局部三维坐标系

Ray-based Relative Encoding（RRE）是 UCPE 的主体。它不把射线编码为六维向量，而是为每个 token 构造世界到射线局部坐标系的刚体变换。这样，两个 token 的注意力关系可以由两个局部坐标系之间的相对 SE(3) 精确描述。

4.1 三个局部坐标轴如何确定

设当前 token 的世界射线方向为 \(d_{world}\)，相机 y 轴在世界中的方向为 \(cam_y=R_{cam}[:,1]\)。UCPE 依次构造：

\[\begin{aligned} z_{ray}&=\operatorname{normalize}(d_{world}),\\ x_{ray}&=\operatorname{normalize}(cam_y\times z_{ray}),\\ y_{ray}&=\operatorname{normalize}(z_{ray}\times x_{ray}). \end{aligned}\] (4.1)

这三个向量形成右手正交基。z 轴锁定观察方向；x 轴由相机向下方向与视线叉乘得到，通常指向图像右侧；y 轴再由 z 与 x 叉乘补全。相较于任意构造一个垂直向量，使用 \(cam_y\) 作为参考保留了相机 roll 的信息。

\[R_{l2w}=[x_{ray}\ y_{ray}\ z_{ray}]\in SO(3),\qquad R_{w2l}=R_{l2w}^{T}\] (4.2)

这里 \(R_{l2w}\) 的三列分别是局部 x、y、z 轴在世界坐标中的表示。局部坐标原点放在世界相机中心 \(t_{cam}\)，因此完整的世界到射线局部变换为：

\[T_i^{rw}=\begin{bmatrix}R_i^T&-R_i^Tt_i\\0^T&1\end{bmatrix},\qquad T_i^{wr}=\begin{bmatrix}R_i&t_i\\0^T&1\end{bmatrix}\] (4.3)

记号 \(T_i^{rw}\) 表示 world→ray，输入世界齐次点，输出第 \(i\) 条射线的局部坐标。代码变量 raymats 保存的就是 \(T_i^{rw}\)，后续作为 viewmats 输入 PRoPE 风格注意力。

4.2 两条射线之间的相对几何

把射线 \(j\) 局部坐标中的点变到射线 \(i\) 局部坐标，需要先回到世界，再进入 \(i\)：

\[T_{i\leftarrow j}=T_i^{rw}T_j^{wr}\] (4.4)

略去齐次最后一行，展开旋转和平移：

\[\begin{aligned} R_{i\leftarrow j}&=R_i^TR_j,\\ t_{i\leftarrow j}&=R_i^T(t_j-t_i),\\ x_i&=R_i^TR_jx_j+R_i^T(t_j-t_i). \end{aligned}\] (4.5)

这就是 RRE 的几何含义：\(R_i^TR_j\) 描述两个观察方向的相对旋转，\(R_i^T(t_j-t_i)\) 描述从相机 \(i\) 指向相机 \(j\) 的基线在射线 \(i\) 局部坐标中的表示。它不再依赖一个任意的全局原点，而是以接收注意力的射线为参照。

同一帧、同一相机中心

若 \(t_i=t_j\)，平移项为零，仅剩不同像素视线之间的旋转。内参和畸变正是通过这些方向差异进入注意力。

跨帧、相机发生平移

若 \(t_i\neq t_j\)，相对变换包含旋转后的基线。网络因而能区分纯旋转与带视差的相机移动。

需要注意，RRE 不是把注意力显式限制为某个物理极线约束，也没有在代码中直接计算所有 token 对的 \(N\times N\) 个 SE(3)。它保存每个 token 的局部变换，再通过 Q/K 的矩阵组合让点积隐式获得相对关系，避免了显式构造巨大的成对几何张量。

4.4 RRE 的存储与计算代价

若总 token 数为 \(N=FHW\)，viewmats 的浮点元素数为 \(16BN\)。相较 \(N^2\) 注意力矩阵，这是一项关于 \(N\) 的线性存储开销。真正增加的计算主要来自每条支路的 Q/K/V/O 投影、逐 token 矩阵运算和一次压缩后的自注意力。论文延迟实验表明，UCPE 总生成时间相对同 Wan 基线方法仅有小幅增加，但这属于论文在指定硬件与配置下的报告，不应外推为任意分辨率下的固定比例。

05 / UNIFIED CAMERA MODEL

UCM：把视场角、焦距与鱼眼畸变连成一条射线

Unified Camera Model（UCM）用一个额外的 \(\xi\) 参数扩展针孔投影。UCPE 使用它生成覆盖针孔、广角、鱼眼乃至极端鱼眼的训练数据与控制信号。理解 UCM 的正向投影与反投影，才能理解“统一相机”具体如何落地。

5.1 从水平视场角到焦距

官方公开接口中的 x_fov 接受角度制数值，并在内部通过 torch.deg2rad 转为弧度。图像宽度为 \(W\)，UCM 参数为 \(\xi\)，焦距为：

\[f_x=f_y=\frac{W}{2}\frac{\cos(xFoV/2)+\xi}{\sin(xFoV/2)}\] (5.1)

当 \(\xi=0\) 时，公式退化为 \(f=W/2\cot(xFoV/2)\)，正是水平视场角与针孔焦距的关系。角度单位是常见的集成错误：若把已经转为弧度的值再次传给接受度数的接口，会产生完全不同的焦距和射线束。

5.2 UCM 正向投影

设相机坐标点为 \([X,Y,Z]^T\)，其到原点距离为 \(r=\sqrt{X^2+Y^2+Z^2}\)，主点为 \((c_x,c_y)\)，则：

\[\begin{aligned} u&=f_x\frac{X}{Z+\xi r}+c_x,\\ v&=f_y\frac{Y}{Z+\xi r}+c_y. \end{aligned}\] (5.2)

\(\xi=0\) 时分母就是 \(Z\)，回到针孔模型。非零 \(\xi\) 改变径向投影规律，从而模拟更广阔的视场与镜头畸变。分母中的 \(r\) 是三维点到相机中心的距离，不是二维图像半径，也不是 \(X^2+Y^2\) 的平方根。

5.3 公开代码中的反投影

UCPE 实际调用的 equi2pers 路径在 equi2pers/torch.py · ucm_unproject_grid 中实现。先把像素偏移归一化为 \(x,y\)，再恢复方向：

\[\begin{aligned} x&=(u-c_x)/f_x,\qquad y=(v-c_y)/f_y,\qquad r^2=x^2+y^2,\\ \alpha&=\xi+\sqrt{1+(1-\xi^2)r^2},\\ \gamma&=\frac{\alpha}{1+r^2},\\ d^{cam}&=[\gamma x,\ \gamma y,\ \gamma-\xi]^T. \end{aligned}\] (5.3)

\[d^{cam}=\frac{[x,y,1]^T}{\sqrt{1+x^2+y^2}}\] (5.4)

这与式 (2.3) 的归一化针孔射线完全一致，是检查实现是否正确的重要单元测试。对于一般 \(\xi\)，还需要关注根号定义域、有效视场、坐标 y 方向和主点约定。

5.4 为什么 UCM 适合 UCPE

UCM 的作用不是替代所有现实镜头模型，而是提供一个连续、可采样、能够覆盖大视场变化的参数族。训练时通过不同 \(xFoV,\xi\) 组合产生多种投影下的视频和轨迹；测试时只要新模型能够反投影为射线，RRE 接口就保持相同。论文还展示了未见 Brown-Conrady 模型上的零样本例子，但完整 360° ERP 失败，说明“统一接口”不等于“任意投影都必然泛化”。

06 / ABSOLUTE ORIENTATION ENCODING

AOE：为相对射线几何补上“世界的上方向”

Absolute Orientation Encoding（AOE）解决 RRE 的信息盲区：即使所有相机与射线在世界中整体旋转，射线间相对关系仍可能不变，但视频中的天空、地面和重力方向已经改变。AOE 用 Latitude 与 Up 两个逐射线量提供绝对朝向。

6.1 为什么相对编码无法唯一决定 pitch 与 roll

考虑所有 \(R_i\) 与 \(t_i\) 同时经一个全局刚体变换。相对项 \(R_i^TR_j\) 中的全局旋转会抵消，基线也只变到相应局部坐标中；RRE 并没有一个外部参考告诉它哪个方向是重力反方向。对于纯旋转轨迹，这种歧义尤其直观：局部视线之间的夹角相同，并不说明相机相对于地平线处于相同姿态。

UCPE 采用 x 右、y 下、z 前的相机约定，并令世界上方向 \(u^{wld}=[0,-1,0]^T\)。因此世界 y 轴负方向是“上”，正方向是“下”。如果数据预处理后世界坐标轴定义不同，AOE 必须同步转换，否则 Lat 和 Up 会给出相反或错误的信息。

6.2 Latitude：射线在世界中的纬度

设单位世界射线 \(d=[X_w,Y_w,Z_w]^T\)，其纬度定义为：

\[Lat=\operatorname{atan2}\left(-Y_w,\sqrt{X_w^2+Z_w^2}\right)\] (6.1)

当射线朝世界上方向时，\(Y_w<0\)，Lat 为正；朝向地面时为负；位于水平面时接近零。Lat 是一个标量图，每个空间 token 一个值，再沿时间帧排列。它不是相机中心的高度，也不是相机外参中的单个欧拉角，而是每条射线的绝对俯仰信息。

6.3 Up：把世界上方向转成图像位移

仅有 Lat 仍不足以清楚表达所有 roll 信息。Up 图的做法是：将当前射线朝世界上方向旋转一个很小固定角度 delta=0.1 rad，再把旋转后的射线重新投影回当前镜头，观察像素坐标向哪里移动。设单位旋转轴为 \(\hat k=\operatorname{normalize}(d\times u^{wld})\)，Rodrigues 公式为：

\[d_{up}=d\cos\delta+(\hat k\times d)\sin\delta+\hat k(\hat k^Td)(1-\cos\delta)\] (6.2)
\[\Delta p_{up}=\Pi_\psi(d_{up})-\Pi_\psi(d),\qquad Up=\operatorname{normalize}(\Delta p_{up})\in\mathbb R^2\] (6.3)

这里 \(\Pi_\psi\) 是相同镜头模型的正向投影。因为 Up 最终表示图像平面位移，它自动包含当前内参与畸变对方向变化的影响。与直接给网络一个世界向上向量相比，这种设计更贴近 token 所在的二维视觉坐标。

6.4 代码中的通道顺序与注入方式

官方 camera_control.py · compute_up_lat_map 返回 up_map 和 lat_map，Wan pipeline 再按以下方式拼接：

因此实际张量通道是 \([up_x,up_y,lat]\)。论文文字有时写为 \([Lat,Up]\)，两者是描述顺序与代码拼接顺序的差异；复现和自定义数据接口必须以代码张量顺序为准。最终 cam_emb 的形状是 \([B,N,3]\)，随后由 Linear(3,D) 映射到 token 维度并相加。

07 / HYBRID GEOMETRIC ATTENTION

混合注意力：RRE 如何进入 Q、K、V、O

构造 viewmats 只完成了几何准备。UCPE 真正影响生成的地方，是把逐射线 SE(3) 变成注意力隐藏通道上的线性变换，同时保留二维 RoPE 对图像网格位置的表达。

7.1 每个 head 的 ½ + ¼ + ¼ 通道布局

设单个注意力 head 的维度为 \(d_h\)。UCPE 将通道划分为三个互不重叠的子空间：前 \(d_h/2\) 通道应用逐射线几何矩阵，中间 \(d_h/4\) 通道应用水平 RoPE，最后 \(d_h/4\) 通道应用垂直 RoPE。

\[q_i=\operatorname{Concat}(q_i^{geo}\in\mathbb R^{d_h/2},\ q_i^{x}\in\mathbb R^{d_h/4},\ q_i^{y}\in\mathbb R^{d_h/4})\] (7.1)

这种分工避免让单一表示承担全部任务。SE(3) 子空间处理三维观察几何，水平与垂直 RoPE 子空间保留规则图像网格中的相对位置先验。对于经过 VAE 与 patchify 的视频 token，二维网格仍是内容组织的重要归纳偏置，完全移除 RoPE 并非必然更优。

½：per-ray SE(3)+¼：horizontal RoPE+¼：vertical RoPE

7.2 Q、K、V、O 使用不同方向的矩阵

在默认 Ks=None 路径中，令 \(P_i\) 为第 \(i\) 个 token 的 viewmats，即世界到射线局部变换。官方 PRoPE 风格实现取 \(P_T=P^T\)、\(P_{inv}=P^{-1}\)，并按下表作用：

位置几何子空间水平 / 垂直 RoPE 子空间目的
Query\(P_i^Tq_i\)正向位置旋转把查询转换到适合相对几何点积的表示。
Key\(P_j^{-1}k_j\)正向位置旋转与 Query 组合后形成 \(P_iP_j^{-1}\) 的相对关系。
Value\(P_j^{-1}v_j\)正向位置旋转让被聚合的信息也经过一致的几何变换。
Output\(P_i o_i\)inverse=True 逆旋转把聚合结果映回当前 token 的输出表示。

只看几何子空间，Query 与 Key 的点积可写为：

\[(P_i^Tq_i)^T(P_j^{-1}k_j)=q_i^TP_iP_j^{-1}k_j\] (7.2)

由于 \(P_j^{-1}=T_j^{wr}\)，所以 \(P_iP_j^{-1}=T_i^{rw}T_j^{wr}\)，恰好就是式 (4.4) 的“射线 j 局部 → 世界 → 射线 i 局部”。这解释了矩阵方向为何不能任意交换：它不是为了让矩阵形式更复杂，而是为了让注意力点积直接包含相对坐标变换。

不是显式构造 N×N 几何矩阵 实现只保存每个 token 的 \(P_i\)，在 Q/K 上分别作用。相对变换 \(P_iP_j^{-1}\) 在点积的代数关系中隐式出现，无需额外存储 \(N^2\) 个 SE(3)。

当矩阵第二维等于序列长度时，代码进入逐 token 矩阵路径，而不是整帧共享矩阵路径：

thirdparty/prope/torch.py · 逐 token 矩阵乘法
if matrix.shape[1] == seqlen:
    feats_ = feats.view(batch, num_heads, seqlen, feat_dim // D, D)
    out = torch.einsum("btij,bntpj->bntpi", matrix, feats_)

这里的 D 是局部矩阵操作的维度，feat_dim // D 表示一个 head 中被几何矩阵覆盖的分块数量。UCPE 传入的是 \(4\times4\) 齐次矩阵，配合铺展方式在指定通道上执行块对角式变换。阅读代码时应把 D 与整个 DiT 的隐藏维度区分开。

7.4 为什么 V 与 O 也必须参与

如果只变换 Q/K，注意力权重会感知几何，但 Value 仍是未经坐标调整的内容向量；加权求和后再直接输出，几何表达与内容表达之间可能不一致。UCPE 对 K/V 使用同一组 transforms_kv，再对输出使用相反方向的 \(P\) 与逆 RoPE，使“注意力分配—信息聚合—结果写回”形成闭环。

不过，几何变换不是可逆性在任意浮点条件下都绝对无损的保证。矩阵条件数、数据类型、归一化与零初始化分支都会影响实际训练。严格诊断时，可分别关闭几何、AOE 和 RoPE 子空间，检查控制误差与生成质量的变化。

08 / SPATIAL ATTENTION ADAPTER

Spatial Attention Adapter：把相机分支轻量插入视频 DiT

UCPE 不直接微调 Wan 的全部参数，而是在每个 DiT 自注意力块旁增加一个独立、压缩的相机注意力分支。该分支同时接收视频 token、RRE 矩阵和可选 AOE 嵌入，再把结果作为残差加回主干。

8.1 独立投影与压缩维度

设主干 token 维度为 \(D\)，压缩系数为 \(C\)。相机分支的注意力隐藏维度为 \(D/C\)，head 数也按同一系数减少。它拥有自己的 Q/K/V/O 投影，而不是复用主干投影权重；因此可以专门学习相机控制，同时让原始 Wan 注意力继续负责原有生成能力。

8.2 AOE 在投影前加到 token 上

\[\widetilde x_i=x_i+W_{aoe}\,\operatorname{AOE}_i,\qquad q_i=W_q\widetilde x_i,\quad k_i=W_k\widetilde x_i,\quad v_i=W_v\widetilde x_i\] (8.1)

这与 RRE 的乘性注入完全不同。AOE 先改变分支的 token 表示，再经 Q/K/V 投影；RRE 则在投影之后对隐藏向量进行几何变换。若把 cam_emb 错当成 viewmats，或者把三维 AOE 直接送入矩阵乘法接口，张量形状和语义都会同时出错。

8.3 before、parallel、after 三种插入位置

模式结构含义特征
before相机分支在主注意力之前处理特征更接近前置条件调制；论文消融称 Pre-Attn。
parallel相机分支与原自注意力读取同一输入，输出相加默认与主实验配置；保留原分支并增加独立几何残差。
after相机分支在主注意力之后继续处理更接近后置修正；论文消融称 Post-Attn。

默认并行分支可简写为：

\[h_{out}=h_{base}+\operatorname{Attn}_{base}(x)+W_o\,\operatorname{Attn}_{cam}(\widetilde x;P)\] (8.2)

8.4 零初始化为何重要

训练开始时，out_proj.weight=0 且 out_proj.bias=0，因此无论相机分支内部输出什么，W_o Attn_cam 都严格为零，整个 DiT 初始行为等于未加控制的原模型。随着反向传播更新输出投影，相机分支才逐渐获得影响生成结果的能力。

零初始化并不意味着整个分支永远没有梯度。输出层为零时，较前面的 Q/K/V 层在第一步可能梯度受限，但输出层本身可以收到非零梯度；一旦输出层脱离零点，前面的层也进入正常训练。这是一种常见的稳定适配策略，而不是冻结适配器。

结构上的参数效率 参数效率主要来自“只训练适配器”和“同时压缩隐藏维度与 head 数”，而不是把 \(4\times4\) 矩阵当作一个小向量。论文默认配置报告 35.6M 可训练参数，原 Wan 文本编码器、DiT 与 3D VAE 权重保持冻结。

9.1 时间采样与空间网格

Wan 的 3D VAE 时间压缩倍率为 4。对于 81 个 RGB 帧，潜时间长度为 \(F=(81-1)/4+1=21\)，与 pose[:, ::4] 的采样一致。空间 token 网格则不能只看图像宽高：若 VAE 空间缩放为 \(s\)，DiT patch 高宽为 \(p_h,p_w\)，则 \(H_p=H_{img}/(sp_h)\)、\(W_p=W_{img}/(sp_w)\)。

UCM 反投影直接在注意力 patch 网格上执行，而不是先在完整 RGB 分辨率生成超大射线图再简单平均。这一点使 d_cam 的空间维度天然与 token 数对齐，也意味着每个 patch 的几何代表点由网格采样约定决定。

WorldCrafter 的序列还包含记忆 \(M\)、近期上下文 \(z_r\) 与当前待去噪片段 \(z_t\)。本地 transformer.py 明确把相机分支结果写入全序列的后半段，历史部分保持零：

            current_norm_hidden_states, camera_control_ucpe_input

其中 \(m\) 是当前尺度网格索引，\(W_s\) 是当前宽度，\(W_{ref}\) 是参考宽度。该式把 patch 中心先映射到参考网格，再恢复为零基索引；简单使用整数倍率 \(mW_{ref}/W_s\) 会漏掉半格中心修正。

10.4 compact_ucpe：精确存储压缩，不是激活量化

本地 compact_ucpe.py 对 UCPE 线性层参数做一种保守的 BF16 存储优化。转换前必须满足 torch.equal(p, p.bfloat16().float())，即每个参数都能被 BF16 精确表示；否则直接拒绝转换。前向时再把权重和 bias 转回 FP32 参与计算。

worldcrafter/fast/compact_ucpe.py · BF16 存储、FP32 计算
def _forward(self, x):
    return F.linear(
        x, self.weight.float(),
        None if self.bias is None else self.bias.float()
    )

if not torch.equal(p, p.bfloat16().float()):
    raise ValueError("UCPE storage conversion would lose information")
p.data = p.data.bfloat16()
layer.forward = types.MethodType(_forward, layer)

所以它不是“把相机矩阵量化成 BF16 后近似推理”，也不是把激活统一压成 BF16。它只减少满足精确表示条件的参数存储；运行时仍有 FP32 转换成本。可训练参数若处于任意浮点值，通常不会满足这个严格条件，因此它更适合特定的已训练/特殊初始化状态，而非泛化为通用无损半精度训练。

10.5 流式、多 GPU 与 RepEncoder 的边界

流式分块

每个 chunk 重新构造当前相对几何并与记忆/上下文组合。它是长视频生成组织方式，不改变 RRE 的局部坐标公式。

多 GPU context parallel

context_parallel.py 中的 K/V all-gather 用于跨设备上下文注意力，不等于 UCPE 自己发明了 KV cache。

几何缓存

geometry_cache.py 可复用可复用的几何结果，但不能把跨 denoising step、跨 chunk 的缓存当作天然合法；坐标基准与网格必须一致。

RepEncoder

RepEncoder 是独立的记忆条件路径，负责另一路历史表达。它不是 RRE、AOE 或 Spatial Attention Adapter 的组成部分。

本地所谓 absolute 模式也应谨慎理解：它使用“当前 chunk 内相对几何 + 世界上方向信息”。由于每个 chunk 位姿先相对其首帧，不能仅凭模式名就断言整条长轨迹始终处于一个全局固定坐标原点中。

官方方法与本地扩展对照 官方 UCPE 负责统一射线、RRE/AOE 与相机注意力；WorldCrafter 额外负责 33 帧 chunk、当前 token 注入、Fast 金字塔、参数存储、流式记忆和多 GPU 调度。二者可以组合，但论文实验不能自动证明这些本地扩展的速度或质量。

11.2 相机控制指标如何计算

论文从生成视频估计相机轨迹，再与目标轨迹比较。旋转误差使用两个旋转矩阵之间的测地角，平移误差使用欧氏距离；CamMC 则直接比较相机矩阵向量化后的差异：

\[\operatorname{RotErr}=\sum_i\arccos\frac{\operatorname{Tr}(R_i^T\hat R_i)-1}{2}\] (11.1)
\[\operatorname{TransErr}=\sum_i\|t_i-\hat t_i\|_2,\qquad \operatorname{CamMC}=\sum_i\|\operatorname{Vec}(T_i)-\operatorname{Vec}(\hat T_i)\|_2\] (11.2)

评估位姿均相对首帧，所有方法在相同的 16 个采样时间戳比较。这里的 RotErr、TransErr、CamMC 是求和形式，不应与逐帧平均角度或平均位移混用。FoV、径向畸变 \(k_1,k_2\)、Pitch、Roll 用于检查内参与绝对姿态控制；FVD、FID、CLIP 分别衡量视频分布、图像分布和文本语义一致性。

  • 未见投影模型。论文展示 Brown-Conrady 的零样本例子，支持“射线接口有助于模型迁移”的判断；完整 360° ERP 失败则给出明确反例。

12 / LIMITATIONS, REPRODUCTION AND CONCLUSION

适用边界、复现清单与结论

UCPE 的贡献可以概括为“以逐射线局部 SE(3) 统一相机条件，并用轻量几何注意力注入视频 DiT”。但它仍受训练位姿、镜头覆盖、局部坐标退化与基础模型能力约束。

12.1 方法与工程限制

限制一：训练依赖可靠相机位姿 数据构建需要 SLAM 提供有效轨迹，训练信号因而继承位姿估计的误差、尺度和筛选偏差。没有位姿的普通视频不能直接进入同一训练流程；错误的世界轴定义还会同时破坏 RRE 与 AOE。
限制二：控制范围不等于全部摄影参数 当前控制覆盖相机位姿、内参与畸变，但论文明确未覆盖变焦过程中的复杂镜头行为、对焦和景深等效果。FOV 可调也不意味着已模拟真实镜头的全部光学属性。
限制三：统一接口不保证任意投影零样本成功 Brown-Conrady 示例体现了一定泛化能力，完整 360° ERP 却失败。新投影能够反投影成射线只是接口前提；若射线分布远离训练覆盖，网络仍可能无法生成正确内容。
限制四：RRE 存在局部坐标退化 当相机 y 轴与射线方向接近平行，构造 x 轴的叉积趋近零。eps 只能抑制数值除零，不能在严格退化时凭空确定唯一的 roll 参考轴。

此外还有两个实际边界。其一，相机控制精度依赖从生成视频重新估计轨迹的工具，评估误差并不全是生成模型误差。其二，轻量适配器减少的是可训练参数与部分训练成本，并不会消除大模型视频扩散本身的推理开销。

12.3 最小复现与调试清单

  1. 确认版本。记录论文 v2、官方 commit、PyTorch/CUDA/FlashAttention 版本以及本地 WorldCrafter 修改状态。
  2. 确认外参方向。检查输入是否确为 camera-to-world；用单位阵和已知平移验证 d_world=Rd_cam、o_world=t_cam。
  3. 验证针孔特例。令 xi=0，比较 UCM 输出与归一化的 [(u-cx)/fx,(v-cy)/fy,1]。
  4. 验证局部旋转。检查 \(R_{l2w}^TR_{l2w}\approx I\)、\(\det R\approx1\)，并检查近退化射线的叉乘范数。
  5. 验证成对变换。随机选择两条射线，比较 viewmats[i] @ inverse(viewmats[j]) 与显式 \(T_i^{rw}T_j^{wr}\)。
  6. 验证 token 对齐。断言 N=F·Hp·Wp，并确保视频 token、viewmats、cam_emb 都按 T→H→W 展平。
  7. 验证 AOE 方向。构造水平、向上、向下射线，检查 Lat 符号；构造已知 roll，检查 Up 的图像位移方向。
  8. 验证零初始化。训练前比较关闭和开启相机分支的输出，理论上应一致；随后确认 out_proj 能获得非零梯度。
  9. 最后再做性能比较。固定主干、采样器、步数、帧数、分辨率、硬件与精度；分别报告控制指标、FVD/FID/CLIP 和延迟。
若只复现推理，可先使用官方权重和示例位姿，避免把数据处理、SLAM、训练与推理问题混在一次调试中。若复现训练，则应先小规模过拟合单个片段，检查分支是否确实能学习相机条件。

12.4 结论：如何准确理解 UCPE 的创新

UCPE 最重要的思想不是“把更多相机参数喂给网络”，而是让网络在正确的几何坐标系中计算注意力。UCM 把不同镜头转成射线；RRE 把每条射线变成局部 SE(3)，使 Q/K 点积包含射线间相对旋转与平移；AOE 补上世界上方向；PRoPE 风格通道划分让三维几何与二维 RoPE 共存；Spatial Attention Adapter 则以零初始化并行残差稳定接入冻结的视频 DiT。

论文结果支持这一设计：在同 Wan 基座下，UCPE 以约 35.6M 可训练参数获得显著更低的相机控制误差，并在 RealEstate10K OOD 测试的三个相对位姿指标上最佳。同时，AOE 对平移指标存在取舍，最小压缩分支的视觉指标与控制指标也不完全一致，部分 Wan 方法仍在若干视觉质量子指标上领先。这些结果共同说明：UCPE 是更强的几何条件接口，而不是脱离主干、数据与评估设置的万能质量保证。

对于 WorldCrafter，本地集成进一步把 UCPE 放入分块长视频、当前 token 注入、粗到细生成和多 GPU 上下文并行系统。正确的分析方式是把“论文方法的有效证据”与“本地工程的静态设计”分开，再通过固定配置的实测验证二者组合后的效果。
