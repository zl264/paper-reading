这不是“又一个 Plücker adapter”

AC3D 主要回答三个为什么：为什么训练很久仍然运镜不足？为什么控制增强后画质变差？为什么输入相机后物体容易不动？它分别用噪声调度、层级选择、静止相机动态数据回应。

1. 相机运动为什么是低频问题

相机平移和旋转往往引起整幅画面的平滑位移与透视变化，首先决定粗结构；纹理、边缘等高频细节在去噪后期逐步形成。如果训练平均分配各噪声尺度，网络可能没有足够机会学习“大结构运动”，而后期强条件又会干扰纹理。

AC3D 将训练噪声从标准 logit-normal 改为偏向 [0.6,1] 的截断正态，均值约 0.8、标准差 0.075；推理也只在前 40% 去噪区间启用相机。这里的时间方向按该论文 rectified-flow 定义理解：越接近 1 越噪。

t ∼ TruncNormal(μ=0.8, σ=0.075, interval=[0.6,1])(1)

这不是简单地“少训练后期”，而是把控制学习集中到最适合决定全局运动的阶段。迁移到其他 scheduler 时必须先核对 t 的方向和含义。

2. 轻量相机支路与时间压缩

输入包含每帧 4×4 相机矩阵与 3×3 内参，采用 VD3D 风格 Plücker。全卷积 encoder 将射线场与视频 token 空间对齐；对 4× 时间压缩，使用因果一维卷积把每像素 F×6 射线序列转为 (F//4)×32。

轻量 DiT-XS 相机支路为 128 维、4 头，视频 token 对 camera token 做 cross-attention，形成反馈。相机支路不接收文本、分辨率等 context，减少它利用文本捷径猜运动的可能。

图 1：AC3D 不是均匀地向所有层强加相机。频谱分析促使训练偏向高噪声；中间层 probing 促使只在前 8 层注入；动态静止相机数据解除主体冻结偏差。

讲解用实现 · 非官方源码：因果时间相机编码
class CausalCameraTimeEncoder(nn.Module):
    def __init__(self, in_channels=6, out_channels=32, ratio=4):
        super().__init__()
        self.ratio = ratio
        self.conv = nn.Conv1d(in_channels, out_channels,
                              kernel_size=ratio, stride=ratio)

    def forward(self, rays):
        # rays: [B,H,W,F,6]；保持像素网格，分别压缩时间。
        B,H,W,F,C = rays.shape
        x = rays.permute(0,1,2,4,3).reshape(B*H*W,C,F)
        x = self.conv(x)                         # [BHW,32,F/ratio]
        return x.reshape(B,H,W,32,F//self.ratio).permute(0,4,3,1,2)
# 因果 padding、边界首帧及精确输出布局应按真实 VAE 时间定义补齐。

3. 为什么只在前 8 个 block 注入

作者 probing 无条件 VDiT 的中间表征，发现模型本身已经隐式包含相机信息，而且只有部分层保留明显的位姿信号。全层持续注入外部位姿可能覆盖模型中层的既有表达，造成视觉质量下降。

最终 AC3D 只在最前 8/32 块前加入相机反馈，让早期层确定视角与全局结构，后续层主要恢复视频细节。这个“8”是该 11.5B 骨干的分析结果，不是所有 DiT 的固定最优值。

hl+1 = DiTBlockl(hl + 1[l<8]·CameraFeedbackl(hl,c))(2)
讲解用伪代码 · 非官方源码：层级与时刻共同控制
for layer_id, block in enumerate(main_dit.blocks):

4. 静止相机 + 动态物体：拆掉数据捷径

RealEstate10K 等位姿数据多为静态场景。若只有相机变化的视频才带位姿条件，模型可能学到“有相机输入 → 所有像素只按背景几何移动”，从而压制真实物体动态。

AC3D 将 65K RealEstate10K 与 20K 动态场景/静止相机视频结合，并令相机条件始终开启。静止相机提供了明确的负例：即使位姿不变，物体仍可运动。这比简单增加更多静态机位数据更直接地改变条件分布。

冻结主干、rectified-flow 训练，最终 6K steps；文本与相机使用独立 CFG 方向。可以用下式概括其双条件引导：

e = (1+wy+wc)s(t,c) − wys(c) − wcs(t)(3)

5. 评价与尺度处理

相机精度通常从生成视频重新估计轨迹再与目标比较。SfM 的平移存在尺度模糊，论文使用 metric depth 对 SfM 平移做尺度校准。因而“TransErr”不一定是没有尺度对齐的绝对米制误差；比较不同论文时要核查其标定协议。

论文说明 256² 训练可零样本泛化更高分辨率，但这不代表所有分辨率和所有长宽比都有相同相机精度。原始 VAE 时间压缩和 RoPE 仍需一致。

6. 局限与迁移建议

  • 没有显式 3D cache，回看同一场景仍可能漂移。
  • 静止相机动态数据解决一种伪相关，不自动完成任意物体与相机的独立控制。
  • 前 8 层和高噪声区间是骨干相关超参数，不应硬编码到新模型。
  • 相机支路、反馈 attention 与多条件 CFG 增加训练和推理成本。

迁移时建议先训练一个小型 pose probe，读取各层特征预测位姿，再决定注入层；用频谱或运动幅度随时间变化确认何时控制最有效。

7. 实践路线

  1. 复现一个基础 Plücker DiT baseline，记录轨迹与画质。
  2. 只改训练/推理时间调度，观察大运动是否改善。
  3. 逐层扫描注入位置，不假设越多越好。
  4. 加入静止相机动态视频，检查人物/物体是否恢复运动。
  5. 最后引入独立 camera CFG，并测量额外前向成本。

附录 A：把诊断转化为可测实验

频谱诊断可将相邻帧流场/图像变化做傅里叶变换，观察相机诱导运动是否集中于低频。工程上更简单的代理指标是：在不同去噪时刻开启或关闭相机，测输出相机轨迹误差与纹理指标的变化。若后期开启只降低画质而几乎不改善轨迹，说明主要控制应放在早期。

层级 probing 可冻结各层特征，训练一个轻量回归器预测当前位姿；若某些中间层已经能准确恢复相机，则重复强注入未必有益。对 32 层主干可扫描前 2、4、8、16、32 层，记录控制误差、动态幅度与视觉质量，而不是机械选择 8。

数据去偏的最小实验是：使用同一动态场景，渲染静止相机与运动相机两个版本。如果静止相机输入也生成静止人物，则问题更多在生成先验；如果只有带非零位姿输入才冻结人物，则说明模型利用了相机条件的伪相关。论文的 20K 静止相机动态数据正是为后者设计。

代码 1：CameraFeedback

CameraFeedback · 轻量支路与前 8 层反馈（讲解用实现，非官方源码）
class CameraFeedback(nn.Module):
    def __init__(self, video_dim=4096, camera_dim=128, heads=4):
        super().__init__()
        self.query = nn.Linear(video_dim,camera_dim)
        self.key = nn.Linear(camera_dim,camera_dim)
        self.value = nn.Linear(camera_dim,camera_dim)
        self.attn = nn.MultiheadAttention(camera_dim,heads,batch_first=True)
        self.out = nn.Linear(camera_dim,video_dim)
        nn.init.zeros_(self.out.weight)
        nn.init.zeros_(self.out.bias)

    def forward(self, video_tokens, camera_tokens):
        # 主干 video 维与轻量 camera 维不必相同。
        q = self.query(video_tokens)
        k,v = self.key(camera_tokens),self.value(camera_tokens)
        feedback,_ = self.attn(q,k,v)
        return self.out(feedback)

# 在主循环中：
for layer, block in enumerate(main_vdit.blocks):
    if layer < 8 and timestep >= 0.6:
        cam_state = camera_dit[layer](cam_state)   # 不含文本 context
        video_tokens = video_tokens + feedback[layer](video_tokens,cam_state)
    video_tokens = block(video_tokens,text_context)
# 不在后 24 层继续读取相机；这是 AC3D 特定骨干的选择。

附录 E：显式位姿推理流程

先由 Plücker 构造 camera token，逐层经轻量 DiT-XS 更新；仅在前 8 块且高噪声早期将 camera feedback 加进视频 token。后期 24 块不再强加相机。推理采用文本和相机的不同 guidance 权重，需与训练空条件定义一致。

推理前要明确：位姿是 c2w 还是 w2c、是否首帧相对、K 是否像素单位、帧率是否经过 VAE 压缩，以及 unconditional 分支采用哪一种空相机。只把这些数值变成合法 shape 不足以保证几何正确。
