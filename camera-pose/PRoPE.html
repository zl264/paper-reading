01 / OVERVIEW核心结论：相机不是附加标签，而是注意力的几何坐标系

PRoPE 的核心思想可以压缩成一句话：把每张图像对应的完整相机投影矩阵，以“相对投影关系”的形式注入注意力，使不同视图中的 patch token 能在统一的几何规则下交互。它不是简单把相机参数拼到图像特征后面，也不要求为每一对 token 显式构造一个巨大的几何张量。

在自然语言中，token 的“位置”通常是一维序列下标；在多视图视觉中，一个 patch 的位置却同时取决于它在图像中的二维坐标、拍摄它的相机内参、相机在世界中的外参，以及它与其他视图之间的空间关系。论文图 1 正是通过这一类比提出问题：既然语言 Transformer 需要位置编码，多视图 Transformer 就需要一种能够描述观察视角的“相机位置编码”。

已有的 raymap 方法可以提供像素射线，却依赖任意选定的全局坐标系；CaPE 与 GTA 引入相对外参，具有全局坐标不变性，却不能完整描述焦距、主点和视锥。PRoPE 将内参的齐次提升与外参的刚体变换合成为一个可逆的 \(4\times4\) 投影矩阵，再通过注意力前后的线性变换，让 \(P_iP_j^{-1}\) 自然出现在 token \(i\) 与 token \(j\) 的相互作用中。

一句话理解 PRoPE 的归纳偏置 对查询 token 而言，另一个视图的特征不应只在“原始相机坐标”中被读取，而应先被逆向投影到一个可比较的表示，再经过当前查询相机的投影规则参与打分与聚合。几何因此进入注意力算子本身，而不是停留在输入 embedding 的外围。

02 / MOTIVATION研究背景：多视图 token 为什么必须绑定视角？

单图视觉 Transformer 通常将图像切分成规则 patch，并借助二维位置编码保留空间布局。然而，多视图任务接收的不是一张孤立图像，而是一组带有拍摄关系的观测。可将其写为 \(\{(\mathbf I_i,\mathbf K_i,\mathbf T_i^{cw})\}_{i=1}^{N}\)，其中 \(\mathbf I_i\) 是第 \(i\) 张图像，\(\mathbf K_i\) 是内参，\(\mathbf T_i^{cw}\) 是从世界坐标到相机坐标的外参。

如果直接把所有 patch 拼接后送入普通自注意力，注意力权重只由视觉内容与二维 patch 位置决定。两个外观相似、图像坐标相同的 patch，可能来自相邻相机，也可能来自方向完全相反的相机；对网络而言，仅看 RGB token 很难区分这两种情况。新视图合成、立体匹配和多视图推理都需要知道：某个 token 从哪里观察世界，以及另一个 token 应如何被变换到它的观察框架中。

理想相机编码需要满足什么条件？

论文对编码方式的讨论实际上包含四个彼此牵制的目标。第一，它应包含足够完整的相机信息，不能只描述平移和旋转而忽略焦距变化。第二，它应尽可能相对化，避免网络记住没有意义的世界坐标原点。第三，它要容易嵌入标准 Transformer，而不是要求重写所有注意力 kernel。第四，它应能同时影响特征匹配和特征聚合；只改变注意力分数，未必足以让 value 的几何含义保持一致。

输入端编码

把射线、位姿或相机向量加到 patch embedding。实现直接，但几何主要作为额外特征存在，后续注意力仍按普通内容相似度交互。

算子内相对编码

让查询与键的内积、值聚合乃至输出都依赖相机关系。PRoPE 属于此类，更接近 RoPE 对序列位置的建模方式。

PRoPE 的关键贡献不是“首次使用相机参数”，而是发现投影矩阵的组合规则与注意力的线性代数结构可以精准对接。它将“完整相机视锥”与“相对位姿不变性”这两个此前难以兼得的目标，放进同一个可逆矩阵框架。

三个任务，同一种几何机制

论文没有将方法局限于单一生成模型，而是在新视图合成、立体深度估计与空间认知任务上验证，并进一步考察模型规模增长、输入视图数量变化以及 CAT3D 中的集成效果。这样的实验设计意在证明：PRoPE 是一种通用的多视图 Transformer 编码，而不是某个特定解码器的技巧。

03 / GEOMETRY几何预备知识：从世界点到像素，再到可逆投影

3.1 内参：相机坐标如何变成像素坐标

针孔相机的内参矩阵写为下式。\(f_x,f_y\) 是以像素为单位的焦距，\((c_x,c_y)\) 是主点，\(s\) 是轴间 skew。多数现代数据集将 skew 视为零，官方 PRoPE 的解析内参求逆也采用这一假设。

$$\mathbf K_i=\begin{bmatrix}f_x&s&c_x\\0&f_y&c_y\\0&0&1\end{bmatrix},\qquad \tilde{\mathbf x}_{img}\sim \mathbf K_i\begin{bmatrix}X_c\\Y_c\\Z_c\end{bmatrix}.$$
(1)

这里的 \(\sim\) 表示齐次坐标意义下相差一个非零尺度。将三维点映射到图像时，最后还要除以第三个齐次分量。因此普通的 \(3\times4\) 相机投影包含透视除法，不能直接当作可逆四维线性变换使用。

3.2 外参：严格区分 world-to-camera 与 camera-to-world

本文沿用官方代码的约定：viewmats 是 camera <- world，即世界到相机的 \(\mathbf T_i^{cw}\in SE(3)\)。若世界点与相机点都使用四维齐次坐标，则：

$$\mathbf T_i^{cw}=\begin{bmatrix}\mathbf R_i^{cw}&\mathbf t_i^{cw}\\\mathbf 0^\top&1\end{bmatrix},\qquad \mathbf x_i^c=\mathbf T_i^{cw}\mathbf x^w.$$
(2)

相机中心并不是 \(\mathbf t_i^{cw}\)，而是世界坐标下的 \(\mathbf o_i=-(\mathbf R_i^{cw})^\top\mathbf t_i^{cw}\)。这是工程接入中最常见的方向错误之一：如果上游框架保存的是 camera-to-world，就必须先求逆，不能仅更换变量名。

3.3 普通投影与齐次提升

常规 \(3\times4\) 投影矩阵为 \(\mathbf P_i=[\mathbf K_i\;\mathbf0]\mathbf T_i^{cw}\)。它把四维世界点压成三维图像齐次坐标，维度上便不可逆。PRoPE 的关键处理是将 \(3\times3\) 内参嵌入四维单位矩阵：

$$\widetilde{\mathbf P}_i=\underbrace{\begin{bmatrix}\mathbf K_i&\mathbf0\\\mathbf0^\top&1\end{bmatrix}}_{\operatorname{lift}(\mathbf K_i)}\mathbf T_i^{cw}\in\mathbb R^{4\times4}.$$
(3)

这一矩阵不再立即执行“三维到二维”的降维，而是保留第四维，使内参和外参都能作为可逆线性映射参与特征变换。只要焦距非零且外参合法，\(\operatorname{lift}(\mathbf K_i)\) 与 \(\mathbf T_i^{cw}\) 都可逆，因此 \(\widetilde{\mathbf P}_i\) 可逆。后文在不引起歧义时，将 \(\widetilde{\mathbf P}_i\) 简记为 \(\mathbf P_i\)。

为什么“可逆”如此重要？ 相对编码需要同时构造 \(P_i^\top\)、\(P_j^{-1}\) 与输出端的 \(P_i\)。若直接使用不可逆的 \(3\times4\) 投影，就无法形成闭合的相对变换链。齐次提升不是代码上的小技巧，而是整个方法成立的代数前提。

3.4 从像素恢复世界射线

对像素 \((u,v)\)，先以 \(\mathbf K_i^{-1}[u,v,1]^\top\) 得到相机坐标中的方向，再左乘 \((\mathbf R_i^{cw})^\top\) 转为世界方向。射线由世界原点和世界方向共同确定：

$$\mathbf d_i^{u,v}\propto(\mathbf R_i^{cw})^\top\mathbf K_i^{-1}[u,v,1]^\top,\qquad \mathbf o_i=-(\mathbf R_i^{cw})^\top\mathbf t_i^{cw}.$$
(4)

比例符号表示射线的方向可乘任意非零正尺度而不改变几何意义。Naive 与 Plücker raymap 都建立在这条射线上，而 CamRay 则保留相机局部方向。PRoPE 选择不逐像素显式构造射线，而是用产生整个射线族的投影矩阵来描述相机。

04 / COMPARISON已有编码：射线、相对位姿与完整视锥之间的取舍

4.1 Naive raymap 与 Plücker raymap

Naive raymap 通常将 \([\mathbf o_i;\mathbf d_i^{u,v}]\) 作为每个像素的几何特征；Plücker 表示则使用 \([\mathbf o_i\times\mathbf d_i^{u,v};\mathbf d_i^{u,v}]\)。叉积项是射线关于原点的矩，方向与矩共同给出一条三维直线的 Plücker 坐标。二者都与像素对齐，并能表达完整相机几何，因此在空间认知等任务中仍然很有价值。

问题在于，它们把世界原点、坐标轴方向和全局尺度选择直接写进特征。若把整个场景与所有相机一起做刚体坐标变换，实际图像与相对拍摄关系没有改变，raymap 数值却会变化。网络因而需要额外学习“哪些坐标变化不影响任务”。

4.2 CaPE 与 GTA：相对外参解决了什么，又遗漏了什么？

CaPE 和 GTA 通过 \(\mathbf T_i^{cw}(\mathbf T_j^{cw})^{-1}\) 建立视图 \(j\) 到视图 \(i\) 的相对关系。全局坐标变换会在矩阵乘积中抵消，因此这类方法天然具有全局刚体坐标不变性。区别在于，CaPE 主要变换 Q/K，而 GTA 还将相对几何扩展到 V 和注意力输出 O。

然而 \(SE(3)\) 外参只描述相机支架如何运动，不描述镜头如何成像。两个相机可以拥有完全相同的旋转和平移，却因焦距、视场角或主点不同而产生不同图像。对这些情况，\(T_iT_j^{-1}\) 仍然只是同一个相对位姿，无法表达完整 frustum。

4.3 CamRay：相机局部射线是补充，而非相对外参的替代品

CamRay 使用相机局部坐标下的像素方向：

$$\mathbf M_{i,\mathrm{CamRay}}^{u,v}=\mathbf R_i^{cw}\mathbf d_i^{u,v}\propto\mathbf K_i^{-1}[u,v,1]^\top.$$
(5)

这个表示直接告诉 token“像素在自己相机的哪个方向”，对局部视锥非常敏感，却不单独提供完整的跨视图相对关系。论文表 3 显示，将 CamRay 与 GTA 或 PRoPE 组合通常更好：前者补充局部射线信息，后者提供视图间几何。

05 / DERIVATIONPRoPE 核心推导：相对投影关系如何出现？

5.1 一个 \(4\times4\) 矩阵同时描述内参与外参

对视图 \(i\)，令 \(\mathbf L_i=\operatorname{lift}(\mathbf K_i)\)，则 \(\mathbf P_i=\mathbf L_i\mathbf T_i\)。它的逆可按相反顺序写成 \(\mathbf P_i^{-1}=\mathbf T_i^{-1}\mathbf L_i^{-1}\)：先撤销内参映射，再从相机坐标回到世界坐标。代码没有调用通用矩阵求逆，而是分别利用刚体变换与无 skew 内参的结构解析计算。

5.2 视图 \(j\) 到视图 \(i\) 的完整投影关系

将查询视图 \(i\) 的投影与键/值视图 \(j\) 的逆投影组合，得到 PRoPE 最重要的矩阵：

$$\boxed{\mathbf P_i\mathbf P_j^{-1}=\mathbf L_i\,\mathbf T_i\mathbf T_j^{-1}\,\mathbf L_j^{-1}}.$$
(6)

按矩阵作用顺序从右向左阅读：首先以 \(\mathbf L_j^{-1}\) 撤销视图 \(j\) 的内参；接着以 \(\mathbf T_j^{-1}\) 从相机 \(j\) 回到世界，再以 \(\mathbf T_i\) 进入相机 \(i\)；最后以 \(\mathbf L_i\) 施加视图 \(i\) 的成像规则。中间恰好出现 GTA 所使用的相对外参 \(\mathbf T_i\mathbf T_j^{-1}\)，两侧则补上 GTA 缺失的内参因子。

直观解释 GTA 回答“相机 j 的坐标轴如何运动到相机 i”；PRoPE 回答“相机 j 的成像坐标如何经过三维相对运动，再由相机 i 的镜头重新成像”。后者因此能感知 zoom、FOV 与主点变化。

5.3 不显式构造 pairwise 几何张量

一种直接做法是为所有 token 对 \((i,j)\) 计算 \(\mathbf P_i\mathbf P_j^{-1}\)，再将其编码为 attention bias。但这会产生随 token 数平方增长的相机关系张量。PRoPE 采取另一种方式：在注意力之前分别处理每个 token 的 Q/K/V，使矩阵乘积在内积时自然形成。

因此，对 \(C\) 个相机只需准备 \(C\) 份 \(P,P^\top,P^{-1}\)，再把每份矩阵应用到该相机对应的 patch token 上。相对几何存在于代数组合结果中，而不是存在于一个显式的 \(T\times T\times16\) 张量中。

06 / ATTENTION完整结构：Q/K/V/O 如何共同实现相对投影编码？

6.1 先只看投影部分

暂时忽略二维 RoPE，并假设每个特征向量都由若干四维块组成。PRoPE 对查询、键、值分别施加：

$$\bar{\mathbf q}_i=\mathbf P_i^\top\mathbf q_i,\qquad \bar{\mathbf k}_j=\mathbf P_j^{-1}\mathbf k_j,\qquad \bar{\mathbf v}_j=\mathbf P_j^{-1}\mathbf v_j.$$
(7)

将它们代入注意力内积，转置与逆矩阵的组合自动给出相对投影：

$$\bar{\mathbf q}_i^\top\bar{\mathbf k}_j=(\mathbf P_i^\top\mathbf q_i)^\top(\mathbf P_j^{-1}\mathbf k_j)=\mathbf q_i^\top\mathbf P_i\mathbf P_j^{-1}\mathbf k_j.$$
(8)

这里 Q 使用 \(P_i^\top\) 而不是 \(P_i\)，正是为了在内积展开时通过 \((P_i^\top q_i)^\top=q_i^\top P_i\) 得到正确顺序。注意力权重仍由 \(\alpha_{ij}=\operatorname{softmax}_j(\bar q_i^\top\bar k_j/\sqrt{d_h})\) 计算，因此可以直接使用 PyTorch 的 scaled dot-product attention。

6.2 为什么 V 与 O 也必须变换？

如果只变换 Q/K，几何会影响“选择谁”，但被选择的 value 仍留在各自原始表示中。PRoPE 进一步令 \(\bar v_j=P_j^{-1}v_j\)，并在聚合后左乘查询相机的 \(P_i\)：

$$\bar{\mathbf o}_i=\mathbf P_i\sum_j\alpha_{ij}\mathbf P_j^{-1}\mathbf v_j.$$
(9)

这样，来自不同相机的 value 先经各自逆投影进入可组合形式，加权和后再回到查询视图的几何表示。Q/K 的几何匹配与 V/O 的几何聚合由此保持一致。需要注意的是，由于 \(\alpha_{ij}\) 同时依赖内容与其他通道的位置编码，不能把整个输出简单理解成一次纯粹的坐标变换；准确说法是投影结构约束了值聚合的代数路径。

6.3 与二维 RoPE 组成块对角变换

相机矩阵只说明视图间关系，并不能取代图像内部 patch 的行列位置。官方实现把每个 attention head 的 \(d_h\) 个通道分为三个连续区段：

$$\mathbf D_t^{\mathrm{PRoPE}}=\begin{bmatrix}\mathbf D_t^{\mathrm{Proj}}&\mathbf0&\mathbf0\\\mathbf0&\mathbf D_t^{\mathrm{RoPE},x}&\mathbf0\\\mathbf0&\mathbf0&\mathbf D_t^{\mathrm{RoPE},y}\end{bmatrix},\qquad \mathbf D_t^{\mathrm{Proj}}=\mathbf I_{d_h/8}\otimes\widetilde{\mathbf P}_{i(t)}.$$

其中 \(i(t)\) 是 token \(t\) 所属相机，\(\otimes\) 是 Kronecker 积，对应代码里的“重复平铺多个 \(4\times4\) 块”。投影区占 \(d_h/2\)，x-RoPE 与 y-RoPE 各占 \(d_h/4\)。三段的变换规则如下：

6.4 一个具体的通道例子

官方测试使用 head_dim=16。此时前 8 个通道被 reshape 为两个四维块，分别与同一个相机投影矩阵作用；第 9–12 个通道用于 x 坐标的两组二维旋转；最后 4 个通道用于 y 坐标的两组二维旋转。若 head_dim=64，则有 32 个投影通道、16 个 x-RoPE 通道和 16 个 y-RoPE 通道。

head_dim 的实际约束比单个 assert 更严格 源码显式检查了 head_dim % 4 == 0，但投影区还要求 (head_dim // 2) % 4 == 0，RoPE 区段也要求通道数为偶数。综合起来，实际应选择 8 的倍数，例如 16、64、128；仅能被 4 整除并不够。

6.5 Split RoPE 而非 interleaved RoPE

官方实现明确采用 split ordering：一个 RoPE 区段的前半部分是 \(x_{in}\)，后半部分是 \(y_{in}\)，而不是把相邻两个通道依次配对。其正向公式为 \([\cos\theta\,x+\sin\theta\,y,\;-\sin\theta\,x+\cos\theta\,y]\)，逆向公式交换相应符号。接入其他 RoPE 实现时若混用两种通道排列，数值上仍可运行，却会改变频率与通道的对应关系。

07 / PROPERTIES数学性质与计算边界

7.1 全局坐标不变性

设所有世界到相机外参共同右乘一个全局刚体变换 \(\mathbf G\)，即 \(\mathbf T_i'=\mathbf T_i\mathbf G\)，内参保持不变。相对投影中的 \(\mathbf G\) 与其逆严格抵消：

$$(\mathbf T_i\mathbf G)(\mathbf T_j\mathbf G)^{-1}=\mathbf T_i\mathbf G\mathbf G^{-1}\mathbf T_j^{-1}=\mathbf T_i\mathbf T_j^{-1}.$$
(11)

所以 \(\mathbf P_i'\mathbf P_j'^{-1}=\mathbf P_i\mathbf P_j^{-1}\)。该性质针对全局刚体坐标重参数化，不应被扩大解释为对任意尺度归一化、错误标定或非刚体形变都自动鲁棒。

7.2 退化为 GTA / CaPE 类编码

当内参提升矩阵为单位阵时，\(P_i=T_i\)，PRoPE 的投影项立即变成 \(T_iT_j^{-1}\)，即 GTA/CaPE 类相对 \(SE(3)\) 编码。官方函数中传入 Ks=None 会直接选择 GTA 分支，这是最明确的代码级退化路径。

需要区分“数学上严格退化”与“实验中内参不具区分度”。固定内参并不总意味着 \(L_iT_iT_j^{-1}L_j^{-1}=T_iT_j^{-1}\)，因为非单位内参与刚体矩阵通常不交换。Objaverse 固定内参实验中 GTA 与 PRoPE 数值完全一致，更适合解释为该受控设置下额外内参信息未带来可观察差异，而不是据此推出所有固定内参任务都等价。

7.3 同相机注意力退化为 RoPE

当查询和键/值来自同一相机时，投影内积满足 \(P_iP_i^{-1}=I\)。同视图 self-attention 的投影项不再引入跨相机差异，保留下来的主要是 patch 的二维 RoPE。论文在 UniMatch 中同时改造跨视图注意力与同视图自注意力，后者正利用了这一自然退化性质。

7.4 复杂度：不改变注意力的主导阶，但绝非免费

PRoPE 的重要工程优点是变换后仍可调用 torch.nn.functional.scaled_dot_product_attention，因而能够复用 PyTorch 所选择的融合或高效注意力后端。它也没有构造显式 token-pair 投影张量。不过，额外的 reshape、einsum、split/cat 和 RoPE 运算都有真实成本；官方测试中的 benchmark 默认被跳过，本文不声称任何未实测的速度提升或开销比例。

9.1 为什么先归一化内参？

不同数据集的图像分辨率和焦距量级可能相差很大。官方代码将 \(f_x,c_x\) 除以图像宽度，将 \(f_y,c_y\) 除以图像高度，并把归一化主点减去 \(0.5\)，使坐标中心移至零附近：

$$\widehat f_x=\frac{f_x}{W},\quad \widehat f_y=\frac{f_y}{H},\quad \widehat c_x=\frac{c_x}{W}-\frac12,\quad \widehat c_y=\frac{c_y}{H}-\frac12.$$
(13)
内参归一化与 P / Pᵀ / P⁻¹（官方代码）

Ks_norm[..., 1, 1] = Ks[..., 1, 1] / image_height
Ks_norm[..., 0, 2] = Ks[..., 0, 2] / image_width - 0.5
Ks_norm[..., 1, 2] = Ks[..., 1, 2] / image_height - 0.5
Ks_norm[..., 2, 2] = 1.0

Ks_norm 从全零矩阵创建，只写入 \(f_x,f_y,c_x,c_y\) 和右下角 1，因此 skew 等未显式复制的项保持为零。这与后面的无 skew 解析求逆一致，但也说明官方路径不是面向任意完整 \(3\times3\) 内参矩阵的通用实现。

9.2 结构化解剖求逆

源码定位：prope/torch.py:429–458
SE(3) 逆、K 的齐次提升与无 skew 求逆
def _invert_SE3(transforms):
    Rinv = transforms[..., :3, :3].transpose(-1, -2)
    out = torch.zeros_like(transforms)
    out[..., :3, :3] = Rinv
    out[..., :3, 3] = -torch.einsum(
        "...ij,...j->...i", Rinv, transforms[..., :3, 3]
    )
    out[..., 3, 3] = 1.0
    return out

def _invert_K(Ks):
    # 官方 docstring：Assumes no skew.
    out = torch.zeros_like(Ks)
    out[..., 0, 0] = 1.0 / Ks[..., 0, 0]
    out[..., 1, 1] = 1.0 / Ks[..., 1, 1]
    out[..., 0, 2] = -Ks[..., 0, 2] / Ks[..., 0, 0]
    out[..., 1, 2] = -Ks[..., 1, 2] / Ks[..., 1, 1]
    out[..., 2, 2] = 1.0
    return out

刚体逆使用 \(R^{-1}=R^\top\) 与 \(t^{-1}=-R^\top t\)，内参逆直接写出对角与主点项。相比通用 torch.linalg.inv，这种做法更简单、维度固定，也避免了对每个相机做通用 LU 求解；但它依赖输入确实是合法刚体矩阵和无 skew 针孔内参。

9.3 Ks=None 就是官方 GTA 路径

在内参缺失时，源码直接令 P=viewmats、P_inv=_invert_SE3(viewmats)。因此不需要伪造单位内参矩阵来“模拟 GTA”；None 是官方明确支持的开关，也便于做完全对应的消融。

11 / MODULE & CROSSModule 缓存、自注意力与跨注意力

11.1 为什么还需要 Module 封装？

函数式接口每次都要准备投影和 RoPE apply function。官方 PropeDotProductAttention 将相机配置固定下来，预计算并缓存 coeffs_x_0/1、coeffs_y_0/1 以及三个 apply function，随后可分别调用 _apply_to_q、_apply_to_kv、_apply_to_o。

RoPE 系数以 persistent=False 的 buffer 形式保存，意味着它们可随模块移动到相应设备，却不应成为新 checkpoint 的持久状态。模块的 load_state_dict 还处理旧 checkpoint 中可能遗留的系数键，避免非持久缓存造成加载不匹配。这部分属于工程兼容性，不改变 PRoPE 数学。

11.2 自注意力

自注意力中 Q/K/V 的序列和相机集合相同，因此同一个模块即可完成：

Module 自注意力的概念流程

out = F.scaled_dot_product_attention(q, k, v, **kwargs)

11.3 跨注意力：源视图与目标视图不能混用配置

跨注意力中 Q 来自 source token，K/V 来自 target token，两者可能具有不同相机数、patch 网格和图像尺寸。官方函数式 API 的等形状断言并不覆盖这一般情形，应使用两个 Module 的分阶段方法：source 模块处理 Q 和 O，target 模块处理 K/V。

官方跨注意力模式

v_tgt = attn_tgt._apply_to_kv(v_tgt)
o_src = F.scaled_dot_product_attention(q_src, k_tgt, v_tgt, **kwargs)
o_src = attn_src._apply_to_o(o_src)

这里 attn_src 与 attn_tgt 必须分别根据自己的 viewmats/Ks 和 patch 配置准备变换。最终输出位于 source 查询的表示空间，所以 O 必须由 source 模块处理，而不是 target 模块。

11.4 官方测试能说明什么？

tests/test_prope_torch.py 默认以 torch.float64 检查函数式 API 与 Module API 的一致性，示例配置包含 3 个相机、8×8 patch、4 个 head 和 head_dim=16。这能验证实现路径一致，但不等于证明任意 dtype、任意形状或任意 fused 后端都已覆盖。性能 benchmark 测试带有 skip 标记，不能从仓库测试中直接引用本地速度结论。

def _apply_tiled_projmat(feats, matrix):
    batch, num_heads, seqlen, feat_dim = feats.shape
    D = matrix.shape[-1]
    assert feat_dim % D == 0

    if matrix.shape[1] == seqlen:
        # 本地扩展：matrix 为 [B, seqlen, D, D]
        feats_ = feats.view(
            batch, num_heads, seqlen, feat_dim // D, D

本地 RoPE 预计算返回 torch.cos(angles).to(dtype), torch.sin(angles).to(dtype)，_lift_K 创建输出时也显式使用 dtype=Ks.dtype。这些修改对混合精度流水线很实用，但并不自动解决长焦距导致的病态矩阵；dtype 一致性和数值稳定性是两个不同问题。

16 / LIMITATIONS局限性、风险与工程落地清单

16.1 作者明确讨论的三项局限

  1. 长焦距与数值稳定性。长焦距配置可能使投影矩阵条件数变差，带来数值不稳定。归一化内参有助于控制尺度，却不保证任意焦距组合都良态；低精度训练尤其需要检查。
  2. 主要针对针孔相机。径向/切向畸变使单一全局投影矩阵无法精确描述所有像素。作者指出，对畸变相机可能需要按 patch 构造局部投影近似。
  3. 多频率编码不直观。投影矩阵乘法通常不可交换，不能像 RoPE 的多个二维旋转那样直接构造直观的多频相机参数编码。PRoPE 因而将投影与 RoPE 分块，而不是试图把投影矩阵简单频率化。

16.2 独立工程判断

除作者陈述外，从官方代码还可以得到几项落地边界。首先，_invert_K 明确假设无 skew，归一化代码也没有保留 skew。其次，方法假定相机参数已知；它不会自动修正标定误差、SLAM 位姿噪声或时间戳不同步。再次，“不增加可学习参数”只描述参数数量，Q/K/V/O 的额外线性变换仍可能带来吞吐与显存带宽成本。

最后，PRoPE 的数学不变性不等于训练结果对任意坐标操作完全不变。如果图像预处理改变了 crop、resize 或主点，却没有同步更新 K，输入给 PRoPE 的矩阵就已经不再对应实际图像。类似地，将 camera-to-world 误当 world-to-camera 时，矩阵仍可逆、形状仍正确，错误却不会由 assert 捕获。

一个容易被忽略的前提 PRoPE 编码的是“你提供的相机模型”，不是“真实世界的相机模型”。图像增强、resize、crop、归一化和位姿估计必须先保证几何一致，编码器才能发挥理论优势。

16.3 接入前检查清单

  • 确认 viewmats 是 camera-from-world；若上游为 camera-to-world，先整体求逆。
  • 确认 token 顺序为 camera → y → x，且 x fastest；检查 patchify/flatten 是否完全一致。
  • 确认 \(T=C P_xP_y\)，Q/K/V 的 head_dim 采用 8 的倍数。
  • 图像 resize/crop 后同步更新焦距与主点；image_width/height 使用与 K 对应的图像尺寸。
  • 检查焦距非零、外参旋转合法，并在目标训练 dtype 下监测 NaN、Inf 与矩阵条件。
  • 若有 skew 或镜头畸变，不要直接假设官方无 skew 针孔路径仍然准确。
  • 跨注意力分别构造 source 与 target 模块，Q/O 用 source，K/V 用 target。
  • 需要 fused SDPA 时保留“先变换 Q/K/V、后调用 SDPA、再变换 O”的顺序。
  • 区分官方 per-camera 与 WorldCrafter per-ray 分支，核对矩阵第二维究竟是 C 还是 T。
  • 在目标任务上实测速度、显存和精度，不把“无参数”误读为“无开销”。

16.4 何时优先考虑 PRoPE？

当任务包含多视图 token 交互、相机参数可信、内参可能变化，并且模型已经或计划使用标准 SDPA 时，PRoPE 是非常有针对性的选择。若相机完全未知，首先要解决的是位姿与内参估计；若视图高度畸变，可能需要局部投影或其他相机模型；若只是单图任务，PRoPE 的跨视图投影优势通常没有发挥空间。

17 / CONCLUSION总结：PRoPE 的真正创新在哪里？

PRoPE 把多视图 Transformer 的相机条件化从“附加特征”推进到“相对算子结构”。通过一个可逆的齐次投影矩阵，它同时保留内参和外参；通过 \(P_i^\top q_i\)、\(P_j^{-1}k_j\)、\(P_j^{-1}v_j\) 与输出端 \(P_i\)，相对投影 \(P_iP_j^{-1}\) 无需显式 pairwise 张量便进入注意力；通过投影与 x/y RoPE 的块对角分配，它同时建模跨视图几何和图内二维位置。

从理论上看，它兼具全局刚体坐标不变性、向 GTA 的明确退化路径和同相机下向 RoPE 的自然退化。从工程上看，它不需要新增可学习参数，也不必修改标准注意力 kernel。从实验上看，变化内参 NVS 是最有力的证据，空间认知、深度估计和 scaling 结果进一步支持其通用性；但 Objaverse 固定内参的持平、RGBD Sq Rel 的恶化以及 CAT3D 九视图 LPIPS 的轻微回退，都要求我们避免“所有场景一律更好”的过度结论。

因此，对 PRoPE 最准确的评价不是“一种更强的相机向量”，而是：一种将投影相机几何与注意力线性代数对齐的相对位置编码框架。它的价值来自几何结构、可逆代数与可实现性三者的结合。

最终记忆公式 \(\bar q_i=P_i^\top q_i,\ \bar k_j=P_j^{-1}k_j,\ \bar v_j=P_j^{-1}v_j,\ \bar o_i=P_i\sum_j\alpha_{ij}\bar v_j\)。由此得到 \(q_i^\top P_iP_j^{-1}k_j\)，其中 \(P_iP_j^{-1}=L_iT_iT_j^{-1}L_j^{-1}\)。
