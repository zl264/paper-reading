不要把它理解为 CameraCtrl 的简单换 backbone

一代解决在 U-Net 上如何编码射线并在多个 motion module 融合；二代转向 DiT、动态场景和长程探索：输入端一次 patchify 相加、全参数联合训练，以及跨 clip 的干净历史和共享世界参考。

1. 大相机运动会暴露哪三个问题

  1. 动态减弱：静态 RealEstate10K 训练使模型倾向只移动背景，物体运动被冻结。
  2. 视角范围受限：训练轨迹不足时，大角度旋转/平移会失真或生成不足。
  3. 跨段漂移：逐段生成若各自重设参考系，长轨迹与场景外观会不一致。

CameraCtrl II 的结构简化与数据/训练改造是一起设计的，不能只复制输入端相加而忽略其余部分。

2. 轻量相机注入：在 patchify 后一次相加

每帧仍构造 6×h×w Plücker 场。视频 VAE 时间压缩 4×、空间压缩 8×，所以每 4 帧采样一次相机位姿，使其与 latent 时间对应；视频与相机分别 patchify 后直接相加。

zfeat = Patchifyvideo(zt) + Patchifypose(P)(1)

之后正常进入所有 DiT block，没有 CameraCtrl 一代的多尺度时序 QKV 融合，也不是 AC3D 的前 8 层支路。全部主干参数解冻，使模型能够把几何条件融入整个时空生成过程。

图 1：输入端一次融合与跨段历史条件。有/无位姿数据联合训练保留动态；共同世界参考帧降低长时轨迹漂移。

3. 全参数联合训练与动态数据

训练目标仍是条件噪声预测：

L = E ||ε − ε̂θ(zt,c,s,t)||22(2)

有相机标注和无标注数据按 4:1 联合训练，无标注数据使用全零 Plücker，既利用更大视频分布也支持 camera CFG。与一代只训练相机支路不同，二代全部主干可训练。

RealCam 使用 VGGSfM 标注动态视频，并结合 metric depth / RANSAC 将平移转换到米制尺度，同时平衡轨迹分布。阶段一 192×320 约 100K steps；阶段二 384×640 约 50K steps，同时学习多 clip 扩展。后续再做 progressive distillation 和可选一步蒸馏。

4. 多 clip：历史条件与共享世界参考

生成第 i+1 段时，将上一段 clean token z₀ⁱ 与当前 noisy token zₜⁱ⁺¹ 拼接，二元 mask 标明历史与待去噪区域；损失只计算当前段。

Input = [z0i ; zti+1]，  Loss = MSE(ε̂i+1, εi+1)(3)

所有 clip 的相机轨迹都相对最初首帧。如果每段都以自己的第一帧重新归零，同一个世界坐标会在段边界变化；共享参考避免这一点，但并不能完全消除视觉遗忘。与 GEN3C 的外部 3D cache 相比，这里历史主要以 clean token 保留。

讲解用伪代码 · 非官方源码：连续片段生成
reference_w2c = all_camera_w2c[0]
relative_c2w = reference_w2c.inverse() @ all_camera_c2w
history = initial_condition_latent
chunks = []

    noisy = torch.randn_like(current_clean_shape)

    condition_mask = make_mask(history_frames=history.shape[time_dim])
    generated = diffusion_sample(joint, condition_mask, current_camera)

6. 局限与实现边界

没有显式持久点云或极线约束，因此长时一致性依靠历史 token、共享坐标与训练，而不是严格 3D 保证。全参数训练成本比即插即用 adapter 高，模型和 RealCam 数据处理也不能从一代 main 仓库直接获得。

每 4 帧采样位姿可能与快速变化的相机运动不完全对齐；大角度和高速轨迹需要额外评估。本文不将论文项目页误写为已核验完整开源实现。

7. 复现重点

  • 核对 VAE 首帧独立与后续四帧压缩对应哪些相机。
  • 无标注数据的全零位姿必须和推理 null camera 语义一致。
  • 历史 clean token 不加与当前段相同的噪声。
  • 跨段轨迹使用最初参考系，禁止逐段重新归零。
  • 分别评估单段动态、长程相机精度和重访一致性。

附录 A：连续轨迹与多 clip 的具体形状约定

假设输入 121 个像素帧，首帧独立、其后每 4 帧形成一个 latent 时刻，则得到 31 个 latent 帧。相机也应取 0,4,…,120 共 31 个，而不是对位姿张量做任意线性插值到 31 帧；后者会改变运动速度和时间对应。

生成下一段时，上一段输出是 clean latent，不参与当前 timestep 加噪；当前段则从当前高斯状态去噪。二元 mask 让模型和历史都清楚哪些 token 已确定。训练 loss 若把历史段也算入，会额外优化已给真实/生成条件，而不是专注当前轨迹预测。

相机 patchify 与视频 patchify 的输出 token 数必须完全相同，才能逐 token 相加。空间分辨率变化时 K 和 Plücker 图需同步调整；使用全零 Plücker 的无位姿数据与“首帧相对静止轨迹”是否同义，应按训练定义检查，不可仅凭张量都是零推断。

代码 1：PluckerPatchInjection

PluckerPatchInjection · 输入端一次融合（讲解用实现，非官方源码）
class PluckerPatchInjection(nn.Module):
    def __init__(self, video_channels, patch_hw, dim):
        super().__init__()
        self.video_patch = nn.Conv3d(video_channels,dim,
            kernel_size=(1,*patch_hw),stride=(1,*patch_hw))
        self.camera_patch = nn.Conv3d(6,dim,
            kernel_size=(1,*patch_hw),stride=(1,*patch_hw))

    def forward(self, noisy_video, plucker_latent_frames):
        # noisy_video: [B,C,F',h,w]
        # plucker_latent_frames: [B,6,F',H,W]，与 VAE 时间网格已对齐。
        v = self.video_patch(noisy_video).flatten(2).transpose(1,2)
        p = self.camera_patch(plucker_latent_frames).flatten(2).transpose(1,2)
        assert v.shape == p.shape
        return v+p                            # 后续正常进入全部 DiT
# 论文描述为 patchify 后相加；具体卷积 vs  unfold 属教学实现选择。

阶段一在 192×320 训练约 100K steps，阶段二 384×640 约 50K steps并学习多 clip 扩展。RealCam 用 VGGSfM 和 metric-depth/RANSAC 得到米制轨迹并平衡分布。有标注和无标注视频按 4:1 联合训练，全部主干参数更新；这与一代只训练相机模块不同。

附录 E：显式位姿推理流程

将上一段 clean token 与当前 noisy token 拼接，二元 mask 标明历史与待生成区域。整段相机共享最初首帧参考，只在输入端与视频 patch 相加。生成后当前段成为下一段历史。没有外部 3D cache，所以回看一致性仍依赖历史 token 与学习到的世界先验。

推理前要明确：位姿是 c2w 还是 w2c、是否首帧相对、K 是否像素单位、帧率是否经过 VAE 压缩，以及 unconditional 分支采用哪一种空相机。只把这些数值变成合法 shape 不足以保证几何正确。
