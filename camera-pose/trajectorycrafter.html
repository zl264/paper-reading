和 ReCamMaster 的任务相似，结构不同

TrajectoryCrafter 先用深度把源视频投影到目标机位，扩散模型看到粗糙的新视角；再从源视频 reference token 中读取细节。ReCamMaster 公开 Wan 版则直接拼接干净源 latent 与带噪目标 latent，通过全时空注意力完成重渲染。

1. 确定性视角变换

源帧 Iᵢˢ 与深度 Dᵢˢ 在内参 K 下反投影为动态点云 Pᵢ。根据源相机与目标相机的相对变换 Tᵢʳ，把三维点重新投影为目标视角 Iᵢʳ，同时输出可见性 mask。

Pi=Φ−1([Iis,Dis],K)(1)
Iir,Mir=Φ(TirPi,K)(2)

这一步由相机位姿直接决定，网络不必从 RT 学投影。但单目深度不是真值：动态前景、遮挡边界和反光区域会出现错点，重投影只能作为条件而非最终答案。

图 1：几何决定“从哪里看”，源视频参考决定“内容是什么”。view token 提供目标机位可见结构；reference token 补充未被准确重建的外观与动态。

2. 双流条件：View tokens 与 Reference tokens

view 流接收目标视角渲染图与 mask，经 VAE 后与 noisy target latent 通道拼接，再 patchify 成 token；文本 token 与 view token 拼接进主 DiT。

reference 流将源视频单独编码为 reference tokens。在继承的 DiT blocks 之间插入 Ref-DiT：text/view 先做 3D attention，再以 view 为 query、reference 为 key/value 做 cross-attention。

Hview′ = Hview + CrossAttn(Q=Hview, K=Hsource, V=Hsource)(3)

这种结构把“目标位姿下哪些区域已有几何”与“源视频中的外观/动作是什么”分开。与只做点云 inpainting 相比，它能从原视频补回更清晰内容；与 ReCamMaster 的全 token self-attention 相比，它使用更明确的参考 cross-attention。

讲解用伪代码 · 非官方源码：双流条件 forward
render_latent = vae.encode(torch.cat([warped_rgb, warp_mask],dim=1))
view_tokens = patchify(torch.cat([noisy_target, render_latent],dim=1))
reference_tokens = source_reference_encoder(vae.encode(source_video))
for block, ref_block in zip(main_dit_blocks, ref_dit_blocks):
    view_tokens = block(view_tokens, text_tokens)
    view_tokens = ref_block.spatial_temporal(view_tokens, text_tokens)
    view_tokens = view_tokens + ref_block.cross_attention(
        q=view_tokens, k=reference_tokens, v=reference_tokens)

3. 双重再投影：从普通单目视频构造训练条件

真实同步动态多机位数据很难获得。论文对单目视频随机选相对变换 ΔT，先投影到新视角，再用 ΔT⁻¹ 投影回原机位。由于遮挡与出界，返回的渲染会有孔洞；原始视频则可作为目标。

Vwarp = Render(DepthCloud(V), ΔT−1ΔT) ≈ V，但有遮挡空洞(4)

这样从 60K OpenVid 动态数据制造“带缺陷的条件—原目标”配对，结合 120K DL3DV / RealEstate10K 静态三元组。注意 ΔT⁻¹ΔT 在代数上为单位阵，但离散深度重投影并不无损；正是遮挡和采样产生训练所需 mask。

讲解用实现 · 非官方源码：双重再投影数据构造
points = unproject(source_rgb, source_depth, K, source_w2c)
new_view, new_mask = render(points, delta_T @ source_w2c, K)
# 用新视角深度/点云再投回原相机，而非简单把 RGB 连续 warp。
returned_view, returned_mask = render(
    unproject(new_view, new_depth, K, delta_T @ source_w2c),
    source_w2c, K)
condition = torch.cat([returned_view, returned_mask], dim=0)
target = source_rgb
# 目标位姿在训练中为“回到原机位”；mask 提供缺失区域监督。

4. 两阶段训练为什么这样安排

  1. 阶段一：使用全部动态/静态数据，训练 DiT 与 Ref-DiT 的 3D attention，冻结 cross-attention，暂不注入 reference。先让 view 流学会根据渲染和 mask 完成目标。
  2. 阶段二：仅用多视角静态三元组，训练 Ref-DiT cross-attention 和 patch embedding，其余冻结。让参考流学习从源图读取内容，同时避免动态伪配对干扰。

损失沿用视频噪声回归，而不是额外把点云渲染误差作为最终视频损失。该策略利用已有单目与静态数据，但并不能彻底消除真实动态几何错误。

5. 推理：从用户轨迹到目标视频

  1. 估计源视频逐帧深度和源位姿，构造动态点云。
  2. 把用户目标位姿转换为相对源相机的变换，渲染 RGB 与 mask。
  3. 分别准备 view tokens 和 source reference tokens。
  4. 在多个扩散步中，主 DiT 负责视频生成，Ref-DiT 负责读取源内容。
  5. VAE 解码目标 latent；检查遮挡边界、动作同步与目标轨迹精度。

6. 局限与选型

  • 单目深度误差在大角度下被放大，尤其是动态前景与遮挡边界。
  • 源视频只观测一个窄视角，完全未知区域不能靠 reference 恢复真实内容。
  • 双流注意力增加序列读取与显存开销；结果依赖训练数据的视角分布。
  • 如果只需要静态单图探索，GEN3C 的持久 cache 更直接；如果强调动态源内容同步，可比较 ReCamMaster 与本文双流方案。

7. 实现检查

  • 区分源/目标 w2c 与相对变换 Tᵢʳ 的方向。
  • 重投影时保留 z-buffer 与有效 mask，避免前后表面混叠。
  • source reference 的时间轴必须与目标动作时刻同步。
  • 双重再投影应真实经过深度与离散渲染，不是数学上直接恒等。
  • 分别测试小角度、极端视角、动态遮挡和未知背面。

附录 A：重投影、参考流与 mask 的对齐

对每个源时刻 i，深度 Dᵢˢ 与该时刻 RGB 一起反投影为动态点云，因此点云不仅是静态背景，也包含人物运动后的瞬时位置。Tᵢʳ 必须是“从源 i 到目标 i”的相机变换；若误用目标 0 或源 0，会让动作时刻与相机轨迹错位。

渲染时使用 z-buffer 或等价可见性处理，记录空洞 mask。view token 和 reference token 的时间索引都对应同一 i，Ref-DiT 才能把源人物动作转移到目标位置。mask 的空间下采样也要与 noisy latent 的 patch 大小一致。

在双重再投影训练中，从新视角回到原视角时必须估计/保存新视角深度，并经过真实离散投影。只在数学上把 ΔT 与逆矩阵相乘得到 I、但不执行渲染，不会产生任何训练用遮挡空洞。这个细节决定了数据构造是否有效。

下面的 2 段代码将该论文的条件表示、张量变换与融合接口连成可读的 PyTorch 结构。它们是依据论文机制编写的教学实现，非官方源码；目的是把每个模块的输入、输出和训练位置说清楚，不宣称与原模型逐行等价。实际模型仍需要相应的 VAE、位置编码、mask、scheduler、预训练权重和数据处理。

代码 1：ViewConditionEncoder

ViewConditionEncoder · 渲染图与 mask 进入 view tokens（讲解用实现，非官方源码）
class ViewConditionEncoder(nn.Module):
    def __init__(self, vae, latent_channels=16, dim=3072):
        super().__init__()
        self.vae = vae
        # 渲染 RGB latent + mask latent + 带噪目标 latent。
        self.patch = nn.Conv3d(latent_channels*3,dim,
                              kernel_size=(1,2,2),stride=(1,2,2))
    def forward(self, target_noisy, rendered_rgb, render_mask):
        rendered = self.vae.encode(rendered_rgb).latent
        mask = self.vae.encode(render_mask.repeat(1,3,1,1,1)).latent
        joint = torch.cat([target_noisy,rendered,mask],dim=1)
        return self.patch(joint).flatten(2).transpose(1,2)
# 论文采用渲染图+mask 的 VAE 条件与 noisy target 通道拼接；
# 这里通道数仅作示例，不是官方 CogVideoX 配置。

代码 2：RefDiTBlock

RefDiTBlock · 源视频作为 K/V（讲解用实现，非官方源码）
class RefDiTBlock(nn.Module):
    def __init__(self,dim,heads):
        super().__init__()
        self.view_attn=nn.MultiheadAttention(dim,heads,batch_first=True)
        self.ref_attn=nn.MultiheadAttention(dim,heads,batch_first=True)
        self.norm1,self.norm2=nn.LayerNorm(dim),nn.LayerNorm(dim)

    def forward(self,view_tokens,reference_tokens,text_tokens):
        # 教学上将文本与 view 序列拼接；实际 RoPE/mask 必须跟随基座。
        joint=torch.cat([text_tokens,view_tokens],dim=1)
        joint=joint+self.view_attn(self.norm1(joint),self.norm1(joint),self.norm1(joint))[0]
        view=joint[:,text_tokens.shape[1]:]
        ref=self.ref_attn(self.norm2(view),reference_tokens,reference_tokens)[0]
        return view_tokens+ref
# 训练第一阶段冻 ref_attn，第二阶段重点学习参考读取；
# 官方同步多视数据/双重投影构造不能由此类简化 forward 替代。

附录 E：显式位姿推理流程

逐时刻由源 RGB-D 建立点云，按目标位姿重投影；view 流接收新视角渲染与 mask，reference 流接收源视频。每个 Ref-DiT 先做 text/view 的 3D attention，再以 view 为 Q 从 source K/V 读取。最后去噪并解码目标视频。

推理前要明确：位姿是 c2w 还是 w2c、是否首帧相对、K 是否像素单位、帧率是否经过 VAE 压缩，以及 unconditional 分支采用哪一种空相机。只把这些数值变成合法 shape 不足以保证几何正确。

附录 F：代码级验证清单

  • 源到目标的 Tᵢʳ 方向与同一时刻索引必须一致。
  • 渲染使用 z-buffer/可见性 mask，避免前后表面混叠。
  • 双重再投影要真实执行两次离散渲染，不能只做矩阵恒等。
  • 比较大角度、动态遮挡和源视频完全未观测区域。
