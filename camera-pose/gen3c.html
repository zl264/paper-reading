GEN3C：以显式时空 3D Cache 驱动精确相机控制

从 RGB-D 反投影、目标 W2C/K 渲染，到 Cosmos 通道融合与长视频缓存更新

论文版本：arXiv:2503.03751v1，2025-03-05；论文作者来自 NVIDIA、University of Toronto 与 Vector Institute。官方公开仓库为 nv-tlabs/GEN3C，README 记录代码和模型于 2025-06-06 发布。本文源码均按固定快照 db2ffe12ced12ddafcec5e0422ee46ce8520746b 解读；源码许可证为 Apache-2.0，模型另受 NVIDIA Open Model License 约束。本文只做论文与静态源码阅读，未执行模型训练或推理，也未进行本地速度、显存或画质实测。

先划清两个实现的边界。论文主体实验使用 Stable Video Diffusion（SVD）：4 通道、仅空间压缩的 latent，以 mask 乘法保留渲染信息，并在首层后跨视角 max-pool。论文 §5.7 另报告 Cosmos 扩展。当前公开仓库发布的是 GEN3C-Cosmos-7B 推理实现：16 通道时空 VAE、两个 RGB-D buffer、RGB 与 mask 分别编码后拼接，以及 16+16×4+1=81 通道 DiT 输入。下文会分别标注“论文 SVD 机制”和“公开 Cosmos 源码”，不会把后者倒写成前者的网络细节。

1. 问题定义：相机控制不只是把位姿数字交给网络

GEN3C 处理的是带源观测的位姿可控视频生成与新视角合成。源观测可以是一张图像、若干静态视图，或具有逐帧深度和源相机参数的视频；目标则是用户指定的逐帧相机序列。它要同时解决三个问题：目标画面遵循指定视角、重新看到旧区域时不“忘记”场景、点云渲染没有覆盖的地方仍能生成合理内容。

纯参数条件方法把 W2C、射线或 Plücker embedding 输入网络，网络必须自己学习“这组数字意味着哪些像素怎样移动”。GEN3C 将这一步交给确定性几何：先以单目深度建立带颜色的点云，再把同一批世界点投影到目标相机，得到有缺陷但视角明确的 warped RGB 与覆盖 mask。扩散模型不再从零推断相机—图像映射，而是学习修复错误深度、遮挡边界和未观测区域。

(It, Mt) = R(P, W2Ct, Kt)，  X̂1:F = D(fθ(Zτ; E(I1:F), M1:F, ctext/image))(1)

这里 P 是显式时空缓存，R 是点云前向渲染，E/D 是 VAE 编解码器。RGB 渲染给出可见内容，mask 告诉模型何处缺少可靠观测。因此“精确”首先来自条件图像本身已按目标相机重投影，而不是额外的位姿损失；最终视频仍由生成模型产生，并不等同于严格的多视图几何重建。

这一设计还解释了它与其他相机控制方法的真实区别：MotionCtrl/CameraCtrl 主要依靠数值或射线条件的网络学习；训练免费的深度 warp 方法通常在去噪过程中权衡 warp 约束；GEN3C 则微调模型，让它把 warped video 当作可持续更新的场景条件。相比逐场景优化 NeRF/3DGS，它用生成先验补全稀疏观测，但补全内容不保证是真实世界中被遮挡的原貌。

2. RGB-D 反投影与目标 W2C/K：实际进入渲染器的数学对象

核心接口使用世界到相机矩阵 W2C，而非相机到世界矩阵 C2W。源帧与目标帧可以不同，但所有点必须位于同一个世界坐标系，深度、平移和相机轨迹也必须使用一致的尺度。对源像素 (u,v)，若输入 d(u,v) 是沿相机 Z 轴的 z-depth，而不是到相机中心的欧氏距离，则：

K = [[fx,0,cx],[0,fy,cy],[0,0,1]]，  W2C = [[R,t],[0,1]]，  pc = d(u,v)K−1[u,v,1]T(2)
p̃w = W2Csrc−1[pc;1]，  q̃ = KtgtW2Ctgtp̃w，  (u′,v′) = (qx/qz, qy/qz)(3)

其中 fx,fy 是像素单位焦距，cx,cy 是像素主点；R,t 把世界点变到相机坐标。代码对有效深度像素计算 K⁻¹[u,v,1]，乘深度后再左乘 inverse(w2c) 得到世界点。目标投影直接使用目标 W2C 和目标 K，所以平移、旋转与焦距变化都在扩散网络之前发生。

3. Cache3D 如何渲染：覆盖 mask、深度过滤与 buffer 维

初始化时，Cache3D_Base 把输入整理成 [B,F,N,V,C,H,W]：B 是 batch，F 是源时间，N 是静态帧 buffer，V 是视角。深度与对应源 W2C/K 被反投影为同样网格化的世界点 [B,F,N,V,H,W,3]，RGB 和大点数组主要保存在 CPU，渲染时按小批传到 GPU。

cache_3d.py:151-236 对每个目标时刻复制同一组目标 W2C/K 到各个 N buffer，再调用 forward_warp。后者投影世界点，以 q_x/q_z,q_y/q_z 得到 flow，执行带深度的 bilinear splatting，并输出 warped RGB、warped mask 和可选深度。公开实现要求这里的 V=1；多图样例把候选源放在 N 维，而不是走论文公式的 V 维池化。

张量/选项实际含义实现细节
rendered_warp_images[B,F,N,3,H,W]，RGB 范围 [-1,1]每个 buffer 独立投影到同一个目标 W2C/K；无信息区域需结合 mask 判断，不能把黑色像素当成有效观测
rendered_warp_masks[B,F,N,1,H,W]，有效覆盖为 1，空洞为 0不是源帧条件指示器，也不是物体语义分割；它描述该目标像素是否由 cache 覆盖
filter_points_threshold=0.05过滤深度不连续处5×5 窗口内 (local_max-local_min)/(local_mean+eps) 小于阈值且深度为正才可靠，见 forward_warp_utils_pytorch.py:338-353
foreground_masking额外处理前景遮挡把目标相机中的点构成网格，以 Warp 做 ray-triangle intersection，并遮蔽明显更近的 mesh 区域；这不是通用动态物体 mask
noise_aug_strength不同 buffer 的渲染噪声增强Cache3D_Buffer.render_cache 按 buffer 年龄分配噪声幅度；默认强度为 0，不能把它当作扩散噪声本身

对单图而言，论文所说的“沿 L 个时间复制同一 cache”在公开实现中主要通过渲染时 expand 完成，不需要在内存里复制 L 份点云。对动态 Cache4D，start_frame_idx 选择对应的源时间窗口；若目标请求超过已有源帧，持久化实现会钳制到末尾可用窗口，而不是凭空生成新的真实深度状态。

4. 网络结构：论文 SVD 融合与公开 Cosmos 81 通道输入

图 1：公开 Cosmos 推理主线的自制结构图。相机矩阵只进入几何渲染器，不作为 Plücker 或 12 维位姿向量送入 DiT；虚线以外的实线均表示实际数据依赖。N=2 时，RGB 与 mask 各两次 VAE 编码，共 64 个条件通道。

论文中的 SVD 版本

论文采用 SVD 的 4 通道 latent：L 帧视频编码为 [L,4,H/8,W/8]，时间长度不压缩。每个源视角的 warped RGB 经过冻结 VAE，mask 经 min-pooling 对齐 latent 分辨率；随后按论文 Eq.(2) 将有效区域 latent 与带噪目标 latent 拼接。各视角分别通过第一层 In-Layer，再对视角维 max-pool，从而保持视角排列不变性，并避免在原始点云空间强行融合未对齐深度。

z′v = In-Layer(Concat(zv ⊙ M′v, zτ))，  z′ = MaxPool{z′1,…,z′V}(4)

论文特别强调，早期尝试把 mask 直接作为一个新通道会增加训练参数，对训练中未出现过的 OOD mask 泛化较差，所以主模型选择 mask 与 latent 逐元素相乘。这是 SVD 论文机制，不可据此推断公开 Cosmos 也只有 4+4 个输入通道。

公开 Cosmos 版本：mask 也经过 VAE

model_gen3c.py:26-57 固定 chunk_size=121。对每个 N buffer，warped RGB 从 [B,121,3,H,W] 调整为 [B,3,121,H,W] 后编码；mask 先由 0/1 映射到 -1/+1，再复制为三通道，使用同一个 encode 接口另行编码。每个 buffer 因而产生 RGB 16 通道和 mask 16 通道，列表按 [RGB₀,mask₀,RGB₁,mask₁] 拼接。

5. 训练目标与数据：学会“修复渲染”，而非只学习轨迹标签

训练样本由“cache 渲染条件 + 新相机轨迹上的目标 RGB 视频”成对组成。对真实视频，过去或未来的帧被用作观测，连续目标片段模拟新的观看路径；对合成动态场景，则可直接从多条相机轨迹渲染 RGB-D 与新视角真值。论文使用通用 denoising score-matching 目标，目标采用预训练 SVD 实践中的 z₀=E(x)，而不是把网络约束成光流或深度回归器。

L(θ) = Ex,τ,ε[ ||f′θ(zτ; R(P,C), τ, cCLIP) − z0||²2 ]，  zτ=ατz0+στε(6)

论文明确冻结 VAE encoder，使用预训练 decoder，并以首帧 CLIP embedding 作为附加条件；渲染条件和 CLIP 条件的 dropout 比例均为 15%。其余表述应准确写成“微调修改后的视频扩散模型”，第三阶段只微调 temporal layers；论文未提供逐层冻结清单，不应杜撰公开 Cosmos checkpoint 的具体冻结/参数初始化策略。

数据论文中的用途与标注配对方式
RE10K74,766 个真实室内外房产片段；DROID-SLAM 位姿，DAV2 深度并对齐 SLAM 尺度等间距随机选 V∈[1,4] 帧建 cache，目标为包含其中一个观测帧的 L 帧连续视频
DL3DV约 10k 真实场景视频；标注协议同 RE10K同上，用于提升空间一致性与跨场景泛化
Waymo Open Dataset1000 个驾驶场景，每个 200 帧；DAV2 深度刚性对齐 LiDAR 尺度三个同步相机的 L 帧共同形成 V=3 cache，目标仅取 FRONT 相机
Kubric4DGCD 的 3000 个多物体动态合成场景，以点云序列渲染所需 RGB-DV∈[1,4] 条动态相机轨迹作条件，另一条轨迹作目标，提供真实多视角动态监督

SVD 主模型采用 AdamW，学习率 3×10−5：第一阶段在 RE10K/DL3DV 上以 320×576、14 帧训练 100K iteration；第二阶段在四个数据集上以 576×1024、14 帧再训练 100K；第三阶段仅调 temporal layers，在四数据集上训练 10K，随机序列长度 14–56 帧，输入先 resize 到 576×1024 再 center crop 到 320×576。论文称整个训练约使用 32 张 A100 四天，这是论文报告而非本文实测。

论文 §5.7 的 Cosmos 扩展以 Cosmos1.0 Diffusion 7B Video2World 为基座，在 RE10K 和 DL3DV 上微调 10,000 steps、batch size 64，并以 Cosmos tokenizer 编码渲染帧。公开快照的 INSTALL.md:43-48 仍把 Post-training 标为 under construction，仓库中的 GEN3C 文件主要是推理管线；不能用论文的训练数字替代一份公开训练脚本，也不能假定公开权重恰好复现论文 SVD 结果。

6. 推理与长视频：121 帧、重叠一帧、深度对齐及双缓存更新

单段公开 Cosmos 推理从噪声 latent 开始，以文本 embedding、首帧 condition latent、warped RGB/mask 为条件迭代去噪，最后 VAE 解码。gen3c_pipeline.py 把 warped 张量写入 data_batch["condition_state"] 与 ["condition_state_mask"]，再调用 generate_world_from_video，见 gen3c_pipeline.py:227-259。公共 CLI 默认是 35 个扩散步、guidance=1、704×1280、24 FPS；论文 SVD 附录则是 25 步、CFG=3，两者不是同一组默认值。

长视频被分为长 121 帧的 chunk，相邻 chunk 共用一帧：首段索引 [0,120]，第二段从索引 120 开始，到 240，依此类推。新段输出的第 0 帧被丢弃，拼上 video_new[1:]。因此总帧数必须为 120N+1，即 121、241、361……；源码校验见 gen3c_single_image.py:110-113。这不是 121 帧重叠，而是每段 121 帧、只重叠 1 帧、每段净增 120 帧。

这里用于更新的是上一段最后一帧，它的目标相机索引正好是下一段的 start_frame_idx。该 RGB 帧先经 MoGe 估计深度，再更新 cache，同时作为下一段首帧图像条件；所以“重叠一帧”既提供图像连续性，也提供新观测几何。

论文的深度尺度对齐

论文附录先将已有 cache 渲染到边界帧相机，得到 dtgt 和覆盖 mask M，再对 MoGe/DAV2 类单目深度 d 求全局尺度和偏移，只在可靠覆盖区最小化重投影深度差：

s,t = argmins,t ||(s·d + t − dtgt)·M||²2，  d′=s·d+t(7)

对齐后的 RGB-D 用该边界帧 W2C/K 反投影，再加入 cache。没有重叠的区域不能为尺度估计提供几何约束；若 mask 很稀疏或旧 cache 本身错误，优化也可能不稳定。

公开实现并不照搬这条公式

cache_3d.py:246-316 默认使用 alignment_method="non_rigid"。它先在旧 cache 上渲染目标深度与 mask，然后 camera_utils.py:225-345 在逆深度域执行带 0.1/0.9 分位离群过滤的最小二乘仿射对齐；非刚性路径再优化一个逐像素 scale map，共 100 次 Adam iteration，以反投影点 L1 数据项加上 lambda_arap=0.1 的局部平滑项，最后才反投影新点。这与论文 Eq.(4) 的全局 z-depth s·d+t 有关联，但实现更复杂，不能写成完全相同。

公开单图 cache 的 frame_buffer_max=2 也不是论文所描述的无限 append。第一次更新把最新边界帧放在 slot 0、原种子帧保留在 slot 1；后续更新替换 slot 0，最老生成历史不会全部保留。因此长视频一致性来自“原始观测 + 最近边界观测 + 首帧条件 + 生成先验”，不是一个不断增长的完整世界点云。动态 Cache4D 则直接用输入视频所有已有 RGB-D 帧，长段循环不做上述 MoGe cache 更新，见 gen3c_dynamic.py:286-317。

7. 相机 UI、命名预设与显式自定义轨迹教学

命令行 helper camera_utils.py:142-222 返回 generated_w2cs [1,F,4,4] 和 generated_intrinsics [1,F,3,3]。支持 left/right/up/down/zoom_in/zoom_out/clockwise/counterclockwise；这里的 zoom 是沿 Z 平移，不是修改焦距。若 K 只给一张 3×3，会沿 F 维复制；若给逐帧 K，则保留输入的时间维。

直线轨迹在初始相机坐标中按 i × movement_distance × center_depth / F 累进，符号决定方向；公开单图 CLI 把 center_depth 固定为 1.0，默认 movement_distance=0.3，所以幅度不是绝对米制承诺。旋转模式有 center_facing（朝估计中心）、no_rotation（保持原朝向）和 trajectory_aligned（随平移调整朝向）。圆周预设实际调用 spiral helper，X/Y 半径使用 movement_distance，Z 半径默认为 0。

none 不是普通单图 CLI 的可用轨迹预设。单图 parser 虽接受 --trajectory none，但 generate_camera_trajectory 并不实现该分支；持久化模式正是要求设为 none，再绕过 helper、直接调用 inference_on_cameras。因此自定义矩阵不能只靠给原 CLI 加 none，必须接入持久化接口或替换轨迹生成调用。

GUI 真正提供的是逐帧 C2W 与内参编辑

gui/README.md:99-177 描述了完整工作流：拖入图像或预处理视频来 Seed，服务端建立 cache；客户端可录制 viewport 相机、从当前相机添加关键帧、插值/分割/复制/删除关键帧、在 Local 或 World 空间编辑平移旋转、保存/加载 JSON 路径。每个关键帧还能修改 Field of view，或把 FoV 应用到全部关键帧，从而通过逐帧 K 实现真正变焦；论文的 Dolly Zoom 正是位姿与内参同时变化。

GUI 的 Authored 路径在归一化路径时间 linspace(0,1,F) 上求值，生成 C2W、逐帧焦距和主点；播放速度只影响预览，不等于视频 FPS。API 的 api_types.py:30-95 接收 cameras_to_world [F,3,4]、像素单位 focal_lengths [F,2]、相对主点 principal_points [F,2] 和 resolutions [F,2]，然后补齐 4×4、求逆成 W2C，并构造 K。客户端请求不足 121 帧时重复最后相机补齐，完成后裁掉 padding，见 client.py:381-502。需要独立复现时，应检查导出 JSON 中的实际矩阵，而不是把关键帧时间等同于匀速三维运动。

讲解用接线代码 · 非官方独立入口

下面代码只是基于已核对接口的教学改写，不是仓库自带脚本。它在单图程序已经建立 cache 和 pipeline 后，替换 gen3c_single_image.py:340-350 的预设生成调用。轨迹在 MoGe 初始相机坐标系内做纯平移：W2C 的旋转保持单位阵，相机中心沿 X 做往返、沿 Y 做小幅二次谐波；W2C 平移取负号，因为相机中心为 −Rᵀt。K 使用 MoGe 返回的初始内参并逐帧复制，后续官方 121 帧循环和 cache 更新逻辑无需改变。

讲解用实现 / 自定义轨迹接线 · 非官方独立源码，未执行
import torch

def make_custom_w2c_k(initial_k: torch.Tensor, num_frames: int):
    """返回官方 render_cache 所需的 [1,F,4,4] W2C 与 [1,F,3,3] K。"""
    assert num_frames >= 121 and (num_frames - 1) % 120 == 0
    device, dtype = initial_k.device, initial_k.dtype
    phase = torch.linspace(0.0, 2.0 * torch.pi, num_frames,
                           device=device, dtype=dtype)

    # 单图入口的 initial_w2c=I；t 是 W2C 平移，不是相机世界中心。
    w2cs = torch.eye(4, device=device, dtype=dtype).repeat(1, num_frames, 1, 1)
    w2cs[0, :, 0, 3] = -0.08 * torch.sin(phase)       # 相机世界 X ≈ +0.08 sin(phase)
    w2cs[0, :, 1, 3] = -0.02 * torch.sin(2 * phase)   # 幅度使用深度所在世界单位
    intrinsics = initial_k.reshape(1, 1, 3, 3).repeat(1, num_frames, 1, 1)
    return w2cs, intrinsics

# 替换原脚本中的 generate_camera_trajectory(...) 调用：
generated_w2cs, generated_intrinsics = make_custom_w2c_k(
    initial_k=initial_cam_intrinsics_for_traj,
    num_frames=args.num_video_frames)
assert generated_w2cs.shape == (1, args.num_video_frames, 4, 4)
assert generated_intrinsics.shape == (1, args.num_video_frames, 3, 3)

# 后续仍调用官方接口；首段示例，长视频切片沿用原循环：
rendered_warp_images, rendered_warp_masks = cache.render_cache(
    generated_w2cs[:, 0:pipeline.model.chunk_size],
    generated_intrinsics[:, 0:pipeline.model.chunk_size])

若要加入旋转或变焦，应保持同一套约定：用局部相对变换 At 左乘初始 W2C（即 W2Ct=AtW2C0），或从明确的 C2W 构造后整体求逆；逐帧改变 fx,fy 时同步更新 K[t]。如果使用已有场景坐标而非单图初始坐标，所有新相机必须仍在 cache 的世界系中。动态视频还要求目标帧索引与源时间一一对应；任意时间戳数组不会自动重定时物体运动，GUI API 注释也明确 timestamps 可能被模型忽略。

9. 失败模式、计算代价与一致性边界

深度和渲染误差不会被自动“消灭”

  • 错误尺度或内参：反投影点不再位于真实表面，目标视差会整体错误；深度与 W2C 平移若单位不一致，轨迹幅度也会失真。
  • 遮挡边界与细结构：单目深度常在物体边缘混合前后景，forward splatting 会产生拉伸、飞点、裂缝和空洞。局部连续性过滤与 mesh masking 只能筛掉部分问题。
  • 新内容不是观测：mask=0 的区域完全依赖视频先验补全。大幅转身、离开原有视锥或极端外推时，纹理和结构可能看似合理但与真实场景不符。
  • 反馈误差：单图长视频把上一段生成图重新深度估计并写入 cache。生成伪影、深度偏差和错误对齐可进入后续条件；非刚性 scale map 还可能用局部形变“迁就”不一致点云。
  • 多视图冲突：论文让生成模型聚合深度未对齐、曝光不同的视图，避免直接点云拼接，但并不保证度量尺度、光照或视图相关材质都正确。

论文在双视图实验中加入以深度 5%/95% 分位间距为标准差尺度的高斯噪声，观察到噪声增大时指标下降；这说明模型有一定修复能力，而不是证明对任意深度错误鲁棒。补充材料也明确展示其能修复部分 rail/light 投影错误和填补缺失区域，这些是定性结果，不应扩展成“保证恢复真实几何”。

相机运动与物体运动只在有条件地解耦

静态单图 cache 共享同一几何，若模型生成行走人物或形变物体，旧点云无法描述其新三维状态；长视频仅更新最近边界帧，也不能恢复完整动态场景。动态视频模式则把源时刻 t 的 RGB-D 点云作为物体状态，再用目标相机重投影，因此可以较明确地分离“已有物体运动”和“新相机运动”。但这种分离依赖逐帧深度、源 W2C/K、同步和尺度都可靠，并不是网络从单目视频自动学到的通用动态三维分解。论文的限制也明确写道：动态内容生成依赖预生成视频提供物体运动，如何从文本提示运动仍是开放方向。

成本来自整条管线，而不只是 DiT

公开单段需要 Cosmos 7B DiT、VAE 编解码、文本编码和首帧编码；两个 buffer 的 RGB 与 mask 要执行四次条件 VAE encode。每个扩散步的代码都会计算 conditional 与 unconditional 两次网络输出。每个长视频边界还增加 MoGe 深度推理、cache 深度渲染、默认 100 步非刚性深度对齐和点反投影；前景 mesh masking 又需要 ray-triangle intersection。cache 通过 CPU 驻留和小批 warp 缓解显存，但增加传输，offload 也会引入模型搬运成本。

论文 SVD 的参考是单张 A100 上 14 帧约 30 秒、25 步；公开 Cosmos 默认 121 帧、35 步、704×1280，不能直接比较或套用这个速度。README 只声明在 H100/A100 上测试，并称 full offload 推理观察到的峰值显存约 43GB，实际随系统变化；这不是本文本地实测，也不是所有 GPU 的显存保证。GUI 还提示单服务实例未测试多用户并发。

输入与几何检查

  • 固定源码到 db2ffe12ced12ddafcec5e0422ee46ce8520746b，确认使用 Gen3C-Cosmos-7B 权重，而不是误加载 SVD 或普通 Cosmos Video2World checkpoint。
  • 单图确认 MoGe 深度可视化和主点/焦距合理；多帧确认 RGB、depth、mask、W2C、K 的帧数、宽高和 dtype 一致，mask 已知为 1。
  • 确认深度是 z-depth 还是射线距离；当前默认 is_depth=True。若改变此语义，必须同步检查反投影逻辑。
  • 用已知静态点手算一次 K·W2C·W2C_src⁻¹·dK⁻¹p，检查左右/上下方向、旋转方向和尺度；不要将 C2W 当 W2C 直接传入。
  • resize 时缩放 fx/fy/cx/cy；center crop 时主点减偏移。GUI/API 的 principal point 是相对值，而 cache 内部 K 使用像素值。
  • 先用 --save_buffer 检查每个目标视角的 warped RGB、mask 和深度，再判断是否值得启动扩散生成。

轨迹、长视频与结果诊断

  • 轨迹数组必须是 [1,F,4,4] 与 [1,F,3,3]，且 F=120N+1；自定义旋转需为有效刚体变换，矩阵不能含意外缩放或剪切。
  • 241 帧应有两次 121 帧生成，共用索引 120 的边界帧；最终保存 121+120=241 帧。若拼接处跳变，检查边界帧 RGB、cache slot、W2C/K 索引和 mask 覆盖。
  • 单图长视频确认边界帧确实经过 MoGe 和深度对齐，且最新帧位于 slot 0；若希望重新从原图开始，在 GUI 重新 Seed，避免沿用服务端已更新的 cache。
  • 动态视频确认 Cache4D 时间窗口与目标帧对齐，且没有误以为它会像单图路径一样在线更新所有生成帧。
  • 分别评估几何跟随与生成真实性：检查回环重访区域、遮挡空洞、细线/纹理、前景边界，而不能只看单帧画质。所有定量复现都应使用论文对应基座、分辨率、采样设置和测试协议。
