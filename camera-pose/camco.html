这篇论文真正新增了什么？

不是再一次把 Plücker 接到视频模型，而是把问题拆成两部分：位姿编码负责“镜头怎样动”，极线约束注意力负责“目标帧应从哪里读取源内容”。后者给 3D 一致性一个可计算的几何归纳偏置。

1. 任务：单张图像如何按指定机位运动

输入是一张参考图和相机轨迹，输出沿该轨迹观察同一场景的视频。和 T2V 相比，首帧已经提供外观，所以问题重点不是任意创作，而是保留已有物体与布局，在相机移动时合理产生视差并补全被遮挡区域。

仅输入 RT 向量时，网络需要自己学习像素位置与三维射线的关系；仅做注意力拼接时，又没有明确限制目标位置能读取哪些源像素。CamCo 分别用 Plücker 与 ECA 解决这两个缺口。

2. 位姿表示与相机模块

对每个像素 (u,v)，通过内参逆矩阵得到相机系射线，再旋转到首帧参考坐标。以相机中心 o 与单位方向 d 构成六维 Plücker 向量：

d = normalize(Rc2wK−1[u,v,1]T)，  p=[o×d, d] ∈ R6(1)

六通道射线图与图像在空间上逐像素对齐。原图和局部 patch 的几何不再是隐含在 12 个全局数值里，网络能通过卷积和时序层直接读取。平移归一化很重要：如果同一位移在一组数据中代表 0.1 米、另一组中代表 10 米，moment 的尺度会严重不一致。

论文正文方向公式中的符号排版需要结合几何定义阅读；不能不加判断地把外参平移加在射线方向上。这里采用与公开同类实现一致的“从相机中心出发的单位射线”解释。

图 1：CamCo 的双几何通路。Plücker 告诉模型相机怎样移动；ECA 约束跨帧特征从对应极线读取。两者都不等于完整三维重建。

3. ECA：极线注意力逐步怎么走

假设源帧上像素 x 的深度未知，那么它对应三维空间的一条射线。把这条射线投到目标相机中，得到一条极线；目标帧的对应点只能在这条线上（静态场景、相机标定正确的前提下）。ECA 就在这条线上重采样源特征。

Q = WqXtarget，  Ke,Ve = Sampleepipolar(Xsource)(2)
ECA = softmax(QKeT/√d)Ve(3)

复杂度由全图 cross-attention 的 O((HW)²) 降为 O(HW·l)，l 是每条极线的采样数。它是软约束：attention 仍可选择线上不同深度位置，也可能从错误的几何采样中学习补偿。

讲解用伪代码 · 非官方源码：从位姿构造极线采样
# K_s, K_t: [B,3,3]; T_w2c_s/T_w2c_t: [B,4,4]
rays_s = backproject(pixel_grid(H, W), K_s)       # [B,H,W,3]
depth_candidates = torch.linspace(d_min, d_max, L)

4. 训练与推理：静态几何之外保留物体动态

CamCo 使用 SVD 的 EDM clean prediction 训练框架，可概括为网络接收加噪 clean latent、噪声强度与条件，回归原始视频。条件以一定概率丢弃，以支持 classifier-free guidance。

L = E ||Dθ(x+n; σ,cimage,ccamera) − x||22(4)

训练首先在 RealEstate10K 上学习静态场景几何，再用 Particle-SfM 标注并筛选的约 12K WebVid 动态片段微调。ECA 训练冻结视频骨干，避免为了适应新约束破坏已有生成先验。论文没有完整列出每个阶段所有组件的冻结表，本文不补写不存在的细节。

推理时先准备首帧图像与整条相机序列；逐层计算射线特征和 ECA 对应，随后按 SVD scheduler 迭代去噪。相机输入不应因文本 negative prompt 而删除。

讲解用实现 · 非官方源码：归一化首帧相对轨迹
def normalize_camera_track(c2w):
    # c2w: [F,4,4]，同一世界坐标中的相机位姿。
    w2c = np.linalg.inv(c2w)
    rel = w2c[0:1] @ c2w                 # 首帧为 I
    centers = rel[:, :3, 3]
    scale = np.linalg.norm(centers, axis=-1).max()
    rel = rel.copy()
    if scale > 1e-8:
        rel[:, :3, 3] /= scale
    return rel                           # 平移尺度归一化
# K 仍需按目标分辨率缩放；归一化的是平移，不是内参或旋转。

5. 它能保证什么，不能保证什么

  • 能提供：目标视角的显式条件、静态场景对应关系的几何归纳偏置、比全图注意力更集中的跨帧读取。
  • 不能提供：真实深度与遮挡的自动真值、未观测区域的真实内容、动态物体严格服从静态极线。
  • 主要失败来源：SfM 位姿噪声、深度候选范围、极端视角下首帧信息不足、动态数据规模与多样性。

与 CameraCtrl 相比，CamCo 多了显式 ECA；与 GEN3C 相比，它不维护完整的持久 RGB-D cache；与 ReCamMaster 相比，它的输入是首图而非完整动态源视频。

6. 复现与调试顺序

  1. 在已知 K、位姿的合成静态场景验证极线：源像素对应点投影应落在计算线上。
  2. 画出源帧、目标帧和极线叠加图，再检查 grid_sample 的 xy 顺序及归一化范围。
  3. 验证无位姿输入时仍接近 SVD 原输出；随后逐步增加旋转/平移。
  4. 加入动态区域 mask 或动态微调，避免 ECA 强制运动物体服从静态几何。
  5. 分别评测轨迹精度、视觉质量与遮挡补全，不用单一指标代替三者。

7. 对自定义模型的启示

如果已有可靠首帧和相机标定，与其让模型隐式学习所有像素位移，可以在 attention 的 key/value 采样中直接注入极线先验。更稳妥的工程实现通常还需深度置信度、可见性 mask 与动态区域处理；这些是对论文机制的工程补充，不应冒充论文原有组件。

附录 A：14 帧输入与逐层几何数据流

论文实验中通常生成 14 帧。输入图像提供第一帧外观，14 个相机定义各帧观察位置；每个 temporal block 的 Plücker 需匹配当前特征的空间大小，不匹配时通过插值下采样。ECA 中的目标特征是 hw×d，沿首帧极线采样的特征是 hw×l×d，注意力矩阵因此是 hw×l，而不是 hw×hw。

一个合理的调试样本是固定焦距、沿 x 方向小幅平移并始终看向同一点。先检查首帧是否保持参考外观，再检查近处物体是否比远处背景产生更大位移。若所有区域位移相同，可能是深度/视差没有被模型学到；若动态物体也被强行限制在静态极线上，说明需要动态数据或额外可见性处理。

论文使用 COLMAP 评估输出相机，并做首帧相对化和尺度归一化；重建失败率也作为指标。故不能只挑选 COLMAP 成功案例后宣称整体相机误差，必须同时报告成功率与重建覆盖。

代码 1：CameraControlAdapter

CameraControlAdapter · 位姿特征进入时序模块（讲解用实现，非官方源码）
import torch
from torch import nn
import torch.nn.functional as F

class CameraControlAdapter(nn.Module):
    """Pixel-aligned Plucker -> temporal feature; simplified teaching module."""
    def __init__(self, channels):
        super().__init__()
        # 视频 C 通道 + 六通道 Plücker；逐点 1×1 卷积保留空间对应。
        self.fuse = nn.Conv2d(channels + 6, channels, kernel_size=1)
        # 教学上让整个融合层从零开始，训练初态不影响主干。
        nn.init.zeros_(self.fuse.weight)
        nn.init.zeros_(self.fuse.bias)

    def forward(self, video_feature, plucker):
        # video_feature: [B,F,C,h,w]
        # plucker:       [B,F,6,H,W]
        B,F,C,h,w = video_feature.shape
        p = F.interpolate(plucker.flatten(0,1), size=(h,w),
                          mode="bilinear", align_corners=False)
        x = video_feature.flatten(0,1)
        delta = self.fuse(torch.cat((x,p), dim=1))
        return video_feature + delta.reshape(B,F,C,h,w)

# 实际 ECA 仍在此后计算；这段并不取代 CamCo 的几何注意力。

代码 2：EpipolarCrossAttention

EpipolarCrossAttention · 极线采样与局部注意力（讲解用实现，非官方源码）
class EpipolarCrossAttention(nn.Module):
    def __init__(self, dim, heads=8):
        super().__init__()
        assert dim % heads == 0
        self.heads = heads
        self.q = nn.Linear(dim, dim)
        self.k = nn.Linear(dim, dim)
        self.v = nn.Linear(dim, dim)
        self.out = nn.Linear(dim, dim)

    def forward(self, target, source, sample_xy, valid):
        # target: [B,HW,C]，source: [B,HW,C]
        # sample_xy: [B,HW,L,2]，目标点在源帧极线上的采样位置。
        # valid: [B,HW,L]，遮挡/出界 mask。
        B,HW,C = target.shape
        L = sample_xy.shape[2]
        grid = sample_xy.reshape(B,1,HW*L,2)
        src = source.transpose(1,2).reshape(B,C,1,HW)
        # 真实实现要把 HW 还原为 H×W；此处为可读性省略该一步。
        line_feat = F.grid_sample(src, grid, align_corners=True)
        line_feat = line_feat.reshape(B,C,HW,L).permute(0,2,3,1)
        q = self.q(target).reshape(B,HW,1,self.heads,-1)
        k = self.k(line_feat).reshape(B,HW,L,self.heads,-1)
        v = self.v(line_feat).reshape(B,HW,L,self.heads,-1)
        logits = (q*k).sum(-1) / (C//self.heads)**0.5
        logits = logits.masked_fill(~valid[...,None], -1e4)
        attention = logits.softmax(dim=2)
        out = (attention[...,None]*v).sum(dim=2).reshape(B,HW,C)
        return target + self.out(out)
# 若某点全部无效，应显式给零输出，而不是让 softmax 产生 NaN。

附录 E：显式位姿推理流程

准备首帧与目标 K/位姿，先构造 Plücker 图；各时序层用 1×1 卷积融合几何，ECA 以目标像素 query 读取首帧极线 K/V。SVD 按连续噪声 scheduler 去噪，CFG 从首帧约 1 到末帧约 3 线性变化。每帧都可使用不同内外参，但训练分布外的极端轨迹仍可能失败。

推理前要明确：位姿是 c2w 还是 w2c、是否首帧相对、K 是否像素单位、帧率是否经过 VAE 压缩，以及 unconditional 分支采用哪一种空相机。只把这些数值变成合法 shape 不足以保证几何正确。

附录 F：代码级验证清单

  • 用已知 3D 点与双机位验证极线，不先用生成视频调几何。
