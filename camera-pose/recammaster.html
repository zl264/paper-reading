ReCamMaster：用目标相机轨迹重拍一段动态视频

从论文的帧维条件机制，到公开 Wan2.1 参考实现中的位姿坐标变换、65,520 个 token、逐块相机注入与 Flow Matching 采样。

论文依据：arXiv:2503.11647v2，2025-07-09。论文使用未公开的内部 T2V 模型；公开代码是迁移到 Wan2.1-T2V-1.3B 的参考实现，并非论文内部模型。本文源码核对快照为 fcf98bc86e876bb534518cd99e8a65b282f0f16e。以下不复述论文指标为本地实测，也未执行模型训练或推理。

1. 任务边界：不是编辑机位标签，而是重新生成同一场动态过程

ReCamMaster 解决的是开放域单视频的重拍摄（re-capturing）：给定源视频 Vs、目标文本 pt 和目标相机序列 camt，生成目标视频 Vt。输出应从新机位观察同一个动态场景，既保留源视频的多帧外观，又让同一动作在相同时间发生。它不是把整段视频投射到一幅静态背景，也不是只生成具有相似主题的另一段新视频。

论文将输入与输出都写为 f×c×h×w，目标外参为 camt=[R,t]∈Rf×3×4。一个必须理解的简化是：模型不输入源相机轨迹 cams。作者认为现实单目视频的 SfM 位姿难以准确获得，因此让网络从源视频 token 中自行理解源机位与动态内容；同样不输入源、目标内参，因为真实视频的焦距、主点等往往未知。于是，这里的“精确控制”指给定外参条件下的生成式重渲染，而不是已知完整标定的几何渲染器。

先分清两套模型。论文附录描述的是内部 3D-VAE + DiT，每个基础块含空间注意力、3D 时空注意力和交叉注意力。公开仓库改用 Wan2.1 的全时空 self-attention 块，并明确提示公开版本未必达到论文演示效果。下文的 480×832、21 个 latent 时刻、30 个 block、1,536 维、65,520 token 等数字均属于公开 Wan2.1 实现，不能倒推为论文内部模型配置。

这项任务的主要难点来自遮挡：新机位可能看到源视频中从未出现的区域。ReCamMaster 不恢复唯一真实 4D 场景，而借助 T2V 先验生成合理内容。因此“时间同步”和“看似三维一致”可以与“遮挡区域符合真实几何”相分离，后者并无确定性保证。

2. 为什么是帧维拼接：让两个视频在每个时空注意力块直接交换信息

设 VAE 编码为 zs=E(Vs)、zt=E(Vt)。论文比较三种视频条件路径：通道维拼接把两份 latent 合成 [zs,zt]channel 后再 patchify，输入通道和首层卷积都要改变；视角维方案分别 patchify，再增加专门的 view-attention；ReCamMaster 则分别 patchify，沿帧维组成 xi=[xs,xt]frame。

xs = patchify(zs),　xt = patchify(zt),　xi = [xs, xt]frame-dim ∈ Rb×2f×s×d(1)

关键不只是“把序列变长”。由于 3D self-attention 本来就在所有时空 token 间运行，源、目标不需要额外跨视角层：每一个基础块都能根据内容对应关系读取对方的信息。源视频提供外观与动作，目标分支在扩散过程中逐步决定新视角；只切出目标侧输出即可。论文表 3 在其内部实验设置下报告，frame-dim 相比 channel-/view-dim 同时改善视觉质量、相机误差和视角同步；这些是论文实验结果，不是公开 Wan 权重或本文复测结果。

这个设计保留原 DiT 的输入通道数，却付出明显的序列计算代价：公开实现单支视频有 32,760 token，拼接后为 65,520；全局 self-attention 的注意力交互随序列长度近似二次增长。也就是说，性能来自密集、逐层、全局的源目标交互，并非免费的轻量 adapter。

Rectified Flow 与回归目标

论文用直线路径连接数据 latent z0 和高斯噪声 ε，再学习速度场 vΘ。公开 scheduler 以 σ 表示论文的连续时间变量，训练目标直接实现为 noise - sample，与直线路径的速度 ε-z0 一致。

zσ = (1-σ)z0 + σε,　ε ~ N(0,I),　L = E‖vΘ(zσ,σ) - (ε-z0)‖22(2)

公开实现只在前半段目标 latent 上计算 MSE，再乘 scheduler 的时间权重；后半段源 latent 始终恢复为干净条件，详见 train_recammaster.py:330–367 与 flow_match.py:62–79。这比给两个分支同时加噪更符合“源视频是观察条件”的语义。

3. 显式目标轨迹：从 UE5 JSON 到 21×12，并处理两种首帧参考

论文层面的输入是每帧 3×4 旋转和平移，没有 Plücker 射线、深度图或内参矩阵。公开代码则规定了一条非常具体的预处理链：从 frame0, frame4, …, frame80 各取一个矩阵，因此 81 个 RGB 时刻对应 21 个相机向量。JSON 中每台相机是一个含四行方括号的字符串；代码解析、转置，依次选择列 [1,2,0,3]，翻转第 1 列（零基索引）的前三行，并把平移从厘米除以 100 转为米，得到代码命名为 c2w 的 4×4 齐次矩阵。

时间约定：公开 loader 对源视频读取连续的 0–80 帧，对目标相机每 4 帧采样一次。代码没有使用 JSON 时间戳，也没有从源视频估计 FPS 来重采样轨迹。公开数据集 README 标注视频为 15 FPS，但推理保存函数固定写 fps=30；这只是输出封装帧率，不能把 21 个位姿误称为“21 个原始视频帧”或自行补一套时间同步假设。

3.1 公开训练：相对源视频首帧

对同一场景，loader 先选目标相机 tgt_idx，再从其余九台相机随机选源相机 cond_idx。记源首帧 c2w 为 S0，目标第 i 个采样时刻为 Ti。helper 被逐个调用为 get_relative_pose([S0,Ti])，其返回列表的第一项永远是单位阵、第二项才是 S0-1Ti；外层总是取第二项。因此 i>0 的 20 个训练位姿以源首帧为参考，但 i=0 被额外固定为单位阵，并不保留 S0-1T0 的源目标首帧相对变换。

Pitrain = I（i=0）；Pitrain = (S0)-1Ti（i=4,8,…,80）；取 [R|t] 的前三行并展平为 12 维(3)

3.2 公开推理：相对目标轨迹首帧

推理没有源机位可用，代码把同一 helper 的第一个参数改成目标首帧 T0：i=0 仍由 helper 直接给单位阵，i>0 时 Piinfer=T0-1Ti。后续矩阵描述相对于目标起点的旋转和平移。与训练的本质差别是：训练非首项参考源首帧，推理非首项参考目标首帧；两者首项在代码中都被强制为单位阵。论文正文没有说明这一训练/推理差异，公开仓库也未在此处给出推导解释。

4. 公开 Wan2.1 数据流：VAE、42 个 latent 时刻与 65,520 token

公开入口将 RGB 整理为 [B,C,T,H,W]=[1,3,81,480,832]，像素归一化到 [-1,1]。Wan VAE 输出 16 通道，空间压缩 8 倍；时间方向首帧单独处理，其后每 4 帧一组，所以 Tlatent=1+(81-1)/4=21。VAE 还按通道执行均值/标准差归一化，公开实现直接使用均值 mu 作为输出 latent，见 wan_video_vae.py:492–550 和 wan_video_vae.py:599–618。

图 1　公开实现的结构图。注意论文概念公式按源、目标书写，而公开 pipeline 和训练 loader 都按目标、源排列；模型学习的是这套固定排列，不能在迁移时任意交换。

patch embedding 是 Conv3d(16,1536,kernel=stride=(1,2,2))，所以每支视频有 21×(60/2)×(104/2)=21×30×52=32,760 个 token；拼接后得到 [1,65520,1536]。65,520 是源与目标合计，不是单个视频或单个 block 新增的相机 token 数。Wan2.1-T2V-1.3B 对应 30 层、12 个注意力头，配置见 wan_video_dit.py:454–468。

每个 block 的相机注入位置

公开 DiT 源码 · 相机在 self-attention 前加性注入
# wan_video_dit.py:203-220
input_x = modulate(self.norm1(x), shift_msa, scale_msa)
cam_emb = self.cam_encoder(cam_emb)
cam_emb = cam_emb.repeat(1, 2, 1)
cam_emb = cam_emb.unsqueeze(2).unsqueeze(3).repeat(1, 1, 30, 52, 1)
cam_emb = rearrange(cam_emb, 'b f h w d -> b (f h w) d')
input_x = input_x + cam_emb
x = x + gate_msa * self.projector(self.self_attn(input_x, freqs))
x = x + self.cross_attn(self.norm3(x), context)
input_x = modulate(self.norm2(x), shift_mlp, scale_mlp)
x = x + gate_mlp * self.ffn(input_x)

这与论文式 Fi=Fo+Ec(camt) 的设计意图一致，但具体位置要按源码描述：公开 Wan 块中没有论文内部模型那种单独的空间注意力后再接 3D 注意力，而是在调制后的 norm1(x) 上加相机向量，再进入全局 self-attention。cam_encoder 每个 block 各有一份；21 个向量先沿时间复制为 42，再广播到固定的 30×52 网格。source token 也收到同一条目标轨迹，而不是源相机轨迹。

分辨率不是自由参数。上述 repeat(1,1,30,52,1) 是硬编码。虽然 pipeline 接受 height/width/num_frames 参数，改动它们会改变 patch 网格或时刻数，却不会自动修改这里的 30、52 和时间复制逻辑，容易在 reshape 或加法时失配。论文内部实现也不能据此推断采用了同样的固定网格。

5. UE5 多机位同步数据：监督来自同一场动态过程，而非单视图伪深度

训练需要同一时间、同一角色动作下的多台移动相机。作者在 Unreal Engine 5 中组合 3D 环境、带动画的人物与预定义相机轨迹，每个动态场景渲染 10 台同步相机，每次随机取两台分别作为源与目标。这种配对直接监督“动作保持不变、观察机位改变”，避免从普通单目视频强行构造不可靠的源相机与动态 4D 标注。

论文统计为 136K 视频、13.6K 动态场景、40 个 3D 环境、122K 相机轨迹；附录另列 70 个人物模型和约 100 种动画。相机起始位置在人物周围的半球范围采样，运动覆盖 pan、tilt、平移、弧线、随机平滑折线与静止，50% 恒速、50% 非线性变速。论文还使用 27K 首帧不重合视频做附加实验，说明模型并非只能让输出首帧等于输入首帧；不应把这一附加结论缩小成公开示例的唯一能力。

公开 loader 在训练前将每个视频独立编码并缓存 .tensors.pth；训练时从目标缓存路径中识别 camNN，再加载同场景另一机位的缓存，沿无 batch 的 latent 第 1 维（时间）拼为 [16,42,60,104]。文本 embedding 使用目标缓存，image embedding 为空。这一结构也解释了为什么不能随意把不同场景或不同动作的视频拼成“源目标对”。

6. 冻结、初始化与训练目标：论文策略没有被公开脚本完整复刻

论文的策略是保留基础 T2V 能力，只微调 camera encoder 与 3D-attention；条件 latent 加 200–500 个 noise scheduling steps 的中等噪声以减小合成/真实域差；以 20% 概率把源视频全部 f 帧替换为高斯噪声，另以 20% 概率替换第 2 帧起的 f-1 帧，从而统一 T2V、I2V、V2V 相机控制。论文训练配置为 10K steps、384×672、学习率 0.0001、batch size 40。

公开代码只明确恢复了其中一部分。它先对整个 pipeline 禁梯度，再重新开启名称含 cam_encoder、projector、self_attn 的模块。因而 Wan self-attention 的 q/k/v/o 及 Q/K RMSNorm 都训练，cross-attention、FFN、patch/time/text embedding、head 和各 modulation 仍冻结；VAE 与文本特征在数据预处理阶段缓存，也不在此优化。

零初始化 cam_encoder 使训练起步时新相机偏置为零；projector=I 则让已有 self-attention 残差通路保持恒等映射，并不是把 self-attention 输出清零。这与论文“camera encoder and projector are zero-initialized”的文字不同，应以各自版本分别陈述。完整初始化与冻结代码见 train_recammaster.py:270–327。

公开训练不是论文训练策略的逐项开源。该脚本把拼接后的后半段直接恢复成原始干净 latent，没有实现论文所述对条件施加 200–500 steps 中等噪声，也没有 20% 全帧/20% 除首帧外的 source-latent dropout。不能把这三项论文技巧写进“公开代码默认配置”。公开 README 命令另用每 GPU batch size 1、steps_per_epoch=8000、max_epochs=100、学习率 1e-4，并称未探索最优超参数；这也不是论文的 batch 40、10K steps。

7. 推理与采样：源 latent 每轮重拼，CFG 只更新目标侧

公开主入口依次加载 Wan2.1 DiT、UMT5 文本编码器和 VAE，再为每个 block 创建新增层并以 strict=True 加载完整 ReCamMaster DiT state dict。默认权重路径为 models/ReCamMaster/checkpoints/step20000.ckpt。源视频编码一次，目标从高斯噪声开始；50 个推理步中，每轮重新将当前目标 latent 与固定干净源 latent 拼接，所以 self-attention 总能读取未扩散的源条件。

公开 pipeline 源码 · 拼接、双文本 CFG 与目标侧 Euler step
# wan_video_recammaster.py:272-288
tgt_latent_length = latents.shape[2]
for progress_id, timestep in enumerate(self.scheduler.timesteps):
    timestep = timestep.unsqueeze(0).to(
        dtype=self.torch_dtype, device=self.device)
    latents_input = torch.cat([latents, source_latents], dim=2)
    noise_pred_posi = model_fn_wan_video(
        self.dit, latents_input, timestep=timestep, cam_emb=cam_emb,
        **prompt_emb_posi, **image_emb, **extra_input, **tea_cache_posi)
    if cfg_scale != 1.0:
        noise_pred_nega = model_fn_wan_video(
            self.dit, latents_input, timestep=timestep, cam_emb=cam_emb,
            **prompt_emb_nega, **image_emb, **extra_input, **tea_cache_nega)
        noise_pred = noise_pred_nega + cfg_scale * (
            noise_pred_posi - noise_pred_nega)
    else:
        noise_pred = noise_pred_posi
    latents = self.scheduler.step(
        noise_pred[:, :, :tgt_latent_length, ...],
        self.scheduler.timesteps[progress_id],
        latents_input[:, :, :tgt_latent_length, ...])

这里的 CFG 是正/负文本条件之差；源视频和 cam_emb 在两次前向中完全相同，并不是“无相机”或“无源视频”的 CFG。默认 cfg_scale=5.0，num_inference_steps=50，seed=0；负向提示是入口中一长串固定中文质量/畸变负面词。调用和默认参数见 inference_recammaster.py:242–257。

scheduler 是 FlowMatchScheduler(shift=5,sigma_min=0.0,extra_one_step=True)。每步按 z ← z + vΘ(σnext-σ) 更新，等价于该离散化下的 Euler step；最后仅解码目标侧 21 个 latent 时刻为 81 帧。相关实现见 wan_video_recammaster.py:194–250 与 flow_match.py:18–50。

自定义相机 JSON 的真实入口与限制

--dataset_path 只改变源视频与 metadata.csv 的根目录，不会改变目标相机路径。在固定提交中，相机仍固定读取工作目录下的 ./example_test_data/cameras/camera_extrinsics.json；--cam_type 1…10 选择 cam01…cam10。因此，把自己的视频目录传给 CLI 并不等于已经使用了自己的轨迹。最直接的可控改法是给数据集类新增显式 JSON 路径和相机 key，同时原样保留解析、转置、轴变换、厘米转米和目标首帧相对化。

讲解用实现 / 伪代码 · 非官方源码：把固定轨迹路径改为显式参数
# 以下是基于公开 loader 的改动示意，不是仓库中已有的 CLI 功能。

self.camera_json = camera_json

这段伪代码只解决路径注入，不会把任意 COLMAP/OpenCV JSON 自动变成正确格式。公开示例每帧每机位是特定字符串布局，原始样本可见 camera_extrinsics.json:1–25。若自己的数据已经是常规行主序 c2w，盲目再转置会出错；正确做法是先明确现有矩阵方向和坐标轴，再适配上述预处理，并检查输出的 21×3×4 矩阵，而不是仅检查“文件能打开”。

8. 与代表方法的真实区别：3D 一致性来自哪里，又没有保证什么

方法源动态内容如何进入相机/几何条件与额外代价与 ReCamMaster 的关键区别
ReCamMaster源、目标 latent 分别编码后沿帧/时间拼接，所有时空 self-attention 块共享交互只给目标 3×4 外参，不给源外参和内参；序列翻倍不依赖点跟踪、显式 4D 重建或逐视频优化
GCD论文基线采用通道维视频条件Kubric 合成配对训练论文关注其通道条件与较窄训练域对真实视频泛化的限制
Trajectory-Attention / DaS从源视频提取 3D 点轨迹等动态信息，再作为生成条件依赖上游点跟踪质量ReCamMaster 直接让网络从源 token 学动态对应，没有显式点轨迹中间层
ReCapture先生成相机控制的 anchor video，再适配用户视频图像级多视图扩散 + 时空 LoRA，需逐视频优化ReCamMaster 推理不是每个输入重新优化一套 LoRA
MotionCtrl / CameraCtrl主要面向文本或图像条件视频生成的机位控制分别使用外参 embedding、Plücker 射线等条件设计不能把它们的轨迹编码器和输入约定直接套到 ReCamMaster 的 21×12 外参路径

ReCamMaster 的三维一致性有三个来源：同步多机位训练对提供跨视角监督；源/目标 token 的逐层全局交互维持相同时间和内容对应；大规模 T2V 先验补足不可见区域。它没有显式优化多视图重投影误差，也不维护点云、mesh、NeRF 或 3D Gaussian 场景表示。因此，它能在遮挡区生成视觉上合理的内容，却不保证不同输出之间共享唯一、可测量的真实 4D 几何。

物体运动与相机运动也只是学习到的条件解耦，不是严格可分离变量。目标外参控制机位，源 token 同时携带外观、背景和物体动作；当视角改变过大、源机位理解错误或文本与源内容冲突时，网络可能通过改变人物几何或动作来“满足”新视图。论文的视角同步指标改善不能解释成所有动态细节都严格一致。

9. 失败模式与工程风险：从模型先验到硬编码逐层排查

  1. 手部与小物体：论文附录明确展示手部动作质量差、很小物体生成失败，属于继承自基础 T2V 的不足。换成 Wan2.1 公开权重不会自动消除这些生成先验问题。
  2. 不可见区域的语义漂移：大角度绕行、快速 zoom-out 或严重遮挡要求生成源视频未显示的人物背面、地面或背景。结果可能合理但不符合原场景，身份、服装纹理和接触关系尤其需要人工检查。
  3. 动态不同步：快速复杂动作下，源目标注意力对应可能失败，表现为动作提前/滞后或肢体形变。增加 CFG 主要调文本引导，不是通用的时间同步修复器。
  4. 位姿方向与尺度错误：把 w2c 当 c2w、漏掉转置/列重排/轴翻转、厘米未除以 100，或训练时误用目标首帧而推理时误用源首帧，都会导致轨迹语义不一致。先看相对矩阵，再谈模型质量。
  5. 训练/推理分支次序错误：公开实现是目标噪声在前、干净源 latent 在后。若改成论文公式字面上的源在前，却不同时改切片和相机/训练语义，scheduler 可能更新源侧或把目标当条件。
  6. 自定义分辨率与帧数失配：相机广播固定为 2×21 个时刻、30×52 个 patch；公开模型按 81 帧、480×832 路径构造。修改 pipeline 参数并不会自动推广这层硬编码。
  7. 自定义文件“没有生效”：只改 --dataset_path 仍会读仓库示例相机；修改同名 JSON 与新增自己的 JSON 文件是两件不同的事。还应留意运行工作目录，因为路径是相对路径。
  8. 时间与内参错觉：代码每 4 个原始帧取一个外参，内参并不进入网络；保存 FPS 也不从源视频读取。不能声称模型显式执行了焦距可控或物理时间标定。
  9. 计算代价：65,520 token 在 30 个 block 中做全局注意力，CFG=5 时每个采样步需正、负文本两次前向，共 50 步。序列翻倍是论文自认的限制；不能把“只训练部分参数”误解成“推理只运行部分网络”。

结果核验建议：除整体画质外，至少并排看源/目标同帧的动作相位、人物身份、地面接触、遮挡边界和相机运动方向。对论文中的稳定化、局部“超分辨率”和 outpainting 应用也应如此：zoom-in 后细节变多不等于恢复了真实高频，zoom-out 的新区域更是生成内容。

10. 公开仓库结构与复现检查清单

固定提交不是只有一份推理脚本，而是把 ReCamMaster 改造放进一套 DiffSynth 代码中；同时仓库还包含许多与本文模型无关的 SD、Flux、Hunyuan 等模块。复现时只需围绕以下真实路径追踪，不要把整个 diffsynth 目录都当成 ReCamMaster 新增代码。

官方安装与权重说明见 README.md:56–145。以下是阅读和复现时的检查清单，不表示本文已经执行这些命令：

  • 固定源码到 fcf98bc86e876bb534518cd99e8a65b282f0f16e，确认使用的是 Wan2.1-T2V-1.3B 三个基础权重和兼容的 ReCamMaster step20000.ckpt；strict load 若缺 cam_encoder/projector，应先查权重/代码版本而不是随意 strict=False。
  • 按 example_test_data 准备 videos/ 与两列表头为 file_name,text 的 metadata.csv；视频至少 81 帧。图像会经过保持比例的预缩放、center crop、resize 与 [-1,1] 归一化。
  • 确认目标相机真正来自预期 JSON 和 cam_type。自定义轨迹时检查 0,4,…,80 共 21 项、4×4 矩阵、轴方向、米制平移和 [1,21,12] 输入。
  • 分别打印或断言：源/目标 latent 各为 [1,16,21,60,104]；拼接为 [1,16,42,60,104]；patch 后为 [1,65520,1536]；训练与推理目标切片都是前 21 个 latent 时刻。
  • 训练时确认后半段在加噪后恢复为干净源 latent，loss 只算前半段； optimizer 仅收到 self_attn、cam_encoder、projector 参数，并核对 projector 为单位阵而非零矩阵。
  • 若使用公开训练脚本复现，记录它未包含论文的 200–500 条件噪声与 20%/20% 源 latent 替换；若自行补齐，应把它标成研究改动，不再称“原公开脚本默认”。
  • 推理记录 seed=0、50 steps、CFG=5、shift=5、输出尺寸/帧数及负向提示；不要只凭输出 FPS 或视觉效果宣称相机精度。
  • 改动帧数、分辨率、长宽比或 latent patch 规则前，先移除/推广每块相机广播中的 30×52 与时间复制假设，并同步检查 RoPE 网格、head unpatchify 和目标切片。
