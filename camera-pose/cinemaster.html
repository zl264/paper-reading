与“只控制相机”的区别

CineMaster 把电影生成拆成场景布置和摄影：用户在三维空间放置物体 box、设定类别和相机运动；系统将它们转换成深度/语义布局与独立 RT，避免所有意图都只能压缩成一句文本。

1. 从交互式 3D 场景到扩散条件

第一阶段是交互界面：物体用 3D bounding boxes 表达，用户在三维空间拖动和设定运动，相机用关键帧与轨迹描述。第二阶段将 box 经 Blender 投影成每帧深度图，同时记录类别与实体 mask；相机则转为每个 latent frame 的 3×4 RT。

这样做的意义不是用 Blender 直接出最终视频，而是产生扩散模型可读的结构条件。最终外观、材质、运动和遮挡细节仍由视频扩散模型生成。

2. Camera Adapter：为什么保留独立 RT

如果只有深度图，相机移动和物体移动都可能表现为 box 在图像中改变位置。独立 RT 为网络提供相机坐标变换，使它更容易区分“物体动了”与“观察者动了”。

每帧 12 维 RT 经 MLP 映射到 token 维度，广播相加到视频 token；论文还描述在 self-attention 与 temporal-attention 之间再次通过 residual 注入。与 Plücker 不同，它不构造逐像素射线，几何布局主要由另一条深度 ControlNet 提供。

cf = MLP(flatten([Rf|tf]))，  h′f,h,w=hf,h,w+cf(1)

3. Semantic Layout ControlNet 如何保留实体身份

深度只说明远近，不说明“这个框是车还是人”。CineMaster 将类别 embedding 按实体 mask 放到对应空间位置，与深度 latent 拼接后 MLP 融合。ControlNet 复制 N/2 个 DiT blocks，hidden states 加回主模型。

因此布局控制同时具有几何和语义，减少多物体场景中的身份互换。box 是粗粒度几何，并不能精确控制人物轮廓、手指或细粒度遮挡。

讲解用实现 · 非官方源码：按实体放置语义 embedding
B,F,H,W = depth_latent.shape[0], depth_latent.shape[2], *depth_latent.shape[-2:]
semantic = torch.zeros(B,F,H,W,embed_dim)

4. 三阶段训练与 flow matching

模型采用 rectified flow / conditional flow matching。将 clean latent z₀ 与噪声 z₁=ε 在线性路径上插值，网络学习速度：

zt=(1−t)z₀+tε，  L=E ||(ε−z₀)−vΘ(zt,t,c)||²(2)
  1. 167K dense-depth 视频上预训练 ControlNet，先学深度条件。
  2. 用 156K 视频和 118K 图像适配 3D box 与语义布局。
  3. Semantic Layout ControlNet 与 Camera Adapter 联合训练，使用 99.6K 自有标注视频与 10.4K RealEstate10K，按 3:1 采样。

分阶段避免一开始就要求模型同时学布局、类别、相机与文本的全部组合。论文内部模型和训练数据不等于公开可下载的完整训练包。

5. 推理：只在早期采样阶段启用结构条件

论文在 50 步采样中，前 25 步使用布局条件，前 15 步使用相机条件。其解释是让粗布局与运动先形成，后期更多保留生成细节。

这与 AC3D 的高噪声相机控制有共同直觉，但数值不可互相照搬。关闭条件时应明确是置零、移除 residual，还是切换 unconditional 分支；不同实现的语义不同。

6. 3D-aware 不等于严格 3D 一致

3D box 和深度是强布局先验，独立 RT 提供位姿，但论文没有跨帧重投影一致性损失或持久 3D cache。它不能保证复杂背面、精细几何和动态遮挡严格正确。

当用户指定不合理布局、相机穿过物体、遮挡完全未知时，模型仍依赖生成先验。ControlNet 与相机 residual 也可能相互竞争，需要联合训练而不是任意拼接现成模块。

7. 复现与对比重点

  • 把用户 3D box、相机关键帧、Blender 渲染与 latent 帧率对齐。
  • 分别测试物体运动 + 静止相机、相机运动 + 静止物体。
  • 比较只有深度、深度+语义、再加 RT 的增量贡献。
  • 验证 entity mask 不因多物体重叠而混淆类别。
  • 扫描布局/相机启用步数，记录轨迹、布局和视觉质量变化。

附录 A：一个具体导演输入如何变成训练/推理条件

设想用户在原点放一个人物 box，在右侧放一辆车，相机从人物前方缓慢向右环绕。系统首先将 box 在世界空间的角点和相机位姿序列送入渲染器，得到每帧深度和实体 mask；人物与车辆的类别 embedding 分别放在对应 mask 区域。相机 RT 则单独经 MLP 注入，不烧录进深度通道。

如果物体也移动，box 随时间变化、相机 RT 同时变化，深度图反映二者合成后的可见布局。独立 RT 给模型提供分解线索，但不保证网络总能完美解耦。对车与人互相遮挡的场景，渲染器需确定前后关系与可见 mask，不能只把两张完整 mask 相加。

训练三阶段分别解决深度跟随、语义布局和相机联合控制；这意味着自定义复现若直接同时训练全部模块，可能遇到不同的优化稳定性。推理早期逐步撤掉布局/相机，也要求调度器以一致的时间方向计数。

代码 1：SemanticLayoutCondition

SemanticLayoutCondition · 深度与实体语义联合（讲解用实现，非官方源码）
class SemanticLayoutCondition(nn.Module):
    def __init__(self, depth_channels, classes, dim):
        super().__init__()
        self.class_embedding = nn.Embedding(classes,dim)
        self.fuse = nn.Conv3d(depth_channels+dim,dim,1)

    def forward(self, depth_latent, entity_masks, class_ids):
        # depth_latent: [B,Cd,F,H,W]
        # entity_masks: [B,N,F,H,W]，每一维 N 是一个实体的可见区域。
        B,N,F,H,W = entity_masks.shape
        embedding = self.class_embedding(class_ids)      # [B,N,D]
        semantic = (entity_masks.unsqueeze(-1)*embedding[:,:,None,None,None,:]).sum(1)
        semantic = semantic.permute(0,4,1,2,3)           # [B,D,F,H,W]
        return self.fuse(torch.cat([depth_latent,semantic],dim=1))
# mask 来自 Blender 对 3D box 的投影，不是模型自回归生成的 mask。

附录 E：显式位姿推理流程

用户先摆好物体和相机，系统生成逐帧深度、mask、类别与 RT；ControlNet 和 Camera Adapter 将条件注入 DiT。50 步采样的前 25 步使用布局、前 15 步使用相机。box 是粗几何，无法指定人物精细轮廓或真实遮挡背面。

推理前要明确：位姿是 c2w 还是 w2c、是否首帧相对、K 是否像素单位、帧率是否经过 VAE 压缩，以及 unconditional 分支采用哪一种空相机。只把这些数值变成合法 shape 不足以保证几何正确。
