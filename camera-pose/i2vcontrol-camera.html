最直接的理解

不是让网络从 12 个外参数字猜每个像素怎么动，而是先利用首帧深度，把目标相机下“原来的三维点落到哪个像素”算出来。相机控制因此变成像素对齐的二维轨迹图，同时用非刚体项保留主体动作。

1. 视频运动分解：相机刚体项与主体残差

设场景点 p 在连续时间 λ 下的位置变化由两部分组成：

F(p,λ) = Rλp + tλ + G(p,λ)(1)

R、t 描述相机系下的刚体变化，G 表示人体/物体相对世界的非刚体或自主运动。只拟合 R、t 会把主体动作误认为相机变化；只给二维轨迹又无法区分运动来源。论文将两者拆开，分别用于视角与主体强度控制。

Tλ = Π(RλΩ + tλ)(2)

Ω 是首帧由深度反投影的点集，Π 是投影。T 是二维稠密点轨迹，模型看到的是“这个像素随时间往哪里移动”，不是抽象外参。

图 1：相机诱导运动与主体运动的显式拆分。位姿先作用于首帧点云，网络读取投影点轨迹；主体高阶运动单独编码，避免位姿控制压制人物动作。

2. 主体运动强度为什么可以独立调节

mλ = |Ω|−1 ∫Ω ||∂G(p,λ)/∂λ||2 dp(3)

m 衡量非刚体项的时间变化幅度。离散实现以相邻帧差分近似导数。把轨迹的二维位移通道与平铺的 m 拼成三通道控制视频，可以在相机旋转/平移不变时增加或减弱人物动作。

该强度是聚合统计量，不指定每个关节的精细动作；它适合调节整体动态程度，不等于完整的人体姿态控制。

讲解用实现 · 非官方源码：投影轨迹与强度图
# points0: [H,W,3]，由首帧 RGB-D 反投影得到。
# relative_w2c: [F,4,4]，目标/当前相机相对首帧的变换。
points = points0.reshape(-1,3)
trajectory = []
for T in relative_w2c:
    cam = points @ T[:3,:3].T + T[:3,3]
    uv = cam[:,:2] / cam[:,2:3].clamp_min(1e-6)
    uv = uv * K[:2,:2].diag() + K[:2,2]
    trajectory.append(uv.reshape(H,W,2))
T = np.stack(trajectory)                    # [F,H,W,2]
motion_strength = np.linalg.norm(np.diff(G, axis=0), axis=-1).mean()
control = np.concatenate([T, np.broadcast_to(motion_strength, T[...,:1].shape)],-1)
# 控制轨迹通常用相邻帧差分而非绝对像素坐标；必须与训练定义一致。

3. 控制怎样进入 MagicVideo-V2

二维轨迹 T 的形状为 (T,2,H,W)，主体强度平铺后形成 (T,3,H,W)。卷积 adapter 将其变换到视频 token 的时空尺寸与通道宽度，在 self-attention 前与 token 序列拼接；注意力完成后去掉控制 token，恢复视频形状。

这种“额外控制 token”允许条件与视频通过 self-attention 相互读取，而不是只把一个小向量加到时间 embedding。论文声称其设计与具体骨干无关，但具体 token 布局仍需按 MagicVideo-V2 实现。

讲解用伪代码 · 非官方源码：控制 token 的接入
control_video = torch.stack([flow_x, flow_y, strength_map], dim=2)
control_tokens = conv_adapter(control_video)       # [B,Nc,C]
video_tokens = patchify(noisy_video_latent)        # [B,Nv,C]
joint = torch.cat([control_tokens, video_tokens], dim=1)
joint = self_attention(norm(joint)) + joint

4. 数据与训练

论文使用约 30K 自有动态视频，UniDepth 提供米制深度，SpatialTracker 提供三维轨迹；迭代刚体拟合 / L-BFGS 用来区分静态背景与动态区域。只有 adapter 被训练，MagicVideo-V2 主干冻结，扩散损失和 scheduler 保持基模型设置。

这套预处理本身构成重要工程成本：深度尺度、动态 mask 和轨迹跟踪错误都会改变控制图。训练时还需要保证目标轨迹、主体强度与像素视频严格同步。

5. 与 Plücker 方法的本质区别

维度Plücker 条件I2VControl-Camera 点轨迹
网络读取每像素三维射线三维点在新视角的二维位置/位移
深度依赖不是必须，模型隐式学习视差显式依赖首帧深度
相机/物体解耦需数据或额外模块由刚体项与非刚体项显式分解
遮挡补全由生成先验完成点轨迹无法提供未见内容，仍靠生成先验
失败敏感性位姿与训练分布深度、跟踪、刚体拟合和出界点

6. 失败模式与适用边界

  • 深度错误会把静态背景点投到错误位置，产生拉扯或扭曲。
  • 首帧不可见区域没有 Ω 点，不能靠轨迹知道应该生成什么。
  • 复杂遮挡、透明物体、反射与快速非刚体运动不满足简单刚体分解。
  • 主体强度只是一个标量/时序曲线，不等于完整动作编辑。
  • 轨迹条件可能与源图内容冲突，例如要求看见完全未知的背面。

7. 复现检查

  • 验证深度单位、相机中心与投影公式，检查 z≤0 与出界点。
  • 确认轨迹保存的是绝对位置还是相邻位移；两种约定不可混用。
  • 对静止主体 + 运动相机、静止相机 + 动态主体做隔离测试。
  • 给控制 token 与视频 token 明确的时间/位置对应。
  • 主体强度 m 的计算区域 Ω 必须明确，避免背景噪声主导。

附录 A：从输入到位姿轨迹的预处理清单

首先用 UniDepth 将首帧变为带尺度的深度，再把每个像素反投影成 Ω。随后依据目标 R、t 得到逐帧相机系点坐标，剔除相机后方或无效深度，并通过 K 投影到像素。若控制图保存的是相邻帧位移，要计算 Tλ−Tλ₋₁，首帧与未覆盖位置置零。

主体运动估计需要把静态背景和动态前景分开：静态点用于拟合刚体 R、t，动态点残差形成 G。若直接用全部点拟合相机，人物动作可能污染外参；若动态 mask 太保守，背景误差又会被当作主体运动。

控制视频在 adapter 前还需与 noisy latent 的帧率、空间尺寸和取值范围对齐。注意力拼接时保留控制 token 数 Nc，以便输出切回 Nv；但训练好的模型需要学到这些 token 的类型和时间位置，不能只在一个未经训练的基座上直接拼接就期待可控。

代码 1：CameraToPixelTrajectory

CameraToPixelTrajectory · 从 RGB-D 和位姿计算条件（讲解用实现，非官方源码）
def camera_to_pixel_trajectory(depth, K, target_w2c, reference_w2c):
    # depth:[H,W]，K:[3,3]，位姿为 [F,4,4]；全部采用列向量约定。
    H,W = depth.shape
    v,u = np.meshgrid(np.arange(H),np.arange(W),indexing="ij")
    pix = np.stack([u,v,np.ones_like(u)],axis=-1)
    rays = pix @ np.linalg.inv(K).T
    points_c = rays * depth[...,None]
    # 首帧到世界，再从世界到各目标相机。
    points_w = points_c @ reference_w2c[:3,:3].T + reference_w2c[:3,3]
    flow=[]; valid=[]
    for w2c in target_w2c:
        pc = points_w @ w2c[:3,:3].T + w2c[:3,3]
        z = pc[...,2]
        uv = pc[...,:2]/np.maximum(z[...,None],1e-6)
        uv = uv @ K[:2,:2].T + K[:2,2]
        flow.append(uv)
        valid.append((z>0)&(depth>0))
    return np.stack(flow), np.stack(valid)
# 实际训练还需前景/背景分解；不要把无效点直接用巨大坐标喂网络。

代码 2：TrajectoryAdapter

TrajectoryAdapter · 控制 token 与视频 token 交互（讲解用实现，非官方源码）
class TrajectoryAdapter(nn.Module):
    def __init__(self, token_dim):
        super().__init__()
        self.spatial = nn.Sequential(
            nn.Conv2d(3,64,3,stride=2,padding=1),nn.GELU(),
            nn.Conv2d(64,128,3,stride=2,padding=1),nn.GELU(),
            nn.Conv2d(128,token_dim,1))
        self.type_embedding = nn.Parameter(torch.zeros(1,1,token_dim))

    def forward(self, flow_xy, subject_strength, latent_hw):
        # flow_xy: [B,F,2,H,W]；strength: [B,F]
        B,F,_,H,W = flow_xy.shape
        m = subject_strength[:,:,None,None,None].expand(B,F,1,H,W)
        control = torch.cat([flow_xy,m],dim=2).flatten(0,1)
        feat = self.spatial(control)
        feat = F.adaptive_avg_pool2d(feat,latent_hw)
        tokens = feat.flatten(2).transpose(1,2).reshape(B,F,-1,feat.shape[1])
        tokens = tokens.flatten(1,2) + self.type_embedding
        return tokens
# self-attn 后按 tokens.shape[1] 切掉控制段；位置编码须另行设计。

附录 E：显式位姿推理流程

将首帧点云按目标 R/t 逐帧变换与投影，得到稠密轨迹图；主体强度平铺为第三通道，经 adapter 后在 self-attention 前拼接。注意力后去除控制 token，视频主干继续去噪。无需输入每个像素的 GT 轨迹，但必须处理深度无效、出界与遮挡。

推理前要明确：位姿是 c2w 还是 w2c、是否首帧相对、K 是否像素单位、帧率是否经过 VAE 压缩，以及 unconditional 分支采用哪一种空相机。只把这些数值变成合法 shape 不足以保证几何正确。
