显式相机位姿可控视频生成：原理、结构与源码详解

从一串 [R | t]，到逐像素 Plücker 射线、时序注意力、极线约束与可更新 3D cache。

本文聚焦一个更严格的问题：用户明确给出相机外参、内参或轨迹，模型怎样把这份几何条件变成逐帧像素？不是介绍“推近、环绕”等文本运镜，也不是把物体轨迹控制误当作相机控制。

资料基线：2026-11-27 下载的 arXiv 原文与官方公开源码。精读 MotionCtrl、CameraCtrl、ReCamMaster、GEN3C；结构解析 CamCo、VD3D、CMG、AC3D、CameraCtrl II、CineMaster、TrajectoryCrafter、I2VControl-Camera。官方源码按所下载分支快照解读；没有公开实现的部分明确标为“论文机制 + 讲解用实现”，不冒充官方代码。本文只进行了几何示例测试与 HTML 静态检查，未运行这些大型模型的训练或生成。

显式相机控制不是“把 12 个数拼进 prompt”，而是建立一条完整的数据合同：世界坐标与相机坐标 → 首帧相对位姿 → 与像素/latent 对齐的几何表示 → 特定层与去噪时刻的融合 → 用同步视频与精确位姿监督。任何一步的坐标、尺度、时间压缩或条件 dropout 不一致，都会表现为运镜不准、主体冻结或场景变形。

1. 范围与地图：哪些才算“显式输入相机位姿”

纳入本文的方法至少满足一条：直接接受 R,t,K；或接受位姿后将其确定性地转换为 Plücker 射线、投影点轨迹、点云渲染图等条件。ReCamMaster 的目标轨迹、CameraCtrl 的逐像素射线、GEN3C 的 3D cache 渲染都属于这一范围。

不纳入：只用“camera moves left”等文本提示；只给一段参考视频而不恢复或指定几何；只控制人体/物体而没有相机输入。免训练方法虽然可能从相机轨迹生成 latent warp，但本次优先深入前述有直接公开实现的主线，以免把几十种方法写成浅层摘要。

2. 先统一几何：c2w、w2c、内参与相对位姿

2.1 同一个“位姿矩阵”有两种相反含义

设世界点 Xw 到相机点 Xc 的变换为 Tw2c=[R|t]：

Xc = R Xw + t(1)

而 c2w 是它的逆：

Tc2w = Tw2c−1 = [ RT | −RTt ](2)

其中 −RTt 才是相机中心在世界坐标中的位置。把 t 直接当相机位置，是轨迹可视化、Plücker 射线和点云重投影最常见的错误之一。

坐标轴也是数据合同的一部分。本文讲解示例采用 OpenCV：+x 向右、+y 向下、+z 向前。OpenGL 常用 +y 向上、相机看向 −z；UE 又有自己的轴与单位。仅交换 c2w/w2c 名称而不检查轴方向，会生成相反方向或翻转的运镜。

2.2 内参决定“一个像素对应哪条射线”

K = [ fx 0 cx ; 0 fy cy ; 0 0 1 ]，   x̃ = K−1[u+0.5,v+0.5,1]T(3)

+0.5 表示在像素中心采样。改变 f 是视场/变焦，改变相机中心是 dolly/平移，二者都常被口语称为“zoom”，但视差效果不同。内参从归一化坐标转换到像素坐标时，fx、cx 乘 W，fy、cy 乘 H；resize 与 crop 也必须同步变换 K。

2.3 为什么多数方法先相对首帧

Tirel = T0,w2c Ti,c2w，   T0rel = I(4)

这把首帧相机作为新世界原点，消除整个数据集全局坐标系任意摆放的影响，但不消除平移的绝对尺度。对于 Plücker 的 moment o×d，相机中心放大十倍，输入数值也会放大十倍。因此 CamCo 归一化平移、GEN3C 依据场景深度控制移动距离、后续 MeRoPE 等工作继续处理 metric scale，并不是无关紧要的工程修饰。

讲解用 NumPy 实现 · 坐标系与相对位姿
def relative_w2c(reference_w2c, target_w2c):
    # 首帧相机成为参考坐标系；返回值是 c2w 的相对轨迹。
    # 适用于同一刚体世界变换下的两组绝对位姿。
    return np.linalg.inv(reference_w2c) @ target_w2c

def look_at_w2c(eye, target, up=(0., 1., 0.)):
    # OpenCV: +x right, +y down, +z forward。
    z = normalize(target - eye)
    x = normalize(np.cross(z, up))
    y = np.cross(z, x)
    R = np.stack((x, y, z), axis=0)
    T = np.eye(4)
    T[:3, :3] = R
    T[:3, 3] = -R @ eye
    return T

完整可运行示例见 scripts/camera_geometry_demo.py。它验证了首帧相对位姿为单位阵、射线方向为单位向量、Plücker 方向与 moment 正交；这些测试只验证几何，不验证生成模型。

3. Plücker 射线：为什么比直接展平 RT 更适合像素模型

把 3×4 RT 展成 12 个数，网络需要自行学习“第几个数对应哪个像素、平移与旋转如何共同决定视差”。Plücker 表示则先完成逆投影：每个像素都附带一条从相机中心发出的三维射线。

duv = Rc2w · normalize(K−1[u+0.5,v+0.5,1]T)(5)
muv = o × duv，   puv = [muv, duv] ∈ R6(6)

d 是单位方向，o 是世界坐标中的相机中心，m 编码直线相对原点的位置与尺度。对一条射线上任意点 x=o+λd，都有 x×d=m，因此它表示的是整条线，不是某个已知深度的三维点。

  • 纯旋转：相机中心不变，m 不变，d 随像素与旋转改变；可描述 pan/tilt。
  • 纯平移：d 不变，m=o×d 改变；但模型仍需从图像/深度先验推断视差大小。
  • 空间对齐：6 通道 H×W 场天然可以和卷积、patchify、特征相加配合，比单个全局向量保留更多局部几何。
讲解用实现 · 从 K、c2w 生成 [H,W,6] 射线图
def plucker_rays(w2c, K, H, W):
    R, t = w2c[:3, :3], w2c[:3, 3]
    center_world = -R.T @ t
    u, v = np.meshgrid(np.arange(W), np.arange(H))
    pixels = np.stack((u + .5, v + .5, np.ones_like(u)), -1)
    dirs_camera = pixels @ np.linalg.inv(K).T
    dirs_world = dirs_camera @ R       # R_c2w = R_w2c.T
    dirs_world /= np.linalg.norm(dirs_world, axis=-1, keepdims=True)
    moments = np.cross(dirs_world, center_world)
    return np.concatenate((dirs_world, moments), axis=-1)

3.1 时序压缩后的对齐

视频 VAE 常把 4 个像素帧压成 1 个 latent 时间步。若视频 latent 有 F′ 帧而相机仍有 F 帧，直接相加会发生 shape 或语义错位。CameraCtrl 的 U-Net 没有时间压缩，保持逐帧 Plücker；CameraCtrl II 每 4 帧取一个位姿；AC3D 用因果 1D 卷积把 F×6 射线序列映射为 F/4×32，信息保留更充分；ReCamMaster 对 81 帧取 0,4,…,80，得到 21 帧相机。

4.1 扩散训练没有因为相机而改变根本目标

zτ = add_noise(z0, ε, τ)，   L = || ε − εθ(zτ,τ,ctext,ccamera) ||22(7)

MotionCtrl、CameraCtrl 等采用噪声预测的形式可这样概括。VD3D 使用 EDM clean prediction；ReCamMaster、CineMaster、AC3D 等使用 flow matching / rectified flow 时，预测目标改为速度场：

zτ=(1−τ)z0+τε，   vtarget=ε−z0，   L=||vθ−vtarget||2(8)

训练数据必须提供同一段视频的图像与相机监督。推理则从纯噪声开始，反复调用条件网络，再把预测交给 DDIM/EDM/FlowMatch scheduler。camera encoder 通常在去噪循环外只算一次；扩散主干每步都会读取它。

4.2 文本 CFG 与相机 CFG 不是一回事

e = e∅,∅ + sT(eT,∅−e∅,∅) + sC(eT,C−eT,∅)(9)

这是 CMG 解耦文本和相机引导的写法。普通文本 CFG 的负分支通常仍保留同一相机条件，因此提高文本 guidance 并不等价于提高轨迹遵循。代价是解耦引导需要更多分支前向。

5. MotionCtrl：把逐帧 W2C 外参注入时序注意力

论文 2312.03641官方源码骨干：VideoCrafter / LVDM输入：F×12公开 main：含模型改造与推理；提交 6242d554

5.1 原理：全局相机运动应与时间特征交互

MotionCtrl 把运动分为相机运动与物体运动：前者影响整幅画面的跨帧变化，适合放进 temporal transformer；后者更局部，用空间卷积 adapter 处理。本文只深入相机分支 CMCM（Camera Motion Control Module），OMCM 可关闭。

每一帧输入 world-to-camera 外参 RTi=[Ri|Ti]，按行展开为 12 维：

[r00,r01,r02,tx, r10,r11,r12,ty, r20,r21,r22,tz](10)

没有焦距或主点 K 输入；不能从 MotionCtrl 的 12 维格式推出它支持独立变焦/内参控制。公开 Gradio 可视化中的相对位姿函数也不是主模型必经预处理，不能默认所有输入都会再次首帧归一化。

5.2 精确结构：不是一个庞大的独立位姿编码器

公开 VideoCrafter main 分支直接给每个 temporal block 新增 cc_projection = Linear(C+12, C)。它位于该 block 的第一个 self-attention 之后、第二个 self-attention 之前。同一帧的 12 维向量复制给该帧所有 H×W 个空间位置。

图 1：MotionCtrl 的帧级条件融合。相机向量对所有空间位置相同，其优势来自时序层而不是逐像素几何。

6. CameraCtrl：多尺度 Plücker 编码与时序 QKV 融合

6.1 真实输入格式与预处理

公开 main 并不是直接读取一个 4×4 NumPy 数组，而是读取 RealEstate10K 风格文本。每行 19 个字段：

CameraCtrl trajectory text · 每行数据合同
timestamp  fx  fy  cx  cy  0  0  w2c_00 ... w2c_23
# index: 0    1   2   3   4  5  6   7 .............. 18
# fx,fy,cx,cy 是归一化内参；w2c 是 3×4 行优先矩阵。
# 像素内参 = (fx*W, fy*H, cx*W, cy*H)。

代码把 12 个外参数补成 4×4 w2c，再求逆得到 c2w。默认 relative_pose=true，以首帧相机建立相对坐标；随后用像素中心采样构造 [m=o×d,d] 六通道 Plücker 图。

官方 inference.py · Plücker 射线构造（节选）
xs = (i - cx) / fx * zs
ys = (j - cy) / fy * zs
directions = torch.stack((xs, ys, zs), dim=-1)
directions = directions / directions.norm(dim=-1, keepdim=True)
rays_d = directions @ c2w[..., :3, :3].transpose(-1, -2)
rays_o = c2w[..., :3, 3]
rays_o = rays_o[:, :, None].expand_as(rays_d)
rays_dxo = torch.cross(rays_o, rays_d)
plucker = torch.cat([rays_dxo, rays_d], dim=-1)
plucker = plucker.reshape(B, c2w.shape[1], H, W, 6)
官方源码：inference.py，单位射线与六通道布局

这里 +z 向前、像素横纵坐标分别由 (i+0.5−cx)/fx 与 (j+0.5−cy)/fy 得到。六通道固定为 moment 在前、direction 在后。若自己的格式是 c2w，不要再次求逆；若自己的原始图像尺寸不是默认 1280×720，必须同步调整参数。

6.2 CameraPoseEncoder 的逐层结构

输入先重排成 [B,6,F,H,W]，帧维折叠进 batch 后逐帧做二维卷积。PixelUnshuffle(8) 把 6 通道变为 384 通道，同时空间缩小八倍；这相当于把局部 8×8 射线块完整重排到通道，而不是先用大步长卷积丢掉信息。

层级主要操作单帧通道 / 空间（默认输入）返回主 U-Net
Unshuffle + conv-in6→384；3×3 conv 到 320320，32×48[B,320,16,32,48]
Stage 12×(ResBlock + Temporal Block)320，32×48同上
Stage 2AvgPool 下采样 + 2×复合块640，16×24[B,640,16,16,24]
Stage 3AvgPool 下采样 + 2×复合块1280，8×12[B,1280,16,8,12]
Stage 4AvgPool 下采样 + 2×复合块1280，4×6[B,1280,16,4,6]

每个 Temporal Block 把 [(BF),C,h,w] 变为 [(Bhw),F,C]，沿时间做 8 头 pre-LN self-attention，再接 GEGLU FFN 残差。这样同一空间位置的射线随时间如何变化也被编码，而不是只有一张静态几何图。

官方 pose_adaptor.py · 多尺度特征回传（节选）
def forward(self, noisy_latents, timesteps,
            encoder_hidden_states, pose_embedding):
    bs = pose_embedding.shape[0]       # [B,6,F,H,W]
    features = self.pose_encoder(pose_embedding)
    features = [rearrange(x, '(b f) c h w -> b c f h w', b=bs)
                for x in features]
    noise_pred = self.unet(
        noisy_latents, timesteps, encoder_hidden_states,
        pose_embedding_features=features).sample
    return noise_pred
官方源码：pose encoder 不读取 noisy latent，避免外观泄漏

6.3 融合公式：不是简单的 x + pose

默认只替换 down/up motion module 内名称为 0 的第一个 temporal self-attention，mid motion module 关闭；该 AnimateDiffV3 配置共 8 个融合点。每个尺度将 Plücker 特征插值/对齐到 U-Net 特征尺寸，再经过零初始化 merge：

x′ = x + s·Linearmerge(x+p)，   Q=Wqx′，K=Wkx′，V=Wvx′(11)

attention 输出之后仍保留原始 x 的 residual。merge 全零初始化让初始控制影响为零，但参数仍可经扩散损失学习；不能把它误解为“模型没有控制梯度”。

官方 attention_processor.py · 位姿进入 Q/K/V（节选）

    * pose_embedding_scale + hidden_states

key_value_hidden_state = query_hidden_state

6.4 一个训练 step 与一次推理

  1. 文本以 10% 概率替换为空串；图像经 VAE 得到 [B,4,16,32,48] latent。
  2. 采样高斯噪声和 timestep，DDIM scheduler 加噪；CLIP 提供文本 embedding。
  3. Plücker 经 PoseAdaptor 产生四个尺度的特征；冻结的 SD/AnimateDiff 主干预测 epsilon。
  4. 损失 MSE(ε̂,ε)；优化器只接收 pose encoder 与名字含 merge 且非 LoRA 的参数。
  5. 推理时位姿编码器在 25 步 DDIM 循环外只运行一次；每个 step 的正负文本分支共享同一组相机特征，默认文本 CFG=14。
复现边界：main 是 AnimateDiffV3，不是 SVD 分支；论文 50K steps 与公开 YAML 25K steps 不同；论文/附录与代码的部分 Adam 参数也不相同。公开训练循环的 resume 路径留有 pdb.set_trace()。本文报告这些差异，而不把官方实验配置和公开示例强行写成一致。

7. CamCo：Plücker 控制之外，再用极线注意力约束 3D 一致性

论文 2406.02509项目页骨干：SVD / I2V重点：极线约束本文不声称有官方实现

CameraCtrl 学到“轨迹影响视频”的软映射，但没有强制目标帧的某个像素只能从几何对应的位置读取内容。CamCo 在 SVD 上引入两个互补组件：Plücker camera control module 负责位姿，Epipolar Constraint Attention（ECA）负责跨视角对应。

7.1 控制分支

每像素 Plücker 与视频特征沿通道拼接，再通过部分零初始化的 1×1 卷积恢复到原通道，送入 temporal attention。所有相机相对首帧，平移按离原点最远的相机距离归一化，缓解不同场景尺度差异。

7.2 极线注意力到底在计算什么

首帧像素 x 对应一条三维射线，该射线在目标帧中的投影是一条极线 l。ECA 把目标帧特征作为 query，只在首帧极线上重采样的 l 个位置取 key/value：

ECA(Xtarget,Xsource) = softmax(QKepipolarT/√d)·Vepipolar(12)

这把全图两两对应的 O((HW)²) 候选缩减到 O(HW·l)，同时引入“同一三维点只能落在对应极线上”的几何先验。它是注意力约束，不是完整的多视图重建或硬光度损失；动态物体仍可能偏离静态极线。

图 2：ECA 的归纳偏置。几何限制“从哪里读”，扩散模型决定“生成什么细节”。

7.3 训练与讲解代码

先在 RealEstate10K 静态数据训练，再用 Particle-SfM 标注并筛选的约 12K WebVid 动态片段微调，减轻静态场景偏差。ECA 训练时冻结视频主干。论文对 ECA 的阶段说明较明确，但不能凭空补齐一个官方训练脚本中各模块的完整冻结表。

8. 视频 DiT：VD3D、CMG、AC3D 与 CameraCtrl II

8.1 VD3D：把 Plücker patchify 成与视频同构的 token

论文 2407.12781骨干：SnapVideo FIT约 230M 可训练参数

U-Net 方法可以在卷积特征上直接加多尺度射线图；SnapVideo 的 FIT 则以 patch latent 与完整视觉 token 的 cross-attention 为核心。VD3D 把 6×F×H×W Plücker 张量按视频相同方式 patchify，再经两层 GELU MLP 得到相机 token。

每个 FIT block 的 read cross-attention 处增加并行相机支路：

z′ = FF(XAttn(z,v)) + Convres(FFcam(XAttncam(z,ccam+v)))(13)

相机 cross-attention / FF 从预训练对应层复制，最后接零初始化 1D 卷积残差。训练只更新新增参数，冻结 4B 级基座；低分辨率 base 学相机控制，高分辨率 upsampler 不注入相机并冻结。这种结构的关键不是“DiT 也用了 Plücker”，而是把条件放到 FIT 读取全局视觉 token 的同一接口。

8.2 CMG：表示之外，通道比与推理引导同样关键

论文 2410.10802骨干：OpenSora 1.0 ST-DiT条件：RT 或 Plücker

论文复现了 DiT-MotionCtrl（RT 重复后通道拼接）和 DiT-CameraCtrl（高维 Plücker 特征相加），发现相机控制退化并不能只归咎于 RT 表示。高维、可学习、空间变化的条件注入更有效；在相同融合方式下，RT 也能工作。

推理的 Camera Motion Guidance 使用第（9）式，把文本方向与相机方向分开。训练加入 5% null camera 与 5% camera dropout，后者随机把 70–100% 帧位姿置零，因此还能支持稀疏关键帧位姿控制。它是推理期控制增强，不是新的 3D 一致性模块。

讲解用 PyTorch · 独立 camera CFG
e00 = dit(x, t, text=null_text, camera=null_camera)
e10 = dit(x, t, text=text,      camera=null_camera)
e11 = dit(x, t, text=text,      camera=target_camera)
noise_pred = e00 + text_scale * (e10 - e00) \
                  + camera_scale * (e11 - e10)
# 目标 camera 必须在训练时以相应 dropout 见过 null_camera，
# 否则“无相机”分支可能落在训练分布之外。

8.3 AC3D：低频运动、少层注入与静止相机动态数据

论文 2411.18673骨干：11.5B VDiT / CogVideoX 实验前 8 / 32 block

AC3D 的价值是解释为什么同样是 Plücker + DiT，有些实现不准。其诊断和改造可分成四部分：

  1. 相机运动是低频。训练噪声从普通 logit-normal 改为偏向 [0.6,1] 的高噪声区间，推理只在前 40% 去噪阶段启用相机条件，让网络先决定全局运动，再补细节。
  2. 中层已隐式估计相机。对无条件 VDiT 做 probing，发现不是所有层都需要外部位姿。最终只在最前 8/32 block 注入，降低对原生成能力的干扰。
  3. 轻量相机支路带反馈。128 维、4 头 DiT-XS 处理 Plücker；主视频 token 对 camera token 做 cross-attention。相机支路不输入文本/分辨率等 context，减少捷径。
  4. 去静态偏差。65K RealEstate10K 之外加入 20K 静止相机但动态内容的视频，让“位姿条件开启”不再意味着“场景没有物体运动”。

对于 4× 时间压缩，AC3D 不直接每四帧抽一个位姿，而用因果 1D 卷积把每像素 F×6 序列压为 F/4×32。这比简单丢帧更完整，但也意味着需要训练对应 camera temporal encoder。

讲解用伪代码 · AC3D 的稀疏层级与去噪阶段控制

for i, block in enumerate(main_dit.blocks):
    if i < 8 and diffusion_time >= 0.6:
        video_tokens = video_tokens + camera_feedback[i](
            video_tokens, camera_tokens[i])
    video_tokens = block(video_tokens, text_context)
# 不是在每一个 block、每一个去噪时刻都无差别强加控制。

8.4 CameraCtrl II：输入端一次注入 + 共享世界参考的长序列

论文 2503.10592骨干：约 3B 内部 DiT动态场景探索

与 AC3D 的“前 8 层”不同，CameraCtrl II 进一步简化到输入端：视频 latent 与每 4 帧采样的 Plücker 分别 patchify，然后直接相加，再进入全部 DiT。全部主干参数解冻，用有相机标注和无标注数据按 4:1 联合训练；无标注数据使用全零 Plücker，也支持相机 CFG。

ztokens = Patchifyvideo(zt) + Patchifycamera(P)(14)

多 clip 时，上一段的干净 token z0i 与当前 noisy token zti+1 沿序列拼接，二元 mask 区分条件与待生成区域，损失只算当前段。所有 clip 的相机都相对最初首帧，而不是各自重新以本段首帧归零，避免长轨迹参考系不断漂移。

没有唯一正确的注入层数。CameraCtrl 的多尺度时序融合、VD3D 的每层 FIT read、AC3D 的前 8 层、CameraCtrl II 的输入端一次注入分别对应不同基座和训练策略。选型应通过 probing / 消融，而不是把“少注入”当成普遍规则。

9. ReCamMaster：目标位姿驱动已有动态视频的重渲染

论文 2503.11647官方源码公开参考实现：Wan2.1-T2V-1.3B；提交 fcf98bc8输入：源视频 + 目标 [R|t]
先区分两套模型：论文使用内部预训练 T2V；公开仓库明确说迁移到 Wan2.1 是参考实现，效果可能不同。以下张量尺寸、30 层/1536 维、50 步、CFG=5 均指公开 Wan 实现，不能反推成论文内部模型配置。

9.1 为什么不只是 CameraCtrl + 一段视频

T2V/I2V 的相机控制只需生成合理内容；视频重渲染还必须保留源视频的角色外观、每一时刻的动作与背景。ReCamMaster 把条件写成 {Vs,camt,pt}：源视频、目标相机轨迹、目标提示词。目标输出既要换机位，又要与源动作同步。

论文将候选方案分为 channel-dim、view-dim 和 frame-dim。它选择 frame-dim：不是把源视频当作额外通道，也不是只加一个独立 view attention，而是让源/目标 token 在原有时空 self-attention 中直接交互。

9.2 公开实现的真实数据流

图 3：ReCamMaster 公开 Wan 实现。源段在整个去噪过程中保持 clean；scheduler 只使用目标段预测。拼接发生在 latent 时间轴，随后统一 patchify。

9.3 每个 block 如何读相机

每个 block 有自己的 cam_encoder 与 projector。公开初始化中 cam_encoder 全零、projector 为单位阵；训练开放 cam_encoder、projector、self_attn，其余主干和文本/FFN 等冻结。注意 projector 不是全零初始化。

同一套 21 帧目标相机会复制到源/目标两段，并未另送一套源轨迹。段身份主要由内容、拼接位置与时空 RoPE 体现。文本 CFG 的正负分支始终共享源视频与相机，不是移除相机的多条件 CFG。

9.4 轨迹预处理与训练监督

公开 JSON 是每帧 4×4 相机矩阵。代码只取像素帧 0,4,…,80，执行转置、轴重排、y 翻转与厘米到米的尺度变换，再转换为相对位姿并展开 [21,3,4]→[21,12]。推理以目标首帧为参考；公开训练则以源首帧为参考构造目标相对位姿。这是源码中必须保留的细节，不能把两者都概括成同一种“首帧归一化”。

训练从同一场景的 10 路同步相机随机选 source 与 target：目标加噪，源保持 clean，只对目标侧计算 flow matching MSE。UE5 数据的价值是同一动作时间戳下的多视角视频 + 精确外参，而不只是“合成图比较漂亮”。论文通过条件 latent 加噪、T2V/I2V 条件 dropout 提升真实视频鲁棒性；这些策略并未全部出现在当前公开 Wan 训练脚本中。

使用公开脚本时的边界：--cam_type 1..10 选择预设轨迹，脚本固定读取 example_test_data/cameras/camera_extrinsics.json，不是通用的任意轨迹上传 CLI。自定义轨迹需替换该 JSON 或修改读取逻辑，并遵守同一坐标转换与 21 帧采样约定。

10. GEN3C：位姿直接驱动 3D cache 渲染，而不是让网络猜视差

论文 2503.03751官方源码公开实现：Cosmos；提交 db2ffe12输入：w2c + K + RGB-D

10.1 核心转变：从条件回归到确定性几何 + 生成补全

纯位姿编码模型必须自己学会：这个像素在下一机位应该移到哪里、被遮挡后什么区域该出现。GEN3C 把其中可确定计算的部分交给传统几何：首图或已生成帧先估计深度，反投影成时空点云 cache；用户给出目标 w2c 和 K 后，直接渲染已知区域与可见性 mask。

Xw(u,v)=D(u,v)·Rc2wK−1[u,v,1]T+Cw(15)
(Iwarp, Mvalid) = Render(CacheRGB-D, Ttarget,w2c, Ktarget)(16)

扩散模型不再主要负责“算出相机对应的像素位移”，而是修复重投影伪影、补全 mask 之外的新区域、推进场景动态。它提升的是已观测结构的可控性与回看一致性；背面、遮挡后完全没有观测的内容依然需要生成先验。

图 4：GEN3C 的几何—生成闭环。相机轨迹不经过 Plücker MLP，而是先改变 cache 的投影结果；生成结果再估计深度、对齐并加入 cache。

10.3 cache 更新为什么不能只是追加点云

11. 扩展：导演布局、动态重定向与主体运动解耦

11.1 CineMaster：RT 相机与 3D box / 深度布局分开

论文 2502.086393D-aware T2VCamera Adapter + Layout ControlNet

CineMaster 的输入更接近导演工作台：在 3D 空间摆物体 box、指定相机移动，再把 3D box 经 Blender 投影成逐帧深度与语义布局。相机不是 Plücker，而是每 latent 帧的 RT∈R12，经 MLP 对齐 DiT token 维度后广播相加，并在 self-attention / temporal-attention 之间再次残差注入。

另一条 Semantic Layout ControlNet 复制前半部分 DiT blocks，把深度 latent 与按 entity mask 放置的类别 embedding 融合，再把 hidden states 加回主模型。独立 RT 的作用正是解除“box 在屏幕移动究竟来自相机还是物体”的歧义；但它没有跨帧重投影一致性损失，不能声称提供严格 3D 保证。推理只在 50 步中的前 25/15 步分别启用布局/相机，体现“先结构与运动、后细节”的思路。

讲解用伪代码 · 导演条件到视频条件

11.2 TrajectoryCrafter：确定性视角变换 + 源视频参考注意力

论文 2503.05638骨干：CogVideoX-Fun-5B单目动态视频重定向

它先用单目深度构建动态点云，再以源到目标的相对变换 Tir 重投影，得到渲染图与 mask。与 GEN3C 不同，模型额外保留一条源视频 reference token 流，避免在点云有孔洞时只能依赖粗糙渲染。

主 view token 由“渲染图 + mask 的 VAE latent + 噪声”形成；Ref-DiT 先处理 text/view，再以 view 为 Q、reference 为 K/V 做 cross-attention。视角变换由点云决定，外观与动作细节由源视频参考补充。

训练用双重再投影解决动态多视角数据稀缺：对单目视频随机变换 ΔT 投影出去，再用 ΔT−1 投回来，得到与原始目标对齐、但带孔洞的渲染条件；结合静态多视数据分阶段训练。它减少了对同步 4D 数据的依赖，但深度与投影误差仍然存在。

11.3 I2VControl-Camera：把位姿投影成像素点轨迹

论文 2411.06525骨干：MagicVideo-V2相机轨迹 + 主体运动强度

该方法在相机坐标系把视频运动展开为：

F(p,λ) = Rλp + tλ + G(p,λ)(17)

首项是相机导致的刚体变化，G 是主体非刚体运动。对首帧点云 Ω 做目标相机投影，得到稠密二维轨迹 Tλ=Π(RλΩ+tλ)；另用 |Ω|−1∫||∂G/∂λ||dp 表示主体运动强度。两者拼为 [T,3,H,W]，经卷积 adapter 对齐 token 尺寸，在 self-attention 前拼接，注意力后移除控制 token。

这样相机不再只是一个抽象位姿向量，而是显式指出“静态点应移动到哪个像素”；主体强度又避免为了遵循相机轨迹而把人物冻住。代价是需要 UniDepth 深度、SpatialTracker 轨迹和刚体拟合等预处理，开放场景中的深度/跟踪误差会影响条件。

12. 综合代码：一条可复用的位姿条件骨架

下面的代码把前面几个方法共有的步骤组织起来，用于写自己的模型或单元测试。它不是任何一个官方网络的替代品；真正接入时，应选择帧向量、Plücker、cache 渲染或源视频 token 之一，并按基座修改形状。

讲解用 PyTorch 骨架 · 从相机轨迹到条件视频扩散
class PoseConditionedVideoBlock(nn.Module):
    def __init__(self, dim, camera_dim=6, num_heads=8):
        super().__init__()
        self.norm = nn.LayerNorm(dim)
        self.temporal_attn = nn.MultiheadAttention(
            dim, num_heads, batch_first=True)
        # 教学示例：将逐像素相机特征投到视频 token 维度。
        self.camera_proj = nn.Linear(camera_dim, dim)
        nn.init.zeros_(self.camera_proj.weight)
        nn.init.zeros_(self.camera_proj.bias)

    def forward(self, video, camera):
        # video:  [(B·H·W), F, C]，同一空间位置的时序 token。
        # camera: [(B·H·W), F, camera_dim]，已经对齐到每个 token。
        h = self.norm(video)
        h = h + self.camera_proj(camera)
        attended = self.temporal_attn(h, h, h, need_weights=False)[0]
        return video + attended

# 主训练循环（epsilon 版本示意）
video_latent = vae.encode(video)                  # [B,C,F,h,w]
noise = torch.randn_like(video_latent)
noisy_latent = scheduler.add_noise(video_latent, noise, timestep)

rays = resize_and_align_to_blocks(rays, model.scales)
predicted_noise = model(noisy_latent, timestep, text, rays)

# 推理：相机几何只编码一次，循环里复用；不要把 target latent 编码进去。
camera_features = model.encode_camera(rays)
latent = torch.randn(latent_shape)
for timestep in scheduler.timesteps:
    pred = model(latent, timestep, text, camera_features)
    latent = scheduler.step(pred, timestep, latent).prev_sample
video = vae.decode(latent)

12.1 不同方法替换的是哪一部分

  • MotionCtrl：把逐像素 rays 换成每帧 12 维 RT，广播到空间位置；attention 内部用 Linear(C+12→C)。
  • CameraCtrl：encode_camera 是四尺度卷积 + temporal block，融合在 motion module 的第一次时序注意力 QKV。
  • VD3D / AC3D：把 rays patchify / 时间压缩成 token，用独立 cross-attention 支路读取。
  • GEN3C：不把 Plücker 送入网络，替换为 render_cache(target_w2c,K) 的 RGB+mask 条件。
  • ReCamMaster：额外把源视频干净 latent 与目标 noisy latent 沿时间轴拼接，且只优化目标半段。
最小可行实验建议

先用 Blender/UE 合成同一静态场景的同步多视角视频，固定 K 与单位；实现首帧相对 Plücker 和单层时序融合；确认旋转、平移与输入矩阵方向一致后，再加入动态主体、真实 SfM 数据与长时记忆。直接从真实单目大角度视频开始，会把坐标错误、深度错误、动态偏差与生成先验不足混在一起，难以定位。

13.1 从十二篇论文能可靠得出的结论

  1. Plücker 有用，但不是万能答案。CMG 的对比表明，条件维度、融合方式和 guidance 同样重要；不能简单说 RT 一定差、Plücker 一定好。
  2. 注入位置依骨干而变。CameraCtrl 在多个时序模块融合；VD3D 在每个 FIT read 处加并行支路；AC3D 只用前 8 层；CameraCtrl II 只在输入端一次注入。不要把某篇结论当作普遍定理。
  3. 几何一致性与控制精度不是同义词。轨迹对齐可以很好，但背面内容仍可能幻觉；显式 cache 能保留已见结构，却不能凭空知道未观测区域。
  4. 训练分布决定可控范围。RealEstate10K 多为静态场景，且大角度轨迹不足；同步动态多机位、静止相机动态内容和真实度量尺度分别解决不同偏差。
  5. 推理效率必须计入架构。双倍 token、多个 CFG 分支、逐层 cross-attention 与多次扩散步都会增加成本，论文中的精度优势不等于实时可用。

14. 自己实现时的完整检查清单

14.1 数据合同

  • 明确每个矩阵是 c2w 还是 w2c，采用列向量还是行向量，轴朝向和单位是什么。
  • 统一像素中心约定、图像 resize/crop 后的 K、逐帧 K 是否变化，以及首帧相对化公式。
  • 将相机采样时间、视频 VAE 时间压缩、DiT patchify 和 RoPE 坐标放在同一张 shape 表中核对。
  • 轨迹可视化时同时画相机中心、朝向与目标；只看二维路径无法发现朝向颠倒。
  • 在 batch 中保留有效帧 mask；可变长视频不要用 padding 的零位姿冒充真实静止相机。

14.2 模型与训练

  • 控制支路零初始化时，检查梯度路径是否真的可训练；不能仅因输出为零就认为整个支路无梯度。
  • 冻结主干时，逐项打印 trainable parameter 名称，避免把已有 motion module 误算为从零训练。
  • 为无条件文本、无条件相机、源视频 dropout 分别设计概率，明确每个 CFG 分支保留什么。
  • 若只用静态场景训练，加入静止相机 + 动态物体数据，或其他去偏机制，避免主体被冻结。
  • 先验证小位姿、已知深度/合成场景，再测试大角度、动态遮挡与尺度变化。
