核心问题

U-Net 有空间和时序分离的特征层，容易在多尺度 temporal module 插入 Plücker；SnapVideo 的 FIT 用压缩 latent 与视频 token 反复 cross-attention。VD3D 的关键是把几何条件放到这个 read 接口，而不是照搬 U-Net 的加法。

1. 先理解 FIT：视频 token 与 latent token 是两套状态

FIT 将高维视频 patch 压缩到较小的 latent 表示 z，再通过 cross-attention 读取完整视觉 token v。压缩 latent 内部做 self-attention，再读取/写回视觉信息。这样长视频的计算集中在较低维状态上。

因此，简单把 RT 加到文本 context 中会让相机和语义混在同一入口；VD3D 则把逐像素射线场变成与视频 patch 对齐的 camera token，并在 latent 读取视觉信息时增加一条几何支路。

2. 相机表示与时空 patch

每帧相机为 Cf=[Rf;tf] 和 Kf，先变换到首帧参考系，再为每个像素构造方向与 Plücker moment。整段得到 6×F×H×W 张量。

R′f=R1−1Rf，  t′f=tf−t1(1)
p̈f,u,v = [t′f×d̂f,u,v, d̂f,u,v] ∈ R6(2)

随后采用与视频相同的空间 patchify，使每个 camera token 对应相同的时空区域；两层 GELU MLP 将其投影到 Transformer 宽度。相机因此不只是全局运动标签，而是带有局部射线的几何 token。

公式核对：论文 HTML 的部分公式存在 K 与 K−1、归一化分母的排版不一致。实现逆投影时应从针孔模型重新推导，并在已知相机上验证，而不是机械照抄。

图 1：VD3D 把几何场变成 token，而非直接拼入文本。相机 token 与视觉上下文共同进入 read cross-attention；输出经零初始化残差保留原始生成能力。

3. 每个 FIT block 的并行相机支路

z′ = FF(XAttn(z,v)) + Convres(FFcam(XAttncam(z,ccam+v)))(3)

第一条是原预训练视觉支路；第二条由相机 token 和视觉 token 联合提供上下文，初始参数从对应预训练层复制。末尾 Convres 是零初始化一维卷积，使新增支路起初不扰动原输出。训练完成后，主 latent 再进入 FIT 的 self-attention。

这里“冻结基座”不等于整个训练没有梯度：新增 camera attention、FF 和融合模块仍通过视频扩散损失学习。论文称约 230M 参数在 4B 级模型上可训练，是低分辨率控制分支的规模，不是最终输出 upsampler 也接受相机。

讲解用实现 · 非官方源码：FIT 并行相机支路
class FITCameraRead(nn.Module):
    def __init__(self, pretrained_read, dim):
        super().__init__()
        self.visual_read = pretrained_read       # 冻结的原视觉支路
        self.camera_attn = copy.deepcopy(pretrained_read.attn)
        self.camera_ff = copy.deepcopy(pretrained_read.ff)
        self.residual_conv = nn.Conv1d(dim, dim, kernel_size=1)
        nn.init.zeros_(self.residual_conv.weight)
        nn.init.zeros_(self.residual_conv.bias)

    def forward(self, z, visual_tokens, camera_tokens):
        original = self.visual_read(z, visual_tokens)
        guided = self.camera_ff(
            self.camera_attn(z, camera_tokens + visual_tokens))
        delta = self.residual_conv(guided.transpose(1,2)).transpose(1,2)
        return original + delta
# 教学结构省略 RoPE、mask、norm 与 SnapVideo 的真实张量打包。

5. 3D 一致性的来源与限制

VD3D 没有 CamCo 的极线约束，也没有 GEN3C 的点云 cache。它依赖首帧归一化的像素射线、冻结的视频时空先验以及位姿—视频配对学习。因此可以说它提升相机可控性，但不能宣称提供严格多视角几何保证。

动态场景中，相机诱导运动与物体运动可能仍然耦合；大视角下未观测区域需要幻觉。冻结低分辨率主干有利于保持原视频质量，却也限制模型重新学习复杂几何的能力。

6. 实现自己的 DiT 相机支路

  1. 先画出视频 patch 网格与相机射线网格，保证 F、H、W 和时间压缩一致。
  2. 将 camera token 和 visual token 的位置编码分开核对；简单相加前必须同维、同位置语义。
  3. 用零初始化残差验证训练起点不改变原模型。
  4. 先冻结主干做相机回归，再评估是否需要开放时序注意力。
  5. 分别测量旋转误差、平移误差与画面质量，注意 SfM 尺度对齐。

7. 与 AC3D / CameraCtrl II 的差异

方法相机入口结构选择数据/训练特点
VD3DFIT read cross-attention 的并行支路每个 read 处渐进注入冻结基座，低分辨率训练
AC3D轻量 camera DiT + 主干反馈只在前 8/32 块、早期去噪控制高噪声偏置 + 静止相机动态数据

不能把 VD3D 的“每层 read”当作现代 DiT 的唯一标准；其有效性依赖 FIT 的具体接口。

附录 A：相机 token 接口的逐步检查

若一个视频 patch 覆盖 p×p 像素，则相机射线图也必须以同样的 p×p 网格分组。每个 patch 包含 6p² 个几何量，经线性/MLP 投影为 d 维 token；不能先对整幅 Plücker 图做全局平均，否则局部射线信息会消失。

在 read cross-attention 中，query 是压缩 latent z，而上下文包含视觉 token 与 camera token 的组合。实际实现要区分：query 长度决定输出 latent 数，key/value 长度决定上下文长度；相机支路不应把输出长度改成像素 token 数。零初始化 residual conv 的作用是在通道上映射并从一开始抑制新增支路。

论文的 36×64 与 288×512 是模型不同阶段的特征分辨率，不应直接理解为最终用户视频尺寸。训练相机控制时 upsampler 冻结，其输入是 base 的生成结果，不读取原始 Plücker；因此评估必须覆盖完整级联，而非只测 base。

代码 1：CameraPatchEncoder

CameraPatchEncoder · 与视频 patch 对齐（讲解用实现，非官方源码）
class CameraPatchEncoder(nn.Module):
    def __init__(self, patch_h, patch_w, dim, heads=8):
        super().__init__()
        self.patch_h, self.patch_w = patch_h, patch_w
        self.proj = nn.Sequential(
            nn.Linear(6*patch_h*patch_w, dim), nn.GELU(),
            nn.Linear(dim, dim), nn.GELU())
        self.attn = nn.MultiheadAttention(dim, heads, batch_first=True)
        self.ff = nn.Sequential(nn.Linear(dim,4*dim),nn.GELU(),nn.Linear(4*dim,dim))
        self.residual = nn.Conv1d(dim,dim,1)
        nn.init.zeros_(self.residual.weight)
        nn.init.zeros_(self.residual.bias)

    def forward(self, z, visual, plucker):
        # z: [B,Nz,D] latent query；visual: [B,Nv,D] FIT 视觉 token。
        # plucker: [B,F,6,H,W]；要求 H%patch_h=W%patch_w=0。
        B,F,C,H,W = plucker.shape
        p = plucker.reshape(B,F,C,H//self.patch_h,self.patch_h,
                            W//self.patch_w,self.patch_w)
        p = p.permute(0,1,3,5,2,4,6).reshape(B,-1,6*self.patch_h*self.patch_w)
        camera = self.proj(p)
        guided, _ = self.attn(z, camera + visual, camera + visual)
        guided = self.ff(guided)
        return self.residual(guided.transpose(1,2)).transpose(1,2)
# 主分支另算原 visual read；最终 original + 本模块输出。

附录 D：训练算法与梯度路径

在约 65K RealEstate10K 位姿视频上训练低分辨率 base 的相机支路，采用 EDM clean-video 回归，冻结原 SnapVideo 主干。论文给出约 50K steps、约 230M 可训练参数；高分辨率 upsampler 冻结且不加相机。其补充材料含核心相机 FIT block，不等于本文核验了完整公开训练 pipeline。

读代码时的关注点：代码 1 展示怎样将 6p×p 的射线 patch 映射到相机 token，并在 read cross-attention 中形成独立残差；代码 2 展示冻结基座、EDM 加噪和只反传到相机支路。实际 FIT 还有 latent/视觉位置编码、压缩 token 打包与预处理，教学实现故意不伪造这些接口。

附录 E：显式位姿推理流程

从 noisy latent 出发，每个 FIT block 先执行原视觉 read，再计算 camera attention/FF 与零初始化残差，将二者相加后做 latent self-attention。完成 base 生成后交给高分辨率 upsampler。相机条件在采样中持续存在，但不是在每个像素上执行显式渲染。

推理前要明确：位姿是 c2w 还是 w2c、是否首帧相对、K 是否像素单位、帧率是否经过 VAE 压缩，以及 unconditional 分支采用哪一种空相机。只把这些数值变成合法 shape 不足以保证几何正确。
