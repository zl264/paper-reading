01Wan 2.1 是什么

一句话：Wan 2.1 是阿里巴巴通义实验室于 2025 年 2 月开源的「视频生成基础模型套件」，也是业界首个功能完备的 SOTA 级开源视频生成模型——文生视频、图生视频、视频编辑、文生图一应俱全。

1.1 基本事实

  • 发布时间：2025 年 2 月 25 日开源，采用 Apache 2.0 协议（商用友好）。
  • 名字含义：Wan（万）取自「通义万相」，是通义实验室的多模态生成品牌。
  • 核心能力：文字生成视频（T2V）、图片生成视频（I2V）、首尾帧生成（FLF2V）、全能视频编辑（VACE）、文字生成图片（T2I）。支持中英双语提示词，并且是当时少数能生成可读中文字符的视频模型（14B 版本）。
  • 消费级可用：1.3B 模型只需 8.19 GB 显存（约等于一张 RTX 4090 的一半），即可生成 480P、5 秒（81 帧、16 fps）的视频，单卡约 4 分钟一条——这是它出圈的最重要原因。
  • 成绩：发布时在 VBench（视频生成综合基准）上排名第一，超过同时期的多个闭源模型；在美学质量、运动幅度、指令遵循上均有口碑。

1.3 三大组件（先混个眼熟）

整个系统只有三个模型，职责清晰，后面每一章会分别拆开讲：

  • Wan-VAE：3D 因果卷积自编码器，把视频在「时间×高×宽」上压缩 4×8×8 倍，搬进潜空间（第 4 章）；

  • umT5-XXL + CLIP：文本编码器（约 5.7B，多语种）与图像编码器（图生视频用）（第 6 章）。

02原理预备：潜空间扩散与 Flow Matching

Wan 2.1 没有发明全新的范式，而是把近两年验证过的最佳实践组合到了工业级水准：潜空间扩散（Latent Diffusion）+ Flow Matching 训练目标 + DiT 主干。这一章把这些积木一块块讲清楚。

2.1 视频生成的两座大山

直接用扩散模型生成视频，有两个绕不开的问题：

  • 数据量爆炸。一段 5 秒 832×480、每秒 16 帧的视频，原始张量是 3 × 81 × 480 × 832 ≈ 9600 万个像素值。对这样的张量直接做注意力，算力和显存都不可承受。
  • 时空一致性。视频不只是「多张图」——物体形状、光照、运动轨迹在帧间必须连贯，否则就是闪烁的幻灯片。模型需要同时建模时间维与空间维的关系。

Wan 的回答分别是：Wan-VAE（把数据压小 256 倍）与3D 时空联合建模的 DiT（时间、空间 token 放在一起做注意力，配 3D RoPE 编码位置）。

2.2 潜空间扩散：先把世界压小 256 倍

思路与 Stable Diffusion 一致：训练一个 VAE 自编码器，encoder 把视频压成低维 latent，decoder 能还原。扩散过程完全发生在 latent 空间里，只在最后一步 decode 回像素。

Wan-VAE 的压缩率是 4 × 8 × 8（时间 × 高 × 宽）：

视频 3 × 81 × 480 × 832 → VAE encode → latent 16 × 21 × 60 × 104 体积缩小 4×8×8 = 256 倍，通道变为 16
  • 时间维只压 4 倍（且只下采样一次）：运动连贯性对时间分辨率极敏感，压太狠会掉帧感明显。81 帧压到 21 个 latent 帧，满足 帧数 = 4n+1 的对齐要求。
  • 空间维各压 8 倍：与 SD 一致，是「性价比」最好的档位。Wan 团队试过 16 倍空间压缩（如 MAGVIT-v2、Cosmos 的做法），训练变快，但重建质量与生成保真度都会受损。
  • 因果（causal）设计：所有卷积在时间维上只看过去不看未来，这是为了能分块处理长视频（详见第 4 章），1080P 任意长度也能编解码。

2.3 从 DDPM 到 Flow Matching：换一条更直的路

经典 DDPM 的思路是「逐步加噪→学会逐步去噪」，训练时预测的是噪声 ε；路径是弯的（方差调度决定的曲线），推理要走几百上千步。Wan 采用 Flow Matching：网络不再预测噪声，而是预测一个速度场——把噪声「搬运」到数据方向的向量场。

训练时的构造极其简单。设 x₁ 是真实视频 latent（数据），x₀ 是一个标准高斯噪声，直接在两点之间做线性插值：

xt = (1 − t) · x0 + t · x1，   t ∈ [0, 1] t=0 时是纯噪声，t=1 时是纯数据，中间是直线

模型要学的目标——沿这条直线从噪声指向数据的速度向量——也是平凡解：

v* = x1 − x0 对每条插值路径而言都是常向量；训练损失就是让 vθ(xt, t) 逼近它
LFM = Ex₁, x₀, t [ ‖ vθ(xt, t) − (x1 − x0) ‖² ]

推理时从纯噪声出发，沿模型预测的速度场做 ODE 积分走回数据。因为训练路径是直线，ODE 数值求解误差小，几十步就能收敛（Wan 默认 50 步），而传统 DDPM 弯曲路径需要上百步。

图 2-1 左：Flow Matching 的线性插值路径与速度目标；右：timestep shift 重参数化——同样的步数预算被集中到高噪声（结构成形）阶段。曲线按公式 σ = s·t/(1+(s−1)t) 精确绘制。

2.4 时间步怎么采样：logit-normal + shift

训练时，t 不是从 [0,1] 均匀抽取，而是用 logit-normal 分布（先采样标准正态 u，再 t = sigmoid(u)）——让 t 集中在中间段，模型在「最难学的半噪半净」区域获得更多训练信号。这是 SD3、Flux 一脉相承的做法。

推理时则做 timestep shift：把均匀的噪声调度做一次非线性重参数化，等效于把积分步数搬到高噪声区段：

t′ = s · t / (1 + (s − 1) · t) s 即 shift 参数。Wan 训练用 s=5，推理默认也是 5.0（480P I2V 用 3.0，FLF2V/VACE 用 16，1.3B 官方建议 8~12）

直觉解释：视频与图片不同，构图、主体、大运动这类低频结构在高噪声阶段成形，如果步数均匀分配，结构还没长好就进入细化阶段。shift 把步数往前挪（上图中 s=5 时前 50% 的时间轴覆盖了 83% 的噪声区间），先生骨架再长细节。开源代码里的对应实现非常短（推理侧）：

wan/utils/fm_solvers.pyPython
def get_sampling_sigmas(sampling_steps, shift):
    # 在 [0,1] 上均匀取 steps 个点（含端点 1，不含端点 0）
    sigma = np.linspace(1, 0, sampling_steps + 1)[:sampling_steps]
    # timestep shift：与训练时的重参数化同式，s 越大步数越向前（高噪声）集中
    sigma = (shift * sigma / (1 + (shift - 1) * sigma))

    return sigma

2.5 无分类器引导（CFG）

和所有现代扩散模型一样，推理时每一步同时做两次前向：一次带真实提示词（条件），一次带默认负向提示词（无条件）。最终预测在两者之间「外推」，放大文本的控制力：

vcfg = vuncond + w · (vcond − vuncond) w 即 guide_scale，Wan 默认 5.0；太低文本不理你，太高画面过饱和、动作过猛

Wan 的负向提示词是官方调好的一段中文长句（写在 shared_config.py 里，无需自己发明），I2V 模型还会额外加上「镜头晃动」前缀来稳定首帧衔接：

2.6 把训练写成代码（示意实现）

注意：官方仓库只开源了推理代码

Wan2.1 仓库不包含训练脚本（wan/distributions 等训练模块已在开源前移除）。下面的最小训练循环是按技术报告公式复现的示意实现，用于理解原理，非官方代码。

flow_matching_training.py（示意，非官方代码）Python
import torch

def lognormal_t(batch_size, eps=1e-5):
    # logit-normal 时间步采样：u ~ N(0,1)，t = sigmoid(u)
    u = torch.normal(0.0, 1.0, size=(batch_size,))
    t = torch.sigmoid(u)
    return t.clamp(eps, 1 - eps)

def shift_t(t, s=5.0):
    # 训练侧的 timestep shift（与推理侧 get_sampling_sigmas 同一公式）
    return s * t / (1 + (s - 1) * t)

# ---------------- 训练单步 ----------------
B = 8
x1 = vae.encode(batch_videos)                 # 真实视频 latent: (B, 16, 21, 60, 104)
x0 = torch.randn_like(x1)                     # 高斯噪声（与 x1 同形状）
t = shift_t(lognormal_t(B))                   # 采样时间步，并做 shift 重参数化

xt = (1 - t[:, None, None, None]) * x0 + t[:, None, None, None] * x1   # 线性插值
target = x1 - x0                              # 目标速度场：沿直线指向数据

pred = dit(xt, t, context=text_features)      # DiT 前向，预测速度 v
loss = torch.nn.functional.mse_loss(pred, target)
loss.backward()                               # 如此反复，直到收敛

训练完成后，推理就是「从噪声出发、沿学到的速度场积分」：WanT2V.generate()（第 8 章）里的那个 for t in timesteps 循环 + sample_scheduler.step() 干的就是这件事。

为什么帧数必须是 4n+1？

时间维被 VAE 压 4 倍：81 帧 → (81−1)/4+1 = 21 个 latent 帧（首帧单独一块，之后每 4 帧一块）。所以 frame_num 必须满足 4n+1（81 = 4×20+1 ≈ 16fps 下 5 秒）。720P 时 75,600 个 token 的自注意力是显存大头——这也是 Wan 需要序列并行（第 9 章）的原因。

04Wan-VAE：3D 因果自编码器

VAE 是整个系统的「坐标系」：它决定了 latent 空间的形状、压缩率和视频能有多长。Wan-VAE 的两个关键词是「3D」（时空联合压缩）与「因果」（可以流式分块处理），全部实现在 wan/modules/vae.py（662 行）。

4.1 设计目标：压缩率的权衡

技术报告里明确做过对比：把空间压缩率提到 16×（如 MAGVIT-v2、Cosmos 等高压缩路线）确实能让 DiT 训练更快、序列更短，但会损失重建保真度，生成结果的「纹理与文字清晰度」也跟着受损。Wan 选择保守的 4×8×8：

  • 时间 4×：由两次「3D 下采样」各 2× 得到，只压一次。官方验证过更高时间压缩会明显破坏运动平滑度；
  • 空间 8×：由三次下采样各 2× 得到，与 SD 系 VAE 一致；
  • 重建质量：在相同压缩率下，Wan-VAE 的重建指标优于 CogVAE（CogVideoX 所用 VAE）等已被广泛使用的开源视频 VAE。

→ 阶段1 2×ResBlock(96→192) + downsample2d（空间 ÷2） → 阶段2 2×ResBlock(192→384) + downsample3d（时间 ÷2、空间 ÷2）
→ 阶段3 2×ResBlock(384) + downsample3d（时间 ÷2、空间 ÷2） → 阶段4 2×ResBlock(384)（不再下采样）
→ 瓶颈 ResBlock + 单头空间注意力 + ResBlock → head RMS_norm + SiLU + CausalConv3d(384→32) 32 = z_dim×2，随后拆成 mu 与 log_var

解码器（Decoder3d）严格对称：temperal_upsample=[True,True,False] 是下采样表的反转；每个阶段 3 个残差块（比编码器多 1 个，用于吸收跳连宽度），上采样顺序为先两次 upsample3d 再一次 upsample2d。

4.3 核心积木：CausalConv3d（时间因果卷积）

「因果」指时间维上只看过去、不看未来：普通 Conv3d 需要看下一帧才能算当前帧的输出，这对在线/长视频场景不可用。实现方式很聪明——把时间维的 padding 全部挪到前侧（且翻倍），后侧补 0：

wan/modules/vae.pyPython
class CausalConv3d(nn.Conv3d):
    """
    Causal 3d convolusion.
    """

    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        # 官方 Conv3d 的三段 padding (t,h,w) 重排成 F.pad 的五段格式
        # (w左, w右, h上, h下, t前, t后)：时间维前侧 padding 翻倍、后侧为 0
        # —— 这样卷积窗口永远够不到「未来帧」，即时间因果
        self._padding = (self.padding[2], self.padding[2], self.padding[1],
                         self.padding[1], 2 * self.padding[0], 0)
        self.padding = (0, 0, 0)     # 关掉 PyTorch 内部 padding，forward 里手动 pad

    def forward(self, x, cache_x=None):
        padding = list(self._padding)
        if cache_x is not None and self._padding[4] > 0:
            # 分块模式：先把上一块缓存的最后 2 帧拼在当前块前面（历史上下文），
            # 再用历史帧「抵扣」一部分前侧 padding —— 分块结果与整段一次算完全一致
            cache_x = cache_x.to(x.device)
            x = torch.cat([cache_x, x], dim=2)
            padding[4] -= cache_x.shape[2]
        x = F.pad(x, padding)

        return super().forward(x)

网络中每个 CausalConv3d 都支持 cache_x 参数——这就是分块编解码的全部基础设施：所有卷积都缓存自己「看到的最后 2 帧」（CACHE_T=2），下一个块把这 2 帧拼回来，等效于无缝续算。

4.4 时间上 / 下采样：Resample 的交错插帧

空间维的升降采样用普通的最近邻 + 卷积即可，时间维的 2× 升采样则用了一个「交错」技巧：upsample3d 里先用一个 (3,1,1) 的因果卷积把通道数翻倍，再 reshape 成两路、在时间轴上交错排列，得到帧率翻倍的结果：

4.5 分块编解码：无限长视频的秘密

因果卷积 + 帧缓存带来的能力是流式处理：编码时视频按「1 + 4 + 4 + 4 + …」切块，解码时每次只送 1 个 latent 帧（首块产出 1 帧，其后每块产出 4 帧）。显存占用与视频总长无关，Wan 因此能直接编解码 1080P 任意长度的视频：

图 4-1 分块因果解码：每个 latent 帧独立送入 decoder，首块产出 1 帧、其后每块产出 4 帧；块间只传递每层卷积的最后 2 帧缓存。因此编解码的显存开销是 O(1)，与视频长度无关。

代码中这两段循环是整个机制的「调度层」：

wan/modules/vae.py · WanVAE_.encode / decodePython
def encode(self, x, scale):
    self.clear_cache()                  # 每次调用前清空所有卷积的特征缓存
    t = x.shape[2]
    iter_ = 1 + (t - 1) // 4           # 块数 = 1 + (帧数-1)/4
    ## 对encode输入的x，按时间拆分为1、4、4、4....
    for i in range(iter_):
        self._enc_conv_idx = [0]        # feat_idx：本次调用内的卷积计数器
        if i == 0:
            out = self.encoder(         # 第 0 块：只有 1 帧
                x[:, :, :1, :, :],
                feat_cache=self._enc_feat_map,
                feat_idx=self._enc_conv_idx)
        else:
            out_ = self.encoder(        # 其余块：各 4 帧，边走边读写 feat_cache
                x[:, :, 1 + 4 * (i - 1):1 + 4 * i, :, :],
                feat_cache=self._enc_feat_map,
                feat_idx=self._enc_conv_idx)
            out = torch.cat([out, out_], 2)   # latent 在时间维上拼接
    mu, log_var = self.conv1(out).chunk(2, dim=1)   # 32 通道 → (mu, log_var)
    mu = (mu - scale[0]) * scale[1]    # 逐通道标准化，见 4.6 节
    self.clear_cache()
    return mu

def decode(self, z, scale):
    self.clear_cache()
    z = z / scale[1] + scale[0]         # 先做标准化的逆变换
    iter_ = z.shape[2]                  # 逐个 latent 帧解码（不按块）
    x = self.conv2(z)
    for i in range(iter_):
        self._conv_idx = [0]
        if i == 0:
            out = self.decoder(         # 第 1 帧 latent → 1 个像素帧
                x[:, :, i:i + 1, :, :],
                feat_cache=self._feat_map, feat_idx=self._conv_idx)
        else:
            out_ = self.decoder(        # 之后每个 latent 帧 → 4 个像素帧
                x[:, :, i:i + 1, :, :],
                feat_cache=self._feat_map, feat_idx=self._conv_idx)
            out = torch.cat([out, out_], 2)
    self.clear_cache()
    return out
为什么首块特殊？

时间维下采样是 4×，序列必须从「第 1 帧」开始对齐：首块 1 帧 + 后续每块 4 帧的切法，保证每个 4 帧块在时间下采样后恰好收缩为 1 个 latent 帧，且边界处由缓存衔接、无缝等价。这就是帧数必须为 4n+1 的底层原因。

5.1 先看积木：WanAttentionBlock 的解剖

def sinusoidal_embedding_1d(dim, position):
    # dim = 256（freq_dim），position 即 t 张量
    assert dim % 2 == 0
    half = dim // 2
    position = position.type(torch.float64)        # 用 fp64 保证大 t 值的精度

    # calculation：外积得到 [B, 128]，再拼 cos / sin → [B, 256]
    sinusoid = torch.outer(
        position, torch.pow(10000, -torch.arange(half).to(position).div(half)))
    x = torch.cat([torch.cos(sinusoid), torch.sin(sinusoid)], dim=1)
    return x

每个块拿到共享的 e0 [B,6,dim] 后，与自身偏置相加、切成 6 份（chunk(6, dim=1)），按下标各司其职——注意整段计算被强制在 float32 下执行（调制与归一化对精度敏感，bfloat16 容易发飘）：

wan/modules/model.py · WanAttentionBlock.forward（完整）Python
def forward(self, x, e, seq_lens, grid_sizes, freqs, context, context_lens):
    assert e.dtype == torch.float32
    with amp.autocast(dtype=torch.float32):
        # 每层独立偏置 + 全局共享的 6×dim 调制量 → 切成 6 份
        e = (self.modulation + e).chunk(6, dim=1)
    assert e[0].dtype == torch.float32

    # self-attention
    y = self.self_attn(
        self.norm1(x).float() * (1 + e[1]) + e[0],    # e1: scale, e0: shift
        seq_lens, grid_sizes, freqs)
    with amp.autocast(dtype=torch.float32):
        x = x + y * e[2]                              # e2: 门控（gated residual）

    # cross-attention & ffn function
    def cross_attn_ffn(x, context, context_lens, e):
        # 交叉注意力：普通残差，无门控；norm3 即 cross_attn_norm 开启时的额外 LayerNorm
        x = x + self.cross_attn(self.norm3(x), context, context_lens)
        y = self.ffn(self.norm2(x).float() * (1 + e[4]) + e[3])  # e4: scale, e3: shift
        with amp.autocast(dtype=torch.float32):
            x = x + y * e[5]                          # e5: 门控
        return x

    x = cross_attn_ffn(x, context, context_lens, e)
    return x
为什么门控残差重要？

各层的 modulation 以 randn / √dim 的量级初始化（近似 0），意味着训练刚开始时 e₂/e₅ 接近 0，每个块近似恒等映射；加上输出头零初始化（5.6 节），整张网络初始输出为 0。这让 30/40 层的深 Transformer 能稳定起步，是 DiT 系模型的标准技巧。

5.3 3D RoPE：时间 / 高 / 宽的联合位置编码

自注意力的 token 来自一个 (F, H, W) = (21, 30, 52) 的三维网格，模型必须知道每个 token 「在时间第几格、空间第几行第几列」。Wan 用旋转位置编码（RoPE）的 3D 扩展：把每个头的 128 维拆成 64 对共轭频率，再切成三段分给三个坐标轴：

head_dim 128 → 64 个频率对 → 切分 [22, 21, 21] → 时间 t：22 对 · 高 h：21 对 · 宽 w：21 对 22×2 + 21×2 + 21×2 = 128 维，恰好占满

RoPE 的原理：把每对维度看作复平面上的一个向量，按位置乘以不同频率的旋转角。两向量旋转相同角度再求内积，结果只依赖相对位置差——注意力于是天然具备平移等变性。频率表在模型初始化时生成一次：

wan/modules/model.py · 频率表生成与应用Python
@amp.autocast(enabled=False)
def rope_params(max_seq_len, dim, theta=10000):
    # dim 是「频率对数」；每个坐标位置生成 dim 个不同频率的旋转角
    freqs = torch.outer(
        torch.arange(max_seq_len),
        1.0 / torch.pow(theta,
                        torch.arange(0, dim, 2).to(torch.float64).div(dim)))
    freqs = torch.polar(torch.ones_like(freqs), freqs)   # 转成 e^{iθ} 复数形式
    return freqs

@amp.autocast(enabled=False)
def rope_apply(x, grid_sizes, freqs):
    n, c = x.size(2), x.size(3) // 2     # n = 头数，c = 每头频率对数（= head_dim/2 = 64）

    # 按三维坐标切分频率：[c-2*(c//3), c//3, c//3] = [22, 21, 21] → (t, h, w)
    freqs = freqs.split([c - 2 * (c // 3), c // 3, c // 3], dim=1)

    # loop over samples（batch 内逐个样本处理，天然支持不同分辨率）
    output = []
    for i, (f, h, w) in enumerate(grid_sizes.tolist()):
        seq_len = f * h * w

        # 把每对维度视为复数：[..., 2] → complex
        x_i = torch.view_as_complex(x[i, :seq_len].to(torch.float64).reshape(
            seq_len, n, -1, 2))
        # 每个token 的 (t,h,w) 三段频率广播拼接 → [seq_len, 1, 64]
        freqs_i = torch.cat([
            freqs[0][:f].view(f, 1, 1, -1).expand(f, h, w, -1),
            freqs[1][:h].view(1, h, 1, -1).expand(f, h, w, -1),
            freqs[2][:w].view(1, 1, w, -1).expand(f, h, w, -1)
        ],
                            dim=-1).reshape(seq_len, 1, -1)

        # 复数乘法 = 按位置旋转
        x_i = torch.view_as_real(x_i * freqs_i).flatten(2)
        x_i = torch.cat([x_i, x[i, seq_len:]])    # padding 段不旋转
        output.append(x_i)
    return torch.stack(output).float()

5.4 自注意力：QK-RMSNorm + 变长 FlashAttention

def forward(self, x, seq_lens, grid_sizes, freqs):
    # x: [B, L, num_heads, head_dim]
    b, s, n, d = *x.shape[:2], self.num_heads, self.head_dim

    # query, key, value function
    def qkv_fn(x):
        q = self.norm_q(self.q(x)).view(b, s, n, d)   # Q 做 RMSNorm
        k = self.norm_k(self.k(x)).view(b, s, n, d)   # K 做 RMSNorm（V 不做）
        v = self.v(x).view(b, s, n, d)
        return q, k, v

    q, k, v = qkv_fn(x)

    x = flash_attention(
        q=rope_apply(q, grid_sizes, freqs),           # 仅 Q/K 旋转
        k=rope_apply(k, grid_sizes, freqs),
        v=v,
        k_lens=seq_lens,                              # 变长序列：真实长度
        window_size=self.window_size)                 # (-1,-1) = 全局注意力

    # output
    x = x.flatten(2)
    x = self.o(x)
    return x

两个工程细节值得注意：

  • QK-RMSNorm（qk_norm=True）：对 Q、K 各做一次 RMS 归一化。深 Transformer 中 QK 内积的方差会逐层放大，导致注意力饱和（所有 token 权重趋同）；归一化后分数分布稳定，训练显著更稳。SD3、Flux 同款。
  • 变长注意力：batch 内不同样本 token 数不同（如不同分辨率），先 pad 到 seq_len 送进模型，但 flash_attention 内部会按 k_lens 把真实数据紧凑拼接、构造 cu_seqlens 分段表，交给 FlashAttention 的 varlen kernel——padding 段不参与计算，白给的显存与算力都省下来：

5.5 交叉注意力：文本（与图像）如何注入

T2V 版本最朴素——Q 来自视频流，K/V 来自文本 context，一个头也不落地交叉一遍：

wan/modules/model.py · WanT2VCrossAttention.forward（完整）Python
def forward(self, x, context, context_lens):
    b, n, d = x.size(0), self.num_heads, self.head_dim

    # compute query, key, value
    q = self.norm_q(self.q(x)).view(b, -1, n, d)          # Q ← 视频流
    k = self.norm_k(self.k(context)).view(b, -1, n, d)    # K ← 文本
    v = self.v(context).view(b, -1, n, d)                 # V ← 文本

    # compute attention
    x = flash_attention(q, k, v, k_lens=context_lens)

    # output
    x = x.flatten(2)
    x = self.o(x)
    return x

I2V / FLF2V 模型换成 WanI2VCrossAttention：双分支结构，图像 CLIP token 与文本 token 各算一路注意力后相加。判断依据很简单——context 长度减去文本固定 512，多出来的就是 CLIP token（单图 257 个，首尾帧 514 个）：

def forward(self, x, context, context_lens):
    image_context_length = context.shape[1] - T5_CONTEXT_TOKEN_NUMBER
    context_img = context[:, :image_context_length]   # 前 257×n 个 token：CLIP 图像特征
    context = context[:, image_context_length:]       # 其余：umT5 文本特征
    b, n, d = x.size(0), self.num_heads, self.head_dim

    # compute query, key, value（文本分支 + 图像分支各一套 K/V 投影）
    q = self.norm_q(self.q(x)).view(b, -1, n, d)
    k = self.norm_k(self.k(context)).view(b, -1, n, d)
    v = self.v(context).view(b, -1, n, d)
    k_img = self.norm_k_img(self.k_img(context_img)).view(b, -1, n, d)
    v_img = self.v_img(context_img).view(b, -1, n, d)
    img_x = flash_attention(q, k_img, v_img, k_lens=None)   # 图像分支
    # compute attention
    x = flash_attention(q, k, v, k_lens=context_lens)       # 文本分支

    # output：两路注意力结果直接相加
    x = x.flatten(2)
    img_x = img_x.flatten(2)
    x = x + img_x
    x = self.o(x)
    return x

为什么图像条件走独立分支而不拼进文本？技术报告的消融显示：CLIP 视觉特征与 T5 文本特征分布差异大，「双分支再相加」比「直接拼接」在首帧保真度上更优。

5.7 WanModel.forward：把一切串起来

一次完整前向：条件拼接 → patchify → 统一 padding → 时间/文本/CLIP 嵌入 → 逐层堆叠 → 输出头 → unpatchify：

def forward(self, x, t, context, seq_len, clip_fea=None, y=None):
    # x: List[[C, F, H, W]]，t: [B]，context: List[[L, 4096]]，y: 条件视频（I2V）
    if self.model_type == 'i2v' or self.model_type == 'flf2v':
        assert clip_fea is not None and y is not None

    if y is not None:
        # I2V：噪声 x 与条件 y 在「通道维」拼接（16 + 20 = 36 通道）
        x = [torch.cat([u, v], dim=0) for u, v in zip(x, y)]

    # embeddings
    x = [self.patch_embedding(u.unsqueeze(0)) for u in x]   # Conv3d(1,2,2) 切 patch
    grid_sizes = torch.stack([                              # 每个 sample 的 (F,H,W)
        torch.tensor(u.shape[2:], dtype=torch.long) for u in x])
    x = [u.flatten(2).transpose(1, 2) for u in x]           # → [1, L, dim]
    seq_lens = torch.tensor([u.size(1) for u in x], dtype=torch.long)
    assert seq_lens.max() <= seq_len
    x = torch.cat([                                        # 批内 pad 到统一 seq_len
        torch.cat([u, u.new_zeros(1, seq_len - u.size(1), u.size(2))], dim=1)
        for u in x
    ])

    # time embeddings：t → 正弦 256 → MLP → 6×dim（fp32）
    with amp.autocast(dtype=torch.float32):
        e = self.time_embedding(
            sinusoidal_embedding_1d(self.freq_dim, t).float())
        e0 = self.time_projection(e).unflatten(1, (6, self.dim))

    # context：文本 4096 → dim，pad 到 text_len=512
    context = self.text_embedding(
        torch.stack([
            torch.cat([u, u.new_zeros(self.text_len - u.size(0), u.size(1))])
            for u in context
        ]))

    if clip_fea is not None:            # I2V/FLF2V：CLIP token 投影后拼在最前面
        context_clip = self.img_emb(clip_fea)   # bs × 257 (×2) × dim
        context = torch.concat([context_clip, context], dim=1)

    # arguments
    kwargs = dict(e=e0, seq_lens=seq_lens, grid_sizes=grid_sizes,
                  freqs=self.freqs, context=context, context_lens=None)

    for block in self.blocks:           # 30 / 40 层
        x = block(x, **kwargs)

    # head + unpatchify
    x = self.head(x, e)
    x = self.unpatchify(x, grid_sizes)
    return [u.float() for u in x]

最后一步 unpatchify 用一个爱因斯坦求和把维度从「(F,H,W) 网格 × (p,q,r) patch 内偏移 × C 通道」重排回标准视频布局，再用 reshape 把 patch 维度并回空间维：

wan/modules/model.py · unpatchifyPython
def unpatchify(self, x, grid_sizes):
    c = self.out_dim
    out = []
    for u, v in zip(x, grid_sizes.tolist()):
        # [L, 64] → (F, H, W, p, q, r, C)，去掉 padding 段
        u = u[:math.prod(v)].view(*v, *self.patch_size, c)
        u = torch.einsum('fhwpqrc->cfphqwr', u)     # 维度重排成视频布局
        u = u.reshape(c, *[i * j for i, j in zip(v, self.patch_size)])
        out.append(u)                              # → [16, 21, 60, 104]
    return out
einsum 在做什么？

'fhwpqrc→cfphqwr' 只做维度换位不做乘加：把 (F,H,W) 网格坐标、(p,q,r) patch 内偏移、C 通道按「通道优先、网格与 patch 偏移交错（h 与 q 相邻、w 与 r 相邻）」的顺序重排——恰好是 reshape 成 [C, F, H·p, W·r] 之前需要的内存布局。patch 化与还原零损耗，整个 DiT 是一个纯粹的「token 世界」。

06文本与图像编码器：umT5 与 CLIP

DiT 本身是个「聋子」——它不认识汉字，也看不见像素，只认识浮点矩阵。所以提示词和参考图必须先被翻译成它听得懂的「语言」。这一章讲两个翻译官：把文字翻译成矩阵的 umT5-XXL，和把图片翻译成矩阵的 CLIP 视觉塔。

6.1 两种「语言」，两个编码器

回顾第 3 章的流水线图，进入 DiT 的条件有两路：

提示词「一只猫在弹钢琴」文本路径 → umT5-XXL 编码器 → [≤512, 4096] 经 text_embedding 投影到 dim，作为交叉注意力 K/V
参考图像（仅 I2V/FLF2V）图像路径 → CLIP ViT-H 视觉塔 → [257, 1280] 经 MLPProj 投影到 dim，前置拼到 context 里

两路信息最后汇成同一个 context 张量，从第 40 层交叉注意力进入 DiT——模型完全不知道也不关心某段 embedding 来自文字还是图片。这是「条件注入」最干净的实现方式。

6.2 umT5-XXL：被「砍掉后半身」的多语种大模型

T5 家族的原始形态是「编码器 + 解码器」的序列到序列模型（翻译、摘要这类任务需要解码器逐词生成）。Wan 只需要「理解」提示词，不需要它生成文字，于是只保留了编码器塔——参数量直接砍半，推理也更快：

6.3 读 t5.py 源码：与标准 Transformer 的四处不同

T5 系模型与教科书 Transformer 有几处著名差异，读源码时如果不注意会一头雾水。

（1）LayerNorm 用的是 RMSNorm，且没有偏置、没有均值中心化——只除以均方根再乘可学习权重：

wan/modules/t5.py · T5LayerNormPython
class T5LayerNorm(nn.Module):

    def __init__(self, dim, eps=1e-6):
        super(T5LayerNorm, self).__init__()
        self.dim = dim
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))   # 只有缩放，没有偏移

    def forward(self, x):
        # RMSNorm：不做均值减法，直接除以均方根（先升 float32 保精度）
        x = x * torch.rsqrt(x.float().pow(2).mean(dim=-1, keepdim=True) +
                            self.eps)
        if self.weight.dtype in [torch.float16, torch.bfloat16]:
            x = x.type_as(self.weight)
        return self.weight * x

（2）FFN 是门控的（GeGLU 变体）——两条并行投影，一条过 GELU 当「门」，逐元素相乘后再降维。这比普通 FFN 表达力更强，参数量反而省（同样的计算量下宽度更大）：

wan/modules/t5.py · T5FeedForwardPython
class T5FeedForward(nn.Module):

    def __init__(self, dim, dim_ffn, dropout=0.1):
        super(T5FeedForward, self).__init__()
        self.dim = dim
        self.dim_ffn = dim_ffn

        # layers
        self.gate = nn.Sequential(nn.Linear(dim, dim_ffn, bias=False), GELU())
        self.fc1 = nn.Linear(dim, dim_ffn, bias=False)
        self.fc2 = nn.Linear(dim_ffn, dim, bias=False)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        x = self.fc1(x) * self.gate(x)      # 门控：值路 × 激活路
        x = self.fc2(x)
        x = self.dropout(x)
        return x

（3）注意力打分不除以 √d。T5 发现在自己的缩放体系下省掉这一步效果更好（注释也明说了）：

三个工程细节值得注意：其一，返回的是「变长列表」——每个样本只保留有效 token，padding 从不进入 DiT 的注意力（DiT 内部会重新 pad 到统一的 seq_len 以便拼 batch，配合变长 FlashAttention 不浪费算力）。其二，权重以 bf16 加载，全程冻结——扩散训练/推理时文本编码器永远不更新。其三，512 是硬上限，超长提示词会在分词阶段被截断；这也是第 10 章「Qwen 提示词扩写」会控制输出长度的原因之一。

6.6 MLPProj：把 1280 维接进 DiT 的世界

CLIP 输出 1280 维、DiT 要的是 5120（或 1536）维，中间需要一个适配器：

class MLPProj(torch.nn.Module):

    def __init__(self, in_dim, out_dim, flf_pos_emb=False):
        super().__init__()

        self.proj = torch.nn.Sequential(
            torch.nn.LayerNorm(in_dim), torch.nn.Linear(in_dim, in_dim),
            torch.nn.GELU(), torch.nn.Linear(in_dim, out_dim),
            torch.nn.LayerNorm(out_dim))
        if flf_pos_emb:  # NOTE: we only use this for `flf2v`
            self.emb_pos = nn.Parameter(
                torch.zeros(1, FIRST_LAST_FRAME_CONTEXT_TOKEN_NUMBER, 1280))  # [1, 514, 1280]

    def forward(self, image_embeds):
        if hasattr(self, 'emb_pos'):
            bs, n, d = image_embeds.shape
            image_embeds = image_embeds.view(-1, 2 * n, d)     # [B, 2×257, 1280]
            image_embeds = image_embeds + self.emb_pos         # 区分首帧/尾帧
        clip_extra_context_tokens = self.proj(image_embeds)
        return clip_extra_context_tokens

注意 emb_pos 是零初始化的可学习参数：训练开始时它不改变任何东西，随后慢慢学会给首帧组和尾帧组打上不同的「身份标签」——否则模型无法区分两张 257 token 的序列谁是开头、谁是结尾。这个细节在第 7.5 节 FLF2V 那里会再次出现。

07图生视频与任务变体

T2V 之外的所有变体——I2V、FLF2V、VACE——都不是新架构，而是同一套 DiT 换一种喂数据的方式。本章以 I2V 为主线把「条件注入」讲透，其余变体就只是同一主题的变奏。

7.1 I2V 与 T2V 的唯一区别：给 DiT 一份「图纸」

给定一张首帧图像，Wan 把它翻译成三路信息送进 DiT：

① 语义路（粗）：图像过 CLIP 得 257 个 token，经 MLPProj 投影后前置拼接到文本 context 里，走交叉注意力——「这张图里有什么」。② 像素路（细）：图像经 Wan-VAE 压成首帧 latent，与噪声在通道维拼接——「这张图长什么样」。③ 位置路：一个掩码 msk 标记「哪些位置有真值」——告诉模型哪里是给定的、哪里是要画的。

图 7-1 I2V 的输入构造。橙色是「语义/条件」流：CLIP 257 token 进交叉注意力，msk 与首帧 latent 拼成 y；紫色是「数据」流：y 与噪声通道拼接成 36 通道一起进 DiT。论文里把 msk 简化写作单通道掩码，源码实现是 4 通道的时间子位置掩码（见 7.3）。

noise = torch.randn(16, (F - 1) // 4 + 1, lat_h, lat_w,      # 初始噪声 [16,T,lh,lw]
                    dtype=torch.float32, generator=seed_g, device=self.device)

msk = torch.ones(1, F, lat_h, lat_w, device=self.device)
msk[:, 1:] = 0                                    # 视频级掩码：只有第 1 帧是条件帧
msk = torch.concat([
    torch.repeat_interleave(msk[:, 0:1], repeats=4, dim=1), msk[:, 1:]
], dim=1)                                         # 第 1 帧复制 4 份 → [1, 4+F-1, lh, lw]
msk = msk.view(1, msk.shape[1] // 4, 4, lat_h, lat_w)         # [1, T, 4, lh, lw]
msk = msk.transpose(1, 2)[0]                      # [4, T, lh, lw]：时间子位置掩码

clip_context = self.clip.visual([img[:, None, :, :]])          # [1, 257, 1280]

y = self.vae.encode([
    torch.concat([
        torch.nn.functional.interpolate(                       # 首帧双三次缩放到 (h,w)
            img[None].cpu(), size=(h, w), mode='bicubic').transpose(0, 1),
        torch.zeros(3, F - 1, h, w)                            # 后面 F-1 帧全部置零
    ], dim=1).to(self.device)
])[0]                                             # [16, T, lat_h, lat_w]
y = torch.concat([msk, y])                        # [20, T, lat_h, lat_w]
分辨率对齐在算什么

以 480P 为例，max_area = 832 × 480 = 399,360。给定任意宽高比的输入图（比如 3:4 竖图），先按面积守恒算出目标宽高，再把 latent 尺寸吸附到 16 的整倍数（VAE 步长 8 × patch 2），最后反推 h = lat_h × 8。整条链路上任何一个尺寸不是整倍数，patchify 都会切出残缺 patch——这是此类模型最常见的「帧数/分辨率必须对齐」报错的根源。插值那步在 CPU 上做，是为了让结果与 GPU 型号无关（bicubic 在不同后端有微小数值差）。

7.3 msk：帧级掩码是怎么变成 4 通道的

上面那段 msk 代码是全仓库最绕的几行之一，把每步的形状摆出来就清楚了（以 81 帧、480P 为例）：

步骤代码形状（lh=60, lw=104）
1torch.ones(1, F, lh, lw)[1, 81, 60, 104]（全 1）
2msk[:, 1:] = 0[1, 81, ...]：仅第 1 帧为 1
3repeat_interleave(第0帧, 4) + concat[1, 84, ...]：开头变成 [1,1,1,1] + 80 个 0
4view(1, 21, 4, lh, lw)[1, 21, 4, ...]：每 4 帧归一个 latent 帧
5transpose(1, 2)[0][4, 21, 60, 104]：4 个「时间子位置」通道

最终效果：msk 的 4 个通道中，每个通道对应 latent 帧内部的一个时间相位——第 0 个 latent 帧的 4 个相位全部为 1，其余 20 个 latent 帧全为 0。为什么要这么细？回忆第 4 章：VAE 解码时第一个 latent 帧产出 1 帧、其后每个产出 4 帧，且这 4 帧是交错插值出来的——「一个 latent 帧覆盖哪些视频帧」天然是 4 相位结构。掩码做在同样的粒度上，训练时就能把任意位置的条件帧（而不只是首帧）喂给模型：哪里有真值，对应相位就置 1。推理时 I2V 固定首帧、FLF2V 固定首尾帧，只是这个通用机制的两种特例。

7.6 VACE：一个模型干所有编辑活

VACE（Video All-in-one Creation and Editing）把参考图生成、视频控制（深度/姿态/线稿）、局部重绘、视频外延等任务统一进一个模型。它没有改 in_dim，而是给 WanModel 加了一条 ControlNet 式旁支：

控制条件 vace_context 是 96 通道张量（1.3B 版配置，vace_in_dim=96），构成很有讲究：源视频被拆成「保留区」和「待生成区」两路，各自过 VAE 得 16+16=32 通道（保留区有像素、生成区置零）；再拼 64 通道的掩码——每个 latent 像素对应原图 8×8 邻域展平，分辨率信息一点不丢。参考图则编码成「保留区有图、生成区全零」的单帧 latent，拼在时间轴最前面，模型自然学会「把它变成视频开头」。

    def __init__(self, ..., vace_layers=None, vace_in_dim=None, ...):

        self.vace_layers = [i for i in range(0, self.num_layers, 2)] \
            if vace_layers is None else vace_layers
        ...
        # 旁支：一套独立的注意力块，走 vace_context
        self.vace_blocks = nn.ModuleList([...])
        self.vace_patch_embedding = nn.Conv3d(          # 96 通道 → dim
            self.vace_in_dim, self.dim, kernel_size=self.patch_size,
            stride=self.patch_size)

    def forward_vace(self, x, vace_context, seq_len, kwargs):
        ...
        hints = []
        for block in self.vace_blocks:
            c, c_skip = block(c, **new_kwargs)   # 旁支每层产出一个 skip

主干块里的注入只有一行：x = x + hints[self.block_id] * context_scale——旁支的输出按层加到主干的偶数层上，context_scale 可在推理时调节控制强度。也就是说：主干负责「会生成视频」，旁支负责「听控制信号」，两者解耦，多任务能力来自结构而不是多份权重。

8.3 一步去噪的账本

推理慢在哪？把 480P 的一步展开：32,760 个 token × 40 层 DiT × 2 次前向（CFG）× 50 步 ≈ 1.3 亿 token 次层的计算，还不算 VAE。这就是为什么：

14B · 480P · 81 帧 → 50 步 × 2 前向 → 100 次 DiT 前向 RTX 4090 单卡约 10 分钟量级（offload 下更慢）
1.3B · 480P · 81 帧 → 同样步数 → 约 4 分钟 8.19 GB 显存的出处：14B×4Byte 权重根本放不下，1.3B bf16 可以
offload_model=True → 权重 CPU↔GPU 往返 → 显存省、速度降 时间换空间；多卡 FSDP/USP 则是空间换回时间

官方只开源了推理代码，训练细节都在技术报告里。这一章汇总报告中最值得记住的部分——Wan 的性能一半来自架构，另一半来自这些笨功夫。

9.1 数据流水线：十亿级素材怎么筛

候选集包含数十亿图像与视频，清洗按四步走，聚焦三个维度：基本维度、视觉质量、运动质量。

步骤做什么典型手段
① 基础清洗去掉「不该进训练集」的素材OCR 检测过滤文字过多的素材、LAION 美学分类器过滤低质、NSFW 安全模型、水印/黑边/过曝/模糊检测、剔除 AI 生成内容
② 聚类去重同类内容只留代表特征聚类 + 类别平衡，防止数据分布被少数类别淹没
③ 运动筛选只要「动得自然」的视频运动强度评分：保留动作自然、完整、显著的片段，剔除静止或剧烈抖动的
④ 稠密描述给每个素材配「说明书」内部多模态大模型逐条生成 dense caption（见下）

稠密视频描述（Dense Video Caption）是整条流水线里最关键的投入。DALL-E 3 已经验证：用高度描述性的 caption 训练，模型的提示词遵循能力会大幅提升。Wan 为此专门训了一个视频 caption 模型，训练数据覆盖 ID 主体、数量、OCR 文字、镜头角度、运动幅度、细粒度类别、空间关系等角度——最终质量对齐 Gemini Pro 1.5 水平。你写「低角度、镜头缓慢推近、左侧有三人」这种提示词能被听懂，根源在这里。

9.2 训练策略：渐进式分辨率与后训练

预训练采用渐进式策略：先在低分辨率（约 512²）上让模型学会「什么该动、怎么动」，再逐级升到高分辨率（480P→720P）学细节。这样训练吞吐大、也稳定。为补足中英文文字渲染能力，额外混入了带文字的图文数据集——这是 Wan 成第一个能生成中英文字幕效果的开源视频模型的原因。

后训练分两阶段：SFT（用最高质量的少量数据继续训练，提升视觉保真与运动表现）+ 偏好优化（按人类偏好再推一把）。后训练数据从技术、动物、艺术、人文、交通工具等 12 个大类中平衡采样——量不大，但每条都是精挑的。

9.3 训练并行：FSDP + 2D 上下文并行

14B 模型 + 长序列（720P 一个样本 75,600 token，训练时还会到 256K token 上下文），单卡连一个样本都放不下。Wan 的解法是两层并行叠加：

模型权重层面 → FSDP 分片 → 参数/梯度/优化器状态切开摊到多卡 解决「模型大」
序列层面 → 外层 Ring + 内层 Ulysses → 注意力按 2D 网格切分通信 解决「序列长」

Ulysses（序列切头并行）把注意力的头分给组内各卡，通信只在组内小圈子里发生；Ring Attention（外层）把序列分段轮流传递，通信与计算重叠。两者套起来，256K 序列的通信开销从 约 10% 压到 1% 以下。一个有趣的细节：1.3B 模型只有 12 个注意力头，Ulysses 组内卡数必须整除头数（8 卡就除不开）——所以报告建议小模型场景用「Ring 为主、Ulysses 为辅」的搭配。

9.4 推理加速：三个官方 trick

技术原理收益
Diffusion Cache相邻去噪步的 DiT 输出高度相似；对缓存结果做残差补偿而不是每步全算约 1.4×（官方数字，观感几乎无损）
负向提示隔步计算CFG 的负向前向不必每步都算，隔步算一次、中间步复用1.62×（负向前向次数减半以上）
FlashAttention 混合量化注意力里 Q·KT 用 int8、乘 V 用 fp8，softmax 保精度1.27×

注意 9.4 与 8.2 的呼应：generate 里正负提示词先编码、循环里只传 embedding——就是在为「隔步计算负向前向」这类优化留好接口（社区项目 TeaCache 就是在这个位置动刀的，第 11 章会见到）。

9.5 提示词对齐：Qwen 扩写

最后一个「出厂设置」：generate.py 的 --prompt_extend。用户随手写的「猫咪弹钢琴」先被 Qwen 大模型扩写成结构化的专业提示词（主体、动作、镜头、光线、风格），再送进管线。本质上是把「会写提示词」这件事也外包给了 LLM——训练时 dense caption 是 Qwen 系模型写的，推理时再用同族模型把用户输入翻译回那个分布，两头就对上了。可用本地 Qwen 或 DashScope API，也可关闭。

11.2 局限

① 训练代码未开源：仓库只有推理，复现训练需要自己按第 2、9 章拼（数据流水线更无法复现）。② 消费级门槛仍在：14B 单卡跑 480P 需要 offload 换时间；1.3B 效果与 14B 有肉眼差距。③ 时长与多镜头叙事：原生 5 秒（81 帧），长视频要么外延（VACE）要么靠社区方案（Helios），多镜头之间的角色/风格一致性是开放难题。④ 复杂物理交互（手指精细操作、物体碰撞）在技术报告里被官方列为 limitation——这是当前所有视频模型的共同短板。

11.3 演进：Wan2.2 与 Wan2.5

把时间线拉到 2025 年下半年：

Wan2.1（2025-02） → Wan2.2（2025-07）→ MoE 双专家 + 高压缩 VAE 数据再扩：图像 +65.6%、视频 +83.2%
Wan2.2 → Wan2.5（2025-09）→ 音视频同步生成 视觉与声音用同一套全扩散 MoE 架训

Wan2.2 的两个关键设计都直接继承自 2.1 的经验：MoE 按噪声水平分家——高噪声专家负责早期「定结构」（对应第 2 章 shift 把步数前移的洞察），低噪声专家负责后期「抠细节」，总参数 27B、每步只激活 14B，显存与算力不变、效果上涨；Wan2.2-VAE 把压缩率推到 4×16×16（加 patchify 共 4×32×32），token 直接减到四分之一，让 TI2V-5B 在 4090 上 9 分钟生成 720P@24fps。而 Wan2.5 走向「视听一体」：文/图/音生视频，画面与音效由同一模型联合生成。这条演进路线对 2.1 的解读依然是成立的——底座架构没变，变的只是专家数量、压缩率与模态。
