一句话总结

ArgsWorld 把多视图 3DGS 重建、单图/文本条件场景生成、以及长轨迹场景外推统一成同一个四步自回归扩散推理流程：历史图像 latent 固定，当前 chunk 的 RGB latent 与跨视图场景特征共同刷新，3DGS 渲染结果再作为下一去噪步的反馈，从而让扩散模型直接生成可渲染、可外推、可继续编辑的 3D Gaussian 世界。

核心判断：它的“自回归”并不来自单向 causal attention mask，而来自 chunk 级 rollout、历史状态传递以及每个 denoising step 内对完整前缀场景的重新解码。理解这一点，是避免把 ArgsWorld 误读成普通视频自回归模型的关键。

研究背景与动机

近三年的 3D 生成研究大致沿着两条路线推进。第一条是可微渲染驱动的表示学习，例如 3D Gaussian Splatting（3DGS）把场景表示为大量带位置、颜色、不透明度、尺度和旋转的高斯椭球，渲染速度快、几何细节足，但传统 3DGS 依赖逐场景优化，难以变成可泛化的生成器。第二条是扩散生成路线，视频或多视图扩散模型可以从图像或文本生成新视角，但直接输出的多帧 RGB 往往缺少统一的底层 3D 表示，长轨迹上容易漂移，也不容易做几何导出、查询视角渲染或继续外推。

ArgsWorld 关注的正是这两条路线的交叉点：能不能让一个扩散 Transformer 同时承担“理解输入场景”“生成新场景”和“沿新相机继续扩展场景”三种任务，并且最终产物不是一串彼此松散的图像，而是一个可以反复渲染的 3DGS 世界。论文摘要用三句原文概括了它的目标：“It keeps the historical image latents fixed and refreshes the scene features...”，“Our 3D Self-Forcing Distillation trains the model on its own generated histories...”，以及“Distribution matching supervises direct image latents and latents of Gaussian renderings at both generation and additional cameras.”

已有方法的局限可以分成三类。第一，重建模型和生成模型通常分裂：重建倾向于优化一个给定场景，生成倾向于采样一个新场景，二者共享度低。第二，多视图一致性常靠 3D-aware conditioning 或后处理约束实现，但当相机轨迹变长时，仅靠图像 latent 间的直接约束会累积误差。第三，很多 3D-aware 扩散模型在训练时使用真实历史，推理时却使用模型自己生成的历史，这一 train-test mismatch 会导致外推早期小误差在后续 chunk 中不断放大。

ArgsWorld 的出发点是把场景表示拆成两类互补变量：一类是 direct RGB latents，负责快速给出外观内容；另一类是 per-view 场景特征，负责被解码成完整 3DGS。模型在每个去噪步都把当前特征和固定历史 RGB 一起送入 Gaussian decoder，重新解码整个已经生成的前缀，再把前缀在当前相机下的渲染结果编码回 latent，反馈到下一步。这样，“图像生成”与“3D 场景更新”在同一 rollout 中反复耦合。

因此，本文的贡献不在单一步骤的新奇，而在系统层面的统一：同一个 Wan DiT 骨干、同一套四步 scheduler、同一个 `infer_ar.main` 推理入口，同时服务 reconstruction、generation、extrapolation。官方 README 也明确强调 reconstruction 是 conditioned generation，而不是另一套独立的逐场景优化程序。

预备知识：3DGS 与 Flow Matching

3D Gaussian Splatting 的最小必要知识

3DGS 把场景表示为集合 \(G=\{g_i\}\)，每个高斯通常包含中心 \(xyz\)、不透明度 \(\alpha\)、各向异性尺度 \(s\)、单位四元数旋转 \(q\)，以及球谐系数 \(SH\)。渲染某相机图像时，每个像素沿射线累加多个高斯的贡献，得到颜色与深度。它的优势是可微、可导出、渲染快；难点是如何让生成模型一次性预测出一个彼此一致、可长期外推的高斯集合。

ArgsWorld 没有采用“先出图像再离线拟合 3DGS”的两阶段方案，而是让 DiT 直接预测 1024 维场景特征，再由一个 pixel-aligned Gaussian decoder 预测高斯参数。每个 spatial grid location 预测 2 个 Gaussians，因而场景表示与图像 latent grid 严格对齐，便于利用相机射线和 VAE 空间结构。

Flow Matching：从噪声样本预测 clean latent

模型采用 flow matching 形式的扩散过程。给定 clean latent \(z\) 与噪声 \(\epsilon\sim\mathcal N(0,I)\)，在噪声水平 \(\sigma\in[0,1]\) 上构造加噪样本：

$$x_\sigma=(1-\sigma)z+\sigma\epsilon,\qquad \epsilon\sim\mathcal N(0,I)$$

训练目标是预测速度场，等价目标常写作 \(\epsilon-z\)。推理时，若模型输出 \(v_\theta\)，则可估计 clean latent：

$$\hat z=x_\sigma-\sigma v_\theta \tag{1}$$

这就是论文 Eq. (1)。人话解释是：DiT 不直接输出最终图像，而是输出“当前带噪 latent 应向哪个方向流动”，再用当前噪声水平 \(\sigma\) 换算出对 clean latent 的估计。ArgsWorld 的四步推理只是把这个解噪过程截断成很少的几步，并在步与步之间插入 3DGS 渲染反馈。

输入表示：逐视图 VAE latent 与 Plücker ray map

ArgsWorld 以 Wan2.2-TI2V-5B 的视觉 token 化方式为基础，但改成视图独立编码。默认输入分辨率为 \(480\times704\)，经过 VAE 下采样 16 倍后得到 \(30\times44\) latent grid；再做 \(2\times2\) patchification，每个视图得到 \(15\times22=330\) 个 tokens。该设计保留了 Wan 的视觉先验，同时避免把整个轨迹作为一个长视频片段送入 temporal VAE，从而更适合任意相机位姿组合和 session 延续。

相机几何通过六通道 Plücker ray map 注入。对射线原点 \(\mathbf o\) 和单位方向 \(\mathbf d\)，表示为：

$$[\mathbf{d};\ \mathbf{o}-(\mathbf{o}^\top\mathbf{d})\mathbf{d}]$$

前三维给出方向，后三维给出原点到射线最近点的偏移，这种表示与沿射线的尺度无关，适合归一化后的场景坐标。官方 utils.py 的实现非常直接：

官方源码 · utils.py L6–L9 · 六通道 ray map 
def create_raymaps(cameras, h, w):
    rays_o, rays_d = create_rays(cameras, h, w)
    raymaps = torch.cat([rays_d, rays_o - (rays_o * rays_d).sum(dim=-1, keepdim=True) * rays_d], dim=-1)
    return raymaps

这里有两个实现细节值得注意。第一，ray map 是 per-pixel / per-location 的几何条件，而不是仅给模型一个相机参数向量，因此 Transformer 的每个空间 token 都能感知自己对应的射线。第二，ArgsWorld 在推理时会先根据输入相机或第一个 trajectory segment 做坐标归一化；第一个 segment 决定 session 的原点和尺度，后续 segment 必须复用该归一化，才能保证外推时世界坐标连续。

双输出 DiT 与历史状态组织

论文方法的主干是一个 30 层、24 头、head dimension 128 的 Wan Diffusion Transformer。文本条件来自冻结的 UMT5 编码器，最大 512 tokens。与标准视频 DiT 不同，ArgsWorld 的最后预测头分成两支：48 通道 RGB flow velocity 与 1024 通道场景特征。前者用于恢复 direct RGB latent，后者用于 Gaussian decoder。

历史状态由两部分组成：一是固定的历史 direct clean RGB latents \(H_{b-1}\)，二是不断刷新的历史场景特征。这里的关键不是“历史都冻结”，而是“历史 RGB 固定、历史 feature 可随当前 DiT 调用更新”。源码 _dit 明确展示了这一点：

官方源码 · ar_core.py L307–L325 · 历史拼接与双输出 DiT 
def _dit(self, x, raymaps, cond, prev_feat, prev_lat, t, text_emb, hist_lat=None, hist_feat=None):
    n_h = 0 if hist_lat is None else hist_lat.shape[2]
    if n_h > 0:
        tokens_per_frame = (x.shape[-2] // PATCH_HW) * (x.shape[-1] // PATCH_HW)
        x = torch.cat([hist_lat, x], 2)
        cond = torch.cat([hist_lat, cond], 2)
        prev_feat = torch.cat([hist_feat, prev_feat], 2)
        prev_lat = torch.cat([hist_lat, prev_lat], 2)
        timestep = torch.cat([t.new_zeros(n_h * tokens_per_frame),
                              t.reshape(1).expand((x.shape[2] - n_h) * tokens_per_frame)])[None]
    else:
        timestep = t.reshape(1)
    hidden = torch.cat([x, raymaps, cond, prev_feat, prev_lat], 1)
    out = self.generator(hidden_states=hidden, timestep=timestep,
                         encoder_hidden_states=text_emb, return_dict=False)[0]
    v, feats = out.split([LATENT_DIM, FEAT_DIM], 1)
    return v[:, :, n_h:].float(), feats

这段代码解释了四个容易误读的点。第一，历史 latent 被同时拼到 noisy input \(x\)、condition latent \(cond\) 和 feedback latent \(prev\_lat\) 三条路径上，而不是只作为一种 memory。第二，历史 token 的 timestep 被设为 0，当前 chunk token 才使用当前噪声水平，因此模型把历史视为 clean context。第三，速度输出 \(v\) 只保留当前 chunk，即 v[:, :, n_h:]；但 feats 保留了历史和当前所有视图，这正是“历史 feature 被刷新”的证据。第四，attention 本身仍是双向的，官方实现 models/transformer_wan2.py 中使用 is_causal=False。

因此，“Autoregressive” 的因果性来自外层 chunk rollout 和历史状态，而不是 DiT 内部的 causal mask。论文 Table 6 的消融也证明了这一点：把模型改成 causal attention 并冻结历史特征后，generation 和 extrapolation 的 PSNR 分别掉到 8.10 和 8.89，远低于完整模型。这个消融同时改变了 mask 与历史特征更新方式，所以不能把全部下降只归因于 mask。

Gaussian Decoder：从特征到完整前缀 3DGS

Gaussian decoder 是连接扩散 latent 与 3DGS 表示的核心模块。它以可训练的 Wan VAE decoder 深拷贝为骨架，但把输出头从 RGB 重建换成 pixel-aligned 3DGS 预测头。这样做的好处是继承 VAE decoder 的空间上采样和视觉归纳偏置，同时把最终输出约束为可渲染高斯参数。

官方文件 models/reconstruction_model.py 中，WANDecoderPixelAligned3DGSReconstructionModel 的初始化包含几个关键动作：深拷贝 VAE decoder；增加把 DiT 特征注入 decoder 输入激活的 extra_conv_in；把最终卷积输出置为 Identity；新增 PixelAligned3DGS 头；删除部分 temporal upsample 卷积以适配逐视图处理。源码如下：

官方源码 · models/reconstruction_model.py L27–L44 · Gaussian decoder 构造 
self.decoder = copy.deepcopy(vae_model.decoder).requires_grad_(True)
self.post_quant_conv = copy.deepcopy(vae_model.post_quant_conv).requires_grad_(True)

每个 grid location 预测 2 个 Gaussians，每个 Gaussian 共 38 个数：中心 3 维、不透明度 1 维、尺度 3 维、单位四元数旋转 4 维、degree-2 球谐 27 维。其中深度由 trunc_exp 保证为正，中心按射线参数化：

$$xyz = rays\_o + depth \cdot rays\_d$$

不透明度用 sigmoid，旋转归一化为单位四元数，尺度结合深度和 pixel footprint 调整。RGB 与 depth 渲染使用 FP32，以降低大场景或高反差区域的数值不稳定。

四步 chunk-wise 自回归推理

公开推理使用 FlowMatchEulerDiscreteScheduler(num_train_timesteps=1000, shift=3.0)，默认 denoising indices 为 (0, 250, 500, 750)，对应噪声水平大约为 \((1.0, 0.9, 0.75, 0.5)\)。也就是说，模型只做四次 DiT 调用，却要求每次都能把 3DGS 世界向前推进并保持一致性。这只有在 3D 渲染反馈足够强时才成立。

对第 \(b\) 个 chunk、第 \(j\) 个去噪步，论文 Eq. (2) 定义完整前缀场景：

$$G_{b,j}=\mathcal D_{\mathrm{GS}}\left(F_{b,j},\operatorname{sg}(Z_{b,j}),C_{\le b}\right),\qquad Z_{b,j}=[H_{b-1};\hat z_{b,j}] \tag{2}$$

其中 \(H_{b-1}\) 是固定历史 direct RGB latents，\(F_{b,j}\) 是被刷新的历史与当前场景特征，\(\operatorname{sg}\) 表示 stop-gradient，\(C_{\le b}\) 是截至当前 chunk 的相机。这个公式强调：每次解码的是完整前缀，而不是只解码当前 chunk。

随后，论文 Eq. (3) 把当前场景在当前相机下重新渲染并编码，加噪后送入下一步：

$$x_{b,j+1}=(1-\sigma_{j+1})\bar z(G_{b,j},C_b)+\sigma_{j+1}\epsilon,\qquad \bar z(G,C)=\mathcal E(\mathcal R(G,C)) \tag{3}$$

这里 \(\mathcal R\) 是 Gaussian renderer，\(\mathcal E\) 是 VAE encoder。人话解释是：模型先猜当前 clean latent，再解码成 3D 世界，再从 3D 世界重新“拍照”，把照片编码成 latent 并重新加噪，用它替代纯噪声迭代的输入。这就是 3D 一致性反馈。

官方 ar_core.py 的 generate_chunk 把上述公式直接实现为循环：

官方源码 · ar_core.py L347–L365 · 四步采样与渲染反馈 
for i in range(self.num_steps):
    t = self.step_t(i)
    v, feats = self._dit(x, raymaps, cond, prev_feat, prev_lat, t,
                         text_emb, hist_lat, hist_feat)
    x0_2d = x - (t / 1000.0) * v
    decode_lat = torch.cat([hist_lat, x0_2d], 2) if n_h else x0_2d
    gs = gaussians_to_global(
        self.decode_gaussians(feats, decode_lat, local_cams), origin, scale)
    if i < self.num_steps - 1:
        prev_lat = self._render_latents_nograd(gs, cams, height, width)
        prev_feat = feats[:, :, n_h:].float()
        sigma_next = self.step_t(i + 1) / 1000.0
        x = (1 - sigma_next) * prev_lat + sigma_next * torch.randn_like(prev_lat)

world.replace_all(gs, ctx_cams, decode_lat[0], feats[0])

对照代码可确认几件事：x0_2d = x - (t / 1000.0) * v 对应 Eq. (1) 的 clean latent 估计；decode_lat 总是包含历史加当前；每个非最后一步都会执行 _render_latents_nograd 并重新加噪；循环结束后调用 world.replace_all 替换完整世界。“replace_all” 这个命名本身就否定了“旧高斯冻结、只追加新高斯”的简化理解。

3D Self-Forcing Distillation

只靠普通监督训练会遇到一个典型问题：训练时模型看到真实历史，推理时却看到自己生成的历史。为缩小这一差距，论文提出 3D Self-Forcing Distillation：student DiT 与 Gaussian decoder 从 FlashWorld few-step checkpoint 初始化；teacher 与在线 critic 从 3D-adapted diffusion checkpoint 初始化；训练数据来自模型自己生成的 history，而不是始终依赖真实历史。

训练时先无梯度完成若干 chunk 的四步 rollout，再随机选择一个所有 chunk 共享的 replay step \(k\)，带梯度重放该步。论文附录给出采样方式：

$$B\sim\operatorname{Unif}\{2,\ldots,5\},\qquad k\sim\operatorname{Unif}\{1,\ldots,4\}$$

其中 \(B\) 是训练 chunk 数，\(k\) 是重放的 denoising step。训练 chunk 为 8 views，而公开推理默认 chunk size 为 24；二者不能混淆。前 100 global steps 只更新 critic，之后每 4 steps 更新一次 student；评估使用 4200 global steps checkpoint。

分布匹配损失有三个分支。论文 Eq. (4) 定义三类 latent：

$$z_{\mathrm{rgb}}=[\hat z_{1,k};\ldots;\hat z_{B,k}],\quad z_{\mathrm{in}}=\bar z(G_{B,k},C_{\le B}),\quad z_{\mathrm{nov}}=\bar z(G_{B,k},C_{\mathrm{nov}}) \tag{4}$$

\(z_{\mathrm{rgb}}\) 是 student 的 direct RGB latent；\(z_{\mathrm{in}}\) 是当前生成相机下 Gaussian 渲染再编码的 latent；\(z_{\mathrm{nov}}\) 是额外新视角下渲染再编码的 latent。三路 DMD 梯度统一写作论文 Eq. (5)：

$$[\nabla_z\mathcal L_{\mathrm{DMD}}]_i=-\frac{2}{Nw}(\hat z_{\mathrm{real},i}-\hat z_{\mathrm{fake},i}) \tag{5}$$

其中 normalizer 下限为 \(\delta=10^{-6}\)。此外还有 consistency loss，论文 Eq. (6) 要求输入相机下的渲染 latent 与历史加当前 direct latent 一致：

$$\mathcal L_{\mathrm{cons}}=\operatorname{MSE}\left(z_{\mathrm{in}},[H_{B-1};\hat z_{B,k}]\right) \tag{6}$$

这套训练目标的意义在于：direct RGB 分支保证内容生成质量，rendered input 分支保证生成视角下 3D 渲染与直接预测一致，novel view 分支惩罚多视角不一致。Table 6 显示，去掉 rendering DMD 后，generation PSNR 从 11.61 降到 10.82，extrapolation PSNR 从 11.83 降到 10.68，说明 3D 渲染监督不是装饰，而是少步长外推稳定的主要来源。

开源边界：固定 commit 公开了完整推理、session 延续、查询视图渲染与导出，但没有公开可执行训练入口，也没有公开完整的 3D Self-Forcing Distillation / DMD / teacher-critic 训练循环。因此本节公式与训练流程来自论文正文及附录，是“论文描述”，不能等同于当前仓库中的可运行训练代码。
讲解性伪代码边界：下面伪代码依据论文附录 B 与正文描述整理，用于帮助理解 self-forcing rollout，不是官方训练源码。若未来官方公开训练仓库，应以实际实现为准。
讲解性伪代码 · 依据论文 3D Self-Forcing 描述整理，非官方源码 
# 1) 无梯度生成历史
with torch.no_grad():
    histories = student.rollout_chunks(num_chunks=B-1)

# 2) 采样共享 replay step
k = randint(1, 4)

# 3) 带梯度重放最后一个 chunk 的第 k 步
z_rgb = student.replay_step(histories, step=k)
G = decode_gaussians(student.features, concat(histories, z_rgb))
z_in  = encode(render(G, cameras_in))
z_nov = encode(render(G, cameras_novel))

# 4) teacher 与 critic 提供 real/fake 分布匹配信号
loss_dmd = dmd_loss([z_rgb, z_in, z_nov], teacher, critic)
loss_cons = mse(z_in, concat(histories, z_rgb))
(loss_dmd + loss_cons).backward()

三种任务如何进入同一推理入口

官方 infer.py 提供 reconstruction、generation、extrapolation 三种 CLI 模式，但它们最终都转发到同一个 infer_ar.main。这一点正是“统一任务建模”的工程证明。infer.py 中的核心校验如下：

官方源码 · infer.py · 三种模式的输入约束（固定 commit） 
CHUNK_SIZE = 24

if args.mode == 'reconstruction' and len(args.images or embedded) < 2:
    raise ValueError('Reconstruction requires at least two reference images of the same scene')
if args.mode == 'generation' and (len(trajectories) != 1 or len(data[0]['cameras']) > CHUNK_SIZE):
    raise ValueError('Generation uses one trajectory with at most 24 cameras (one chunk)')
if args.mode == 'extrapolation' and sum(len(d['cameras']) for d in data) <= CHUNK_SIZE:
    raise ValueError('Extrapolation requires more than 24 cameras')
if args.reference_indices and not (args.images or embedded):
    raise ValueError('Reference indices require reference images')

三种模式的官方命令如下。Reconstruction 至少需要两张同场景参考图，--reference_indices 对应首个 trajectory segment 中的零基相机槽位：

官方 README · reconstruction 示例 
python infer.py --mode reconstruction \
  --model_id weights/Wan2.2-TI2V-5B-Diffusers \
  --ckpt weights/argsworld.ckpt \
  --input_dir examples --output_dir outputs/reconstruction \
  --images images/0000.png images/0003.png --reference_indices 0 3

Generation 支持单图、多图或无参考图，只允许一个 trajectory segment，且不超过 24 cameras：

官方 README · generation 示例

  --model_id weights/Wan2.2-TI2V-5B-Diffusers \
  --ckpt weights/argsworld.ckpt \
  --input_dir examples --output_dir outputs/generation \
  --trajectory trajectory.json --images reference.png

Extrapolation 可以传入多个 trajectory JSON，每个 JSON 开启一个新 segment；第一个 segment 决定 session 坐标归一化，后续 segment 复用该尺度：

官方 README · extrapolation 示例 
python infer.py --mode extrapolation \
  --model_id weights/Wan2.2-TI2V-5B-Diffusers \
  --ckpt weights/argsworld.ckpt \
  --input_dir examples --output_dir outputs/extrapolation \
  --trajectory trajectory.json trajectory_extend.json --images reference.png

输出方面，final_world.mp4 是 Gaussian 渲染视频，direct_rgb.mp4 是 direct RGB predictions 经 VAE 解码得到的视频，二者不能混为一谈；还会导出 world.ply、session_cameras.pt，若使用参考图则输出 reference_views.jpg。视频默认 8 fps。

这组消融支持本文的核心论点：ArgsWorld 的能力来自“扩散解噪 + 3D 渲染反馈 + 非因果全前缀注意力”的联合，而不是单一模块。把 3D 渲染监督去掉，模型仍能生成图像，但更像普通多视图扩散；把 attention 改成 causal 并冻结历史特征，模型失去根据当前观察重写全局场景特征的能力，长程一致性迅速恶化。

局限与公平比较边界

需要先说明一个事实边界：论文 v1 没有设置独立的 Limitations / Failure Cases / Future Work 小节。因此下面的局限性不是“作者明确自述清单”，而是基于论文实验、架构和公开代码状态做出的独立分析。写作时把它称为作者声明会不准确。

第一，单图生成与外推任务中，ArgsWorld 的 LPIPS 并非最佳。Table 2/3 显示 FlashWorld 在单图任务 LPIPS 更低，说明 ArgsWorld 为了 3D 一致性和可渲染性，在局部感知相似度上付出了代价。若应用更看重单张新视角的纹理逼真度，而不是可导出几何或超长轨迹，FlashWorld 仍有吸引力。

第二，外推速度存在额外开销。Table 3 中 16-view extrapolation 耗时 6.91 秒，高于 FlashWorld 的 4.96 秒和 PixWorld 的 3.04 秒。原因是每个 denoising step 都要重新解码完整前缀并执行 3D 渲染、VAE 编码和再加噪。轨迹越长，完整前缀越大，计算与显存压力也会增长。公开推理默认把 chunk size 设为 24，也部分反映了对计算成本的工程折中。

第三，WorldScore 的 3D Consistency 与 Photometric Consistency 并非最佳。PixWorld 在这些几何/光度一致性子项上更高，说明 ArgsWorld 的统一建模并不自动等价于“几何最稳定”。它更像是在内容生成、主观质量和可外推性之间取得平衡，而不是在每个几何指标上领先。

第四，复现边界明确。当前固定 commit 公开了完整推理、session continuation、query view 渲染与导出，但没有公开可执行训练入口，也没有完整的 3D Self-Forcing Distillation、DMD 与 teacher/critic 训练循环。因此研究者可以复现推理结果，却无法仅靠当前仓库完整复现论文训练曲线。此外，论文中的不同方法存在评测分支差异：ArgsWorld、FlashWorld、PixWorld 评 Gaussian renders，而 Geometry Forcing / Gen3C / Gen3R 评 direct RGB predictions；跨表解读时必须先确认评测对象，否则会把表示差异误判成方法差异。

结论

ArgsWorld 的价值在于把“生成图像序列”升级为“生成并持续维护一个可渲染 3D 世界”。它没有发明全新的扩散理论，而是通过逐视图 VAE、六通道 Plücker ray map、双输出 Wan DiT、完整前缀 Gaussian 解码、四步渲染反馈和 3D Self-Forcing Distillation，把 3DGS 表示嵌入自回归扩散 rollout。结果是 reconstruction、generation、extrapolation 三种任务共享同一模型与同一推理入口，且产物可直接导出、查询和继续扩展。

从研究角度看，ArgsWorld 最值得后续工作继承的是“每次都重新解释完整前缀”的思想：历史不是被冻结的视频帧，而是被固定的 direct RGB context 加上可被当前观察刷新的场景特征。这为长轨迹 3D 生成提供了一种比单纯 causal attention 更稳定的状态组织方式。从工程角度看，当前仓库已经给出完整推理实现，但训练闭环尚未公开；这意味着它是一个优秀的推理框架与研究基线，却还不是一个可以从零完整复现训练的开放训练仓库。
