01Flow Marching 是什么

一句话：Flow Marching 是 MIT 机械工程系 Zituo Chen 与 Sili Deng 提出的「生成式 PDE 基础模型」训练框架，它用一个连续参数 k 把「确定性神经算子（直接预测下一步）」和「Flow Matching（从噪声生成）」两条路统一成同一条插值路径，从而在长时程 rollout 中获得可证明的误差有界性与不确定性量化能力。

关于出处的重要澄清

Flow Marching 不是视频生成领域的技术。你可能在 Self-Forcing、CausVid、MotionStream 等视频论文里听到过「forcing」「marching」这类词，但它们用的是不同方法（Diffusion Forcing、自回归去噪等），均不含 Flow Marching 这一术语。本技术唯一的正式出处是 PDE 基础模型论文 arXiv:2509.18611。考虑到你此前的阅读背景是视频生成（Wan 系列），本文第 9 章会专门给出「PDE 世界 ↔ 视频世界」的概念映射表，帮助你迁移理解。

1.1 它解决什么问题

PDE（偏微分方程）基础模型要做的事是：给定一个物理系统的当前状态 x₀（比如某一时刻的流场、温度场、电磁场），预测它下一时刻的状态 x₁，然后把预测结果再喂回去，一步步滚到很远的未来（long-term rollout）。

现有两条路线各有致命伤：

  • 确定性神经算子（FNO、DeepONet、Graph Neural Operator 等）：直接学一个映射 fθ: x₀ ↦ x₁，训练快、推理一步到位。但误差会指数累积——每步哪怕只有 1% 的误差，滚 100 步就是 (1.01)100 ≈ 2.7 倍，远期预测必然崩。而且无法给出不确定性。
  • Flow Matching / 扩散模型（GenCast、Diffusion Forcing 思路）：从噪声出发积分 ODE/SDE 得到 x₁。误差天然有收缩、能给不确定性，但起点与当前状态 x₀ 无关，要把「已知 x₀」这件事塞进条件里，工程上别扭，且每步都要跑几十次网络前向（采样步数），rollout 极慢。

Flow Marching 的回答是：用一个标量 k ∈ [0,1] 在两者之间连续插值。k=1 就是确定性残差预测（起点 = x₀），k=0 就是标准 Flow Matching（起点 = 噪声），中间值同时享受两边的好处——既以 x₀ 为锚点（信息不丢），又保留噪声注入带来的收缩性与随机性。

02背景预备：PDE 基础模型与误差累积

本章补两块拼图：PDE 基础模型在做什么、为什么长时程 rollout 是它的命门；以及 Flow Matching 的基本构造（注意本文的符号约定与视频领域常见约定不同）。

2.1 PDE 基础模型：从「解一个方程」到「解一族方程」

传统数值方法（有限元、有限差分）是「一方程一求解」：换个边界条件、换个系数，就得重新跑一遍求解器，动辄几小时到几天。神经算子（Neural Operator）的野心是：用一个神经网络学掉整族 PDE 的解算子——给定任意初始条件/边界条件/参数，直接输出解场，前向一次几毫秒。

代表工作：

  • FNO（Fourier Neural Operator）：在傅里叶空间做参数化的积分核，对周期性光滑 PDE 效果好；
  • DeepONet：分支网编码输入函数、主干网编码查询坐标，输出解在该点的值；
  • Graph Neural Operator / MeshGraphNets：用图神经网络处理非结构网格。

这些模型通常被训练成「一步预测器」：输入 x₀，输出 x₁ = x₀ + Δt · f(x₀) 的近似。要得到长时程轨迹，就反复自回归调用。问题就出在这里。

2.2 误差累积：神经算子的阿喀琉斯之踵

设神经算子 fθ 的单步误差上界为 ε，且 f 是 L-Lipschitz 的。N 步 rollout 后，累积误差满足 Gronwall 型不等式：

‖eN‖ ≤ ε · (1 + L + L² + … + LN−1)  ≈  ε · eLN  （当 L > 0） 误差随步数 N 指数增长；L 哪怕只有 0.05，滚 200 步也放大 e10 ≈ 22000 倍

这就是为什么神经算子在短期（几步到几十步）看起来很准，一到成百上千步就数值崩溃、能量漂飞、湍流结构糊掉。要缓解，常见办法是：

  • 多步训练（rollout training / forcing）：训练时就展开多步，把累积误差纳入损失；但步数深了梯度爆炸/消失，且分布漂移（exposure bias）。
  • 加正则/稳定化：能量守恒约束、涡量约束等，治标不治本。
  • 改范式：不再做确定性残差，而是引入随机性——这就到了 Flow Matching。

2.3 Flow Matching 速通（本文符号约定）

符号差异警告

在视频/图像的 Flow Matching 文献里，通常约定 x₀ = 噪声，x₁ = 数据。本文（Flow Marching 论文）的约定不同：

x₀ = 当前状态（已知的物理场）
x₁ = 下一时刻状态（要预测的目标）
z = 标准高斯噪声

路径从「x₀ 与 z 的混合」走向「x₁」。读公式时务必按此约定理解。

Flow Matching 的核心：构造一条从噪声（或噪声+数据混合）到数据的插值路径 xt，训练网络预测沿路径的速度场 vθ(xt, t)。最简单的线性插值（也叫 Optimal Transport 路径）是：

xt = (1 − t) · z + t · x₁，   t ∈ [0, 1] t=0 是纯噪声 z，t=1 是目标数据 x₁

对应速度就是常向量 v* = x₁ − z。训练损失：

LFM = Ex₁, z, t [ ‖ vθ(xt, t) − (x₁ − z) ‖² ]

推理时从 t=0 的噪声出发，用欧拉法（或高阶 ODE 求解器）沿速度场积分到 t=1，得到 x₁ 的采样。关键好处：速度场的 ODE 流带有天然的收缩/耗散结构，使得误差不会像确定性残差那样无界增长——这正是第 4 章要证明的。

Flow Marching 的问题意识是：能不能让 Flow Matching 的起点不是「纯噪声」，而是「已知的当前状态 x₀」，从而把确定性算子的信息利用与 FM 的误差有界性结合起来？答案就是下一章的参数 k。

03核心原理：桥接参数 k 与位置-尺度插值

本章是全文的数学核心。我们逐步推导 Flow Marching 的插值核、速度场、训练目标，以及那个看起来反直觉却极关键的「k-free」设计。

3.1 位置-尺度插值核（论文 Eq.4–6）

Flow Marching 定义带参数 k ∈ [0,1] 的插值路径：

xtk = μt + σt · z 位置项 μt 决定「路径往哪走」，尺度项 σt 决定「噪声掺多少」

其中：

μt = t · x₁ + k(1 − t) · x₀，   σt = (1 − t)(1 − k) 位置项是 x₁ 与 x₀ 的线性凸组合（权重随 t 变化），尺度项随 t 线性衰减到 0

等价地，可以把它写成「起点混合 + 线性走向」的形式，更直观：

xtk = (1 − t) · [ k · x₀ + (1 − k) · z ] + t · x₁ t=0 时起点是 x₀ 与 z 的混合，t=1 时终点恒为 x₁

来看两个端点的行为：

kt=0 起点 x₀kt=1 终点物理含义
1x₀（当前状态，确定）x₁确定性残差预测：从已知状态直接走向下一步
0z（纯噪声）x₁标准 Flow Matching：从噪声生成下一步
0.50.5·x₀ + 0.5·zx₁起点半掺噪声，兼顾锚定与随机性

σt 的行为也值得玩味：k=1 时 σt ≡ 0（全程无噪声，路径是 x₀→x₁ 的直线）；k=0 时 σt = 1−t（噪声随 t 递减到 0，这正是 OT-FM 的标准形式）。

图 1：桥接参数 k 控制插值路径形态。k=1 退化为 x₀→x₁ 的确定性直线，k=0 退化为标准 Flow Matching 的噪声→数据路径，中间值连续过渡。三条路径的终点都是 x₁。

3.2 速度场推导（论文 Eq.7–9）

对 xtk 关于 t 求导，得到路径上的真实速度：

vtk = d xtk / d t = (x₁ − k · x₀) − (1 − k) · z 由 μt' = x₁ − k·x₀ 与 σt' = −(1−k) 相加得到

网络 vθ(xtk, t) 的训练目标就是逼近这个 vtk。验证两个极限：

  • k=1：vt = x₁ − x₀（常数，即残差）——网络只需预测状态增量，与神经算子完全一致；
  • k=0：vt = x₁ − z（标准 FM 速度）。

中间的 k 对应一个「介于残差预测和噪声速度之间」的目标。由于 v 同时依赖 x₁、x₀、z，而 xtk 也由这三者构造，网络理论上可以从 xtk 中反推出足够信息来预测 v——前提是 k 不被当作额外输入（见 3.4）。

3.3 训练目标与 (1−t) 预处理（论文 Eq.10）

条件 Flow Matching 损失为：

LFM = Ex₀, x₁, z, t, k [ ‖ vθ(xtk, t) − vtk ‖² ]

论文在实现时对损失施加了 (1−t) 加权（或等价地对网络输出做 (1−t) 预处理），这与 Flow Matching 社区的常见做法一致：靠近 t=1 时目标已接近干净数据，权重降低；靠近 t=0 时噪声大，权重提高，加速收敛。

为什么要 (1−t) 加权？

直觉上，t→1 时 σt→0，xt 几乎等于 x₁，预测 v 很容易（接近常数），梯度信号弱且易过拟合；t→0 时 σt 最大，预测难度最高。用 (1−t) 重加权让优化器把更多容量花在难的区间。在视频生成的 Wan 模型里你也会看到类似的 flow_shift 调度，思想同源。

3.4 k-free：为什么不把 k 喂给网络

一个自然的想法是：把 k 作为条件输入网络（像时间 t 那样），让它显式知道当前走的是哪条路径。但论文实验发现：把 k 作为输入会（1）减慢收敛，（2）在漂移（drift）时产生有偏梯度。因此采用 k-free 设计：

vθ(xtk, t)   （输入只有 xtk 和 t，不含 k） 训练时 k 从 [0,1] 均匀采样，仅用于构造 xtk；网络通过 xtk 的分布隐式感知 k

这背后的逻辑是：k 已经编码在 xtk 的统计分布里了。给定 xtk 和 t，网络能从「这一点离 x₀ 有多近、噪声有多大」反推 k 的后验。把 k 显式塞入反而引入了一个不必要的条件维度，干扰了速度场学习。

这也是推理时的关键便利：用户可以自由选择 k 来控制行为，而网络本身不需要改。选 k=1 得到确定性预测，选 k=0 得到纯生成式采样，选中间值在两者间权衡。

3.5 附录 B：连续性方程视角（补充）

论文附录 B 从连续性方程（continuity equation）角度验证了该插值核的合法性：一族以 k 为参数的概率流 ptk(x) 满足 ∂tp + ∇·(v·p) = 0，其中 v 是上面的速度场。这保证了通过 ODE 积分得到的样本确实服从目标分布 p1(x₁)。换言之，Flow Marching 不是「凑出来的插值」，而是一个合法的概率流模型，k 只是参数化了一族从不同起点流向同一终点的流。

04误差累积的数学：为什么 FM 不爆炸

Flow Marching 最硬核的理论贡献在附录 A：它证明了基于 Flow Matching 的 rollout 误差是常数有界的，而确定性算子的误差是指数增长的。本章把证明思路讲清楚。

4.1 确定性算子的 Gronwall 爆炸

回顾 2.2：设神经算子 fθ 是 L-Lipschitz，单步误差上界 ε。N 步后：

‖xN − x̂N‖ ≤ ε · Σi=0N−1 Li ≤ ε · eLN 几何级数和；当 L ≥ 1 时随 N 指数/多项式发散

即使 L < 1，几何级数收敛到 ε/(1−L)，看似有界，但实际中神经算子的有效 Lipschitz 常数在分布外区域会急剧增大（数据漂移），导致 L 难以保持 < 1，误差还是会涨。

4.2 Flow Matching 的收缩结构

Flow Marching 的关键观察是：FM 的速度场天然带有一个指向 x₀ 的收缩项。把速度场改写一下（以 k≠0 为例）：

vtk = (x₁ − x₀) + (1−k)·(x₀ − z)·[1/(1−t)] · ... 形式上可分离出一个与 −(xt − x₀)/(1−t) 成正比的耗散项

更严谨地，论文将误差动力学写成：

d e / d t = A(t) · e + δ(t) e = xt − x̂t 为误差，A(t) 含收缩项 −1/(1−t)，δ(t) 为单步建模误差

这个 −1/(1−t) 项就是收缩/耗散的来源：它把误差往 0 拉，且 t 越接近 1 拉力越强（因为 1/(1−t) 发散）。这是 Flow Matching 概率流的固有性质——速度场把概率质量往数据分布 x₁「吸」，对偏离路径的误差起阻尼作用。

4.3 常数上界

对上述带收缩项的线性 ODE 用 Gronwall 引理的「收缩版」（即比较原理），论文得到：

‖eN‖ ≤ [ ρ / ((1 − L)(e − 1)) ] · Dmax ρ 是与路径有关的常数，L < 1 是收缩率，Dmax 是单步最大建模误差

注意：这个上界与 N（rollout 步数）无关。只要单步误差 Dmax 有界、收缩率 L < 1 成立，无论滚多少步，累积误差都被一个常数夹住。这与确定性算子的 eLN 形成鲜明对比。

N‖ 确定性算子：~ eLN（指数爆炸） Flow Marching：被常数上界夹住 上界 ρ/((1−L)(e−1))·Dmax 0
图 2：误差随 rollout 步数的增长对比。确定性神经算子（红）呈指数增长，远期必然崩溃；Flow Marching（紫）因速度场的收缩项，误差被一个与 N 无关的常数（绿虚线）钳住。
证明的前提条件

常数上界成立需要：① 速度场 vθ 在数据分布附近是 L-Lipschitz 且 L < 1（收缩）；② 单步建模误差 Dmax 有界。前者由 Flow Matching 的训练目标保证（网络学到的是指向数据的收敛流），后者是标准假设。在分布外区域 L 可能失效，这也是为什么论文配合物理预训练的 P2VAE 来约束 latent 分布（第 5 章）。

4.4 这对实践意味着什么

  • 长时程 rollout 不再必然发散：只要模型训练充分，滚几万步误差也不会飞。这是 PDE 基础模型从「短期玩具」走向「长时程预测工具」的关键一跃。
  • k 的选择是精度-随机性的 trade-off：k 越大越接近确定性，短期越准但收缩性越弱（k=1 时 σ=0，收缩项消失，回到 Gronwall）；k 越小随机性越强、收缩性越强但短期方差大。实践中 k 取中间值（如 0.3~0.7）兼顾两者。
  • 不确定性是免费的：因为路径含噪声 z，多次采样 k<1 的路径即可得到预测分布，从而量化不确定性（第 6 章展开）。

05架构详解：P2VAE + FMT + 潜在时间金字塔

数学框架确定后，论文搭建了一套完整的生成式 PDE 基础模型：先用 P2VAE 把高维物理场压进 latent，再用 FMT（Flow Marching Transformer）在 latent 空间做 Flow Marching，并通过潜在时间金字塔把注意力复杂度砍掉 15×。

5.1 P2VAE：物理预训练的潜空间自编码器

P2VAE（Physics-pretrained VAE）的架构沿用 Stable Diffusion 的 VAE 风格，但有两个关键定制：

  • 通道与分辨率：输入 c3 p128（3 通道、128×128 物理场），压缩到 c16 p16（16 通道、16×16 latent）。空间压缩 8×8 = 64 倍，通道从 3 升到 16，总体积压缩 12×。
  • 物理预训练：VAE 不只是用像素重建损失训练，还在大量无标注 PDE 轨迹上做预训练（自监督重建），让 latent 空间天然携带物理结构（守恒律、平滑性），约束后续 FMT 的分布外行为。
物理场 x 3 × 128 × 128 → P2VAE encoder → latent y 16 × 16 × 16 体积压缩 12×，空间 64×，通道升 16

这与 Wan-VAE 的角色完全对应（视频领域叫 Wan-VAE，PDE 领域叫 P2VAE），都是「把高维信号压进可操作的 latent」。

5.2 FMT：Flow Marching Transformer

FMT 是执行 Flow Marching 速度场预测的主干，一个基于 SiT（Smooth Induced Transformer）风格的 Transformer，主要组件：

组件设计作用
AdaLN-Zero 调制用 (t, 条件) 生成 scale/shift/gate，零初始化把时间步与历史条件注入每个 Transformer 块，训练初期稳定
RMSNorm + SwiGLU归一化用 RMSNorm，FFN 用 SwiGLU训练稳定、表达能力强（与 LLaMA 同款）
FlashAttention v2高效注意力实现降显存、提速度，支撑长序列
GRU 条件编码 hs把历史状态序列编码为条件向量让 FMT 利用多步历史预测下一步
潜在时间金字塔多分辨率下采样 token注意力复杂度节省 η=15×

5.2.1 GRU 条件：把历史喂进来

PDE 预测需要利用历史（而不只是当前 x₀）。论文用一个 GRU 把历史状态序列 (x−s+1, …, x₀) 编码为隐状态 hs，作为 FMT 的条件输入（通过 AdaLN 调制）。这与视频模型里的「KV cache / 历史帧」是一回事。

hs = GRU(x−s+1, …, x₀) hs 通过 AdaLN 的 scale/shift/gate 注入每个 FMT 块

5.2.2 潜在时间金字塔（Latent Temporal Pyramid）

这是 FMT 最巧妙的工程设计。物理场的 latent 是 16×16×16，展开成 token 是 256 个（16×16），注意力是 O(n²)=65536。但实际上，物理场的不同频率成分需要不同的「时间分辨率」：大尺度结构变化慢、小尺度结构变化快。

论文把 latent 下采样成多个分辨率，组成金字塔：

y₃ 16×16 = 256 tokens 最细粒度
Down(y₂, 2) 8×8 = 64 tokens 2× 下采样
Down(y₁, 4) 4×4 = 16 tokens 4× 下采样
Down(y₀, 8) 2×2 = 4 tokens 8× 下采样，最粗粒度

注意力复杂度从单层的 256² = 65536 降到金字塔总复杂度。论文报告 η = 15× 的注意力计算节省，同时因为粗分辨率 token 覆盖更大感受野，长程依赖建模反而更好。

15× 是怎么算出来的

单层全注意力：256² ≈ 6.56e4。金字塔四层：256² + 64² + 16² + 4² = 65536 + 4096 + 256 + 16 = 69904？不对——关键是金字塔不是四层都做全注意力，而是跨分辨率的稀疏注意力：粗层 token 只与细层对应区域的少数 token 交互。论文的 η=15× 是实测 FLOPs 比例，核心思路是「用多分辨率把 O(n²) 摊薄成接近 O(n)」。这与视频模型里的时空因子化注意力、Hierarchical Attention 异曲同工。

5.2.3 联合损失 L_CFM（论文 Eq.13）

训练时同时优化 Flow Matching 损失与 VAE 重建损失：

LCFM = LFM + λ · LVAE LVAE 是 P2VAE 的重建 + KL 散度，λ 平衡两者

这样 P2VAE 与 FMT 端到端联合训练，latent 空间被同时塑形为「物理上合理」且「Flow Marching 易学好」。

06推理与不确定性量化

训练好 FMT 后，推理就是沿速度场积分。本章讲确定性的 Euler ODE 积分，以及 Flow Marching 的两大不确定性旋钮：k₃（初始条件不确定性）与 η（偶然不确定性）。

6.1 确定性推理：Euler ODE

给定当前状态 x₀（及其历史 hs），选择一个 k，构造起点：

x0k = k · x₀ + (1 − k) · z，   z ~ N(0, I)

然后用 Euler 法从 t=0 积分到 t=1，步数 N=100，dt=0.01：

xt+dtk = xtk + dt · vθ(xtk, t) 共 100 步，每步一次 FMT 前向；终点 x₁k 即下一步预测

把 x₁ 再作为新的 x₀，重复上述过程，就得到长时程 rollout。由于误差是常数有界的（第 4 章），这一过程可以稳定地滚很远。

为什么用 Euler 不用高阶求解器？

Flow Matching 的训练路径是直线（OT 路径），速度场近似常数，Euler 法的截断误差已经很小。高阶求解器（RK4、Heun）每步要多次前向，性价比不高。论文用 N=100 步 Euler，在精度与速度间取得平衡。GenCast 等工作也用类似配置。

6.2 不确定性来源与两个旋钮

PDE 预测的不确定性有两类，Flow Marching 分别用两个独立旋钮控制：

不确定性类型含义旋钮控制方式
初始条件（IC）不确定性当前状态 x₀ 本身有测量噪声/不完备k₃减小 k → 起点掺更多噪声 z → 预测分布更宽
偶然（Aleatoric）不确定性系统本身的随机性（湍流混沌）η在 ODE 中注入 SDE 噪声项，η 控强度

关键点：k₃ 与 h₃（历史长度）解耦——传统方法里历史越长越确定，但 Flow Marching 里你可以独立调 k₃ 来表达「我对当前状态有多不信任」，不受历史长度影响。这是 k-free 设计带来的额外红利。

6.3 k₃：初始条件不确定性

在推理起点 x₀k = k·x₀ + (1−k)·z 中，k 越小，噪声权重越大，相当于承认「x₀ 可能不准，让我从一个更宽的分布出发」。多次采样不同的 z，得到一组 x₁ 预测，其方差即 IC 不确定性。

  • k=1：完全信任 x₀，无 IC 不确定性，确定性预测；
  • k→0：完全不信任 x₀，从纯噪声出发，退化为无条件生成，不确定性最大。

6.4 η：偶然不确定性（reverse-time SDE）

对于混沌系统（如湍流），即使 IC 完全确定，长期演化也发散。Flow Marching 用 reverse-time SDE 注入随机性，把确定性 ODE 升级为：

d x = vθ(xt, t) d t + η · σt · d W dW 是布朗运动增量，η ≥ 0 控制噪声强度；η=0 退化为确定性 ODE

用 Euler-Maruyama 离散化：

xt+dt = xt + dt · vθ(xt, t) + η · σt · √dt · ξ，   ξ ~ N(0, I) σt = (1−t)(1−k) 沿用插值核的尺度项

η 越大，路径随机性越强，多次采样的预测分布越宽，反映系统的混沌性。注意噪声项带 σt，所以靠近 t=1 时噪声自动衰减到 0（因为 σ1=0），保证终点 x₁ 仍是干净数据。

图 4：两个不确定性旋钮。k₃ 控制起点的噪声混合程度（IC 不确定性），η 控制路径中的 SDE 噪声强度（偶然不确定性）。两者独立可调，终点都收敛到 x₁。

6.5 与其他方法的对比

方法起点误差有界不确定性每步开销

7.1 核心：插值核、速度场与损失

"""Flow Marching 核心：位置-尺度插值核、速度场、k-free 损失。

示意实现，对应论文 arXiv:2509.18611 Eq.4-10。
非官方代码，仅用于教学。
"""
import torch
import torch.nn as nn


def interpolate(x0: torch.Tensor, x1: torch.Tensor, k: float, t: torch.Tensor):
    """位置-尺度插值核（论文 Eq.4-6）。

    Args:
        x0: 当前状态 (B, ...)，已知的物理场 latent
        x1: 下一状态 (B, ...)，训练目标
        k:  桥接参数 k ∈ [0,1]
        t:  时间步 (B,) 或 (B,1,...)，t ∈ [0,1]

    Returns:
        xt_k: 插值后状态 x_t^k
        vt_k: 真实速度场 v_t^k
    """
    # 把 t 扩展到与 x0 同维
    while t.dim() < x0.dim():
        t = t.unsqueeze(-1)

    # 标准高斯噪声（Flow Matching 里的 z）
    z = torch.randn_like(x0)

    # 位置项 μ_t = t·x1 + k(1-t)·x0
    mu_t = t * x1 + k * (1.0 - t) * x0
    # 尺度项 σ_t = (1-t)(1-k)
    sigma_t = (1.0 - t) * (1.0 - k)

    # x_t^k = μ_t + σ_t · z
    xt_k = mu_t + sigma_t * z

    # 真实速度 v_t^k = d(xt_k)/dt = (x1 - k·x0) - (1-k)·z
    vt_k = (x1 - k * x0) - (1.0 - k) * z

    return xt_k, vt_k


def flow_marching_loss(v_theta, x0, x1):
    """k-free Flow Matching 损失（论文 Eq.10，带 (1-t) 加权）。

    v_theta: 网络 v_θ(xt_k, t) -> 预测速度
    注意：网络输入只有 (xt_k, t)，不含 k —— k-free 设计。
    """
    B = x0.shape[0]
    device = x0.device

    # t ~ Uniform(0,1)
    t = torch.rand(B, device=device)
    # k ~ Uniform(0,1)，仅用于构造 xt_k，不喂给网络
    k = torch.rand(1, device=device).item()

    xt_k, vt_k = interpolate(x0, x1, k, t)

    # k-free：网络只吃 (xt_k, t)
    v_pred = v_theta(xt_k, t)

    # (1-t) 加权的 MSE 损失
    weight = (1.0 - t)
    while weight.dim() < v_pred.dim():
        weight = weight.unsqueeze(-1)
    loss = (weight * (v_pred - vt_k) ** 2).mean()
    return loss


# ---- 验证两个极限 ----
if __name__ == "__main__":
    x0 = torch.zeros(1, 3, 4, 4)
    x1 = torch.ones(1, 3, 4, 4)
    t = torch.tensor([0.5])

    # k=1：确定性残差，σ=0，速度 = x1 - x0
    xt, vt = interpolate(x0, x1, k=1.0, t=t)

7.2 FMT：带 GRU 条件的 Transformer 速度场网络

fmt_conditional.pyPython
"""FMT (Flow Marching Transformer) 示意实现。

含：时间嵌入、AdaLN-Zero 调制、GRU 条件、潜在时间金字塔。
非官方代码，仅用于教学。
"""
import torch
import torch.nn as nn
import torch.nn.functional as F


class SinusoidalTimeEmbed(nn.Module):
    """正弦时间嵌入（扩散模型标配）。"""
    def __init__(self, dim):
        super().__init__()
        self.dim = dim

    def forward(self, t):
        half = self.dim // 2
        freqs = torch.exp(-torch.log(torch.tensor(10000.0)) *
                          torch.arange(half, device=t.device) / half)
        args = t[:, None] * freqs[None]
        return torch.cat([torch.sin(args), torch.cos(args)], dim=-1)


class AdaLNZero(nn.Module):
    """AdaLN-Zero：用 (t_embed, h_s) 生成 scale/shift/gate，零初始化。"""
    def __init__(self, hidden_dim, cond_dim):
        super().__init__()
        self.norm = nn.RMSNorm(hidden_dim)
        # 把 条件映射成 6 个参数（scale1, shift1, gate1, scale2, shift2, gate2）
        self.linear = nn.Linear(cond_dim, 6 * hidden_dim)
        nn.init.zeros_(self.linear.weight)
        nn.init.zeros_(self.linear.bias)

    def forward(self, x, cond):
        s1, sh1, g1, s2, sh2, g2 = self.linear(cond).chunk(6, dim=-1)
        # cond 需要扩展到 token 维
        x = self.norm(x) * (1 + s1.unsqueeze(1)) + sh1.unsqueeze(1)
        return x, (g1.unsqueeze(1), g2.unsqueeze(1), s2.unsqueeze(1), sh2.unsqueeze(1))


class FMTBlock(nn.Module):
    """一个 FMT 块：RMSNorm + FlashAttn（这里用 SDPA 代替）+ SwiGLU FFN。"""
    def __init__(self, dim, num_heads, cond_dim):
        super().__init__()
        self.adaln = AdaLNZero(dim, cond_dim)
        self.attn = nn.MultiheadAttention(dim, num_heads, batch_first=True)
        self.norm2 = nn.RMSNorm(dim)
        # SwiGLU FFN
        self.w1 = nn.Linear(dim, dim * 4)
        self.w2 = nn.Linear(dim * 4, dim)
        self.w3 = nn.Linear(dim, dim * 4)

    def forward(self, x, cond):
        h, (g1, g2, s2, sh2) = self.adaln(x, cond)
        attn_out, _ = self.attn(h, h, h)
        x = x + g1 * attn_out
        h2 = self.norm2(x) * (1 + s2) + sh2
        ff = self.w2(F.silu(self.w1(h2)) * self.w3(h2))
        x = x + g2 * ff
        return x


class LatentTemporalPyramid(nn.Module):
    """潜在时间金字塔：把 (B, C, H, W) 拆成多分辨率 token 序列。"""
    def __init__(self, downsample_ratios=(8, 4, 2, 1)):
        super().__init__()
        self.ratios = downsample_ratios

    def forward(self, y):
        """y: (B, C, H, W) -> list of (B, N_i, C)"""
        tokens_list = []
        for r in self.ratios:
            if r == 1:
                yi = y
            else:
                yi = F.avg_pool2d(y, kernel_size=r, stride=r)
            B, C, h, w = yi.shape
            tokens_list.append(yi.flatten(2).transpose(1, 2))  # (B, h*w, C)
        return tokens_list  # token 数 4 / 16 / 64 / 256


class FMT(nn.Module):
    """完整 FMT：输入 xt_k 与 t，条件 h_s，输出预测速度。"""
    def __init__(self, in_channels=16, hidden=256, num_heads=8,
                 num_layers=6, cond_dim=128, history_len=8):
        super().__init__()
        self.time_embed = SinusoidalTimeEmbed(hidden)
        # GRU 编码历史状态 -> h_s
        self.history_gru = nn.GRU(input_size=in_channels * 16 * 16,
                                  hidden_size=cond_dim, batch_first=True)
        self.cond_proj = nn.Linear(hidden + cond_dim, cond_dim)
        self.input_proj = nn.Linear(in_channels, hidden)
        self.pyramid = LatentTemporalPyramid()
        self.blocks = nn.ModuleList([FMTBlock(hidden, num_heads, cond_dim)
                                     for _ in range(num_layers)])
        self.output_proj = nn.Linear(hidden, in_channels)

    def forward(self, xt_k, t, history=None):
        """
        xt_k: (B, C, H, W)  当前插值状态
        t:    (B,)          时间步
        history: (B, S, C, H, W) 历史 S 步状态，可选
        """
        B, C, H, W = xt_k.shape
        t_emb = self.time_embed(t)  # (B, hidden)

        # GRU 编码历史 -> h_s
        if history is not None:
            hist_flat = history.flatten(2)  # (B, S, C*H*W)
            _, h_s = self.history_gru(hist_flat)
            h_s = h_s.squeeze(0)  # (B, cond_dim)
        else:
            h_s = torch.zeros(B, self.history_gru.hidden_size, device=xt_k.device)

        cond = self.cond_proj(torch.cat([t_emb, h_s], dim=-1))  # (B, cond_dim)

        # 金字塔 token 化
        tokens_list = self.pyramid(xt_k)
        # 拼接所有分辨率 token
        x = torch.cat(tokens_list, dim=1)  # (B, N_total, C)
        x = self.input_proj(x)

        for blk in self.blocks:
            x = blk(x, cond)

        x = self.output_proj(x)
        # 只取最细分辨率（最后 256 个 token）还原成 (B, C, H, W)
        out = x[:, -H * W:].transpose(1, 2).reshape(B, C, H, W)
        return out

7.3 推理：Euler ODE、SDE 与双旋钮

inference.pyPython
"""Flow Marching 推理：Euler ODE（确定）/ Euler-Maruyama SDE（随机）。

实现 k₃（IC 不确定性）与 η（偶然不确定性）双旋钮。
非官方代码，仅用于教学。
"""
import torch


@torch.no_grad()
def euler_ode(v_theta, x0, k=1.0, num_steps=100, history=None):
    """确定性 Euler ODE 积分：从 x₀^k 积分到 x₁。

    Args:
        v_theta: 训练好的 FMT
        x0: 当前状态 (B, C, H, W)
        k:  桥接参数，控制 IC 不确定性（k=1 确定，k→0 随机）
        num_steps: 积分步数 N
    Returns:
        x1_pred: 预测的下一状态
    """
    device = x0.device
    dt = 1.0 / num_steps

    # 构造起点 x_0^k = k·x0 + (1-k)·z
    z = torch.randn_like(x0)
    xt = k * x0 + (1.0 - k) * z

    for i in range(num_steps):
        t = torch.full((x0.shape[0],), i / num_steps, device=device)
        vt = v_theta(xt, t, history=history)
        xt = xt + dt * vt

    return xt  # t=1 时的状态即 x1 预测


@torch.no_grad()
def euler_maruyama_sde(v_theta, x0, k=1.0, eta=0.0, num_steps=100, history=None):
    """带噪声的 SDE 积分（Euler-Maruyama），η 控制偶然不确定性。

    SDE: dx = v_θ dt + η·σ_t·dW
    """
    device = x0.device
    dt = 1.0 / num_steps

    z = torch.randn_like(x0)
    xt = k * x0 + (1.0 - k) * z

    for i in range(num_steps):
        t_val = i / num_steps
        t = torch.full((x0.shape[0],), t_val, device=device)
        vt = v_theta(xt, t, history=history)

        # σ_t = (1-t)(1-k)
        sigma_t = (1.0 - t_val) * (1.0 - k)
        # 噪声项：η·σ_t·√dt·ξ
        noise = eta * sigma_t * (dt ** 0.5) * torch.randn_like(xt)

        xt = xt + dt * vt + noise

    return xt


@torch.no_grad()
def rollout(v_theta, x0_init, num_steps_ahead=200, k=1.0, eta=0.0,
            ode_steps=100, history=None):
    """长时程 rollout：把每步预测作为下一步输入。"""
    trajectory = [x0_init]
    x_cur = x0_init
    hist = history
    for _ in range(num_steps_ahead):
        if eta > 0:
            x_next = euler_maruyama_sde(v_theta, x_cur, k=k, eta=eta,
                                        num_steps=ode_steps, history=hist)
        else:
            x_next = euler_ode(v_theta, x_cur, k=k, num_steps=ode_steps,
                               history=hist)
        trajectory.append(x_next)
        x_cur = x_next
        # 可选：更新 history（滑动窗口）
    return trajectory

    # 1. IC 不确定性：固定 η=0，扫 k
    for k in [1.0, 0.7, 0.5, 0.3, 0.0]:
        preds = [euler_ode(v_theta, x0, k=k) for _ in range(20)]
        mean_pred = torch.stack(preds).mean(0)
        std_pred = torch.stack(preds).std(0)
        print(f"k={k}: IC 不确定性（预测标准差）={std_pred.mean().item():.4f}")

    # 2. 偶然不确定性：固定 k，扫 η
    for eta in [0.0, 0.1, 0.3, 0.5]:
        preds = [euler_maruyama_sde(v_theta, x0, k=0.5, eta=eta)
                 for _ in range(20)]
        std_pred = torch.stack(preds).std(0)
        print(f"η={eta}: 偶然不确定性={std_pred.mean().item():.4f}")

训练数据覆盖 16 个 PDE 子集，每个子集包含大量轨迹（从数千到数百万条不等），总数据体积达 TB 级。数据类型包括：

09与视频生成方法的对照

考虑到本文读者多来自视频生成背景（Wan 系列），本章给出一张「PDE 世界 ↔ 视频世界」的概念映射表，帮助你把 Flow Marching 的思想迁移到熟悉的领域。

核心同构性

视频生成与时序 PDE 预测在数学结构上高度同构：都是给定历史状态，预测下一状态，然后自回归滚下去。因此 Flow Marching 的核心思想（用 k 桥接确定性残差与 Flow Matching、误差有界、双旋钮不确定性）完全可以移植到视频生成。

9.2 为什么视频领域值得借鉴 Flow Marching

视频生成的长视频问题本质上就是 PDE 的 long-term rollout 问题——逐帧自回归会累积误差（闪烁、漂移、变形）。当前视频领域的主流解法：

  • Diffusion Forcing：训练时随机选「预测起点」，让模型既能从干净帧也能从带噪帧出发，缓解 exposure bias；
  • Self-Forcing（Adobe, arXiv:2506.08009）：在训练中混入模型自己的预测作为条件，缩小训练-推理 gap；
  • DPOT 噪声注入：在条件帧上加噪，提升鲁棒性。

Flow Marching 的 k 参数实际上是把「条件帧加噪」这件事从工程技巧升级为有数学保证的概率流：k 不是随便设的噪声强度，而是插值核的一个连续参数，且误差有界性有严格证明。如果把 Flow Marching 移植到视频生成，理论上可以得到「长视频不漂移 + 不确定性量化」的双重收益。

一个可尝试的视频实验

把 Wan 的 Flow Matching 训练目标改成 Flow Marching 形式：xtk = t·x₁ + (1−t)·[k·x₀ + (1−k)·z]，其中 x₀ 是首帧/已知帧。k 从 [0,1] 均匀采样，网络仍只吃 (xt, t)。推理时用 k∈[0.5, 0.9] 兼顾首帧锚定与生成多样性。这本质上是把「图生视频的首帧条件」从硬约束变成了概率流的一部分，可能改善长视频的首帧一致性与稳定性。

10局限与后续演进

10.1 已知局限

  • 官方代码未发布：截至 2026-11，论文作者未开源实现，GitHub 上的同名仓库多为 404 或占位。复现需自行按公式实现（本文第 7 章给出参考）。
  • 推理步数仍多：每步预测需要 ~100 次 FMT 前向，比确定性神经算子的 1 次前向慢两个量级。虽然误差有界，但 wall-clock 速度仍是工程瓶颈。
  • k 的最优取值依赖任务：不同 PDE、不同噪声水平下，最优 k 不同，需要调参或自适应。
  • 高维空间的 SDE 校准：η 旋钮在高维 latent 空间的校准仍非平凡，不确定性估计的可靠性需要更多验证。

10.2 后续演进：被 Latent Generative Solvers 取代

论文 v2（2026-04）在首页注明：本工作已被后续论文 arXiv:2602.11229《Latent Generative Solvers》 取代。演进方向主要是：

  • 把 Flow Marching 从「单步预测 + rollout」升级为「直接生成整条 latent 轨迹」，进一步减少误差累积；
  • 引入更高效的 latent 求解器，降低推理步数；
  • 扩展到更多物理系统与更高维度。

但 Flow Marching 的核心思想——用连续参数桥接确定性与随机性、并获得可证明的误差有界性——仍然是后续工作的基石。
