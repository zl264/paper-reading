MAR：不预测“词表类别”，而为每个连续 token 学一个分布

Autoregressive Image Generation without Vector Quantization：从 per-token Diffusion Loss，到双向 MAE 编码器、随机顺序 mask、余弦分组采样与官方 PyTorch 源码。

本文逐节阅读 Li、Tian、Li、Deng、He 的 Autoregressive Image Generation without Vector Quantization，并静态核对官方 LTH14/mar 的 MAR、DiffLoss、训练与评估实现。本文未运行模型训练或推理；论文与 README 中的性能/资源声明不写作本地实测。

1. 小白直觉：不是先选定一个词，而是逐渐“长成”一个向量

VQ 类生成模型先把图像编码为离散码本索引，再像语言模型一样预测下一个词。MAR 换了一个问题：如果 latent token 是连续向量，为什么还要先把它塞进有限词表？

它的答案是：自回归真正需要的是“根据过去内容，预测下一个 token 的概率分布”，并不强制这个分布是离散的。对每个连续 token，可以用一个小扩散模型从高斯噪声逐渐生成它，而不是用 softmax 在 K 个类别中做选择。

所以 MAR 的两层结构非常清楚：大的 Transformer 负责根据已知 token 生成条件向量 z，小的 DiffLoss MLP 负责在这个 z 的指导下生成连续 token。

一句话区分：VQ 路线预测“码本第几个词”；MAR 预测“在这个上下文条件下，连续向量可能长什么样”。后者不再受码本量化误差的直接限制，但每个 token 的采样仍需要扩散步骤。

2. 概率分解：从下一 token 到下一组 token

普通自回归模型把 token 序列写成：

p(x¹,…,xⁿ)=∏i=1n p(xi | x¹,…,xi−1)(1)

对 MAR，xi 可以是连续值。网络先根据过去 token 得到条件向量 zi=f(x¹,…,xi−1)，再由扩散过程表示 p(xi|zi)。梯度会从扩散损失回传到 z，从而更新 Transformer。

masked autoregressive 进一步把一次预测推广为“下一组 token”：每一步预测一个子集 X^k，而不是只能选一个 token：

p(X¹,…,XK)=∏k p(Xk | X¹,…,Xk−1)(2)

这些子集按随机顺序覆盖全部 token。它与 MaskGIT 有联系，但 MAR 强调随机顺序与对 token 概率分布的温度采样，而不是只随机化位置调度。

3. Diffusion Loss：连续 token 的训练目标是什么

对每个 token 的真实连续值 x，随机选扩散时间 t，加入高斯噪声 ε，得到带噪 token x_t。条件 MLP 接收 x_t、t 和 Transformer 条件 z，预测噪声：

L = Ex,z,t,ε || ε − εθ(xt,t,z) ||²(3)

这不是对整张图片做一次扩散，而是对每个 latent token建立条件扩散分布。多个 token 可在一个 batch 中并行计算训练损失，但推理时每组 token 仍需经过若干扩散采样步骤。

官方 DiffLoss.forward 使用 1000 步 cosine 训练扩散过程，调用 training_losses 得到 loss，再按 token mask 做加权平均；生成时则使用较少的采样步数（默认 100）。可选的 VLB 输出也与双头通道有关。

官方源码节选 · models/diffloss.py：训练损失
def forward(self,target,z,mask=None):
    t = torch.randint(0,self.train_diffusion.num_timesteps,
                      (target.shape[0],),device=target.device)
    model_kwargs = dict(c=z)
    loss_dict = self.train_diffusion.training_losses(
        self.net,target,t,model_kwargs)
    loss = loss_dict["loss"]
    if mask is not None:
        loss = (loss*mask).sum()/mask.sum()
    return loss.mean()

这里 mask 用于只计算未知/待预测 token；如果把已知 token 也纳入损失，训练任务就不再对应 masked generation。

4. 连续 tokenizer 与数据预处理：KL-16 到底提供什么

MAR 使用 LDM 的 KL-16 连续 autoencoder，而不是 VQ-16 的离散码本。256×256 图像经 stride=16 压缩为 16×16 latent 网格，patch_size=1 时得到 256 个 token，每个 token 包含 vae_embed_dim=16 个连续值。

官方训练循环中，VAE 编码得到对角高斯后验，采样 latent 后乘 0.2325 做尺度标准化。这个系数是当前官方实现的预处理约定；更换 tokenizer 时必须重新核对，而不是把所有 VAE latent 都视为同一尺度。

5. 详细网络：MAE 式编码器—解码器与条件注入

MAR 不是只能使用 causal GPT attention。官方默认 MAR 使用 MAE 式双向编码器与解码器：已知 token 互相可见，未知 token 的位置用 mask token 与位置编码填充，解码器输出每个待预测位置的 z。

组件输入作用与形状

z_projtoken 向量投到 encoder_embed_dim
class/fake latent buffer类别标签或无条件 fake latent64 个 buffer token 稳定条件编码
encoder已知 token + 位置编码双向 attention，只编码未 mask 位置
decoder已知特征 + mask token + 位置编码恢复所有待预测位置的 z
DiffLossz、目标 token、mask逐 token 条件扩散损失

以官方 MAR-L 为例，encoder 和 decoder 各 16 个 block、宽度 1024、16 头，总计约 479M 参数（README 发布模型）；DiffLoss 的 MLP 深度/宽度可在训练配置中独立调节。

6. 随机顺序与 mask：代码到底怎样选择未知 token

每个样本有自己的随机排列 order。训练时 mask ratio 从偏高 masking 的截断分布采样，默认最少约 0.7；把排列前 num_masked_tokens 个位置设为未知。编码器只保留已知 token，解码器再用 mask token 补齐未知位置。

官方源码节选 · models/mar.py：随机顺序与 mask
def sample_orders(self,bsz):
    orders=[]
    for _ in range(bsz):
        order=np.array(list(range(self.seq_len)))
        np.random.shuffle(order)
        orders.append(order)
    return torch.Tensor(np.array(orders)).cuda().long()

def random_masking(self,x,orders):
    mask_rate=self.mask_ratio_generator.rvs(1)[0]
    num_masked_tokens=int(np.ceil(x.shape[1]*mask_rate))
    mask=torch.zeros(x.shape[0],x.shape[1],device=x.device)
    return torch.scatter(mask,dim=-1,
        index=orders[:,:num_masked_tokens],
        src=torch.ones(x.shape[0],x.shape[1],device=x.device))

解码器将 encoder 输出填回已知位置、mask token 填入未知位置，再加 decoder 位置编码和 diffusion 专用位置编码。这样 z 不仅知道“内容是什么”，还知道“需要预测哪个位置”。

7. DiffLoss MLP：时间嵌入与 z 怎样通过 AdaLN 进入

官方 SimpleMLPAdaLN 先把带噪 token x 投影到 MLP 宽度；时间 t 经正弦 embedding + MLP，条件 z 经线性层。两者相加得到 y=t+c，再在每个 residual block 中生成 shift、scale、gate。

h=LN(x)⊙(1+scale(y))+shift(y)，   x′=x+gate(y)⊙MLP(h)(4)

这种调制让条件 z 和时间步共同控制去噪，而不是简单把 z 拼到输入向量。AdaLN 最后一层与输出层采用零初始化，保持初始稳定。

官方源码节选 · SimpleMLPAdaLN.forward
x = self.input_proj(x)
t = self.time_embed(t)
c = self.cond_embed(c)
y = t+c
for block in self.res_blocks:
    x = block(x,y)
return self.final_layer(x,y)

# ResBlock 内部：
shift,scale,gate = self.adaLN_modulation(y).chunk(3,dim=-1)
h = modulate(self.in_ln(x),shift,scale)
h = self.mlp(h)
return x+gate*h

默认训练配置使用 3 个 residual blocks、宽 1024；评估更大模型时可增加 DiffLoss 深度/宽度。主 Transformer 与 DiffLoss 的容量是可分别调整的，不应把它们看成一个不可拆分的网络。

8. 训练调用链：从图片到一次完整反向传播

官方训练链条可整理为：

  1. main_mar.py 创建 MAR、VAE、数据加载器、optimizer 与 EMA。
  2. engine_mar.train_one_epoch 编码图像并标准化 latent。
  3. MAR.forward patchify、随机 order/mask、MAE encoder/decoder、得到 z。
  4. forward_loss 将 target、z、mask 展平，并按 diffusion_batch_mul 复制以增加扩散 batch。
  5. DiffLoss.forward 采样扩散时间并计算条件去噪损失；mask 只保留待预测 token。
  6. 反向传播、梯度裁剪、optimizer step 与 EMA 更新。
官方源码节选 · forward_loss 的扩散 batch
def forward_loss(self,z,target,mask):
    bsz,seq_len,_ = target.shape
    target = target.reshape(bsz*seq_len,-1).repeat(self.diffusion_batch_mul,1)
    z = z.reshape(bsz*seq_len,-1).repeat(self.diffusion_batch_mul,1)
    mask = mask.reshape(bsz*seq_len).repeat(self.diffusion_batch_mul)
    return self.diffloss(z=z,target=target,mask=mask)

diffusion_batch_mul 让每个 token 在同一主 Transformer 条件下拥有更多扩散噪声/时间采样，有助于训练 DiffLoss，但会增加去噪头的计算量。它不是增加图片 batch，也不是复制不同的语义类别。

9. 推理：随机分组、余弦 mask 调度与逐 token 扩散采样

推理从全部 token 未知开始。每次迭代读取当前已知 token，预测本轮要揭示的位置，并用 DiffLoss 从高斯噪声生成这些连续 token。下一轮 mask 长度按 cosine 逐渐减少：

mask_ratio(step)=cos( π/2 · (step+1)/num_iter )(5)

默认 num_iter=64；论文也支持更多/更少步数与速度—质量权衡。每一步新揭示的位置是当前 mask 与下一轮 mask 的差集，而不是简单覆盖所有未知位置。

官方源码节选 · MAR.sample_tokens 的逐组生成
for step in range(num_iter):
    x = self.forward_mae_encoder(tokens,mask,class_embedding)
    z = self.forward_mae_decoder(x,mask)
    mask_ratio = np.cos(math.pi/2.*(step+1)/num_iter)
    mask_len = torch.floor(self.seq_len*mask_ratio)
    mask_next = mask_by_order(mask_len,orders,bsz,self.seq_len)
    mask_to_pred = torch.logical_xor(mask[:bsz].bool(),mask_next.bool())
    z = z[mask_to_pred.nonzero(as_tuple=True)]
    sampled = self.diffloss.sample(z,temperature,cfg_iter)
    cur_tokens[mask_to_pred.nonzero(as_tuple=True)] = sampled
    tokens = cur_tokens.clone()

最终 unpatchify 把连续 token 恢复成 VAE latent，再由 VAE decoder 输出图片。MAR 的外层迭代与 DiffLoss 的内层去噪是两个不同循环，报告速度时需要同时给出 num_iter 与 diffusion sampling steps。

10. CFG：类别条件与 fake latent 怎样配合

训练时类别 embedding 以一定概率替换为可学习 fake_latent，提供无条件生成分支。推理时真实类别与 fake latent 组成两路 batch，分别在 MAR 与 DiffLoss 中生效。

ε = εuncond + cfg·(εcond−εuncond)(6)

官方 forward_with_cfg 在 DiffLoss 内对条件/无条件噪声预测做差分，并保留另一半 VLB 通道。MAR 外层采样还可用线性 schedule 逐步增加 cfg，而非常数；采样后只保留真实类别那一路 token。

官方源码节选 · DiffLoss 的 CFG
half = x[:len(x)//2]
combined = torch.cat([half,half],dim=0)
model_out = self.forward(combined,t,c)
eps,rest = model_out[:,:self.in_channels],model_out[:,self.in_channels:]
cond_eps,uncond_eps = torch.split(eps,len(eps)//2,dim=0)
half_eps = uncond_eps+cfg_scale*(cond_eps-uncond_eps)
eps = torch.cat([half_eps,half_eps],dim=0)
return torch.cat([eps,rest],dim=1)

CFG 的两个层级不要混淆：类别条件影响 MAR 的 z，条件/无条件噪声预测在 DiffLoss 内合并。两路 batch 的顺序和 mask 必须一致，否则可能把不同位置的语义错误混合。

论文比较了 AR/MAR、raster/random 顺序、causal/bidirectional attention、单 token/多 token 预测，以及 VQ-16 与 KL-16 tokenizer。这样的对比帮助我们分别回答：

12. 局限、成本与常见误解

  • 去掉 VQ 不等于去掉采样成本。每个 token 仍需扩散去噪，MAR 外层也需要多次迭代。
  • 双向编码器不等于看见未来真值。训练只编码已知 token，未知位置以 mask token 表示。
  • 连续 token 仍受 tokenizer 限制。KL autoencoder 的重建能力决定 latent 信息上限。
  • 温度作用于生成分布。温度、CFG、外层 num_iter 和内层扩散步共同影响质量与速度。
  • 不同任务需重新校准 latent。更换 VAE、分辨率或数据模态时，0.2325 等预处理常数不能照搬。

13. 复现与单元测试清单

  • 核对 VAE stride、latent 通道、patch_size 与 token 数量；256²/KL-16/patch1 应为 256 token。
  • 检查 latent 标准化系数与缓存数据是否使用同一预处理。
  • 验证随机 order 对每个样本独立，mask 的已知/未知位置与 decoder 填充一致。
  • 检查 diffusion loss 只在 mask 位置计算，diffusion_batch_mul 的 target/z/mask 同步复制。
  • 验证 AdaLN 的时间与 z 条件形状，以及输出双头的语义。
  • 检查 CFG 两路顺序、mask_to_pred 差集和采样后只保留真实类别分支。
  • 分别记录外层迭代数、内层扩散步数、VAE 解码与硬件成本。

附录 A：为什么“预测一个分布”比“选一个类别”更一般

离散 token 的常用做法是把所有可能取值列成 K 类，再用 softmax 和交叉熵学习。这个分布的优点是采样简单：从 K 类中抽一个即可。但它要求事先存在码本，而且量化误差在 tokenizer 阶段已经发生。

MAR 面对连续 token 时不能直接使用有限类别 softmax，因为连续值有无穷多种可能。Diffusion Loss 将每个 token 的分布写成一个由条件 z 控制的去噪过程：训练时让模型在不同噪声强度下恢复噪声方向，推理时通过反向去噪获得样本。这样既能保留连续空间，又能表示同一上下文下多种合理未来。

要理解它与“回归平均向量”的区别，可以想象同一上半张图对应多个合理下半部分。如果只输出均值，结果可能模糊；条件扩散允许从不同初始噪声生成不同细节。它并不意味着每次生成都随机无控制，条件 z、温度、CFG 和采样步数共同约束输出分布。

附录 B：双向注意力为什么仍然可以是自回归

“自回归”描述的是生成概率怎样按顺序分解，而不是要求注意力矩阵必须是三角形。MAR 的 MAE 式编码器只读取当前已知 token，未知 token 以 mask token 占位；双向 attention 只让这些已知内容充分交流，并没有把未来真实 token 偷给模型。

与 causal attention 相比，双向形式的代价是不能直接复用标准 KV cache，且每次分组生成都要重新编码已知 token；收益是已知内容之间通信更充分，并且一次可预测多个未知位置。评价时不能只看注意力方向，还要同时报告分组步数和每次前向成本。

训练中的高 mask ratio 也很重要：如果大部分位置已知，模型任务过于容易；如果几乎全部未知，模型学习从零生成。官方默认以偏高 masking 的分布采样，推理从全未知逐渐揭示，二者共同决定模型看到的条件强度。

附录 C：一个具体数值例子，跟踪训练与推理张量

设 batch=4、图像为 256×256、KL-16 VAE 输出 16 通道，则每张图对应 16×16 个 latent 位置，共 256 个连续 token，每个 token 为 16 维。patchify 后张量为 [4,256,16]。如果 mask ratio=0.75，则每张图约 192 个位置未知、64 个位置已知。

编码器仅处理已知 token 和 buffer；解码器把未知位置恢复为 mask token 并添加位置编码，得到每个待预测位置的条件 z。若 diffusion_batch_mul=4，target/z/mask 会各复制四份，使每个 token 有四次独立扩散时间/噪声训练机会，但主 Transformer 只计算一次。

推理若 num_iter=64，第一次从全 mask 开始；随着 cosine mask_ratio 降低，每轮生成一部分 token。每轮选中的 z 再进入 DiffLoss，从该组 token 的高斯噪声出发，经默认 100 个扩散采样步得到连续值。最后所有 token 拼回 [4,16,16,16]，由 VAE decoder 输出四张图。这个例子说明：256 是 token 数，16 是每 token 维数，64 是 MAR 外层步数，100 是内层去噪步数，四者不能混为一谈。

附录 D：从源码定位常见错误

若 loss 对 mask 归一化异常，检查 forward_loss 的 target/z/mask 是否同步 reshape 与复制；若生成时不同位置语义混乱，检查 mask_to_pred 是否确实是当前 mask 与下一轮 mask 的差集；若 CFG 没生效，检查真实类别与 fake_latent 的 batch 顺序及 forward_with_cfg 的 cond/uncond 顺序。

如果更换 VAE 后图像尺度异常，先检查 latent 标准化系数与解码器分布，而不是先调 CFG。如果训练速度过慢，可分别记录 VAE 编码、MAR 主干、DiffLoss 采样和评估耗时；官方 README 提供 cached latents 的目的正是将重复的 VAE 编码移出训练循环。

这些调试方法都比“重新训练一遍看看”更可控。每一层先验证输入输出合同，再连接下一层，能避免把预处理、mask、扩散和条件问题混成一个无法定位的错误。

附录 E：把 Diffusion Loss 的每个量拆开

设一个真实连续 token 为 x∈R^d，d 是 VAE latent 的通道数。训练时取 ε∼N(0,I)，扩散过程使用自己的 ᾱ_t 将 token 变为 x_t=√ᾱ_t x+√(1−ᾱ_t)ε。这里 x 是真实目标，x_t 是去噪网络输入，ε 是监督目标，z 是 MAR 主干给出的条件。

去噪 MLP 输出对 ε 的估计；论文实现还可包含 variational lower-bound 通道。损失对未知 token 的 mask 加权平均，并沿 batch、token、扩散复制样本聚合。它与 Flow Matching 的速度回归不同：MAR 这里默认预测噪声，采样器是 DDPM 风格反向扩散，不能把 v=ε−x 之类的公式不加转换地代进去。

CFG 只在生成时改变预测噪声方向；训练仍通过 label dropout 学会 fake-latent 无条件分支。若将训练时的真实类别、fake_latent 或 mask 含义改变，就必须重新考虑推理时的无条件分支是否仍在训练分布内。

附录 F：余弦 mask 调度怎样把未知 token 逐步变少

设总 token 数为 N，MAR 外层有 K 次迭代。第 step 次后计划剩余 mask 数约为 floor(N·cos(π(step+1)/(2K)))。当 step 接近 K 时，cos 接近 0，意味着几乎所有位置都被揭示；初始时刻则几乎全部未知。

本轮真正要预测的位置不是简单取“当前 mask 的前几个”，而是当前 mask 与下一轮 mask 的差集：上一轮未知、下一轮将变已知的位置。若差集为空或顺序错误，就会重复采样、漏采样或提前覆盖历史 token。

余弦调度让早期/后期的分组大小不均匀，而 num_iter 控制总外层步数。它与 DiffLoss 内部的扩散步数独立：即使外层只分 64 组，每组 token 仍可能需要 100 次去噪。因此评估速度时必须同时报告两个循环，而不能只说“64 步生成”。

附录 G：冻结、EMA 与训练稳定性在源码里的位置

VAE 在官方训练中只负责编码/解码，不作为 MAR 的训练目标更新；主干与 DiffLoss 才接收扩散损失的梯度。模型权重还维护 EMA 参数，用于评估/生成时提供更平滑的权重估计。EMA 是参数的滑动平均，不是 VQ 码本 EMA，也不是对 latent token 做平滑。

训练循环在每次更新前调整学习率，检查 loss 是否有限，再做梯度缩放、裁剪、optimizer step 与 EMA。若 loss 出现 NaN，官方代码会停止而不是继续掩盖问题。复现时应分别记录主干与 DiffLoss 的梯度、mask 有效元素数、EMA rate 和混合精度配置。

官方训练示例的 batch、epoch、GPU 数量与缓存配置都是资源相关的具体实验设置。本文不将这些说明当作本地实测，也不建议为了“先跑起来”直接删除 mask、标准化或 EMA 等关键语义。

附录 H：tokenizer、MAR 主干与 DiffLoss 分别负责什么

tokenizer 把原始图像变成可计算的连续 latent，它的重建误差决定了信息保留上限；MAR 主干根据当前已知内容推断未知位置的条件向量，决定不同位置之间的语义关系；DiffLoss 则在该条件下表示一个 token 的多模态连续分布。三者不能互相替代。

这带来一个实用诊断方法：如果 tokenizer 单独重建就模糊，先不要怪 MAR；如果已知 token 之间的语义不合理，检查 mask 与主干；如果给定同一 z 时输出总趋向单一均值，则检查 DiffLoss 的噪声采样、训练时间与 CFG。把三层问题分开，比只比较最终 FID 更容易找到真正瓶颈。

官方实现中 models/vae.py 负责 latent 分布与解码接口，models/mar.py 负责 patch/mask/encoder/decoder/采样循环，models/diffloss.py 负责逐 token 去噪，engine_mar.py 负责把这些组件串成训练与评估。阅读仓库时按这条链走，而不是把所有模块当成一个大网络。

附录 I：可以直接写成单元测试的数学与数据不变量

对固定输入 x 和固定 ε，扩散前向应满足 x_t=√ᾱ_t x+√(1−ᾱ_t)ε；当 ᾱ_t=1 时应得到 x，当 ᾱ_t→0 时应接近纯噪声。对量化/连续 tokenizer，需测试编码 latent 的形状、标准化尺度与解码输出范围，而不是只测图片能否保存。

对随机 mask，需检查每张图的 order 是 0…N−1 的排列、mask 数为预期数量、不同样本的 order 不共享；对 decoder，未知位置必须由 mask token 与位置编码构造，不能误读真实未知 latent。对 mask_to_pred，应验证当前未知集合等于本轮已采样集合与下一轮新增集合的并集。

对 CFG，固定同一 x/t 时，真实类别和 fake_latent 两路的噪声预测之差应决定 cond−uncond 方向；将 cfg=1 时应退化为无条件预测。对训练参数，VAE 应保持冻结，MAR/DiffLoss 可训练参数应有非空梯度，EMA 参数不应误注册为 optimizer 的直接训练目标。

附录 J：与 VAR、普通图像扩散和 VQGAN 的真正区别

VAR 的核心是改变自回归顺序为 next-scale；MAR 的核心是改变连续 token 的条件分布表示，并采用随机顺序 masked generation。二者都可以在离散/连续空间中讨论结构，但不要把 VAR 的尺度 mask 与 MAR 的随机 mask 混为同一个算法。

普通图像扩散把整张图作为一个连续状态反复去噪；MAR 把自回归主干与逐 token 扩散头组合，先生成一组 latent token，再对每组 token 做条件去噪。其推理成本由 token 分组、主干前向与去噪头共同决定，而不是只由图像扩散步数决定。

VQGAN 依赖离散码本和索引先验，MAR 直接建模连续 token。取消 VQ 不意味着取消 tokenizer，也不意味着不需要训练/推理调度；它只是将“分类索引”换成“条件连续分布”。

阅读时建议先运行一个单 batch、单尺度/单分组的教学实验，打印每个张量与 mask，再逐步加入 CFG、EMA 与多样本评估。先验证“数据与条件正确”，再讨论生成质量，能避免把大量训练时间浪费在接口错误上。
