1. 问题定义：视频能生成之后，怎样让每一帧“可操作”

普通视频生成模型接收文本或初始图像，输出一段视频；它的条件通常描述整段内容，用户不能在每个时间步决定角色下一步做什么。传统动作条件世界模型则通常需要 (xt, ut, xt+1)，其中 ut 是游戏或机器人环境给出的真实动作。互联网视频大量存在，却很少带有同步按键、机械臂控制量或环境内部状态。Genie 的核心问题是：能否只从这些无动作标签的视频，学到一个能在帧级别接受动作输入的生成式环境。

Genie 的输入是一段视频 x1:T，训练时不需要真实动作或文本标注。视频 tokenizer 将帧变成离散 token z1:T；latent action model（LAM）从相邻帧变化中推断离散潜在动作 at；dynamics model 学习在过去帧 token 与潜在动作条件下预测下一帧 token。推理时输入可以只是一个图像 prompt x1，用户每步给 [0,|A|) 中的整数动作，模型自回归产生后续帧。论文还称可用文本、合成图、照片和草图作为环境起点；其中“文本 prompt”通过文本到图像生成起始画面，不应误解为论文公开了一个直接读取长文本并维护游戏逻辑的引擎。

2. 共同骨架：ST-transformer 如何拆分空间与时间注意力

视频经过 patch embedding 后可形成 T×H×W 个 token。若所有时空 token 进入一个全局自注意力，注意力矩阵规模与 (T·H·W)² 成正比；论文指出视频 token 可达 O(10⁴)，这种成本会成为扩展障碍。Genie 的三个组件都使用 spatiotemporal transformer（ST-transformer）：每个 block 先做单帧内的空间注意力，再做同一空间位置跨 T 帧的时间注意力，最后只放置一个前馈网络 FFW。

X∈RT×H×W×d → SpatialAttn(1,H,W)(X) → CausalTemporalAttn(T,1,1)(X) → FFW(X)(1)

空间层在每一帧内部让 H×W 个位置互相注意；时间层针对固定 (h,w) 位置读取 T 个时间步，并使用 causal mask 防止看见未来。忽略常数与其他层时，空间部分约随 T·(HW)² 增长，时间部分约随 HW·T² 增长，而全时空注意为 (THW)²。论文特别强调占主导的空间计算随帧数线性增长，并非声称整个模型所有项都严格随 T 线性，也并非取消注意力的平方项。时间层仍含 T²，只是其作用维度被限制在同一空间位置。

一个 ST block 在空间与时间层后只保留一个 FFW，省略 post-spatial FFW；论文报告这样能把容量分配给其他组件并改善结果。这里的因果结构既用于 tokenizer 让 zt 汇总 x1:t，也用于 LAM 一次输入完整视频、并行产生各时刻动作，以及 dynamics model 对所有下一帧位置计算训练预测。

教学实现 · 非官方源码（仅说明 ST-block 数据流）
# x: [B, T, H, W, D]；mask_future 是 T×T 的因果掩码
# 本例省略线性投影、归一化、位置编码及具体多头实现
def st_block_teaching(x, spatial_attn, temporal_attn, ffw):
    b, t, h, w, d = x.shape
    x_space = rearrange(x, 'b t h w d -> (b t) (h w) d')
    x_space = spatial_attn(x_space) + x_space
    x = rearrange(x_space, '(b t) (h w) d -> b t h w d',
                  b=b, t=t, h=h, w=w)
    x_time = rearrange(x, 'b t h w d -> (b h w) t d')
    x_time = temporal_attn(x_time, mask=causal_mask(t)) + x_time
    x = rearrange(x_time, '(b h w) t d -> b t h w d',
                  b=b, h=h, w=w)
    return x + ffw(x)  # 每个 ST block 只在末尾调用一次 FFW

这段代码不是论文发布的实现，注意力内部、残差/归一化顺序、位置编码、初始化和并行策略都需要按正式重实现补全。特别是不能将 spatial attention 的 batch 维和时间注意力的 batch 维混用，否则很容易发生跨帧或跨位置信息泄漏。

3. Video Tokenizer：ST-ViViT、离散码本与重建目标

tokenizer 是 VQ-VAE 式视频压缩器，编码器与解码器都采用 ST-transformer。输入 x1:T∈RT×H×W×C，输出每帧 D 个离散索引 z1:T∈IT×D；D 表示一帧离散 latent 的 token 数，不是码本 embedding 的维数。论文 Platformers 模型的 patch size 为 4，码本含 1024 个 code、每个 embedding 32 维。编码器 12 层、d_model=512、8 heads；解码器更大，为 20 层、d_model=1024、16 heads。整体 tokenizer 约 200M 参数。

设编码器输出连续向量 et,i，从码本 E={ek} 中选择欧氏距离最近的 code，得到量化向量 qt,i 和离散索引 zt,i：

zt,i=argmink||et,i−ek||²₂，qt,i=ezₜ,ᵢ，x̂1:T=Dec(q1:T)(2)

论文只表述采用标准 VQ-VAE 目标。可以用常见的三项形式理解其机制：解码器重建、codebook 向编码输出靠拢、编码器承诺不远离所选 code；argmin 的梯度通常通过 straight-through estimator 传给编码器。但论文正文和附录没有逐项写出损失权重，因此以下公式是标准定义的解释，不应把任意 β、γ 数值归于 Genie：

LVQ=Lrecon(x,x̂)+||sg[Eenc(x)]−e||²₂+β||Eenc(x)−sg[e]||²₂(3)

与只在每帧内部做空间压缩的 ViT tokenizer 不同，ST-ViViT 的时间因果注意力让 zt 能包含 x1:t 的历史信息，这对动态预测有利，但也意味着 token 并非独立“单帧压缩结果”。清理缓存、改变 prompt 帧数或打乱视频顺序时必须重新考虑 token 的条件上下文。论文将它与 Phenaki 的 C-ViViT 对比，指出全时空注意力成本较高；ST-ViViT 在其消融设置中取得 FVD 81.4、ΔPSNR 1.66，C-ViViT 为 272.7、1.37，空间 ViT 为 114.5、1.39。该比较采用 patch size 10、batch 128、16 帧，不能直接套到主模型 patch 4 的配置。

教学实现 · 非官方源码（最近邻量化与 straight-through）
# encoded: [B, T, D_tokens, 32]；codebook: [1024, 32]
def quantize_teaching(encoded, codebook):
    distance = ((encoded ** 2).sum(-1, keepdim=True)
                - 2 * encoded @ codebook.T
                + (codebook ** 2).sum(-1))
    indices = distance.argmin(-1)             # 离散视频 token
    quantized = codebook[indices]
    # 前向使用量化值，反向把 decoder 梯度复制到 encoded
    quantized_st = encoded + (quantized - encoded).detach()
    return indices, quantized, quantized_st
# 正式实现还需 VQ 辅助损失、视频 ST encoder/decoder、重建与码本管理

主 tokenizer 以 AdamW 训练 300k steps，warmup 10k，weight decay 10⁻⁴，β₁=β₂=0.9。附录表中 max_lr 与 min_lr 均写为 3e-4，尽管正文提到 cosine decay；复现报告应保留这个原文事实，不要擅自补出最小学习率。tokenizer 先独立训练，之后为 dynamics 提供离散目标和推理解码器。

4. Latent Action Model：把“两帧之间发生了什么”压成少量动作

LAM 是一个条件逆动态/重建系统。编码器读取历史 x1:t 与下一帧 xt+1，输出连续潜在动作 ãt，再经小型 VQ 码本离散化。解码器读取历史与量化动作，重建下一帧 x̂t+1。如果动作不包含有用的帧间变化，解码器就难以重建；如果码本过大，它又可能把场景细节塞进动作而失去可玩性。主 Platformers 实验将动作词表 |A| 限为 8，码本 embedding 为 32 维，patch size 为 16。

ãt=QA(LAMenc(x1:t,xt+1))，x̂t+1=LAMdec(x1:t,ãt)，at∈{0,…,|A|−1}(4)

这里编码器在训练时可以看到 xt+1，因为它要从已经发生的变化中反推动作；解码器不能绕过动作直接读取目标帧，否则动作就无需承载信息。因果时间注意力允许把完整 x1:T 输入一次并产生 ã1:T−1。论文将 LAM 编码器和解码器都设为 20 层、d_model=1024、16 heads，输入归一化到 [0,1]，解码器最终用 sigmoid 输出。模型约 300M 参数。

“无监督动作”不意味着自动得到标准键盘。某个 ID 可能在不同初始帧上表现为左、右、跳或 no-op，但训练前并不知道哪个 ID 对应什么。用户需要尝试这些按钮，并通过跨输入观察归纳其语义。论文指出动作含义在不同输入上保持一致，附录展示左、右、跳、no-op；这不保证八个动作在所有域都一一对应真实按键，也不保证相同 ID 能精确产生固定位移。

论文对比了把 LAM 输入从像素换成视频 token 的方案。token-input 在 Platformers 的 FVD 略低（38.8 对 40.1），可控性 ΔPSNR 却更差（1.33 对 1.91）；Robotics 上像素输入的 FVD 和可控性都更好。这说明压缩 token 会损失部分运动信息，也说明仅追求重建/FVD 可能牺牲动作发现。注意 LAM 的解码器只提供训练信号；推理时 LAM 编码器、解码器均被弃用，仅动作码本用来把用户 ID 查成 embedding。

5. Dynamics Model：decoder-only MaskGIT，而非逐像素扩散

动态模型接收已量化视频 token z1:t−1 和 stop-gradient 的潜在动作 ã1:t−1，预测下一帧 token zt。它使用 decoder-only MaskGIT transformer 与 ST 模块，在 T−1 个历史位置上并行训练对 z2:T 的预测。动作不是简单与对应帧 token 拼接，而是作为加性 embedding加入表示；论文报告这一设计改善可控性。stop-gradient 使 dynamics 的交叉熵不会反向改变 LAM 动作表示，两模块仍有各自训练目标。

pθ(zt|z<t,ã<t)=∏i=1…Dsoftmax(fθ(z<t,ã<t)t,i)，Ldyn=−∑t=2…T∑ilog pθ(zt,i|·)(5)

训练时按 Bernoulli 分布遮盖输入 token z2:T−1，每个训练序列的 mask rate 从 [0.5,1] 均匀采样。这使模型既看到部分已知 token，又学习填补未知 token；标签仍是 tokenizer 产生的真实 z2:T，损失是分类交叉熵。这里“mask 输入”与“以全部真实历史 teacher forcing 做下一帧预测”需要仔细对齐：掩码率和每个位置的可见性决定条件信息，不能让被预测 token 通过非因果注意力泄漏给自己。

主动态模型为 10.1B 参数、48 层、36 heads、d_model=5120、k/q size 128。训练使用 bfloat16 与 QK norm，batch size 512、125k steps、256 TPUv5p；论文附录表 12 一处写 TPUv5，而正文明确写 TPUv5p，引用时以正文并注明原文差异更稳妥。动态模型与约 200M tokenizer、300M LAM 合计约 10.7B，论文概括为 11B；项目网站使用更大的 360p decoder 还会增加参数，不能把这个额外 decoder 当作基础数据管线的必需部分。

6. 数据、过滤与分阶段训练：200k 小时不等于最终训练集

摘要说模型从超过 200,000 小时的公开互联网游戏视频语料学习，而主训练使用过滤后的 30,000 小时 Platformers 数据集，这两个数字描述不同阶段。初始收集按标题中的 2D platformer 关键词筛选，标题或描述需含 speedrun、playthrough 等动作词，并排除 movie、unboxing 等否定词。视频切成 16 秒、10 FPS、160×90 分辨率的片段，每段 160 帧，得到约 55M 段、约 244k 小时；过滤后剩 6.8M 段、超过 30k 小时。

过滤不是简单去重。团队人工标注 10k 个视频，质量分 1 到 5，约投入十小时；训练 11M 参数 ResNet18 二分类器时删除评分 2–4 的样本，把 5 当好、1 当坏，最后根据预测与置信度决定去留。高质量定义强调清晰 gameplay，并排除菜单和主播人脸等干扰。相同 580M 模型在原始 55M 视频与过滤后的 6.8M 视频上比较，FVD 从 61.4 改善到 54.8，说明“数据更多”不必然优于“分布更干净”。

阶段输入与冻结关系主要目标论文设置
先训练 Video Tokenizer视频；独立 VQ-VAE视频重建 + VQ 目标300k steps，AdamW，1024 codes
再联合训练 LAM 与 DynamicsLAM 从像素；Dynamics 从固定 tokenizer 的 tokenLAM 重建；Dynamics 下一 token CE16 帧序列，LAM 8 codes，动作 stop-grad 到 Dynamics
主 Genie 动态模型过滤 Platformers规模化动态预测10.1B，512 batch，125k steps，942B tokens（三组件合计口径）

“联合训练”不是说三个网络从零端到端一起更新，也不是 tokenizer 在动态训练时继续变。正确顺序是先训练并固定 tokenizer，再让 LAM 与 dynamics 并行优化各自目标；dynamics 对 LAM 的 embedding 停止梯度。动态优化器附录给 max_lr=3e-5、min_lr=3e-6、β₁=β₂=0.9、weight decay=1e-4、warmup 5k。

为验证领域通用性，论文还把 RT1 的约 130k robot demonstrations、额外模拟数据和先前工作的 209k 真实机器人 episodes 合并为 Robotics 视频数据，明确不使用其中的动作标签。2.5B 模型在该数据上得到测试 FVD 82.7，并展示一致的上、下、左等潜在动作。它是另一套数据与模型实验，不应与 Platformers 的 11B 主模型或网络视频规模混为一次训练。

7. 推理与可控性：八个按钮如何驱动逐帧生成

推理从 prompt 帧 x1 开始。视频编码器产生 z1；玩家选择整数 a1∈[0,8)，系统从训练好的 LAM 码本取出 embedding ã1=EA[a1]；动态模型根据 z1 和 ã1 用 MaskGIT 采样 ẑ2；tokenizer decoder 把 token 转回图像 x̂2。下一轮把已生成历史与新的用户动作交给 dynamics，如此自回归。可使用多个 prompt 帧，但一个图像是最基本示例。

这段伪代码表达接口而非可直接运行的官方推理器。maskgit_update 的置信度重掩码策略、上下文窗口截断、时间位置和多 prompt 帧处理必须另行实现。主模型每帧采用 25 MaskGIT steps、temperature 2 的随机采样；附录的小 CoinRun 示例则 temperature 1.0、同样 25 steps。温度更高增加采样多样性，也可能降低一致性；动作 ID 只提供条件，不能强制保证精确结果。

为了量化“动作是否真的影响生成”，论文定义 ΔtPSNR。先让 LAM 从真实视频推断动作并生成 x̂t，再随机从 categorical 分布抽动作生成 x̂′t，两者都与真实帧 xt 比 PSNR：

ΔtPSNR=PSNR(xt,x̂t)−PSNR(xt,x̂′t)，实验报告 t=4(6)

若推断动作使结果更接近真实视频，而随机动作较差，该差值为正且越大表示动作条件更有用。它不是“动作准确率”，因为没有真实动作标签；也不是交互延迟、长期一致性或物理正确性的度量。FVD 评价整体视频 fidelity，ΔPSNR 评价这一特定对照下的 controllability，两者必须同时读，且随机动作分布和 roll 到第 4 帧的设置影响数值。

可控性的实际边界同样重要：动作语义是事后探索出来的；少量离散动作不能表达任意细粒度控制；生成的下一帧是概率样本，并非游戏引擎确定性 transition；16 帧记忆和约 1 FPS 运行速度使长时连续游玩仍受限。论文展示草图、真实照片、Imagen 2 图像等 OOD prompt 上角色运动与视差现象，但定性示例不能证明对任意图像都能形成稳定世界。

8. 从动作发现到智能体训练：仍需少量真实动作做映射

Genie 不仅能被人类“玩”，论文还用冻结的 LAM 给 CoinRun 专家视频打潜在动作标签。对专家相邻帧 (xt,xt+1)，计算 at=LAM(xt,xt+1)，再训练策略 π(at|xt) 预测专家在该观测下选择的潜在动作。这一步不需要专家真实动作，因此能把无动作视频转成模仿学习目标；但部署到真实 CoinRun 时，仍需把潜在 ID 翻译为环境动作。

at←LAM(xt,xt+1)，πφ(at|xt) 用 CE 训练；D[a] 收集与 latent a 对应的真实 u，部署时 ut∼D[at](7)

映射字典 D 来自一小批带真实动作的专家序列 (xt,ut,xt+1)：LAM 推断 at，把 ut 添加到 D[at] 的列表，推理时从列表采样。论文报告少至 200 个 expert samples 即可适配，在其图中 LAM 策略可达到使用真实动作的 oracle BC 相同分数。这个结果支持动作空间具有跨域语义，但不能表述为“完全零真实动作训练 CoinRun 控制器”；最后的潜在到真实映射确实使用了真实动作。

BC 策略使用 ST-ViViT 编码 x1:t，历史动作 one-hot 后以加性 embedding 与对应帧表示结合，序列长度 4、batch 16；编码器 12 层、d_model=512、patch 4，策略线性层 512。oracle 与 LAM 版本分别对真实动作或潜在动作做交叉熵。论文还指出 oracle 在 10% 时间随机采样动作表现更好，这是特定实验细节，不是所有 BC 的通用要求。

规模化实验单独考察 dynamics：固定 tokenizer 和 LAM，模型从 40M 扩到 2.7B，训练损失持续下降；2.3B 模型把 batch 从 128、256 增至 448（对应约 1.9M、3.8M、6.6M tokens）也有收益。主模型由此扩到 10.1B dynamics。规模化实验每档训练 200k steps、batch 256，使用 batch parallelism、ZeRO stage-3，大模型另用 tensor parallelism。它证明的是该设置下 loss 的 scaling 趋势，不等价于长期可玩性、真实物理或下游策略性能随参数同样单调提升。

10. 局限、计算成本与实现检查清单

长时记忆与幻觉。论文明确只有 16 帧记忆，在 10 FPS 数据设置下对应很短的上下文；长时离开再返回、物体永久性和关卡状态都难以保证。自回归 transformer 会生成不合理未来，错误还会进入下一步历史。与显式游戏引擎不同，模型没有硬约束碰撞、库存、分数和地图持久性，视觉相似不能代替这些性质。

速度与成本。主模型约 1 FPS，离实时交互仍有距离；每帧 25 次 MaskGIT 迭代、大 transformer 和视频解码都产生推理开销。训练主 dynamics 的论文报告为 6.6×10²² FLOPs、256 TPUv5p、125k steps；scale 表中最大 2.7B 实验也使用 256 TPUv3、16 天。不能用单 GPU 附录案例的一周成本去描述主 11B 模型。显存除参数外还包括时空注意力、optimizer states、视频 batch 和 ZeRO/tensor 分片通信，论文没有给所有硬件上一个可直接套用的显存数字。

动作与评价。动作码本小有利于人类探索，却限制控制表达；码本大可能提升重建但削弱可玩性。LAM 可能把不可控背景变化也吸收到动作中，ΔPSNR 只检验推断动作相对随机动作更接近真实轨迹，并不证明因果可控。跨域 BC 还依赖 200 个真实动作样本建立映射，不应宣称零适配。FVD 和短时 PSNR 无法覆盖长期可玩性、重访一致性与真实任务完成率。

可执行的测试清单。（1）ST 空间注意力测试：同一时间不同位置可通信，不同帧不通信；时间注意力对打乱未来帧的当前输出不变，验证 causal mask。（2）tokenizer 测试：固定码本时最近邻索引与暴力距离一致，straight-through 前向取量化值、反向梯度能到编码器，token ID 全部在 [0,1024)。（3）LAM 泄漏测试：修改 xt+1 应改变推断动作，但不能通过 decoder 的额外目标帧通道绕开动作；推理仅给动作 ID 就能查码本。

（4）Dynamics 对齐测试：zt 与 ãt 的条件对应 zt+1，loss 不能错位到 zt；动作分支应 stop-gradient，mask rate 只落在 [0.5,1]，目标 token 不经过非因果路径泄漏。（5）推理测试：重复同一 prompt、动作序列与采样种子应可复现，用户只改某个动作 ID 时确实重新查码本，不必运行 LAM encoder。（6）评价测试：ΔPSNR 的 x̂ 与 x̂′ 除动作外必须共享 prompt、采样预算与可比随机条件，避免把采样随机性误计为可控性。（7）小规模案例先验证数据包含 10M transitions、16 帧切片无跨 episode 污染，再谈完整训练。
