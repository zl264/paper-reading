1. 它解决的不是“预测漂亮图片”，而是把大模型与小控制器解耦

World Models 研究的是从像素观测学习控制的经典难题。环境在时刻 t 给出图像 ot，智能体产生动作 at，环境再返回下一观测和奖励。若把卷积网络、循环记忆与策略全部放进一个端到端强化学习目标，价值或奖励信号必须同时负责表示学习和信用分配；论文选择把这两项工作分开：用无监督重建与预测训练较大的世界模型，再只在紧凑的策略参数上最大化累计奖励。

整个智能体被拆成 V、M、C 三部分。V（Vision）是卷积 VAE，把一帧图像压缩为连续向量 zt；M（Memory）是带混合密度输出层的 LSTM，根据当前潜向量、动作和过去状态预测下一潜向量的分布；C（Controller）直接以 [zt, ht] 为输入输出动作。V 提供“现在看见什么”，M 的隐藏状态提供“历史以及接下来可能发生什么”，C 只负责把这些特征映射为控制量。这里的 M 不是显式地图或三维场景表示，也不是通用的视频生成器。

模块输入输出监督信号
V：ConvVAE64×64×3 RGB 帧μ、log σ²、采样 z；解码重建帧像素 L2 重建与 KL
M：MDN-RNNzt、at、ht下一 z 的混合高斯参数；Doom 还预测 done下一真实 z 的负对数似然；终止交叉熵
C：线性策略[zt, ht]转向、油门、刹车等动作环境累计奖励，由黑盒优化使用

它与 model-free RL 的差别不只是“多了一个预测网络”：V 和 M 的训练不读取任务奖励，只有 C 的适应度使用奖励。它与普通动作条件视频预测的差别在于最终目标是把 M 当成可替代的潜空间环境，在其中训练策略并迁回真实环境。CarRacing 的主要实验仍让 C 在真实环境上进化；真正完全在梦中训练、再迁回真实环境的是 VizDoom Take Cover 实验。这两个实验不能混为一条训练管线。

关键时序：先用当前观测得到 zt，控制器用 zt 与已有 ht 选 at，随后 M 消费 [zt, at] 更新到 ht+1。不能把“由当前输入产生的下一状态”又当成当前动作所需的旧状态，否则训练与推理会错位。

2. V：卷积 VAE 如何压缩帧，以及 KL 在这里为何有用

原始帧先缩放到 64×64，每个 RGB 通道归一化到 [0,1]。编码器依次使用 32、64、128、256 通道的卷积，卷积核为 4、步长为 2，激活为 ReLU，空间尺寸由 64 依次降为 32、16、8、4。代码随后将特征展平为 2×2×256；这一点依赖框架的卷积尺寸与 padding 行为，不宜在现代重实现中只按公式想当然地省略检查。展平特征分别经过全连接层得到 μ 与 log σ²，重参数化采样 z=μ+σ⊙ε，其中 ε∼N(0,I)。CarRacing 的 z 为 32 维，Doom 为 64 维。

qφ(z|x)=N(μφ(x), diag(σ²φ(x)))，z=μ+exp(½ log σ²)⊙ε(1)

解码器先把 z 映射到 1024 个数并重排，再通过四层转置卷积恢复到 64×64×3，输出使用 sigmoid。优化目标由逐帧重建误差与标准正态先验的 KL 散度组成。对 mini-batch 中每帧求和空间与通道，再对 batch 求均值：

LV(x)=||x−x̂||²₂ + max[−½∑j(1+log σ²j−μ²j−σ²j), δNz](2)

论文正文将其概括为 L2 加 KL；公开源码进一步使用 kl_tolerance=0.5，即 KL 在低于 0.5Nz 时被截断。这是实现中的容差项，不应改写成论文没有给出的通用 β-VAE 权重。VAE 的高斯先验不仅用于生成样本，也使潜空间更连续；当 M 生成的 z 与真实编码略有偏差时，解码器更有可能仍产生合理图像。代价是压缩与任务无关：论文观察到 Doom 中墙面砖纹可能被保留，而赛车路面的任务相关细节反而丢失。

3. M：MDN-RNN 预测的是条件分布，不是一个均值向量

单帧 VAE 不知道车辆运动方向、火球是否即将出现，也不知道同一当前帧之后是否会发生离散事件。M 用 LSTM 汇总历史，并在每个时间步输出下一潜向量的混合高斯密度。设混合数为 K，潜向量维度为 Nz，第 k 个分量的权重、均值和对数标准差分别为 πt,k、μt,k、st,k：

p(zt+1|at,zt,ht)=∑k=1…Kπt,k∏j=1…NzN(zt+1,j;μt,k,j,exp(2st,k,j))(3)

这里采用分量内各维独立的对角高斯，没有预测不同 z 维度之间的相关系数 ρ。CarRacing 使用 K=5、LSTM 隐藏宽度 256、z 维度 32，因此每个样本的 MDN 输出是 5×32×3=480 个数；Doom 的 LSTM 宽度为 512，z 为 64 维，另有终止预测。混合模型可以表示“怪物发射火球”和“不发射”这类离散模式，而单高斯往往把多个未来平均成一个不真实的折中。

训练输入和标签是错位一步的序列：输入为 [zt,at]，标签为 zt+1。这属于 teacher forcing，因为历史 z 来自真实观测的 VAE 编码，而不是模型自己前一步生成的 z。每个 batch 构造时从已存储的 μ、log σ² 重新采样 z，避免 M 死记某一次 VAE 采样。其损失是观测标签在预测混合密度下的负对数似然：

LM=−E[∑j log ∑k πt,k,j N(zt+1,j;μt,k,j,σ²t,k,j)](4)

    return (-0.5 * ((y - mean) / tf.exp(logstd)) ** 2
            - logstd - np.log(np.sqrt(2.0 * np.pi)))

nll = -tf.reduce_mean(tf.reduce_logsumexp(v, 1, keepdims=True))

这一实现的张量重排值得细看：先将 LSTM 输出从 [B,T,H] 展平，再形成 [B×T×Nz,K×3]，最后把目标展平为每个潜维度一行。因此公式中的 π 可理解为每个维度各自的混合权重，由相应输出头产生，而不是只给整条轨迹一个共享混合系数。使用 reduce_logsumexp 而不是先 exp 再求和，是为了避免极小概率下溢和极大概率上溢。现代复现必须对“每个 z 维度的 K 组参数”与“每个时间步的 K 个多元高斯”这两种布局作明确选择；本仓库是前者。

4. C 与 CMA-ES：867 个参数为何足以驾驶

论文将控制器刻意设计为线性映射。CarRacing 的 C 接收 32 维 z 与 256 维 LSTM 输出 h，拼接后为 288 维，映射到转向、油门和刹车三个动作，权重与偏置合计 288×3+3=867。Doom 同时使用 LSTM 的 c 与 h，因此输入是 64+512+512=1088，输出一个连续标量，论文表中控制器参数数为 1088（该表未计偏置；源码相应 Doom 控制器以无偏置形式实现）。

at=Wc[zt;ht]+bc，θC←argmaxθ Eξ[∑trt](5)

小搜索空间让 CMA-ES 可以直接优化控制器，不需要对奖励或环境求梯度，也不要求 V、M 的预测图可微地传回 C。CMA-ES 用多层高斯搜索分布产生候选参数，根据累计奖励排序，更新均值、步长与协方差。协方差使搜索方向能随参数之间的相关性调整，但它并非“免费训练大网络”：论文指出其适合最多几千个参数的解空间，而不应拿它直接进化数百万参数的 VAE。

官方源码节选 · carracing/model.py
def get_action(self, z):
    # CarRacing 的 EXP_MODE=MODE_ZH，特征是 [z, state.h]
    h = rnn_output(self.state, z, EXP_MODE)
    action = np.tanh(np.dot(h, self.weight) + self.bias)
    action[1] = (action[1] + 1.0) / 2.0  # 油门映射到 [0,1]
    action[2] = clip(action[2])          # 刹车裁剪到 [0,1]
    # 用当前 z 和实际输出的动作推进 M，供下一步控制
    self.state = rnn_next_state(self.rnn, z, action, self.state)
    return action

转向保留 tanh 后的 [-1,1]，油门由 [-1,1] 线性映射到 [0,1]，刹车再截断到 [0,1]。如果重实现改用 Gym 新版本或不同环境包装，动作语义、预处理、帧跳过和 episode 终止条件都应单独验证，因为这些东西会改变 C 的适应度，而非无关紧要的工程细节。

官方源码节选 · carracing/es.py
class CMAES:
    def __init__(self, num_params, sigma_init=0.10,
                 popsize=255, weight_decay=0.01):
        self.solutions = None
        self.weight_decay = weight_decay
        import cma
        self.es = cma.CMAEvolutionStrategy(
            num_params * [0], sigma_init, {'popsize': popsize})
    def ask(self):
        self.solutions = np.array(self.es.ask())
        return self.solutions
    def tell(self, reward_table_result):
        # cma 最小化，而环境奖励需要最大化
        reward_table = -np.array(reward_table_result)
        if self.weight_decay > 0:
            l2_decay = -self.weight_decay * np.mean(
                self.solutions ** 2, axis=1)
            reward_table += l2_decay
        self.es.tell(self.solutions, reward_table.tolist())

论文实验采用 population 64，每个候选在 16 个不同初始随机种子上运行，适应度为 16 次累计奖励的均值；每 25 代用 1024 次 rollout 评估当前最佳候选。仓库 train.py 命令行默认值对应 CMA、每 trial 16 episodes、64 workers，但源码顶部还存在供其他实验使用的旧全局默认值，真正生效的是 main(args) 对全局变量的覆盖。阅读此仓库不能只看文件顶部常量。

5. 从真实环境 rollout 到下一动作：张量和状态怎样流动

一次真实 CarRacing episode 开始时，控制器参数固定，V 和 M 的预训练参数也固定，只把 LSTM 的 h、c 清零。环境重置后，每帧执行“编码—选动作—环境前进一步—记忆前进一步”。M 无需将混合分布采样成下一帧才能给 C 提供特征；在真实环境控制中，C 读取的是 M 的隐藏状态，环境自己给出下一真实观测。这一点能避免把梦境采样逻辑错误地套进真实推理。

6. 梦境 rollout：从分布采样、解码到策略迁移

梦境环境不再需要真实环境每一步渲染图像。先从保存的初始帧 μ、logvar 中抽一个 z，随后每一步将当前 z、用户或控制器选择的 a 与 M 的隐藏状态送入 MDN-RNN。对每个潜维度，先根据温度调整混合 logits 并抽分量 k，再在选中的高斯中采样。温度 τ 同时进入混合权重和分量内高斯噪声：

π′k,j=softmax(log πk,j/τ)，kj∼Categorical(π′:,j)，z′j=μkj,j+σkj,j√τ εj(6)

τ→0 时混合选择更尖锐且噪声变小，梦境接近确定性；τ 增大则未来更随机。源码 CarRacing 的 dream_env.py 默认 τ=0.7，Doom 的 doomrnn.py 默认 TEMPERATURE=1.25，而论文 Doom 主实验报告 τ=1.15。数值差异说明“照搬当前脚本”与“复现论文表格”是两种不同目标。

VAE decoder 只在需要可视化梦境时使用，将 z 解码为图像；C 的训练完全可在潜空间进行。CarRacing 的梦境接口把 reward 固定为 0，主要用于可视化，不是一个可直接替代真实奖励训练的完整环境。Doom 则预测 restart/done：输出头额外提供一个 logit，训练用 sigmoid 交叉熵，终止正样本权重为 10，潜向量 NLL 与终止损失相加；推理时 logit>0 即判终止，每存活一步 reward=1，最长 2100 步。由于死亡在单帧上是稀有事件，论文选择阈值判定而非伯努利采样，以降低不稳定。

策略迁移时，真实 Doom 重新用 V 编码观测，并把真实观测对应的 z 与 M 的状态输入同一个 C。论文结果中 τ=1.15 的梦境策略在真实环境 100 次测试得到约 1092±556 的生存步数，高于梦中约 918±546；较高方差和不同温度结果必须一起读。τ=0.1 时虚拟得分接近满分而真实得分很低，是模型被利用的反面证据，不是“更确定就更好”。

CarRacing 的从头训练顺序是：收集数据、训练 VAE、运行 series.py、训练 RNN、将生成的 JSON 放入 vae/、rnn/、initial_z/，最后运行 train.py。评估模型则通过 model.py 加载 controller 的 best JSON。模型权重序列化不是标准 checkpoint：源码将浮点参数乘 10000、四舍五入为整数后存 JSON，加载时除回 10000；测试或转换这些权重时必须保留参数顺序与量化尺度。

依赖具有鲜明的时代限制：CarRacing README 列出 TensorFlow 1.8.0、NumPy 1.13.3、Gym 0.9.4、cma 2.2.0、mpi4py 2，根 README 明确指出 gym 0.9.x 可用而 0.10.x 不可用。数据收集需要 OpenGL/headless X，多 worker 训练依赖 MPI。直接用现代 Gymnasium API 替换 reset/step 返回值并不能保证等价；还需要核对渲染、随机种子和旧环境包装。本文没有安装这些依赖，也没有运行仓库中的模型。

8. 实验说明什么，以及模型为何会被“作弊”

CarRacing 的消融将 M 的贡献展示得很清楚：只给 C 输入 z，线性控制器在 100 次随机测试上为 632±251；增加一个含 40 个 tanh 单元的隐藏层后为 788±141；完整 z+h 线性控制器为 906±21。这里的 h 不是每步枚举多个未来再规划，而是把历史压缩成对控制有用的特征，策略仍然是一步反射式决策。论文参数表给出 CarRacing VAE 4,348,547、MDN-RNN 422,368、C 867，说明主要容量确实放在 V/M 而非 C。

梦境的根本风险是分布外模型误差被策略主动放大。随机策略数据只覆盖部分状态；CMA-ES 会寻找使模型回报最大的动作，包括那些让 M 错误地“不发火球”或让正在形成的火球消失的动作。梦中高分因此可能只是钻了近似模型的漏洞。更棘手的是，C 可以访问 M 的隐藏状态，相当于能看到部分模拟器内部状态，可能更容易发现并利用错误动态。

混合密度与温度是缓解手段而不是正确性保证。MDN 保留多种未来，增加 τ 使控制器不能总沿单一漏洞轨迹获利；但 τ 过大又会让任务难到无法学习。论文表中 τ=1.30 的真实均值低于 τ=1.15，却有较小方差，说明“均值最高”和“策略更稳”并不等价。世界模型的 NLL 或重建图像变好也不自动意味着控制性能提升，必须在真实环境用多随机种子评估。

9. 从一次随机采集到迭代世界模型：不要夸大论文已做之事

对于复杂环境，随机策略可能永远到不了关键区域，论文因此提出迭代流程：初始化 M、C；在真实环境 rollout 并保存动作与观测；训练 M 预测下一观测、奖励、动作和终止，再让 C 在 M 中优化奖励；若任务未完成，就继续收集。M 的高预测损失还可反号作为探索奖励，引导策略进入不熟悉的区域。这里的“预测动作”面向更一般的记忆/技能吸收设想，不是 CarRacing 代码已经实现的输出头。

论文实际展示的是简单任务上一次随机数据采集即可得到可用模型，并未证明这个迭代方案能解决开放世界。V/M 分离便于复用和分别调参，但重建目标不知道哪些细节对奖励重要；联合奖励预测虽能强化任务相关信息，又可能削弱跨任务复用。固定容量 LSTM 还可能遗忘持续收集的数据，论文把外部记忆和更大预测模型列为后续方向，而非已完成组件。

与 Dreamer 一类后续方法相比，这里的 C 是线性黑盒优化策略，V/M 分阶段训练，主要不是通过潜在想象的解析梯度训练 actor-critic。与 Genie 相比，它需要环境中的真实动作标签来训练 M，且输出的是低维 VAE 潜向量分布而非互联网视频规模的离散时空 token。与普通视频生成模型相比，它的评价终点是累计奖励和策略迁移，而不是 FVD 或文本一致性。把这些系统统称为“世界模型”并不意味着训练数据、状态、动作接口与推理成本可以互换。

成本也要拆开报告：V/M 的 GPU 监督训练与 C 的 CPU 并行环境评估是两种资源。论文称单独训练 V 或 M 在单 GPU 上不到一小时，但 CMA-ES 使用 64 核机器、population 64、每候选 16 次评估，并训练到较多代数；不能把“小控制器参数少”误写成“总采样成本低”。梦境可省去游戏渲染和物理引擎，但 LSTM 顺序状态更新仍存在，且最终真实环境评估不可省略。

10. 复现与单元测试清单

数据与 VAE。先固定环境版本、动作重复、图像 resize 和 10,000 条 episode 的选择规则。测试输入 uint8 转 float 后确实除以 255，VAE 输出形状为 [B,64,64,3] 且位于 [0,1]；测试 μ/logvar 到 z 的采样在固定 ε 时逐元素等于公式；KL 在全 μ=0、logvar=0 时应接近容差下限而非随意变成负数。另写测试验证重建损失先对每帧求和再对 batch 求均值，避免误用全局 mean 改变损失尺度。

MDN-RNN。用小 K、小 z 维度和手工 logits 测试 softmax 后每个维度权重和为 1；对照直接计算 log 概率检验 reduce_logsumexp 的 NLL，并包含极大、极小 logstd 的数值稳定性样例。用两条长度不同的伪序列检查 [zt,at]→zt+1 没有 off-by-one；测试每批重新采样 z 而非把 series 中的某一次采样固化。最后断言 CarRacing MDN 每时间步输出 480 个参数，并检查 reshape 后均值不会串到 logstd。

控制与梦境。构造全零 z/h 时动作应仅由 bias 决定；断言转向在 [-1,1]、油门和刹车在 [0,1]。单步测试应验证 C 先用旧 h 算动作，M 再用当前 z 和该动作更新状态；episode reset 后 h、c 必须归零。固定 τ 和随机种子时梦境序列应可重复，τ 改变应同时影响混合选择和噪声尺度。Doom 还需测试 logit=0 的阈值语义、终止权重、reset 时清状态，以及 2100 步上限。

CMA-ES 与系统测试。用二次型或简单可解析回报的玩具控制器检查 ask/tell 的奖励符号：高奖励候选必须优于低奖励候选，而不是被最小化方向反转。检查 867 维向量拆成 bias 与 weight 的顺序、JSON 的 10000 倍量化和 MPI 返回结果的 job index 对齐。用“一条伪观测序列贯穿 extract→VAE→series→RNN→controller”的 dry-run 测试形状与文件路径即可，不需要在此阶段执行完整训练。最终至少报告多个未见随机种子上的真实环境均值、标准差、episode 数和温度，而非仅展示最佳梦境片段。
