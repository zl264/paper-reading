1. I2V 的任务不是重建首帧，而是学习整条条件轨迹

给定归一化到 [-1,1] 的单张参考图像 r，SVD 生成 T 帧 RGB 视频 x0 = (x10,…,xT0)。公开 SVD 默认 T=14，SVD-XT 默认 T=25，训练分辨率都是 576×1024。模型要近似条件分布 p(x0|r)：同一张图可以对应不同合理运动，输出不是由确定性光流或相机参数唯一决定。

论文的核心贡献还包括数据治理：从约 5.77 亿个 clip 的 LVD 出发，经切分、字幕、光流、OCR、美学和 CLIP 筛选形成 1.52 亿样本的 LVD-F，并区分图像预训练、视频预训练和高质量微调三阶段。这一训练策略解释了模型为何能学习通用运动先验；不能把最终效果仅归因于新增的时间注意力。

SVD 不是逐帧自回归模型。每一轮扩散去噪都同时处理全部 T 帧，时间卷积和时间注意力交换帧间信息，因而能在一次生成中协调运动。参考图像同时以局部 latent 和全局 CLIP 图像嵌入进入网络，而帧率、运动分数、条件增强强度作为微条件提供统计偏置。

控制边界：原始 SVD 的 motion_bucket_id 不指定物体位移、旋转矩阵或相机轨迹。论文另外训练了只作用于时间注意力的 camera-motion LoRA 来研究水平移动、缩放、静态等控制；它们不是基础 SVD checkpoint 自带的精确相机接口。

2. 从图像与视频到张量：8 通道 U-Net 输入的来源

视频每帧经冻结的 SD 2.1 VAE 编码器得到四通道 latent，空间尺寸缩小八倍，并乘 scale_factor=0.18215。单段 576×1024、14 帧视频因此从 14×3×576×1024 变成 14×4×72×128；SVD-XT 仅把帧数变为 25。官方脚本把帧维折叠进 batch，而不是保留一个独立的五维 batch-video 张量供整个 U-Net 使用。

参考图像另走一个 AutoencoderKLModeOnly：它采用同一套 SD 2.1 图像编码器结构及对应预训练权重，但取后验均值，不对 latent 分布采样。得到的 1×4×H/8×W/8 latent 复制到 T 帧，与带噪视频 latent 在通道维拼接。因此配置中 in_channels=8、out_channels=4：四通道是当前需要清理的视频噪声，另外四通道是空间对齐的图像条件；网络最终只需预测四通道干净视频的相关量。

Z0 = 0.18215 · Evideo(X0)，   Zσ = Z0 + σN，   Uσ = [Zσ ; repeat(Emode(r̃))](1)

N 是标准高斯噪声，r̃ 是受轻微噪声增强的参考图像，分号表示通道拼接。条件图像本身没有 mask；论文明确说不用 masking，而是把条件帧复制到整个时间轴。这也是它与首帧 inpainting、遮挡预测式插值模型的区别。

在生成脚本中，初始噪声形状是 (num_frames,4,H//8,W//8)。输入高宽要求能被 64 整除，而模型训练偏好 576×1024；其他尺寸即使能通过网络，也处于训练分布之外。图像宽高不相等时 latent 为矩形，U-Net 卷积和空间注意力可以继续处理，不需要套用 DiT 的方形 unpatchify。

3. 同一张图为什么要编码两次：concat 保局部，cross-attention 提供语义

第一条路径是 VAE 条件 latent，负责颜色、纹理、边缘和空间布局，按像素对应的潜网格直接拼到每一帧。训练时参考图像先加噪，论文使用 log σ ∼ N(−3.0,0.5²)，再取 VAE 后验均值。这个轻扰动有助于避免模型把参考条件当作完全无损拷贝；同时 cond_aug 本身也作为一个 256 维微条件输入。

第二条路径是冻结的 OpenCLIP ViT-H/14 图像编码器。它把无额外噪声的 cond_frames_without_noise resize 到 224×224，以 CLIP 均值和标准差归一化，输出 1024 维全局图像嵌入，并保留一个长度为一的 token 维。它替换基础文生视频模型原来的文本 cross-attention context；不是把 VAE latent 投影成 CLIP 特征，也不是同时使用文字提示。

官方源码节选 · encoders/modules.py：条件如何归入三种键
class GeneralConditioner(nn.Module):
    OUTPUT_DIM2KEYS = {2: "vector", 3: "crossattn", 4: "concat"}
    KEY2CATDIM = {"vector": 1, "crossattn": 2, "concat": 1}

    def forward(self, batch, force_zero_embeddings=None):
        output = dict()
        for embedder in self.embedders:
            # 冻结编码器在 no_grad 下运行；同一键的多个输出按指定维度拼接
            emb_out = embedder(batch[embedder.input_key])
            if not isinstance(emb_out, (list, tuple)):
                emb_out = [emb_out]
            for emb in emb_out:
                out_key = self.OUTPUT_DIM2KEYS[emb.dim()]
                if embedder.input_key in (force_zero_embeddings or []):
                    emb = torch.zeros_like(emb)
                if out_key in output:
                    output[out_key] = torch.cat(
                        (output[out_key], emb), self.KEY2CATDIM[out_key])
                else:
                    output[out_key] = emb
        return output

4. 时空 U-Net：先空间、后时间，再融合回每一帧

基础图像模型是 SD 2.1 U-Net。论文在每个空间卷积和空间注意力之后插入时间卷积与时间注意力，加入 656M 新参数，总参数达到 1521M，并对完整模型进行视频训练，而非冻结所有空间权重只训练时间层。开源 VideoUNet 保留编码、中央 bottleneck、带跳连的解码路径，默认通道倍率 [1,2,4,4]，基础通道 320，每级两个残差块。

VideoResBlock 先对 (B·T)×C×H×W 做普通二维 ResBlock，再重排为 B×C×T×H×W，送入一个 dims=3 的 ResBlock。SVD 配置的时间卷积核为 [3,1,1]，即只在时间轴混合三帧，不改变空间位置。然后 AlphaBlender 融合空间输出和时间输出，配置为 learned_with_images；纯图像输入与视频输入可采取不同融合策略。

官方源码节选 · video_model.py：VideoResBlock 的五维时间分支
def forward(self, x, emb, num_video_frames, image_only_indicator=None):
    x = super().forward(x, emb)  # 空间二维 ResBlock
    x_mix = rearrange(x, "(b t) c h w -> b c t h w", t=num_video_frames)
    x = rearrange(x, "(b t) c h w -> b c t h w", t=num_video_frames)
    x = self.time_stack(
        x, rearrange(emb, "(b t) ... -> b t ...", t=num_video_frames))
    x = self.time_mixer(
        x_spatial=x_mix, x_temporal=x, image_only_indicator=image_only_indicator)
    return rearrange(x, "b c t h w -> (b t) c h w")

时间注意力另有两种轴变换。空间分支先把每帧变成 HW 个 token，做空间 self-attention 和以 CLIP 图像为 context 的 cross-attention。时间分支再把 (b t) s c 变成 (b s) t c：对每个固定空间位置 s，T 个时间 token 相互注意。帧序号经正弦编码和 MLP 加到 token 上，否则自注意力不知道时间顺序。

5. fps、motion bucket 与 cond_aug：三个 256 维微条件

论文在 base model 和高分辨率 Text/Image-to-Video 训练中，都以输入视频的帧率和运动分数作为条件。代码将 fps_id、motion_bucket_id、cond_aug 分别送入 ConcatTimestepEmbedderND(outdim=256)。这个类复用正弦时间步嵌入，不是把数值当成一个可直接线性解释的旋钮；三者拼成 768 维 vector，经 U-Net 的 sequential label MLP 后加入扩散时间嵌入。

fps_id 表示训练元数据意义上的帧率条件，默认 6。它会改变模型对相邻帧运动幅度的先验，但官方最终 imageio.mimwrite(video_path, vid) 没有传 fps 参数，因此不能把 fps_id=6 简单当成导出 MP4 容器的播放帧率。要得到确定播放速度，写文件或后处理时还需另行设置帧率。

motion_bucket_id 是数据光流分数分桶后的离散标识，默认 127。它可在训练覆盖范围内偏向更静止或更运动的视频，却不是“像素/帧”的速度，也不保证所有场景单调响应。脚本对大于 255 的值给出警告；fps_id 小于 5 或大于 30 也会警告。这些范围是脚本对分布外条件的提示，不应扩展成物理解释。

cond_aug 默认 0.02。开源推理直接在像素域构造 cond_frames = image + cond_aug * randn_like(image)，而论文训练描述的是从对数正态分布采样增强强度，再经 VAE 编码。前者是发布的默认推理参数化，后者是训练方案，不能把二者说成完全相同的一个 σ 采样过程。过强条件噪声可能削弱首帧外观，过弱又可能加重复制感，应把它视作需按输入调整的分布参数，而非确定的质量开关。

6. EDM 训练：连续 σ、去噪分数匹配与 v 型预条件

在连续时间形式中，加噪样本为 Z = Z0 + n，n ∼ N(0,σ²I)。去噪器 Dθ(Z;σ,c) 预测干净的整段视频 latent，score 由 (Dθ−Z)/σ² 给出。概率流 ODE 可写为 dZ = −σ̇(t)σ(t)sθ(Z;σ(t))dt。训练从指定 p(σ) 抽取噪声级别，以加权平方误差进行去噪分数匹配：

L = E(Z₀,c),σ,n[ λ(σ) ‖Dθ(Z₀+n;σ,c) − Z₀‖²₂ ](2)

λ(σ) 决定不同噪声级别的相对权重。论文初始图像适配取 logσ ∼ N(Pmean,Pstd²)，Pmean=−1.2、Pstd=1，λ(σ)=(1+σ²)/σ²。分辨率越高，低频内容越难被充分破坏，因此论文随训练阶段提高噪声：320×576 视频预训练把 Pmean 增至 0；I2V 基础适配取 0.7/1.6；576×1024 I2V 取 1.0/1.6。这里的 σ 作用于视频 latent，与参考图像的轻微 cond augmentation 是两套噪声。

Dθ(Z;σ) = cskipZ + coutFθ(cinZ; cnoise,c)(3)

SVD 配置选 VScalingWithEDMcNoise：cskip=1/(σ²+1)，cout=−σ/√(σ²+1)，cin=1/√(σ²+1)，cnoise=0.25logσ。也就是说，U-Net 并非直接输出 epsilon；包装器把网络的 v 型输出还原成干净 latent Dθ。σ 很大时 cskip 趋近 0，模型主要依靠 Fθ；σ 趋近 0 时跳跃分支保留 Z。

7. 三阶段训练与冻结策略：先改图像噪声参数，再扩展时间

阶段 I 从公开的 SD 2.1 开始。论文先将离散 epsilon 预条件迁移到连续 σ/v 参数化：前 1k 步冻结 Fθ 除时间嵌入外的全部参数，在 512×512 图像上适配；随后解冻全部 Fθ，在 256×384 上训练 30k 步，总计 31k。这个短暂的部分冻结只是为了让时间嵌入适配新的 cnoise，不是整个 SVD 训练始终冻结空间层。

阶段 II 插入时间层后，在 LVD-F 上以 14 帧、256×384 训练 150k 步，AdamW 学习率 10−4、batch 1536，文本条件以 15% 概率 dropout。再以 14 帧、320×576 训练 100k 步，batch 768，并把 Pmean 提高到 0。阶段 III 才在约 100 万高质量视频上微调具体任务。I2V 不使用文本，而是用参考帧 CLIP 图像嵌入替代文本 context，并加入复制到时间轴的 VAE 条件。

训练时目标视频帧与额外参考帧是两个输入角色。冻结的 CLIP 和 VAE 负责提供条件，主干整体接受扩散损失。最终 checkpoint 结合视觉检查和人工评价选择，而非以单一验证 loss 最小值决定。原始训练数据 LVD 并非随开源仓库完整提供，因此“代码公开”不等于可以从头逐项复现数据筛选和大规模训练。

不要混淆任务：高分辨率文生视频、I2V、帧插值、camera LoRA 与 SVD-MV 都是基于同一个 base prior 的不同微调。I2V 不需要文本；帧插值才使用左右帧与 mask；多视图模型输出的帧轴也不等于真实时间运动。

8. 推理：EDM 离散化、Euler 更新与逐帧线性 CFG

公开 SVD 使用 EulerEDMSampler 与 EDMDiscretization，σmin=0.002、σmax=700、ρ=7，并在末尾追加 0。SVD 默认 25 步，SVD-XT 默认 30 步。与训练时 log-normal 随机 σ 不同，推理使用确定性的 ρ 次幂网格：

σi = [σmax1/ρ + (i/(K−1))(σmin1/ρ − σmax1/ρ)]ρ，   σK=0(4)

采样器把初始标准正态张量乘 √(1+σ0²)，这与输入预条件及 EDM 初始噪声尺度配套。默认 s_churn=0，不加入额外随机 churn。利用 score 与 D 的关系，以 σ 为积分变量时导数是 (Z−Dθ(Z;σ,c))/σ，所以一次 Euler 更新为：

Znext = Z + (σnext−σ) · (Z − Dθ(Z;σ,c))/σ(5)

每一步 guider 先把无条件与有条件输入拼为两倍 batch，得到去噪预测后再合成 Dw=Du+w(Dc−Du)。SVD 的关键变化是 w 随帧索引线性变化：SVD 配置从 1.0 到 2.5，SVD-XT 从 1.5 到 3.0。离参考帧较近的帧使用较小引导，远处帧用更强引导，试图兼顾前段一致性与后段运动、减少固定大引导的过饱和。

return rearrange(x_u + append_dims(scale, x_u.ndim) * (x_c - x_u),
                 "b t ... -> (b t) ...")

因为 CFG 把 U-Net batch 加倍，峰值去噪显存不只与 14 或 25 帧成正比，还包含条件/无条件两路。减少采样步数降低总网络调用次数，但不降低单次 U-Net 的空间 token 和帧数负担。改变随机种子影响初始噪声和 cond augmentation；默认脚本的种子在逐图循环之前设定，批量处理多张输入时的噪声序列需另行注意。

9. 解码器：去闪烁不是把每帧独立送入原 SD decoder

原始 SVD 保留 SD 2.1 的图像编码器，但将 VAE decoder 换成时间感知的 VideoDecoder，官方称为 deflickering decoder。生成器输出的 T×4×72×128 latent 先除 0.18215，再经过含时间卷积的解码残差块。默认 time_mode="conv-only"：卷积与残差块包含 [3,1,1] 时间混合，而中间空间注意力不启用额外时间注意力。它能利用当前送入解码器内的相邻 latent 帧来减少独立解码产生的纹理闪烁。

官方源码节选 · models/diffusion.py 与 temporal_ae.py
# DiffusionEngine.decode_first_stage
z = 1.0 / self.scale_factor * z
n_samples = default(self.en_and_decode_n_samples_a_time, z.shape[0])
for n in range(math.ceil(z.shape[0] / n_samples)):
    z_chunk = z[n * n_samples : (n + 1) * n_samples]
    if isinstance(self.first_stage_model.decoder, VideoDecoder):
        kwargs = {"timesteps": len(z_chunk)}
    out = self.first_stage_model.decode(z_chunk, **kwargs)
    all_out.append(out)

# AE3DConv.forward：二维卷积后增加时间卷积
x = super().forward(input)
x = rearrange(x, "(b t) c h w -> b c t h w", t=timesteps)
x = self.time_mix_conv(x)
return rearrange(x, "b c t h w -> (b t) c h w")

decoding_t 默认 14，控制每次送入 decoder 的帧数；官方注释明确指出它占用大量显存，可降低。它不改 U-Net 去噪帧数，也不缩短生成时长。由于是分批处理，时间卷积不会跨解码 chunk 看到相邻批次，边缘可能与一次性全帧解码不同；追求严格一致性时，应将这一参数纳入验收。

解码输出从 [-1,1] 映射到 [0,1] 并截断，随后加水印、安全过滤、转为 uint8，最后写 MP4。基础 I2V 脚本不像 SV3D 分支那样在解码后强制覆盖首帧，因此不能把输出第一帧假设为逐像素等于输入。配置仓库还包含 svd_image_decoder 变体，不能将其行为混入默认 SVD 的 temporal decoder 讨论。

10. 官方仓库调用链、依赖与适用边界

从 scripts/sampling/simple_video_sample.py 入口开始：load_model 读取 scripts/sampling/configs/svd.yaml 或 svd_xt.yaml，通过 instantiate_from_config 构建 DiffusionEngine；后者装载 VideoUNet、Denoiser、GeneralConditioner、first-stage autoencoder、sampler，并从 safetensors 恢复参数。之后 get_batch 组装条件，conditioner 产出 vector/crossattn/concat，最后 sampler 调用 denoiser 和 OpenAIWrapper 进入 VideoUNet。

这条调用链说明配置文件是网络定义的一部分，而不只是训练超参数。仅替换 checkpoint 而继续使用另一版本配置，可能造成条件键、帧数或 guidance 范围不匹配。环境需要 PyTorch/torchvision、PyTorch Lightning、OmegaConf、einops、open_clip、transformers、kornia、safetensors、xFormers（配置路径下）、OpenCV、imageio、Fire、rembg 及内容检测依赖等；具体版本须按仓库要求文件核对。权重和模型许可也需单独确认。

本地核验范围：本文阅读的是固定提交的静态源码和论文，不声称安装以上依赖、加载 safetensors 或验证实际显存。该固定提交晚于 SVD 初版发布，包含很多后续模型；引用行号均固定到上述完整 SHA，避免 main 分支变化破坏证据。

与 DiT 相比，SVD 是卷积/注意力混合 U-Net，而非全 Transformer token 去噪器；与逐帧图像扩散相比，它在所有生成阶段显式混合时间信息；与视频自回归相比，它不逐帧采样，能双向协调一段视频，却需要一次容纳整段 latent。与相机控制方法相比，基础 SVD 的 motion bucket 只是数据驱动的粗粒度先验，不提供可验证的几何轨迹。

主要限制来自固定短片长度、单图歧义、长时一致性、遮挡后的身份与几何变化，以及高分辨率全帧注意力的计算/显存。参考图不自然、非训练分辨率、极端 fps 或 motion bucket 都可能造成分布外结果。解码器能减少闪烁但不能修复 U-Net 已生成的错误运动；更大的 CFG 也不是无条件改善质量。

11. 复现检查清单：先测接口与数值，再讨论视觉质量

  1. 形状验收：以 B=1、T=14、H=576、W=1024 检查视频 latent 为 14×4×72×128，参考 latent 复制后同样为 14×4×72×128，wrapper 拼接后为 14×8×72×128，网络输出回到 14×4×72×128。SVD-XT 只将 T 改为 25。
  2. 条件键：检查 CLIP 输出在展开前为 B×1×1024，展开后为 (B·T)×1×1024；三个标量各产生 256 维 vector，拼接为 B×768。uc 的 crossattn 与 concat 为零，但 fps、motion、cond_aug 不应被误清零。
  3. 参考噪声：固定 torch 随机数，分别验证 cond_frames_without_noise 未改变，而 cond_frames 恰为 image+cond_aug·ε。若要复现论文训练，还应测试 logσ∼N(−3,0.5²) 的采样和 VAE mode 编码，不要仅运行发布时的固定 0.02 路径。
  4. 轴变换：构造能识别 b,t,h,w 的递增张量，测试 (b t) s c ↔ (b s) t c 往返完全一致；检查时间位置编码随帧索引变化而同一帧不同空间位置共享。VideoResBlock 的输入输出形状也必须一致。
  5. EDM 预条件：对一组 σ 检查四个系数的广播，并用任意 mock F 验证 D=c_skip·Z+c_out·F(c_in·Z,c_noise)。特别确认 U-Net 输出不是直接当 epsilon，score 使用 (D−Z)/σ²。
  6. 离散化与积分：验证 σ 从 700 递减至 0.002，末尾恰有 0，rho=7；用固定 denoiser 手算一个 Euler 步。测试默认无 churn 时不消耗额外高斯扰动，最终零 σ 不发生除零。
  7. 逐帧引导：断言 14 帧的 scale 从 1.0 等距到 2.5，25 帧 XT 从 1.5 到 3.0；用不同 uc/c mock 验证合并顺序是 uc 在前、c 在后，并检查还原后的 (B·T) 帧顺序未交换。
  8. 解码与输出：确认 decode 前除 0.18215，decoding_t 分组求和覆盖全部帧且不改变采样 T。对 chunk 边界记录时间卷积感受野差异；输出 RGB 需做 [-1,1]→[0,1] 和 uint8 转换，写视频时明确容器 fps，而不是依赖 fps_id。
  9. 论文级训练复现：另行核对三阶段数据、批次、学习率、Pmean/Pstd、EMA 和条件 dropout；不要把推理 YAML 当作训练配置。没有 LVD 数据与足够算力时，只能宣称模块级复现或加载官方权重，不能宣称复现论文完整结果。

除大规模视觉评估外，上述大部分检查可用小张量、mock conditioner 和手工答案完成，不需要执行 SVD。本文未运行这些测试；它们是面向后续实现的验收建议。
