01为什么需要 Transformer

1.1 一切要从"序列"说起

语言天生是序列（Sequence）：一句话里的词有先后顺序，而一个词的含义又依赖于它的上下文。"我吃苹果"和"苹果吃我"用的是同样的三个字，意思完全相反。因此，任何处理语言的模型都必须回答两个根本问题：

  1. 理解：如何让每个词"吸收"上下文信息，得到真正属于它的含义表示？
  2. 生成：如何把一个序列转换成另一个序列（翻译：中文 → 英文；摘要：长文 → 短文）？

在 2017 年之前，这两个问题的主流答案是循环神经网络（RNN / LSTM）；2017 年之后，答案变成了 Transformer。要理解 Transformer 解决了什么，得先看看旧方案卡在了哪里。

1.2 RNN 时代的三大困境

RNN 的思路非常直觉：像人阅读一样，从左到右逐词处理，用一个"记忆向量" h 不断更新：

ht = tanh(W · ht−1 + U · xt)

即"第 t 步的记忆 = 对上一步记忆和当前输入的加工"。这个设计简洁优雅，但带来了三个致命问题：

  1. 困境一：无法并行。h2 必须等 h1 算完，h3 必须等 h2……100 个词的句子就要串行 100 步。而 GPU 擅长的是"一万件事同时做"，RNN 的结构让它根本吃不到并行计算的红利，训练大模型慢得难以接受。
  2. 困境二：长程依赖衰减。信息像接力棒一样一站站传下去，每传一次都要乘一次矩阵、过一次 tanh，距离一远，早期信息不断被稀释、覆盖（梯度也会消失）。LSTM 用门控机制缓解了这个问题，但也只是把"能记住的距离"从 ~20 步拉长到 ~100 步，本质没变。
  3. 困境三：信息瓶颈。经典的 Seq2Seq（机器翻译模型）把整个输入句子压缩成一个固定长度的向量，再让解码器仅凭这一个向量生成整个译文。句子一长，这个向量就成了"要背下整本书的一张小抄"，注定记不全。

1.3 注意力机制的破局（2014）

2014 年，Bahdanau 等人在机器翻译中提出了注意力机制（Attention）：解码器每生成一个词时，不再只看那个"小抄向量"，而是回头重新扫一遍源句的所有词，按相关程度加权取用。翻译 "I" 时重点看 "我"，翻译 "machine" 时重点看 "机器"。

这一招直接打破了信息瓶颈，效果立竿见影。但当时的注意力还只是 RNN 的一个"外挂"——主干仍然是循环网络，并行性和长程依赖问题依旧存在。

1.4 2017：Attention Is All You Need

Google 的作者们提出了一个大胆的问题：既然注意力这么好用，能不能把 RNN 完全扔掉，只用注意力？答案就是 Transformer：

  • 完全基于自注意力（Self-Attention），没有任何循环结构；
  • 所有位置同时计算，可以充分利用 GPU 并行；
  • 任意两个词之间的信息路径长度都是 1，长程依赖不再是问题；
  • 在当年的机器翻译任务上取得 SOTA，且训练时间只有之前最好模型的 1/3 以下。

02核心思想：注意力机制

2.1 从"查字典"说起

先忘掉所有公式，想一个你天天在做的事：查字典。你拿着一个"查询"（想查的词），逐一比对字典里每个"键"（词条），找到匹配的那个，取出它的"值"（释义）。

注意力的思路一模一样，只是把"精确匹配"换成了模糊匹配：

  • 查询 Q（Query）：我现在想找什么信息？
  • 键 K（Key）：每个候选信息身上贴的"标签"；
  • 值 V（Value）：每个候选信息的实际内容。

字典只会返回一个结果，而注意力会把所有候选都按匹配程度取一点，做加权平均：

软性注意力 = 加权平均（soft retrieval） 输出 = α1·v1 + α2·v2 + … + αn·vn 其中 αi ≥ 0 且 Σαi = 1，是查询与第 i 个键的"匹配分数"（归一化后）
类比 这就像在图书馆查资料：你的问题（Q）和每本书的目录（K）算相似度，然后按相似度比例把所有书的内容（V）都"复印"一点回来混合。最相关的书复印得多，不相关的复印得少——而不是只借一本。

2.2 Self-Attention：自己看自己

Transformer 里用的是自注意力（Self-Attention）：Q、K、V 全部来自同一个序列。序列里的每个词，都会向包括自己在内的所有词发起查询，根据相关性重新混合信息，得到一个"见过世面"的新表示。

经过一层 Self-Attention 后，每个词的向量不再只是"这个词是什么"，而是"这个词在这个句子里、在这个上下文中是什么意思"。这就是所谓的上下文相关表示（contextualized representation）——同一个"苹果"在"吃苹果"和"苹果手机"里会得到完全不同的向量。

2.3 一个经典例子：指代消解

看这句话：

The animal didn't cross the street because it was too tired.

"it" 指的是 animal 还是 street？人一眼就知道是 animal（因为"累"的是动物）。自注意力让模型也能做到：计算 "it" 与所有词的相关性时，"animal" 会获得最高的注意力权重——"it" 的新向量于是大量吸收了 "animal" 的信息。点击下面任意单词，查看它对其他词的注意力分布（弧线越粗 = 权重越大）：

03数学原理：一步步推导注意力

3.1 符号约定

设一个句子有 n 个词，每个词被表示成 dmodel 维向量。整个句子就是一个矩阵：

X ∈ ℝn × d_model n 行 = n 个词，每行是一个词向量（原论文 d_model = 512）

3.2 Q、K、V 从哪里来：三个投影矩阵

Q、K、V 不是凭空出现的，它们都是输入 X 分别乘以三个可学习的权重矩阵得到的：

Q = XWQ, K = XWK, V = XWV

其中 WQ, WK, WV ∈ ℝd_model × d_k，是模型要学的参数。

理解 每个词向量 xi 被同一组矩阵"加工"出三种角色：
• 它的 Query：当我需要更新自己时，我想找什么？
• 它的 Key：当别人查询时，我能被怎样"检索到"？
• 它的 Value：如果别人选中了我，我实际贡献什么内容？
为什么同一向量要投影出三种角色？因为"我要找什么"和"我能提供什么"是两回事——就像你在招聘网站上的"求职意向"（Query）和"简历关键词"（Key）描述的是同一个你，但写法完全不同。

3.3 完整公式：缩放点积注意力

下面就是 Transformer 的灵魂公式（建议背下来）：

Scaled Dot-Product Attention（缩放点积注意力） Attention(Q, K, V) = softmax( QKT√dk ) V

别被它吓到，我们把右边拆成 4 步，每一步都极其简单：

  1. 打分：S = QKT。Q 的第 i 行（第 i 个词的查询）与 K 的第 j 列（第 j 个词的键）做点积，得到分数 sij = qi·kj，衡量"词 i 对词 j 的关注程度"。点积越大，两个向量方向越一致、越相关。结果 S 是一个 n×n 的打分矩阵。
  2. 缩放：S ← S / √dk。把分数整体除以键向量维度的平方根（为什么？见 3.4 节）。
  3. 归一化：A = softmax(S)。对每一行做 softmax，把分数变成非负、和为 1 的注意力权重——即一个概率分布："词 i 把 100% 的注意力按比例分给所有词"。
  4. 加权求和：Output = A·V。用权重对所有的 Value 加权平均，得到每个词的新表示。第 i 行输出 = αi1v1 + … + αinvn。

3.4 为什么要除以 √dk

这是面试高频问题，值得认真理解。假设 q 和 k 的每个分量都是均值 0、方差 1 的独立随机变量，那么它们的点积（dk 个乘积之和）的方差正好是 dk：

Var(q · k) = Var(q1k1 + … + qdkkdk) = dk

维度越大（dk = 64），点积的数值就天然越大、波动越剧烈。而 softmax 对输入非常敏感——输入一大，它就会把几乎全部概率砸在最大的那个分数上，输出接近 one-hot，梯度几乎为零，训练不动。除以 √dk 恰好把方差重新拉回 1，让 softmax 工作在"温和"的区间。

动手感受一下缩放的作用（拖动滑块改变维度 dk）：

交互演示：缩放如何"驯服" softmax
不缩放：softmax(QKᵀ) — 越来越尖，梯度消失
缩放后：softmax(QKᵀ/√dk) — 分布稳定
四个候选键的基础相似度为 [2.0, 1.4, 1.0, 0.5]。点积分数近似与 √dk 成正比增长，因此不缩放时维度越大、分布越接近 one-hot；除以 √dk 后分布与维度无关，保持稳定。

3.5 softmax：把分数变成分布

softmax 把一行任意实数分数 z = (z1, …, zn) 变成概率分布：

softmax(z)i = eziΣj ezj

它有两个关键性质：放大差异（分数差 1，概率比约 2.7 倍）和可微（能反向传播）。数值很大时 ez 会溢出，实现中通常先减去行最大值再计算（数值稳定技巧）。

3.6 维度变化总览

步骤操作形状变化（单头，n 个词）
①输入 X(n, dmodel)
②Q = XWQ，K = XWK，V = XWV各 (n, dk)
③打分 S = QKT / √dk(n, n)
④权重 A = softmax(S)(n, n)，每行和为 1
⑤输出 A·V(n, dk)，与 V 同形
优雅之处 整个注意力没有任何循环——全部是大矩阵乘法，一次算出所有词的新表示，GPU 的最爱。

3.7 多头注意力（Multi-Head Attention）

一个注意力头只有一种"关注方式"。但语言里的关系是多样的：一个词可能同时需要关注指代对象（it → animal）、语法搭配（动词 → 宾语）、相邻修饰（形容词 → 名词）。只给一个头，就像只允许你用一个标准去理解所有关系。

Transformer 的做法：并行做 h 次独立的注意力，每个头有自己的投影矩阵，在各自的低维子空间里"各看各的"，最后拼接融合：

Multi-Head Attention（原论文 h = 8） headi = Attention(XWiQ, XWiK, XWiV) MultiHead(X) = Concat(head1, …, headh)WO

原论文中 dmodel = 512，h = 8，所以每个头 dk = dv = 512 / 8 = 64。注意一个精妙的设计：总计算量和总参数量与单头 512 维几乎相同——不是把模型变大 8 倍，而是把同一个预算切成了 8 份不同视角。

3.8 计算复杂度

自注意力的瓶颈在 QKT：形状 (n, dk) × (dk, n)，复杂度 O(n²·d)，且需要存储 n×n 的注意力矩阵。n = 1000 时矩阵有 100 万个元素，n = 100K（长文档）时就是 100 亿——这就是"上下文长度"成为大模型核心指标的由来，也是 FlashAttention、稀疏注意力等后续优化的动机（见第 8 章）。

04整体架构：逐层拆解

4.1 鸟瞰全局

原论文的 Transformer 是一个编码器–解码器（Encoder–Decoder）结构，用于机器翻译。先建立整体印象：

  • 编码器 Encoder：负责理解输入序列，输出一组"看完了整个句子"的表示向量；由 N = 6 个完全相同的层堆叠而成。
  • 解码器 Decoder：负责生成输出序列，一次生成一个词；同样 N = 6 层，但每层多一个"交叉注意力"子层，用来随时查阅编码器的理解结果。
  • 两边各有输入模块（词嵌入 + 位置编码），解码器顶部有输出模块（线性层 + softmax，给出词表上的概率）。
读图口诀 数据自下而上流动；蓝色系属于编码器，橙色系属于解码器，紫色是注意力，绿色是前馈网络。每一层的输出形状不变（n × 512），堆 6 层就是在反复"精炼"表示。

4.2 输入端：从文字到向量

第一步：分词（Tokenization）

模型不认识汉字和英文单词，只认识整数 ID。分词器把文本切成 token（词、子词或字符），再查词表映射成 ID。现代模型几乎都用 BPE / SentencePiece 这类子词算法："unhappiness" 可能被切成 "un" + "happi" + "ness"，这样既能控制词表大小（如 3 万～10 万），又能处理生僻词。本教程第 6 章的代码会跳过分词，直接用整数序列，聚焦模型本身。

第二步：词嵌入（Embedding）

一个 nn.Embedding(V, d_model) 的查找表：词表里每个 token ID 对应一行 512 维的可学习向量。这就是模型对"词义"的初始记忆（训练中不断被更新）。原论文还把嵌入乘以 √d_model（约 22.6），让嵌入值的量级与后面要加上的位置编码相匹配。

第三步：位置编码（Positional Encoding）

3.4 节说过：Self-Attention 是"近视眼"，天生分不清词序。解决办法朴素得惊人——把每个位置的特征直接加到词向量上。原论文用不同频率的正弦、余弦函数生成位置向量：

位置编码：偶数维用 sin，奇数维用 cos PE(pos, 2i) = sin( pos / 100002i / d_model ) PE(pos, 2i+1) = cos( pos / 100002i / d_model )

pos 是词的位置（0, 1, 2, …），2i、2i+1 是向量的维度编号。频率从 1 到 1/10000 呈几何级数递减：低维变化快（像"秒针"，每走一步都明显变化），高维变化慢（像"时针"，走很多步才转一圈）。任意固定偏移 k，PEpos+k 都可以表示成 PEpos 的线性函数——这让模型很容易学到相对位置关系。

交互演示：位置编码热力图（横轴 = 向量维度，纵轴 = 词位置）
注意底部（低位置）：左侧高频维度条纹密集、右侧低频维度几乎不变——每个位置因此得到独一无二的"指纹"。原论文 d_model = 512，这里可视化前 256 维。
思考 为什么用"加法"而不是"拼接"来融合位置与词义？拼接会扩大维度、增加参数；相加则假设"位置信息"与"词义信息"可以共存于同一个 512 维空间里——实践证明这足够好用。另外，现代大模型（如 LLaMA）已改用更优雅的 RoPE 旋转位置编码（第 8 章），但"必须显式注入位置信息"这一原则从未改变。

4.3 编码器层：两个子层打天下

每个编码器层只做两件事，每件事都包着"残差 + 归一化"的外壳：

子层 1：多头自注意力（通信）

就是第 3 章讲的 Multi-Head Self-Attention：层内所有位置互相交换信息。可以把它理解为一次全局通信——"每个词去打听全句的消息，然后更新自己"。

子层 2：逐位置前馈网络 FFN（思考）

FFN(x) = max(0, xW1 + b1)W2 + b2

两层 MLP：先升维到 dff = 2048（4 倍），过 ReLU，再降回 512。关键：它对每个位置独立、相同地作用（position-wise），词与词之间不交流。如果说注意力负责"开会收集情报"，FFN 就是"回办公室独自消化情报、做深度加工"——模型的多数参数（约 2/3）都藏在 FFN 里，大量研究认为它承担了知识存储的功能。

外壳：残差连接 + 层归一化

每个子层的输出（Post-LN，原论文写法） output = LayerNorm( x + Sublayer(x) )
  • 残差连接 x + Sublayer(x)：给梯度修一条"高速公路"。不管子层学得多么糟糕，恒等映射总保证信息不丢、梯度能直接回传，这让几十层深的堆叠成为可能（ResNet 的思想）。
  • LayerNorm：对每个 token 的 512 维特征做标准化（减均值、除标准差，再学一个缩放和平移），把数值范围稳住，训练更平稳。注意它和 BatchNorm 的区别：LN 按"单样本单位置"归一，与批大小和序列长度无关——正适合变长序列。
深入：Post-LN 与 Pre-LN 的区别

原论文把 LayerNorm 放在残差之后（Post-LN）：output = LN(x + Sublayer(x))，每一层的输出总是被归一化，干净但深了难训（需要 warmup 帮扶）。

GPT-2 之后流行把 LN 放到子层之前（Pre-LN）：output = x + Sublayer(LN(x))，主干上没有归一化操作，梯度一路畅通，深模型更稳定，现代大模型基本都用 Pre-LN 或其变体 RMSNorm。本教程第 6 章按原论文实现 Post-LN，并在代码注释里标出改一行即可切换。

4.4 解码器层：三个子层 + 一个铁律

解码器层比编码器层多一个子层，并且第一条子层戴上"枷锁"：

子层 1：带掩码的自注意力（Masked Self-Attention）

解码器是在生成序列：生成第 t 个词时只允许看前 t−1 个词，绝不能偷看未来——否则训练就是在"抄答案"，模型什么也学不到。实现方式是在 softmax 之前，把打分矩阵上三角部分（未来位置）填成 −∞，softmax 后这些位置的权重精确地变成 0：

因果掩码（causal mask）：−∞ 经 softmax 后归零 Attention 分数矩阵（4 词示例）： [ s₁₁  −∞  −∞  −∞ ]
[ s₂₁  s₂₂  −∞  −∞ ]
[ s₃₁  s₃₂  s₃₃  −∞ ]
[ s₄₁  s₄₂  s₄₃  s₄₄ ]
精妙之处 训练时解码器其实是一次并行计算所有位置的（把整个目标序列一起喂进去），全靠这个下三角掩码保证"第 t 个位置只见过去"——既享受了并行，又守住了因果律。这是 Transformer 训练效率的关键设计之一。

子层 2：交叉注意力（Cross-Attention）

这是解码器与编码器的唯一接口，也是"翻译时查原文"的实现：

  • Q 来自解码器：我现在要生成的词，需要什么信息？
  • K、V 来自编码器输出：源句每个词的"检索标签"和"内容"。

生成 "machine" 时，Q 会与 "机器"、"学习" 的 K 高度匹配，于是把它们的 V 大量吸进来。这个设计极其通用：语音识别（音频 → 文本）、图像描述（图像 patch → 文字）里两个序列之间的对齐，用的都是同一个 Cross-Attention 组件。

子层 3：FFN + Add & Norm

与编码器完全相同。6 层解码器堆叠后，最终再过一次 LayerNorm，送入输出层。

4.5 输出层：从向量到词

解码器顶部是一个 Linear(512 → V)（V 是词表大小，如 3 万），把每个位置的 512 维向量投影成 V 个 logits，再经 softmax 变成词表上的概率分布，取概率最高的（或采样）作为下一个词。

05一次翻译的完整数据流

把前 4 章串起来。任务：把 "我 爱 机器 学习" 翻译成 "I love machine learning"，假设已生成到第 3 步，看第 4 步（生成 "learning"）如何发生：

  1. 编码器整句处理一次：4 个 token → 嵌入 + 位置编码 → (4, 512) 矩阵 X。经过 6 层编码器，每层先做自注意力（每个词吸收全句信息，"机器"和"学习"互相看到对方），再过 FFN 精炼。输出 memory：(4, 512)——它将保持不变，被解码器反复查询。
  2. 解码器拿到已生成的开头：当前已生成 "<bos> I love machine"（右移一位的目标序列），同样做嵌入 + 位置编码，得到 (4, 512)。
  3. 解码器第 1 子层：Masked 自注意力。4 个位置互相交流，但因果掩码保证 "machine" 只能看 "<bos> I love machine"，看不见未来（本来也没有未来）。这一步让已生成部分内部协调一致。
  4. 解码器第 2 子层：Cross-Attention。Q 来自第 3 步的输出，K/V 来自编码器的 memory。生成 "learning" 的查询与 "学习" 的键最匹配 → 大量吸收 "机器学习" 的表示。
  5. 第 3 子层 FFN + 输出层：深度加工后，取最后一个位置的向量 (512,) → Linear → (37000,) → softmax → 得到 "learning" 概率最高 → 输出。然后把 "learning" 拼回输入，回到第 2 步，直到生成 <eos> 结束。

def clones(module: nn.Module, N: int) -> nn.ModuleList:
    """深拷贝 N 份模块：堆叠 N 层时，每层需要各自独立的参数"""
    return nn.ModuleList([copy.deepcopy(module) for _ in range(N)])


def subsequent_mask(size: int) -> torch.Tensor:
    """因果掩码（下三角为 True）：第 t 个位置只能看到位置 0..t
    返回形状 (1, size, size)，方便后续广播到 batch 和多头维度"""
    attn_shape = (1, size, size)
    mask = torch.triu(torch.ones(attn_shape), diagonal=1)  # 上三角为 1（未来）
    return mask == 0                                        # 取反：能看到的地方为 True

6.2 核心：多头注意力（对应第 3 章）

这是整个模型的心脏，请对照 3.3 节的 4 个步骤阅读。特别留意形状注释——理解多头机制的关键就是弄懂每一次 reshape：

class MultiHeadAttention(nn.Module):
    """多头注意力：自注意力（q=k=v 时）与交叉注意力（q 来自解码器）共用此实现"""

    def __init__(self, d_model: int, num_heads: int, dropout: float = 0.1):
        super().__init__()
        assert d_model % num_heads == 0, "d_model 必须能被 num_heads 整除"
        self.d_model = d_model          # 模型宽度，如 512
        self.num_heads = num_heads      # 头数，如 8
        self.d_k = d_model // num_heads # 每个头的维度，如 64
        # 4 个投影矩阵：W_Q, W_K, W_V, W_O（原论文公式中的 4 个大矩阵）
        self.linears = clones(nn.Linear(d_model, d_model), 4)
        self.attn = None               # 保存注意力权重，便于可视化
        self.dropout = nn.Dropout(p=dropout)

    def forward(self, query, key, value, mask=None):
        # query/key/value: (B, L_q, d_model)，mask: (B, 1, 1, L_k) 或 (B, 1, L_q, L_k)
        if mask is not None:
            mask = mask.unsqueeze(1)    # (B, 1, ...) -> (B, 1, 1, ...)，广播到所有头
        nbatches = query.size(0)

        # ---- 第①步：线性投影 + 拆分多头 ------------------------------
        # (B, L, 512) -投影-> (B, L, 512) -view-> (B, L, 8, 64) -transpose-> (B, 8, L, 64)
        # 直觉：把 512 维向量切成 8 段，每段交给一个头独立处理
        query, key, value = [
            lin(x).view(nbatches, -1, self.num_heads, self.d_k).transpose(1, 2)
            for lin, x in zip(self.linears, (query, key, value))
        ]

        # ---- 第②~④步：缩放点积注意力（打分、缩放、softmax、加权） ----
        x, self.attn = self.attention(query, key, value, mask=mask, dropout=self.dropout)

        # ---- 第⑤步：合并多头 + 输出投影 ------------------------------
        # (B, 8, L, 64) -transpose-> (B, L, 8, 64) -view-> (B, L, 512)，再乘 W_O
        x = x.transpose(1, 2).contiguous().view(nbatches, -1, self.d_model)
        return self.linears[-1](x)

    def attention(self, query, key, value, mask=None, dropout=None):
        """缩放点积注意力：softmax(Q K^T / sqrt(d_k)) V   —— 第 3 章的灵魂公式"""
        d_k = query.size(-1)
        # 打分 + 缩放：(B, h, L_q, d_k) @ (B, h, d_k, L_k) -> (B, h, L_q, L_k)
        scores = torch.matmul(query, key.transpose(-2, -1)) / math.sqrt(d_k)
        if mask is not None:
            # mask 为 False（不许看）的位置填 -1e9，softmax 后权重趋近 0
            scores = scores.masked_fill(mask == 0, -1e9)
        # 对最后一维（key 的位置）做 softmax，每行成为概率分布
        p_attn = F.softmax(scores, dim=-1)
        if dropout is not None:
            p_attn = dropout(p_attn)
        # 加权求和：(B, h, L_q, L_k) @ (B, h, L_k, d_k) -> (B, h, L_q, d_k)
        return torch.matmul(p_attn, value), p_attn
三个实现细节 ① 为什么用 -1e9 而不是 float("-inf")？ 防止整行都被掩掉时 softmax 得到 NaN。
② contiguous() 是干嘛的？ transpose 只改变步长不搬数据，view 需要连续内存，所以要先 contiguous 再 view。
③ 三个输入参数同名同形：自注意力时传 (x, x, x)；交叉注意力时传 (解码器x, memory, memory)——一套代码两种用法。

class PositionalEncoding(nn.Module):
    """正弦位置编码：直接加到词嵌入上（register_buffer 表示它是常量，不参与训练）"""

    def __init__(self, d_model: int, dropout: float = 0.1, max_len: int = 5000):
        super().__init__()
        self.dropout = nn.Dropout(p=dropout)

        # 预计算一个 (max_len, d_model) 的编码表
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len).unsqueeze(1).float()      # (max_len, 1)
        # 10000^(2i/d_model) 的指数部分，用 exp/log 形式保证数值稳定
        div_term = torch.exp(
            torch.arange(0, d_model, 2).float() * -(math.log(10000.0) / d_model)
        )
        pe[:, 0::2] = torch.sin(position * div_term)   # 偶数维：sin
        pe[:, 1::2] = torch.cos(position * div_term)   # 奇数维：cos
        pe = pe.unsqueeze(0)                            # (1, max_len, d_model)
        self.register_buffer("pe", pe)                  # 存为常量，随模型搬运设备

    def forward(self, x):
        # x: (B, L, d_model)。取前 L 个位置的编码相加（广播到整个 batch）
        x = x + self.pe[:, : x.size(1)]
        return self.dropout(x)

class PositionwiseFeedForward(nn.Module):
    """逐位置前馈网络：512 -> 2048 -> 512，对每个位置独立作用"""

    def __init__(self, d_model: int, d_ff: int, dropout: float = 0.1):
        super().__init__()
        self.w_1 = nn.Linear(d_model, d_ff)   # 升维 4 倍
        self.w_2 = nn.Linear(d_ff, d_model)   # 降回来
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        # x: (B, L, d_model) -> (B, L, d_ff) -> (B, L, d_model)
        return self.w_2(self.dropout(F.relu(self.w_1(x))))


class LayerNorm(nn.Module):
    """层归一化：对最后一维（每个 token 的 d_model 个特征）做标准化
    手写版本帮助理解；实际项目直接用 nn.LayerNorm(features) 即可"""

    def __init__(self, features: int, eps: float = 1e-6):
        super().__init__()
        self.eps = eps
        self.a_2 = nn.Parameter(torch.ones(features))   # 可学习的缩放 gamma
        self.b_2 = nn.Parameter(torch.zeros(features))  # 可学习的平移 beta

    def forward(self, x):
        mean = x.mean(-1, keepdim=True)
        std = x.std(-1, keepdim=True)
        return self.a_2 * (x - mean) / (std + self.eps) + self.b_2


class SublayerConnection(nn.Module):
    """残差连接 + LayerNorm（Post-LN，与原论文一致）
    想改成现代的 Pre-LN？把下面一行换成：return x + self.dropout(sublayer(self.norm(x)))"""

    def __init__(self, size: int, dropout: float):
        super().__init__()
        self.norm = LayerNorm(size)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, sublayer):
        # sublayer 是任意子层（注意力或 FFN）的函数
        return self.norm(x + self.dropout(sublayer(x)))

transformer_from_scratch.py · EncoderLayer / DecoderLayer
class EncoderLayer(nn.Module):
    """编码器一层 = 自注意力 + FFN，各带残差外壳"""

    def __init__(self, size, self_attn, feed_forward, dropout):
        super().__init__()
        self.self_attn = self_attn
        self.feed_forward = feed_forward
        self.sublayer = clones(SublayerConnection(size, dropout), 2)
        self.size = size

    def forward(self, x, mask):
        # 子层1：自注意力（q=k=v=x，序列内部互相通信）
        x = self.sublayer[0](x, lambda x: self.self_attn(x, x, x, mask))
        # 子层2：前馈网络（逐位置深加工）
        return self.sublayer[1](x, self.feed_forward)


class DecoderLayer(nn.Module):
    """解码器一层 = 掩码自注意力 + 交叉注意力 + FFN"""

    def __init__(self, size, self_attn, src_attn, feed_forward, dropout):
        super().__init__()
        self.size = size
        self.self_attn = self_attn    # 子层1：对目标序列自身的掩码注意力
        self.src_attn = src_attn      # 子层2：交叉注意力（查编码器 memory）
        self.feed_forward = feed_forward
        self.sublayer = clones(SublayerConnection(size, dropout), 3)

    def forward(self, x, memory, src_mask, tgt_mask):
        m = memory
        # 子层1：掩码自注意力 —— tgt_mask 是下三角因果掩码，防偷看未来
        x = self.sublayer[0](x, lambda x: self.self_attn(x, x, x, tgt_mask))
        # 子层2：交叉注意力 —— Q 来自 x（解码器），K/V 来自 m（编码器）
        x = self.sublayer[1](x, lambda x: self.src_attn(x, m, m, src_mask))
        # 子层3：前馈网络
        return self.sublayer[2](x, self.feed_forward)

6.6 堆叠成编码器与解码器

transformer_from_scratch.py · Encoder / Decoder
class Encoder(nn.Module):
    """N 层编码器堆叠，最后补一次 LayerNorm（Post-LN 结构的收尾）"""

    def __init__(self, layer: EncoderLayer, N: int):
        super().__init__()
        self.layers = clones(layer, N)
        self.norm = LayerNorm(layer.size)

    def forward(self, x, mask):
        for layer in self.layers:
            x = layer(x, mask)      # 每层输出形状不变，直接喂给下一层
        return self.norm(x)


class Decoder(nn.Module):
    """N 层解码器堆叠，最后补一次 LayerNorm"""

    def __init__(self, layer: DecoderLayer, N: int):
        super().__init__()
        self.layers = clones(layer, N)
        self.norm = LayerNorm(layer.size)

    def forward(self, x, memory, src_mask, tgt_mask):
        for layer in self.layers:
            x = layer(x, memory, src_mask, tgt_mask)
        return self.norm(x)

transformer_from_scratch.py · Embeddings / Generator / EncoderDecoder
class Embeddings(nn.Module):
    """词嵌入查找表。注意乘 sqrt(d_model)：让嵌入量级与位置编码匹配（原论文 3.4 节）"""

    def __init__(self, d_model: int, vocab: int):
        super().__init__()
        self.lut = nn.Embedding(vocab, d_model)
        self.d_model = d_model

    def forward(self, x):
        # x: (B, L) 整数 token ID -> (B, L, d_model)
        return self.lut(x) * math.sqrt(self.d_model)


class Generator(nn.Module):
    """输出层：Linear(d_model -> vocab) + log_softmax
    用 log_softmax 而非 softmax，可直接对接 nn.NLLLoss（数值也更稳定）"""

    def __init__(self, d_model: int, vocab: int):
        super().__init__()
        self.proj = nn.Linear(d_model, vocab)

    def forward(self, x):
        return F.log_softmax(self.proj(x), dim=-1)


class EncoderDecoder(nn.Module):
    """Transformer 总装：编码器 + 解码器 + 两套嵌入 + 生成器"""

    def __init__(self, encoder, decoder, src_embed, tgt_embed, generator):
        super().__init__()
        self.encoder = encoder
        self.decoder = decoder
        self.src_embed = src_embed     # 源语言：Embedding + PositionalEncoding
        self.tgt_embed = tgt_embed     # 目标语言：Embedding + PositionalEncoding
        self.generator = generator

    def forward(self, src, tgt, src_mask, tgt_mask):
        """训练时的完整前向：一次并行算出所有目标位置的概率"""
        return self.decode(self.encode(src, src_mask), src_mask, tgt, tgt_mask)

    def encode(self, src, src_mask):
        return self.encoder(self.src_embed(src), src_mask)

    def decode(self, memory, src_mask, tgt, tgt_mask):
        return self.decoder(self.tgt_embed(tgt), memory, src_mask, tgt_mask)


def make_model(src_vocab, tgt_vocab,
               N=6, d_model=512, d_ff=2048, h=8, dropout=0.1) -> EncoderDecoder:
    """按原论文的超参数构建完整模型（所有默认值 = Attention Is All You Need 的 base 版）"""
    c = copy.deepcopy
    attn = MultiHeadAttention(d_model, h, dropout)
    ff = PositionwiseFeedForward(d_model, d_ff, dropout)
    position = PositionalEncoding(d_model, dropout)

    model = EncoderDecoder(
        Encoder(EncoderLayer(d_model, c(attn), c(ff), dropout), N),
        Decoder(DecoderLayer(d_model, c(attn), c(attn), c(ff), dropout), N),
        nn.Sequential(Embeddings(d_model, src_vocab), c(position)),
        nn.Sequential(Embeddings(d_model, tgt_vocab), c(position)),
        Generator(d_model, tgt_vocab),
    )

    # 参数初始化：Xavier 均匀分布，让初始权重方差适中，训练起点稳定
    for p in model.parameters():
        if p.dim() > 1:
            nn.init.xavier_uniform_(p)
    return model

06+训练实战：教模型学会"倒序输出"

模型写完了，怎么证明它真的能学？我们来做一个不需要分词器、不需要下载语料、CPU 五分钟就能训完的玩具任务：

任务定义 输入一个随机数字序列，让模型输出它的倒序。
输入：[3, 7, 1, 9, 5]　→　输出：[5, 9, 1, 7, 3]
这个任务看似简单，却要求模型完整编码整条序列、再按相反顺序逐词生成——恰好同时锻炼编码器的理解和解码器的生成，是绝佳的入门任务。

6.9 造数据：什么是"<bos> / <eos> / 右移一位"

train_reverse.py · 数据生成（接在前面代码之后）
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

PAD, BOS, EOS = 0, 1, 2        # 特殊 token：填充、序列开始、序列结束
VOCAB = 16                     # 词表：2 个特殊 token + 数字 3~15
SEQ_LEN = 8                    # 每条序列固定 8 个数字（简化处理，不做 padding）


def data_gen(batch_size=64):
    """无限产出 (src, tgt_in, tgt_out, src_mask) 训练批次"""
    while True:
        # 1) 源序列：随机数字（避开特殊 token）
        src = torch.randint(3, VOCAB, (batch_size, SEQ_LEN), device=device)

        # 2) 目标 = 源的倒序
        rev = torch.flip(src, dims=[1])

        # 3) 解码器的输入 = <bos> + 倒序     （"右移一位"：开头补 BOS）
        tgt_in = torch.cat(
            [torch.full((batch_size, 1), BOS, device=device), rev], dim=1
        )
        # 4) 监督标签 = 倒序 + <eos>          （模型要预测的"下一步"）
        tgt_out = torch.cat(
            [rev, torch.full((batch_size, 1), EOS, device=device)], dim=1
        )

        # 5) 源掩码：全部可见（1 = 可看）
        src_mask = torch.ones(batch_size, 1, SEQ_LEN, device=device)

        yield src, tgt_in, tgt_out, src_mask

这里出现了三个关键约定，画出来一目了然（以倒序任务为例，目标序列为 [5, 9, 1, 7, 3]）：

解码器输入 tgt_in（右移一位）监督标签 tgt_out含义
<bos> 5 9 1 7 3 5 9 1 7 3 <eos> 位置 t 的输入是"已生成的答案的前 t 个词"，标签是"第 t+1 个正确词"——模型学的是预测下一步

为什么输入要右移一位？如果输入和标签完全对齐，位置 0 的输入是 "5"、标签也是 "5"，模型只需要学会"照抄当前输入"——什么也学不到。右移一位后，位置 0 的输入是 <bos>、标签是 "5"，模型才被迫真正去预测。这就是所谓的 Teacher Forcing：训练时解码器的输入永远用标准答案（老师的手把手示范），而不是模型自己可能出错的生成结果。

6.10 损失函数与 warmup 学习率

train_reverse.py · Noam 优化器（原论文的学习率调度）
class NoamOptimizer:
    """原论文的 warmup 调度：前 warmup 步线性升温，之后按 1/sqrt(step) 降温
    lrate = d_model^(-0.5) * min(step^(-0.5), step * warmup^(-1.5))"""

    def __init__(self, model_size, factor, warmup, optimizer):
        self.optimizer = optimizer
        self._step = 0
        self.warmup = warmup
        self.factor = factor
        self.model_size = model_size
        self._rate = 0

    def rate(self, step=None):
        if step is None:
            step = self._step
        return self.factor * (
            self.model_size ** (-0.5)
            * min(step ** (-0.5), step * self.warmup ** (-1.5))
        )

    def step(self):
        self._step += 1
        rate = self.rate()
        for p in self.optimizer.param_groups:
            p["lr"] = rate          # 手动更新学习率
        self._rate = rate
        self.optimizer.step()
为什么要 warmup 训练初期参数是随机的，梯度方向不可靠；Post-LN 结构对学习率又很敏感。先小步热身（几百到几千步线性升到峰值），再缓慢衰减，能显著稳定训练。这是原论文能训成 Post-LN 的关键配套技巧。

6.12 推理：自回归逐词生成

训练时解码器"一次吃整句"，推理时没有标准答案可抄，只能一个词一个词生成，每步把新词拼回输入再算下一步：

train_reverse.py · 贪心解码
def greedy_decode(model, src, src_mask, max_len=20):
    """自回归推理：每轮只关心最后一个位置的概率，取最大者拼回输入"""
    model.eval()
    with torch.no_grad():
        memory = model.encode(src, src_mask)          # 编码器只算这一次

        ys = torch.full((src.size(0), 1), BOS, dtype=torch.long, device=device)
        for _ in range(max_len):
            tgt_mask = subsequent_mask(ys.size(1)).to(device)
            out = model.decode(memory, src_mask, ys, tgt_mask)   # (B, L, d_model)
            log_prob = model.generator(out[:, -1])    # 只取最后位置！(B, V)
            next_word = log_prob.argmax(dim=-1, keepdim=True)    # 贪心：取最大概率
            ys = torch.cat([ys, next_word], dim=1)    # 拼回输入，进入下一轮
            if (next_word == EOS).all():
                break                                  # 全部样本生成完毕
        return ys

07训练与推理：一枚硬币的两面

7.1 训练：并行计算，一次到位

再强调一次这个最容易被忽略的事实：训练时解码器不是逐词运行的。我们把整个目标序列（右移一位）一次性喂入，靠因果掩码保证每个位置只见过去，于是 10 个词的句子一次前向就同时产生 10 个"下一步预测"，10 个位置一起算交叉熵损失、一起反向传播。这种"并行教师强制"正是 Transformer 训练效率碾压 RNN 的根本原因。

训练推理
解码器输入标准答案（右移一位）自己已生成的词
运行方式整句并行，一次前向自回归循环，逐词生成
掩码作用保证因果性（不许抄未来答案）天然因果（未来还不存在），掩码退化为形状对齐
速度瓶颈序列长度平方的注意力每生成一个词都要重算一遍解码器

7.2 推理的加速钥匙：KV Cache

朴素推理有个巨大浪费：生成第 t 个词时，前面 t−1 个词的 K、V 投影其实没变，却要整段重算。KV Cache 把历史轮次的 K、V 缓存下来，每轮只计算新 token 的 Q、K、V 并追加——把每步复杂度从 O(t²) 降到 O(t)。代价是显存占用随上下文线性增长，这正是"长上下文很贵"的直接原因，也是 GQA/MQA（第 8 章）要解决的问题。

7.3 解码策略：贪心、采样与束搜索

  • 贪心（Greedy）：每步取概率最高的词。简单快，但容易陷入"车轱辘话"。argmax 即可（6.12 节已实现）。
  • 采样（Sampling）：按概率分布抽签，配合温度（temperature）控制随机性——温度越高越发散，越低越保守。ChatGPT 式对话模型的常用方式，另可加 top-k / top-p 截断。
  • 束搜索（Beam Search）：同时保留 k 条最优路径（如 k=4），最后选总概率最高的完整序列。翻译等"有标准答案"的任务用它能涨点，开放式生成反而容易呆板。

08Transformer 家族与现代演进

8.1 三大流派：只用一半，或全都要

原论文是完整 的 Encoder-Decoder。但很快大家发现：按任务需要，拆开单用效果也很好。由此形成三大流派，几乎覆盖了今天所有知名模型：

流派代表模型注意力形式典型任务
Encoder-only BERT、RoBERTa、ALBERT 双向自注意力（每个词能看全句） 理解类：分类、抽取式问答、语义匹配
Decoder-only GPT 系列、LLaMA、Qwen、DeepSeek 因果自注意力（只看左边，即掩码自注意力） 生成类：对话、写作、代码；今天的 LLM 主流
Encoder-Decoder T5、BART、原始 Transformer 编码器双向 + 解码器因果 + 交叉注意力 序列到序列：翻译、摘要、语音识别

BERT 的预训练方式是"完形填空"（随机遮住 15% 的词让模型猜，双向注意力正合适）；GPT 的预训练方式是"预测下一个词"（正是我们 6.12 节写的自回归，因果掩码保证不抄答案）。ChatGPT 本质上就是一个超大的"GPT + 预训练 + 指令微调 + 人类反馈强化学习（RLHF）"。

8.2 跨界：Vision Transformer（ViT）

2020 年，ViT 把一张图切成 16×16 的小方块（patch），每个 patch 当作一个"词"（展平后线性投影成向量），加上位置编码后直接丢进标准编码器——图像分类效果媲美甚至超越 CNN。这证明了 Transformer 是一个与模态无关的序列处理架构：只要你能把数据表示成 token 序列（文字、图像块、音频帧、蛋白质序列、动作片段……），它就能处理。

09总结与延伸阅读

9.1 一页纸回顾

  1. 动机：RNN 无法并行、长程依赖衰减 → 用全连接的 Self-Attention 取代逐词接力。
  2. 核心公式：Attention(Q, K, V) = softmax(QKT/√dk)·V；打分 → 缩放 → 归一化 → 加权。
  3. 多头：h 个头在各自子空间关注不同模式，拼接融合，总代价不变。
  4. 位置编码：注意力天生无序，用 sin/cos 把位置加进向量。
  5. 架构：编码器（自注意力 + FFN）×6 理解输入；解码器（掩码自注意力 + 交叉注意力 + FFN）×6 生成输出；每个子层都套残差 + LayerNorm。
  6. 训练：右移一位 + Teacher Forcing + 因果掩码 = 并行训练生成模型；交叉熵损失；warmup 学习率。
  7. 推理：自回归逐词生成，KV Cache 加速；贪心/采样/束搜索三选一。
  8. 后代：BERT（双向理解）、GPT（因果生成）、T5（ seq2seq ）、ViT（图像）、以及 RoPE/GQA/FlashAttention 等现代组件。

9.2 检验学习效果的几个问题

Q1：为什么除以 √dk 而不是 dk？
点积的方差是 dk，标准差是 √dk。除以标准差（而非方差）才能把分数的尺度归一到 ~1 的量级，正好落在 softmax 的"敏感但不饱和"区间。
Q2：自注意力为什么需要位置编码，CNN 需要吗？
自注意力的输出对输入排列是等变的（打乱词序只会打乱输出行序），本身无法区分顺序，必须显式注入。卷积核在固定网格上滑动，天然绑定空间位置，所以 CNN 不需要额外位置信息。
Q3：训练和推理时，解码器的运行方式有何不同？
训练时整句并行输入（Teacher Forcing + 因果掩码防作弊），一次算出所有位置的损失；推理时无答案可抄，只能自回归：每步取最后位置的预测拼回输入，循环至 <eos>；KV Cache 可避免重复计算历史 K/V。
Q4：BERT 和 GPT 的注意力有什么本质区别？
BERT 用双向注意力（无因果掩码），每个词能看全句，适合理解类任务；GPT 用因果掩码注意力（只看左侧历史），适合逐词生成。前者预训练做"完形填空"，后者做"预测下一词"。
Q5：残差连接和 LayerNorm 各自为什么不可少？
残差提供恒等通路，保证深层网络梯度能直达底层（可训性）；LayerNorm 稳定每层输出的数值分布，防止层层堆叠后数值漂移（稳定性）。二者组合是深堆叠的"脚手架"。
